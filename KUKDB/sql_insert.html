INSERT

  • The INSERT statement is Data Manipulation Language (DML) command, it is used to add new rows of data to a table.

INSERT statement is used to:

  • Insert single rows or multiple rows into a table.
  • Add values to either all columns in a row or only specified columns.
  • Insert data based on values from another table using the INSERT INTO ... SELECT form.

Basic Syntax

1. Inserting Single Row

INSERT INTO table_name ( column1, column2, . . . )
VALUES ( value1, value2, . . .) ;

2. Inserting Multiple Rows

INSERT INTO table_name ( column1, column2, . . . )
VALUES ( value1, value2, . . .) ,
VALUES ( value1, value2, . . .) ;

3. Inserting Data from Another Table

INSERT INTO table_name ( column1, column2, . . . )
SELECT column1, column2, . . .
FROM another_table ,
WHERE condition ;

Examples

  • Add/Insert a single row to the employees table
INSERT INTO employee ( EmpID, First_name, Last_name, department_name,location )
VALUES ( 101, 'Kumar', 'Kanaka', 'Finance', 'India') ;

  • Insert Multiple rows to the employees table
INSERT INTO employee ( EmpID, First_name, Last_name, department_name,location )
VALUES ( 101, 'Kumar', 'Kanaka', 'Finance', 'India' ) ,
( 102, 'Harsh', 'Thammi', 'Product', 'New York' ) ;

  • Inserting Only Specific Columns
INSERT INTO employee ( EmpID, First_name, Last_name )
VALUES ( 104, 'John', 'Rises' ) ;
  • In above example, columns department_name and location will be set to NULL or its default value if defined.

  • Inserting Data from Another Table: - Copy data from the archived_employees table to the employees table.
INSERT INTO employee ( EmpID, First_name, Last_name, department_name, location )
SELECT employee_id, fname, lname, dept_name ,location
FROM archived_employees
WHERE dept_name = ' Sales' ;

  • Inserting Data Using Default Values: - Some databases allow inserting rows and using DEFAULT values where available
INSERT INTO employee ( EmpID, First_name, Last_name, department_name, location )
VALUES ( DEFAULT , 'Mark', ' Robert', 'HR', 'Germany' ) ;
  • Here, the employee_id will be set to its default value (often an auto-incremented number) if it’s defined as such in the table schema.

Advanced Use Cases for INSERT


1. Using INSERT IGNORE or ON DUPLICATE KEY UPDATE (MySQL)


In MySQL, use INSERT IGNORE to skip inserting rows with duplicate keys instead of throwing an error.

INSERT IGNORE INTO employee ( EmpID, First_name, Last_name, department_name, location )
VALUES ( 105, 'sham', ' Green', 'Sales', 'Hong Kong' ) ;

  • Use ON DUPLICATE KEY UPDATE to handle conflicts by updating instead of inserting.
INSERT INTO employee ( EmpID, First_name, Last_name, department_name, location )
VALUES ( 105, 'sham', ' Green', 'Sales', 'Hong Kong' )
ON DUPLICATE KEY UPDATE ( 105, 'sham', ' Green', 'Sales', 'Hong Kong' ) ;

2. Using RETURNING (PostgreSQL and Oracle)


In PostgreSQL and Oracle, use the RETURNING clause to capture values (like auto-generated IDs) from newly inserted rows.

INSERT INTO employee ( First_name, Last_name, department_name, location )
VALUES ( 'Satee', ' Anna', 'IT', 'India' )
RETURNING EmpID ;

3. Using OUTPUT (SQL Server )


SQL Server also supports the INSERT statement and allows OUTPUT to capture the inserted rows.

INSERT INTO employee ( EmpID, First_name, Last_name, salary )
VALUES ( 107, 'Reeti', ' Mona', 4500 ) ;

4. Oracle

Oracle supports inserting data using sequences for auto-increment.

INSERT INTO employee ( EmpID, First_name, Last_name, salary )
VALUES ( emp_seq.NEXTVAL, 'Tom', ' Hasin', 10000 ) ;

Common Errors in INSERT Statements


  • NOT NULL Constraint Violation : Occurs when you skip a NOT NULL column and don't provide a default value
INSERT INTO employee ( EmpID, salary )
VALUES ( 109, 20000 ) ;
- - Error: First Name and Last Name cannot be NULL

  • Duplicate Key Error: Happens if you try to insert a row with a primary key that already exists.
    • Solution: Use INSERT IGNORE or ON DUPLICATE KEY UPDATE (MySQL).
  • Data Type Mismatch: Occurs when inserting a value with a type incompatible with the column's data type.
INSERT INTO employee ( EmpID, salary )
VALUES ( 111, 'TenThousand' ) ;
- - Error: Salary should be a numeric value

  • Constraint Violations : Be mindful of unique and foreign key constraints, as violating them will prevent inserts.

Do’s and Don’ts When Using INSERT

Do's :-

  • Do use prepared statements for dynamic inserts in application code to prevent SQL injection.
  • Do specify column names explicitly for clarity and to reduce errors if the table schema changes.
  • Do insert in batches for better performance when dealing with large datasets.

Don'ts :-

  • Don’t rely on implicit order of columns when not specifying column names, as this can lead to errors if the table structure changes.
  • Don’t hard-code primary key values (like employee_id) if the column is set to auto-increment or has unique constraints, as this may cause conflicts.
  • Don’t insert unvalidated or incomplete data - Ensure data integrity by validating inputs before adding rows.
