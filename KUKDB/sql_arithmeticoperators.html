Arithmetic Operators

Arithmetic operators are used to perform basic mathematical calculations in SQL.

  • They are applied within queries to manipulate and calculate values in expressions or directly in table data.
  • They can be applied to numeric columns, constants, and expressions.
Arithmetic Operators are
Operator Description Purpose Example
+ Addition Used to add two or more numeric values. It works like the plus symbol in basic mathematics. 10 + 20 = 30
- Subtraction Used to subtract one numeric value from another. It is similar to the minus symbol in basic mathematics. 100 - 20 = 80
* Multiplication Used to multiply two numeric values. It functions like the multiplication symbol in mathematics. 5 * 6 = 30
/ Division Used to divide one numeric value by another. It performs the division operation as in basic mathematics. 50/5 = 10
% Modulus (remainder after division) Returns the remainder of a division operation. Commonly used to check for even/odd values or to cycle through numbers. 7/2 = 1

NOTE : -

Advanced Scenarios

Example 1: Arithmetic in WHERE Clause

Find employees with a yearly salary (calculated as monthly_salary * 12) greater than 500,000.

SELECT * FROM EMPLOYEE WHERE SALARY *12 > 500000 ;

Example 2: Combining Multiple Operators

Calculate total profit percentage

SELECT Product_id,
(revenue - cost) / revenue * 100 AS profit_percentage
FROM sales ;

Order of Precedence for Arithmetic Operators

Operator Precedence Level Associativity Description
* , / , % High Left to Right Multiplication, Division, Modulus
+ , - Low Left to Right Addition, Subtraction

Key Points :

  • Operators with higher precedence (*, /, %) are evaluated before those with lower precedence (+, -).
  • When operators have the same precedence, evaluation proceeds from left to right.
  • Parentheses () can override the default precedence and force specific order of execution.

Sample Example

SELECT 10 + 20 * 2 - 5 / 5 FROM DUAL ; - - In Oracle
SELECT 10 + 20 * 2 - 5 / 5 AS result ; - - In Other Databases
- - result = 49

Step-by-Step Execution of above examples

  • Evaluate Multiplication (*) : 20 * 2= 40
  • Evaluate Division (/) : 5 / 5 = 1
  • Evaluate Addition (+) : 10 + 40 = 50
  • Evaluate Subtraction (-) : 50 - 1 = 49

Sample Example

SELECT 10 + 20 * 2 - 5 / 5 AS Final_result FROM DUAL ; - - In Oracle
SELECT 10 + 20 * 2 - 5 / 5 AS result ; - - In Other Databases
- - result = 49

Using Parentheses for Explicit Precedence


To change the order of execution, use parentheses. Operations inside parentheses are always evaluated first.

Example with Parentheses

SELECT ( 10 + 20 ) * ( 2 - 5 / 5 ) AS Final_result FROM DUAL ; - - In Oracle
SELECT ( 10 + 20 ) * ( 2 - 5 / 5 ) AS result ; - - In Other Databases
- - result = 30

Step-by-Step Execution of above exampls

  • Evaluate Division (/) in Parentheses: 5 / 5 = 1.
  • Evaluate Subtraction (-) in Parentheses : 2 - 1 = 1.
  • Evaluate Addition (+) in Parentheses: 10 + 20 = 30.
  • Evaluate Multiplication (*): 30 * 1 = 30.

Example 3: Handling NULL Values

If any operand is NULL, the result of the operation is NULL


  • Let's assume, for EMPID = 107 salary was credited (null).
EMP_ID ENAME CITY SALARY DOJ
107 Vardhan Noida (null) 20-07-2023

SELECT EMP_ID , ENAME, SALARY, SALARY / 30 AS Day_Salary ,
SALARY + 5000 AS NEW_SALARY ,
SALARY - 2300 AS NET_AMOUNT,
SALARY * 12 AS Annual_Income
FROM EMPLOYEE ;

Output

EMP_ID ENAME SALARY Day_Salary NEW_SALARY NET_AMOUNT Annual_Income
107 Vardhan (null) (null) (null) (null) (null)

Solution:

SELECT EMP_ID , ENAME, SALARY, COALESCE(SALARY , 0 ) / 30 AS Day_Salary ,
COALESCE(SALARY , 0 ) + 5000 AS NEW_SALARY,
COALESCE(SALARY , 0 ) - 2300 AS NET_AMOUNT ,
COALESCE(SALARY , 0 ) * 12 AS Annual_Income
FROM EMPLOYEE ;

Output

EMP_ID ENAME SALARY Day_Salary NEW_SALARY NET_AMOUNT Annual_Income
107 Vardhan (null) 0 -1200 0 0

Example 4: Using Arithmetic in GROUP BY

Calculate average profit for products with a cost greater than 100.


SELECT product_id , AVG( revenue - cost ) AS avg_profit
FROM sales
GROUP BY product_id
HAVING AVG( revenue - cost ) > 100 ;


Example 5: Conditional Arithmetic

Compute a 10% tax for products priced above $100, otherwise, apply a 5% tax.


SELECT EMP_ID , ENAME , SALARY ,
    CASE
      WHEN SALARY >= 50000 THEN SALARY * 0.2
      WHEN SALARY BETWEEN 30000 AND 50000 THEN SALARY * 0.1
      ELSE SALARY
    END AS TaxAmount
FROM EMPLOYEE ;


Example 6: Percentage Contribution

Calculate the percentage of sales contributed by each product.


SELECT ProductID , Price * Quantity AS ProductRevenue ,
        ( Price * Quantity ) * 100.0 / SUM( Price * Quantity ) OVER ( ) AS PercentageContribution
FROM Sales ;

- - SUM(Price * Quantity) OVER () computes the total revenue.
- - (Price * Quantity) * 100.0 / SUM(...) calculates the percentage contribution.

Common Errors :-

1. Division by Zero


  • Cause :- Using / where the divisor is zero.
  • Fix :- Use a conditional check to avoid zero division (NULLIF)
    • SELECT Price / NULLIF( Discount, 0 ) AS SafeDivision
    FROM Products ;

2. Data Type Mismatch


  • Cause :- Applying arithmetic on non-numeric data types (e.g., strings).
  • Fix :- Ensure the columns are numeric or use CAST/CONVERT.
    • SELECT CAST( Price AS FLOAT) * Quantity AS Total
    FROM Products ;

3. Overflow Errors

  • Cause :- Operations exceeding the data type's limit (e.g., adding large numbers to an INT column).
  • Fix :- Use appropriate data types like BIGINT or DECIMAL.

  • Fully supports arithmetic operations.
  • Division by zero raises an error. Handle it using CASE.

  • Supports all arithmetic operations, including modulus (%).
  • Division by zero raises an error. Handle it using TRY...CATCH or NULLIF.
    • Here give link to example.

MySQL :

  • Similar to SQL Server, supports % for modulus.
  • Division by zero results in NULL. Use IF or CASE for handling:.
    • Here give link to example.
    SELECT order_id,
    IF( quantity = 0, NULL , total_price / quantity ) AS unit_price
    FROM orders ;

Best Practices for Arithmetic Operators

  • Handle Division by Zero :- Use CASE, IF, or NULLIF to avoid errors
  • Null-Safe Operations :- Always handle NULL values with COALESCE or similar functions.
  • Optimize Expressions :- Avoid redundant calculations in SELECT or WHERE. Instead, use computed columns or common table expressions (CTEs).
  • Be Aware of Data Types :- Ensure operands are compatible data types (e.g., integer with integer, decimal with decimal).
  • Avoid Complex Expressions in WHERE :- Use pre-computed values or indexed columns to improve query performance.
