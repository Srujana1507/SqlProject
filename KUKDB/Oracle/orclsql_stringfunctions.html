String Functions in Oracle SQL

String functions in Oracle SQL are built-in functions that allow manipulation and transformation of character data (VARCHAR2, CHAR, CLOB, etc.).


These functions allow you to modify, format, extract, and analyze string values in various ways.



Key Features of String Functions

Feature Description
String manipulation Modify strings by concatenating, replacing, or trimming characters.
Case Conversion Convert text to uppercase, lowercase, or capitalize the first letter.
Substring Extraction Extract a portion of a string based on position and length.
Pattern Matching Perform pattern-based searches using LIKE or REGEXP functions.
Length Calculation Determine the length of a string in characters or bytes.
Whitespace Handling Remove leading/trailing spaces from strings.
Encoding & Decoding Encode or decode strings (e.g., TRANSLATE, REPLACE).
Numeric & Date Conversion Convert numbers and dates to string formats and vice versa.

String Functions in Oracle SQL

Function Description Use Case
CHR(number) Returns the character for the given ASCII code. CHR(65) FROM dual; → 'A'
UPPER(str) Converts all characters to uppercase. UPPER('oracle') → 'ORACLE'
LOWER(str) Converts all characters to lowercase. LOWER('ORACLE') → 'oracle'
INITCAP(str) Capitalizes the first letter of each word. INITCAP('oracle sql') → 'Oracle Sql'
CONCAT(str1, str2) Concatenates two strings. CONCAT('Oracle', ' SQL') → 'Oracle SQL'
LENGTH(str) Returns the number of characters in a string. LENGTH('Oracle') → 6
SUBSTR(str, start, length) Extracts a substring from a given string. SUBSTR('Oracle SQL', 1, 6) → 'Oracle'
INSTR(str, substr, start, occurrence) Finds the position of a substring. INSTR('Oracle SQL', 'SQL') → 8
REPLACE(str, old_substr, new_substr) Replaces occurrences of a substring. REPLACE('Oracle SQL', 'SQL', 'PL/SQL') → 'Oracle PL/SQL'
TRANSLATE(str, from_chars, to_chars) Replaces characters using mapping. TRANSLATE('SQL', 'SQ', 'PL') → 'PLL'
TRIM( [ [ LEADING | TRAILING | BOTH ] trim_character FROM ] trim_source ) Remove leading or trailing characters (or both) from a string. TRIM(' Hello World ')
LTRIM(string, trim_chars) Removes leading occurrences of a character. LTRIM('000123', '0') → '123'
RTRIM(str, char) Removes trailing occurrences of a character. RTRIM('123000', '0') → '123'
LPAD(string, length, pad_string) Left-pads a string with a specified character. LPAD('99', 5, '0') FROM dual; → '00099'
RPAD(string, length, pad_string) Right-pads a string with a specified character. RPAD('ABC', 5, '_') FROM dual; → 'ABC__'
REGEXP_LIKE(str, pattern) Checks if a string matches a pattern. REGEXP_LIKE('Oracle123', '[0-9]') → TRUE
REGEXP_REPLACE(str, pattern, replacement) Replaces a pattern with another string. REGEXP_REPLACE('Oracle123', '[0-9]', '') → 'Oracle'
REGEXP_SUBSTR(str, pattern, position, occurrence) Extracts a substring using a regex pattern. REGEXP_SUBSTR('abc123xyz', '[0-9]+') → '123'
ASCII(string) Returns the ASCII code of the first character. ASCII('A') FROM dual; → 65
SOUNDEX(string) Returns a phonetic representation of a string. SOUNDEX('Smith') FROM dual; → 'S530'
DIFFERENCE(str1, str2) Returns a value representing the phonetic similarity between two strings. DIFFERENCE('SMITH', 'SMYTH') FROM dual; → 4

Advantages of String Functions in Oracle SQL

Advantage Description
Data Cleansing Helps clean data by removing unwanted characters and spaces.
Improved Readability Case conversion functions enhance data presentation.
Enhanced Data Formatting Helps in formatting and modifying string data efficiently.
Efficient String Searching Functions like INSTR and REGEXP_LIKE allow for advanced text searches.
String Comparison Functions like SOUNDEX help in fuzzy matching.
Supports Internationalization Works with multi-byte character sets like Unicode.
Supports Regular Expressions Provides powerful pattern-matching capabilities.
Simplifies Queries Reduces the complexity of SQL queries.
Data Extraction Extracts necessary information from large strings.

Disadvantages of String Functions in Oracle SQL

Disadvantage Description
Case-Sensitivity Issues Some functions are case-sensitive, requiring explicit conversions.
Performance Overhead Functions like REPLACE and TRANSLATE can impact performance for large datasets.
Limited to Character Data Cannot be used directly on numeric or date data without conversion.
Complexity in Large Queries Using multiple string functions in a query can make it harder to read and debug.
May Require Casting Some functions require explicit type conversion when used with other data types.
Memory Usage Processing large text data with string functions can consume more memory.


Limitations of String Functions in Oracle SQL

Limitation Description Example Suggestion
Maximum String Length Constraints VARCHAR2 limited to 4000 bytes (unless MAX_STRING_SIZE = EXTENDED), CLOB supports up to 4GB. CONCAT('Very long string...', 'Another long string...') → ORA-01489: Result of string concatenation is too long Use CLOB for large text, or break long strings into smaller parts.
Function Behavior Differences in CLOB vs. VARCHAR2 Some functions (RPAD(), LPAD(), CONCAT()) do not work directly with CLOB. CONCAT(CLOB_column, 'text') → Error. Convert CLOB to VARCHAR2 using TO_CHAR().
Performance Overhead Multiple string functions in queries slow down execution. UPPER(LOWER(INITCAP(column))) causes unnecessary processing. Optimize function usage, avoid redundant functions.
Case Sensitivity Issues Oracle is case-sensitive in string comparisons. SELECT * FROM employees WHERE name = 'Uday'; → Won’t match 'uday'. Use UPPER(column) = UPPER(value) for case-insensitive search.
CONCAT() Limitation CONCAT() can only join two strings at a time. CONCAT('Hello', ' World', '!') → Error. Use `
String Positioning Errors SUBSTR(), INSTR() fail or return incorrect results if the position is out of range. SUBSTR('Oracle', 10, 2) → Returns NULL. Validate positions before using SUBSTR() or INSTR().
TRIM(), LTRIM(), RTRIM() Limitations Only removes single characters, not full words. TRIM('abc' FROM 'abcOracleabc') → Removes only 'abc' from start and end. Use REPLACE() for removing specific words.
Regular Expressions Limitations Regex functions (REGEXP_LIKE(), REGEXP_SUBSTR()) are slower than standard string functions. REGEXP_LIKE(column, '[0-9]') can be slower than INSTR(column, '1') > 0. Use simpler functions (LIKE, INSTR(), REPLACE()) if possible.
Character Set and Encoding Issues LENGTH(), LENGTHB() return different values depending on character encoding. LENGTH('á') → 1 in UTF-8, but 2 in UTF-16. Ensure consistent character set usage across database and application.


Common Errors in String Functions

Error Code Cause Solution
ORA-01756: Quoted string not properly terminated Missing or incorrect use of single quotes in string literals. Ensure all string literals are enclosed in single quotes (''), not double quotes. Example: SELECT 'Oracle's SQL' FROM dual; → Error. Fix: SELECT 'Oracle''s SQL' FROM dual;
ORA-06502: PL/SQL: numeric or value error: character string buffer too small Attempting to store a string larger than the defined column/variable size. Increase the column/variable size (VARCHAR2(100) → VARCHAR2(255)) or truncate the string before insertion.
ORA-12728: Invalid character set specified Using an unsupported character set in string conversion. Ensure the specified character set is valid. Example: SELECT CONVERT('Test', 'INVALID_CHARSET') FROM dual; → Error. Fix: Use SELECT CONVERT('Test', 'AL32UTF8') FROM dual;.
ORA-00904: Invalid identifier Using an invalid column name in a string function. Ensure the column name exists and is correctly referenced. Example: SELECT UPPER(non_existing_column) FROM employees; → Error.
ORA-00909:Invalid number of arguments A function like CONCAT() was used with more than two arguments. Use `
ORA-01830: Date format picture ends before converting entire input string Using an incorrect format mask in string-to-date conversion. Ensure the format matches the input string. Example: TO_DATE('2024-02-11', 'DD-MON-YYYY') → Error. Fix: TO_DATE('11-FEB-2024', 'DD-MON-YYYY').
ORA-00932:Inconsistent datatypes: expected CHAR got CLOB Using a CLOB column with a string function that expects VARCHAR2. Use DBMS_LOB.SUBSTR() before applying functions like UPPER() or LOWER(). Example: SELECT UPPER(DBMS_LOB.SUBSTR(clob_column, 4000)) FROM table_name;
ORA-01858: A non-numeric character was found where a numeric was expected Mixing numeric and string data types incorrectly. Use TO_CHAR() for conversion. Example: SELECT TO_DATE('abc', 'DD-MM-YYYY') FROM dual; → Error. Fix: Provide a valid date format.
ORA-22835: Buffer too small for CLOB to CHAR conversion Attempting to convert a CLOB to VARCHAR2 where the length exceeds the limit. Use DBMS_LOB.SUBSTR() to extract a portion of the CLOB. Example: SELECT DBMS_LOB.SUBSTR(clob_column, 4000) FROM table_name;


Performance Tips for Using String Functions

  • Avoid Using Functions in WHERE Clauses – Using functions like UPPER() in WHERE conditions prevents index usage and can slow queries.
  • Use VARCHAR2 Instead of CHAR – CHAR is fixed-length and consumes extra space.
  • Leverage Indexing for Search Operations – Use indexed columns for filtering instead of applying functions.
  • Use SUBSTR Instead of REGEXP Functions – Regular expressions are powerful but slower compared to simpler substring operations.
  • Minimize Concatenation in Large Queries – Excessive use of || operator can degrade query performance.



Do's and Don'ts of String Functions

Do's Don'ts
Use UPPER(), LOWER() for case-insensitive comparisons. Don’t use string functions in WHERE conditions if possible (it affects performance).
Use LENGTH() to validate non-empty strings before processing. Don’t concatenate long strings without checking their length (to avoid ORA-01489).
Use INSTR() for faster substring searches instead of LIKE. Don’t use CONCAT() for more than two strings; use `
Use TRIM(), LTRIM(), RTRIM() to clean user input. Don’t use REGEXP_* functions if simple functions like REPLACE() can achieve the same result.




UPPER() Function in Oracle SQL


The UPPER() function converts all characters in a string to uppercase.


Syntax

UPPER (string)

Key Features of UPPER()

  • Converts lowercase letters to uppercase.
  • Non-alphabetic characters remain unchanged.
  • Useful for case-insensitive comparisons.

Examples

Scenario 1:- Convert all customer names to uppercase for uniformity in reports.

SELECT customer_id, UPPER ( customer_name ) AS CUST_NAME
FROM customers ;

Scenario 2:- Retrieve customer details based on an email search without case sensitivity.

SELECT * FROM customers
WHERE UPPER (email) = UPPER ('uday.thammi@example.com' ) ;

Scenario 3:- Ensure that all employee names are displayed in uppercase in payroll processing.

SELECT employee_id, UPPER ( employee_name ) AS EMP_NAME , salary
FROM payroll ;

Scenario 4:- Create usernames using the first letter of the first name and full last name, all in uppercase.

SELECT employee_id, UPPER ( SUBSTR (first_name, 1, 1) || last_name) AS username
FROM employees ;

Scenario 5:- Ensure all product codes are stored in uppercase before inserting into the database.

INSERT INTO products (product_id, product_code, description) VALUES ( , UPPER ('abcd123' ), 'New Electronic Item' )
;


LOWER() Function in Oracle SQL


The LOWER() function converts all characters in a string to lowercase.


Syntax

LOWER (string)

Key Features of LOWER()

  • Converts uppercase letters to lowercase.
  • Non-alphabetic characters remain unchanged.
  • Useful for case-insensitive comparisons.

Examples

Scenario 1:- Ensure all email addresses in the database are stored in lowercase to maintain consistency.

SELECT customer_id, LOWER ( email ) AS EMAIL
FROM customers ;

Scenario 2:- Allow users to log in without case sensitivity when entering their usernames.

SELECT * FROM users
WHERE LOWER (username) = LOWER ('UdayHarsha0123' ) ;

Scenario 3:- Convert product names to lowercase to generate REO-friendly URLs.

SELECT product_id, LOWER ( REPLACE (product_name, ' ' , '-' ) ) AS Reo_url
FROM products ;

Scenario 4:- Convert all city names to lowercase for better search accuracy.

UPDATE addresses
SET city = LOWER ( city ) ;

Scenario 5:- Convert all customer feedback to lowercase before performing text analytics.

SELECT feedback_id, LOWER ( comments) AS feedback
FROM customer_feedback ;


INITCAP() Function in Oracle SQL


The INITCAP() function capitalizes the first letter of each word in a string while converting all other letters to lowercase.


Syntax

INITCAP (string)

Key Features of INITCAP()

  • Capitalizes the first letter of each word.
  • Converts all other letters to lowercase.
  • Useful for formatting names, addresses, and titles.
  • Non-alphabetic characters act as word separators.

Examples

Scenario 1:- Ensure all customer names are properly capitalized for better readability.

SELECT customer_id, INITCAP ( full_name ) AS Full_Name
FROM customers ;

Scenario 2:- Convert book titles to title case for consistent display.

SELECT book_id, INITCAP ( book_title ) AS Booktitle
FROM books ;

Scenario 3:- Ensure city and street names in an address database are properly formatted.

SELECT address_id, INITCAP (city) AS City,
INITCAP (street) AS Street
FROM addresses ;

Scenario 4:- Display product names in title case for e-commerce product listings.

SELECT product_id, INITCAP ( product_name ) AS Product_Name
FROM products ;

Scenario 5:- Convert job titles to title case in the HR database for uniformity.

SELECT employee_id, INITCAP ( job_title ) AS Job_Title
FROM employees ;


LENGTH(str) Function in Oracle SQL


The LENGTH() function returns the number of characters in a given string, including spaces and special characters.


Syntax

LENGTH (string)

Key Features

  • Counts characters, including spaces and special symbols.
  • Returns NULL if the input is NULL.
  • Does not count trailing spaces in CHAR datatype due to implicit padding.
  • Useful for validation, reporting, and text analysis.

Examples

Scenario 1:- Identify customers with short names (less than 5 characters) to validate name data.

SELECT customer_id, full_name, LENGTH ( full_name ) AS name_length
FROM customers
WHERE LENGTH ( full_name ) < 5 ;

Scenario 2:- Ensure users have passwords of at least 8 characters.

SELECT user_id, password, LENGTH ( password ) AS Length_of_Password
FROM users
WHERE LENGTH ( password ) < 8 ;

Scenario 3:- Retrieve the longest product name from the products table.

SELECT product_name,
LENGTH ( product_name ) AS Product_Length
FROM products ORDER BY LENGTH ( product_name ) DESC
FETCH FIRST 1 ROW ONLY ;

Scenario 4:- Find email addresses that are too short (less than 10 characters) to check for possible errors.

SELECT email, LENGTH ( email ) AS Email_Length
FROM users
WHERE LENGTH ( email ) < 10 ;

Scenario 5:- Categorize blog posts based on the length of their titles.

SELECT blog_id, title,
    CASE
      WHEN LENGTH (title) < 20 THEN 'Short'
      WHEN LENGTH (title) BETWEEN 20 AND 50 THEN 'Medium'
      ELSE 'Long'
END AS title_category
FROM blog_posts ;


LENGTHB(str) Function in Oracle SQL


The LENGTHB() function returns the number of bytes used to store a string in Oracle SQL.


This is different from LENGTH(), which counts the number of characters. The number of bytes may differ based on the character set used.


Syntax

LENGTHB (string)

Key Features

  • Returns the storage size of a string in bytes, not characters.
  • Useful for databases with multi-byte character sets (e.g., UTF-8).
  • Helps in memory optimization and storage calculations.
  • Returns NULL if the input is NULL.

Examples

Scenario 1:- Find out how much storage different customer names occupy in bytes.

SELECT customer_id, full_name,
LENGTH ( full_name ) AS Char_Count
LENGTHB ( full_name ) AS byte_count
FROM customers ;

Scenario 2:- Identify product names that consume more than 50 bytes of storage.

SELECT product_id, product_name, LENGTHB ( product_name ) AS byte_size
FROM products
WHERE LENGTHB ( product_name ) > 50 ;

Scenario 3:- Find customer usernames that exceed a 20-byte storage limit.

SELECT username,
LENGTHB ( username ) AS bytes_used
FROM users WHERE LENGTHB ( username ) > 20 ;

Scenario 4:- Compare character and byte size of email addresses to optimize storage.

SELECT email, LENGTHB ( email ) AS byte_count
FROM users ;

Scenario 5:- Find blog post titles that might exceed storage limits due to multi-byte characters.

SELECT blog_id, title,
LENGTHB (title) AS storage_bytes
FROM blog_posts
WHERE LENGTHB (title) > 100 ;


Key Difference: LENGTH() vs. LENGTHB()

Function Measures Use Case
LENGTH() Number of characters String length validation
LENGTHB() Number of bytes Storage calculation in multi-byte character sets


CONCAT(str1, str2) Function in Oracle SQL


The CONCAT() function in Oracle SQL is used to combine (concatenate) two strings into a single string.


It accepts exactly two arguments. If more than two strings need to be concatenated, the || (double pipe) operator or CONCAT(CONCAT(str1, str2), str3) must be used.


Syntax

CONCAT (string1, string2)

- - string1: The first string.
- - string2: The second string.
- - Returns a single concatenated string.

Key Features

  • Accepts only two arguments.
  • Returns NULL if either of the strings is NULL.
  • To concatenate more than two strings, use || or nest CONCAT().

Examples

Scenario 1:- Combine first name and last name of customers into a full name.

SELECT customer_id,
CONCAT ( full_name, ' ' || last_name) AS full_name
FROM customers ;

Scenario 2:- Generate company email addresses in the format firstname.lastname@company.com.

SELECT employee_id,
CONCAT (CONCAT ( LOWER ( full_name, ' ' ) , || LOWER (last_name)) || '@company.com' ) AS email_address
FROM employees ;

Scenario 3:- Concatenate product category and product ID to form a unique product code.

SELECT product_id, category,
CONCAT ( category, product_id ) AS unique_code
FROM products ;

Scenario 4:- Generate a meaningful order description by combining order ID and order date.

SELECT order_id,
    CONCAT ( 'Order ' , order_id) || ' places on ' || TO_CHAR (order_date, 'YYYY-MM-DD' ) AS order_description
FROM orders ;

Scenario 5:- Construct URLs using base domain and page name stored in a database.

SELECT page_name,
    CONCAT ( 'https://www.mywebsite.com/ ' , page_name) AS full_url
FROM webpages ;


Limitations of CONCAT()

Limitation Description
Only two arguments Accepts only two strings at a time.
Returns NULL if one argument is NULL If either string is NULL, the result is NULL.

Best Practices

  • Use || when concatenating multiple strings instead of nesting CONCAT().
  • Handle NULL values using NVL() to prevent NULL results.
  • Use TRIM() if concatenating strings with potential extra spaces.


CHR(number) String Function in Oracle SQL


The CHR() function in Oracle SQL returns the character that corresponds to the given ASCII (or Unicode) code.


Syntax

CHR (number)
- - number → The ASCII/Unicode value of the character to be returned.

Examples

Scenario 1:- Insert a newline (CHR(10)) between address lines for better readability in reports.

SELECT customer_name,
    address_line1 || CHAR (10) || address_line2 AS formatted_address
FROM customers ;

Scenario 2:- Generate tab-separated values using CHR(9).

SELECT employee_id || CHAR (9) || name || CHAR (9) || salary AS csv_format
FROM employees ;

Scenario 3:- Retrieve employee names and append the copyright symbol (CHR(169)) next to company names.

SELECT company_name || ' ' || CHAR (169) AS branded_company
FROM companies ;

Scenario 4:- Remove all carriage return characters (CHR(13)) from product descriptions.

SELECT product_id, REPLACE ( description, CHR (13) , ' ' ) AS cleaned_description
FROM products ;

Scenario 5:- Insert a single quote (') in a dynamic SQL query.

SELECT
    'INSERT INTO employees (name) VALUES (' || CHAR (39) || 'John O''Reilly' || CHAR (39) || ');'
FROM DUAL ;


Commonly Used ASCII Codes in CHR()

ASCII Code Character Use Case
CHR(10) Newline (\n) Formatting multiline text
CHR(9) Tab (\t) Creating tab-separated values
CHR(13) Carriage Return (\r) Removing unwanted line breaks
CHR(39) Single Quote (') Handling quotes in dynamic SQL
CHR(34) Double Quote (") Formatting text with quotes
CHR(64) @ symbol Email address formatting
CHR(169) © (Copyright) Adding special symbols in reports

Limitations of CHR()

Limitation Description
Limited to ASCII/Unicode codes Works only with valid character codes.
OS-dependent behavior Some control characters (CHR(10), CHR(13)) may behave differently across OS.
Difficult to read in queries Using numeric codes instead of characters can reduce query readability.

Best Practices

  • Use CHR() for special characters like newline, tab, and quotes in text formatting.
  • Avoid using control characters (CHR(0)-CHR(31)) unless necessary to prevent unexpected behavior.
  • Combine CHR() with REPLACE() to clean unwanted control characters from data.
  • Use CHR(39) for inserting single quotes inside string literals in dynamic SQL.



ASCII(str) String Function in Oracle SQL


The ASCII(str) function in Oracle SQL returns the ASCII (or Unicode) value of the first character in a given string.


Syntax

ASCII (str)
- - str → The input string (only the first character is evaluated).

Examples

Scenario 1:- Retrieve ASCII values of the first character in usernames to analyze naming conventions.

SELECT username,
    ASCII (username) AS first_char_ascii
FROM users ;

-- A → ASCII 65
-- b → ASCII 98
--C → ASCII 67

Scenario 2:- Sort product names based on the ASCII value of their first character.

SELECT product_name
FROM products
ORDER BY ASCII ( product_name ) ;

Scenario 3:- Find customers whose names start with a non-alphabetic character (like @, #, $, etc.).

SELECT customer_name
FROM customers
WHERE ASCII ( customer_name ) < 65 OR ASCII ( customer_name ) > 122 ;

Scenario 4:- Find employees whose names start with lowercase letters (ASCII 97–122).

SELECT employee_name
FROM employees
WHERE ASCII ( employee_name ) BETWEEN 97 AND 122 ;

Scenario 5:- Identify product codes that start with a number (ASCII 48-57).

SELECT product_code
FROM inventory
WHERE ASCII ( product_code ) BETWEEN 48 AND 57 ;


Limitations of ASCII()

Limitation Description
Only evaluates the first character Does not check ASCII values of the full string.
Limited to single-byte characters May not work correctly for multibyte Unicode characters.
Case-sensitive behavior Lowercase (a-z) and uppercase (A-Z) have different ASCII values.
Not suitable for full-text analysis Can only be used for initial character checks.

Limitations of CHR()

Limitation Description
Limited to ASCII/Unicode codes Works only with valid character codes.
OS-dependent behavior Some control characters (CHR(10), CHR(13)) may behave differently across OS.
Difficult to read in queries Using numeric codes instead of characters can reduce query readability.

Best Practices

  • Use ASCII() for sorting, filtering, and character validation in structured text-based data.
  • Combine ASCII() with SUBSTR() to analyze characters beyond the first one in a string.
  • Be cautious when working with non-English characters, as ASCII may not support extended Unicode.



INSTR(str, substring) Function in Oracle SQL


The INSTR() function in Oracle SQL searches for a substring within a given string and returns the position where the substring first occurs. If the substring is not found, it returns 0.


Syntax

INSTR (string, substring [, start_position [, occurrence]])

- - string: The main string where the search is performed.
- - substring: The substring to find in the main string.
- - start_position (Optional): The position in the string to start searching from (default is 1).
- - occurrence (Optional): Specifies which occurrence of the substring to find (default is 1)

Key Features

  • Returns 0 if the substring is not found.
  • If start_position is negative, it starts searching from the end of the string.
  • If occurrence is greater than the available matches, it returns 0.
  • Case-sensitive by default.

Examples

Scenario 1:- Extract the position of @ in email addresses to split username and domain.

SELECT email,
INSTR ( email, '@' ) AS at_position
FROM customers ;

Scenario 2:- Identify where the first space appears in a full name.

SELECT full_name,
INSTR ( full_name, ' ' ) AS first_space_position
FROM employees ;

Scenario 3:- Locate the position of the second occurrence of - in product codes like ABC-123-XYZ.

SELECT product_code,
    INSTR ( product_code, '-' , 1, 2 )
AS second_dash_position
FROM products ;

Scenario 4:- Find whether the word 'bad' appears in product reviews.

SELECT review_text,
    CASE
      CASE INSTR ( LOWER (review_text), 'bad' ) > 0 THEN 'Negative Review'
      ELSE 'Positive Review'
    END AS review_status
    FROM product_reviews ;

Scenario 5:- Extract the last word from a book title by finding the last space in the title.

SELECT book_title,
    SUBSTR ( book_title, INSTR ( book_title, ' ' , -1) + 1 ) AS last_word
FROM books ;


Limitations of INSTR()

Limitation Description
Case-sensitive by default 'apple' and 'Apple' are treated as different strings. Use LOWER() or UPPER() for case-insensitive searches.
Returns 0 if substring not found Unlike NULL, 0 means substring is absent.

REGEXP_LIKE(str, pattern) in Oracle SQL


The REGEXP_LIKE function in Oracle SQL performs pattern matching using regular expressions. It is similar to LIKE, but more powerful because it allows complex pattern searches.


Syntax

REGEXP_LIKE (string, pattern [, match_parameter])

Parameters:
- - string → The column or value to be tested.
- - pattern → The regular expression pattern to match.
- - match_parameter (optional) → Specifies case sensitivity and multi-line handling:
  • 'i' → Case-insensitive match.
  • 'c' → Case-sensitive match.
  • 'n' → Allows dot (.) to match newlines.
  • 'm' → Treats string as multi-line.

Examples

Scenario 1:- Find all customers with an email ending in "@gmail.com".

SELECT customer_id, email
FROM customers
WHERE REGEXP_LIKE (email, '@gmail\.com$' ) ;

  • @gmail\.com$ → Ensures the email ends ($) with @gmail.com.
  • The \. escapes the dot (.), treating it as a literal dot instead of "any character".

Scenario 2:- Retrieve employees whose phone numbers follow the format (XXX) XXX-XXXX.

SELECT employee_id, phone_number
FROM employees
WHERE REGEXP_LIKE (phone_number, '^\(\d{3}\) \d{3}-\d{4}$' ) ;

  • ^\(\d{3}\) \d{3}-\d{4}$ → Matches:
    • ^ → Start of string.
    • \(\d{3}\) → Three digits inside () (area code).
    • \d{3}-\d{4}$ → Three digits, followed by -, then four digits.
    • $ → End of string.

Scenario 3:- Select customers whose names contain only letters (no numbers or special characters).

SELECT customer_name FROM customers
WHERE REGEXP_LIKE (customer_name, '^[A-Za-z]+$' ) ;

  • ^[A-Za-z]+$ → Ensures the entire name consists of only uppercase or lowercase letters.
  • + → Matches one or more letters.

Scenario 4:- Retrieve product codes containing both letters and numbers.

SELECT product_code
FROM inventory
WHERE REGEXP_LIKE (product_code, '.*[A-Za-z].*[0-9].*|.*[0-9].*[A-Za-z].*' ) ;

  • .*[A-Za-z].*[0-9].* → Ensures a product code contains at least one letter and one number.
  • | → OR condition, also checking for reversed order.

Scenario 5:- Find employees whose job titles contain either "Manager" or "Lead", regardless of case.

SELECT employee_id, job_title
FROM employees
WHERE REGEXP_LIKE (job_title, 'manager|lead' , 'i' ) ;
  • 'manager|lead' → Matches either "manager" or "lead".
  • 'i' → Makes the search case-insensitive (matches "Manager", "Lead", "MANAGER", etc.).


Limitations of REGEXP_LIKE()

Limitation Description
Performance Impact Regular expressions are slower than LIKE for simple pattern matching.
Complex Syntax Regular expressions can be hard to read and debug.
Doesn't Return Extracted Data Only checks for matches, but does not extract matching values.
Not Fully Unicode-Supported Some Unicode characters may not match correctly.

Best Practices

  • Use REGEXP_LIKE() only when LIKE is insufficient.
  • Add indexes if used frequently in large datasets.
  • Optimize complex regex patterns to improve performance.

  • match_parameter (optional) →
    • 'i' → Case-insensitive match.
    • 'c' → Case-sensitive match.
    • 'n' → Allows dot (.) to match newlines.
    • 'm' → Treats string as multi-line.


Examples

Scenario 1:- Identify the position of the first digit in customer names (if any).

SELECT customer_name,
    REGEXP_INSTR (customer_name, '[0-9]' ) AS first_digit_position FROM customers ;
    • '[0-9]' → Finds first occurrence of a digit in the customer_name column.
    • Returns 0 if no digit is found.

Scenario 2:- Get the position of the second hyphen (-) in product codes.

SELECT product_code,
    REGEXP_INSTR (product_code, '-' , 1, 2) AS second_hyphen_position FROM inventory ;
      • '-' → Searches for hyphens (-).
      • 1 → Starts search from position 1.
      • 2 → Finds the second occurrence.

Scenario 3:- Find the position where the domain name starts in customer emails.

SELECT email,
    REGEXP_INSTR (email, '@' ) AS domain_start_position FROM customers ;
      - - '@' → Finds the first occurrence of @ to determine where the domain name starts.

Scenario 4:- Find the position of the first occurrence of "error" or "fail" in error messages.

SELECT error_message,
    REGEXP_INSTR ( error_message, 'error|fail' , 1, 1, 0, 'i' ) AS first_error_position FROM system_logs ;

Scenario 5:- Find the position of the first uppercase letter in an employee’s full name.

SELECT full_name
    REGEXP_INSTR ( full_name, '[A-Z]' ) AS first_uppercase_position FROM employees ;


Limitations of REGEXP_INSTR()

Limitation Description
Performance Issues Slower than INSTR() on large datasets.
Complexity Requires knowledge of regular expressions.
Does Not Extract Values Only returns the position, not the matched text.
Limited Unicode Support May not handle all special characters correctly.

Best Practices

  • Use REGEXP_INSTR only when INSTR is insufficient.
  • Optimize regex patterns for better performance.
  • Combine with SUBSTR() to extract text after a specific position.


REGEXP_SUBSTR(str, pattern) in Oracle SQL


The REGEXP_SUBSTR function in Oracle SQL returns the substring that matches a specified regular expression pattern within a given string.


It is similar to SUBSTR(), but allows complex pattern matching using regular expressions.


Syntax

REGEXP_SUBSTR (string, pattern [, start_position [, match_occurrence [, match_parameter]]])


Parameters:
  • string → The input text where the search is performed.
  • pattern → The regular expression pattern to match.
  • start_position (optional) → The position where the search starts (default = 1).
  • match_occurrence (optional) → Specifies which occurrence of the pattern to return (default = 1).
  • match_parameter (optional) →
    • 'i' → Case-insensitive match.
    • 'c' → Case-sensitive match.
    • 'n' → Allows dot (.) to match newlines.
    • 'm' → Treats string as multi-line.


Examples

Scenario 1:- Extract the domain name from an employee’s email address.

SELECT email,
    REGEXP_SUBSTR (email, '@(.+)' , 1, 1, NULL, 1 ) AS domain FROM employees ;
    • '@(.+)' → Captures everything after @.
    • 1 (start position) → Starts from the first character.
    • 1 (match occurrence) → Gets first occurrence.
    • NULL → Default match behavior.
    • 1 (subexpression index) → Returns only the captured part ((.+)).

Scenario 2:- Extract the first word from a product description.

SELECT product_description,
    REGEXP_INSTR (product_description, '^\S+' ) AS first_word FROM products ;
      • ^\S+ → Matches the first sequence of non-space characters (\S) at the start (^).
      • Returns the first word from product_description.

Scenario 3:- Extract the first numeric value from a customer’s address.

SELECT address, REGEXP_SUBSTR (address, '[0-9]+' ) AS first_number FROM customers ;
  • '[0-9]+' → Extracts the first occurrence of numbers in address.

Scenario 4:- Extract the middle name from a full name if available.

SELECT full_name,
    REGEXP_SUBSTR ( full_name, '\S+' , , 1, 2) AS middle_name FROM employees ;
      • \S+ → Matches a sequence of non-space characters (i.e., a word).
      • 1 (start position) → Starts from the beginning.
      • 2 (match occurrence) → Extracts the second word.

Scenario 5:- Extract the first hashtag from a post.

SELECT post_text,
    REGEXP_SUBSTR ( post_text, '#\w+' , 1, 1 ) AS first_hashtag FROM social_media_posts ;


Limitations of REGEXP_SUBSTR()

Limitation Description
Performance Issues Slower than SUBSTR() for simple extractions.
Only One Match Returns only one occurrence (use LISTAGG() for multiple).
Complex Syntax Requires knowledge of regular expressions.

Best Practices

  • Use REGEXP_SUBSTR only when basic SUBSTR is insufficient.
  • Optimize regular expressions for performance.
  • Combine with TRIM() to remove unwanted spaces.


REGEXP_REPLACE(str, pattern, replacement) in Oracle SQL


The REGEXP_REPLACE function in Oracle SQL searches for a pattern in a string using regular expressions and replaces it with a specified value.


It provides more flexibility than the standard REPLACE() function because it allows pattern-based replacements rather than just simple substring replacements.


Syntax

REGEXP_REPLACE (string, pattern replacement [, start_position [, match_occurance [, match_parameter]]])


Parameters:
  • string → The input text where the search and replacement occur.
  • pattern → The regular expression pattern to search for.
  • replacement → The new value to replace the matched pattern.
  • start_position (optional) → The position where the search starts (default = 1).
  • match_occurrence (optional) → Specifies which occurrence of the pattern to replace (default = all occurrences).
  • match_parameter (optional) →
    • 'i' → Case-insensitive match.
    • 'c' → Case-sensitive match.
    • 'n' → Allows dot (.) to match newlines.
    • 'm' → Treats string as multi-line.


Examples

Scenario 1:- Replace the characters in an email before the @ symbol with *** for privacy.

SELECT email,
    REGEXP_REPLACE (email, '@(.+)' , '***' ) AS masked_email FROM employees ;
    • ^[^@]+ → Matches everything before @.
    • Replaces it with ***, masking the email username.

Scenario 2:- Convert phone numbers with different formats into a standard (XXX) XXX-XXXX format.

SELECT phone_number,
    REGEXP_REPLACE (phone_number, '[^0-9]' , '' ) AS cleaned_number FROM customers ;
      • '[^0-9]' → Matches anything that is NOT a digit.
      • Replaces non-numeric characters with an empty string (''), keeping only numbers.

Scenario 3:- Replace specific offensive words with *** in user comments.

SELECT comment_text, REGEXP_REPLACE (comment_text, 'badword|offensiveword' '***' , 1, 0, 'i' ) AS filtered_comment FROM user_comments ;
  • Matches either badword or offensiveword (case-insensitive).
  • Replaces them with ***.

Scenario 4:- Normalize names by replacing multiple spaces with a single space.

SELECT full_name,
    REGEXP_SUBSTR ( full_name, '\S+' , ' ' ) AS cleaned_name FROM employees ;
      • \s+ → Matches one or more spaces.
      • Replaces them with a single space.

Scenario 5:- Remove all digits and special characters, keeping only letters in product names.

SELECT product_name,
    REGEXP_REPLACE ( product_name, '[^A-Za-z]' , '' ) AS cleaned_product_name FROM products ;


Limitations of REGEXP_REPLACE()

Limitation Description
Performance Overhead Slower than REPLACE() for simple substitutions.
Regular Expression Complexity Requires knowledge of regex syntax.
Partial Matches If regex is not well-defined, it may replace unintended parts of the string.

Best Practices

  • Use REGEXP_REPLACE() only when REPLACE() is insufficient.
  • Test regular expressions carefully to avoid unwanted replacements.
  • Optimize regex patterns to avoid performance issues.


SOUNDEX(string) in Oracle SQL


The SOUNDEX() function in Oracle SQL returns a phonetic representation of a string based on its pronunciation. It helps in finding words that sound similar but are spelled differently.


Syntax

SOUNDEX (string)
- - string → The input text for which the phonetic code will be generated.


How SOUNDEX() Works?

  • Converts letters into a four-character code (a letter followed by three digits).
  • Ignores vowels and some consonants unless they appear at the start.
  • Similar sounding words get the same SOUNDEX code.

Word SOUNDEX Code
"Uday" U300
Udhay U300
"Udaya" U300
"Harsha" H620
"Harsh" H620

Examples

Scenario 1:- Retrieve employees whose names sound like "Uday".

SELECT employee_name
FROM employees
WHERE SOUNDEX (employee_name) = SOUNDEX ('Uday') ;

Scenario 2:- Identify potential duplicate customers based on similar names.

SELECT c1.customer_name, c2.customer_name
FROM customers c1, customers c2
WHERE SOUNDEX (c1.customer_name) = SOUNDEX (c2.customer_name)
AND c1.customer_id <> c2.customer_id ;

Scenario 3:- Retrieve cities that sound like "New York" from the database.

SELECT city_name
FROM locations
WHERE SOUNDEX (city_name) = SOUNDEX ('New York') ;

Scenario 4:- Find products with similar-sounding names to "Nike".

SELECT product_name
FROM products
WHERE SOUNDEX (product_name) = SOUNDEX ('Nike') ;

Scenario 5:- Find books by authors whose names sound like "Shakespeare".

SELECT author_name, book_title
FROM books
WHERE SOUNDEX (author_name) = SOUNDEX ('Shakespeare')


Limitations of SOUNDEX()

Limitation Description
Not Precise Matches too broadly, leading to false positives.
Ignores Vowel Sounds Might miss certain phonetic similarities.
Limited to English Works best with English words but struggles with non-English names.
Fixed Code Length (4 chars) Some words may map to the same code, even if they sound different.

Best Practices

  • Use SOUNDEX() for approximate name matching, not exact matches.
  • Combine with other matching techniques (like LEVENSHTEIN for better accuracy).
  • Be cautious of false positives in large datasets.


DIFFERENCE(string1, string2) in Oracle SQL


The DIFFERENCE() function compares two strings using their SOUNDEX() values and returns a similarity score between 0 (no match) and 4 (exact match).


Syntax

DIFFERENCE (string1, string2)
  • string1 → First string to compare.
  • string2 → Second string to compare.


Returns an integer (0 to 4):

Score meaning
4 Exact match
3 Very similar
2 Somewhat similar
1 Weak similarity
0 No similarity

Examples

Scenario 1:- Find employees whose names are similar to "Harsha".

SELECT employee_name
FROM employees
WHERE DIFFERENCE (employee_name, 'Harsha' ) >= 3 ;

Scenario 2:- Identify customer names that may have been entered incorrectly.

SELECT customer_name
FROM customers
WHERE DIFFERENCE (customer_name, 'Hars' ) >= 3 ;

Scenario 3:- Retrieve cities that sound like "Houston".

SELECT city_name
FROM locations
WHERE DIFFERENCE (city_name, 'Houston' ) >= 3 ;

Scenario 4:- Find products that sound like "Nike".

SELECT product_name
FROM products
WHERE DIFFERENCE (product_name, 'Nike' ) >= 3 ;

Scenario 5:- Find authors whose names are close to "Shakespeare".

SELECT author_name, book_title
FROM books
WHERE DIFFERENCE (author_name, 'Shakespeare' ) >= 3 ;


Limitations of DIFFERENCE()

Limitation Description
Limited to SOUNDEX Algorithm Only compares phonetic similarity using SOUNDEX().
Ignores Vowel Sounds Can lead to false positives.
Not Suitable for Exact Matching Best for approximate matches, not precise comparisons.
Fixed Scale (0-4) Doesn't provide a finer level of similarity measurement.

Best Practices

  • Use in combination with SOUNDEX() for better results.
  • Filter results with DIFFERENCE() >= 3 for meaningful matches.
  • Be cautious of false positives, especially in large datasets.
