Aggregation Functions in Oracle SQL

Aggregation functions in Oracle SQL perform calculations on multiple rows of data and return a single summarized value.


These functions are mainly used with the GROUP BY clause but can also be used without grouping to summarize entire result sets.



Key Features of Aggregation Functions

  • Work on a set of rows rather than individual rows.
  • Return a single value based on calculations.
  • Often used with GROUP BY to categorize data.
  • Ignore NULL values (except COUNT(*)).

Why Aggregate Functions?

  • To summarize large datasets (e.g., total sales, average salary).
  • To group data and perform calculations on specific categories.
  • To extract meaningful insights from raw data.

List of Aggregate Functions in Oracle SQL

Function Description NULL Handling
COUNT(*) / COUNT(Column_name) Returns the number of non-null values. Includes NULL values. always returns a number (0 if no rows).
SUM() Calculates the total sum of a numeric column Ignores NULLs
AVG() Computes the average value of a numeric column Ignores NULLs
MIN() Returns the smallest value in a column Ignores NULLs
MAX() Returns the largest value in a column Ignores NULLs
LISTAGG() Concatenates values into a single string with a delimiter Ignores NULLs
MEDIAN() Returns the middle value in a dataset Ignores NULLs
VARIANCE() Computes the statistical variance of a dataset Ignores NULLs
VARIANCE() Computes the statistical variance of a dataset Ignores NULLs
STDDEV() Computes the standard deviation of a dataset Ignores NULLs


Limitations of Aggregation Functions

Function Limitation
COUNT() COUNT(*) includes NULLs, COUNT(column) ignores NULLs
SUM() Works only with numeric columns
AVG() Ignores NULLs, leading to biased averages
LISTAGG() Can exceed VARCHAR2 limits and throw ORA-01489 error
MEDIAN() Performance-intensive on large datasets
VARIANCE() Not useful for small datasets
STDDEV Can be computationally expensive


Common Errors in Aggregation Functions

Error Code Cause Solution
ORA-00937 Aggregate function used incorrectly (without GROUP BY) Use GROUP BY clause properly
ORA-01489 LISTAGG result is too large Use LISTAGG(column, ',') WITHIN GROUP (ORDER BY column) ON OVERFLOW TRUNCATE
ORA-01722 Invalid number in SUM() or AVG() Ensure column contains only numeric data
ORA-01428 COUNT(*) used with DISTINCT Remove DISTINCT or use COUNT(column)
ORA-01427 Using an aggregate function in a subquery that returns multiple rows. Use HAVING COUNT(*) = 1 to filter groups.
ORA-00932 Mixing different data types in aggregate functions. Ensure consistent data types (e.g., no AVG() on VARCHAR).


Performance Tips for Aggregation Functions

  • Use WHERE clause to filter rows before aggregation.
  • INDEX numeric columns to optimize SUM(), AVG(), MIN(), MAX().
  • Avoid COUNT(*) on large tables; use COUNT(1) or indexed columns instead.
  • Use LISTAGG with ON OVERFLOW TRUNCATE to prevent errors.
  • Use parallel query execution (PARALLEL hint) for faster aggregation.



Do's and Don'ts

Do's Don'ts
Use GROUP BY when aggregating data per category. Don't use aggregate functions without GROUP BY unless working on the entire dataset.
Use COUNT(*) when counting all rows, including NULLs. Don't use COUNT(column_name) if you need to count all rows (use COUNT(*)).
Use LISTAGG() for string aggregation. Don't use LISTAGG() without ORDER BY in WITHIN GROUP.
Use COALESCE() with aggregates to handle NULLs. Don't assume that SUM() or AVG() will return 0 when values are NULL (it returns NULL).




COUNT() Function in Oracle SQL


The COUNT() function in Oracle SQL is an aggregate function that returns the number of rows that match a specified condition.


It is commonly used with GROUP BY to count occurrences per group and can be applied to all rows, distinct values, or specific column conditions.


Key Features of COUNT()

Feature Description
Aggregation It counts the number of rows in a result set.
Works with NULLs It ignores NULL values when applied to a specific column.
DISTINCT Support COUNT(DISTINCT column) counts only unique values.
Performance Optimization It can be optimized using indexes, partitions, and hints.
Supports GROUP BY It is widely used in aggregations with GROUP BY.

COUNT() Syntax

COUNT (*) - - Counts all rows, including NULLs
COUNT (column_name) - - Counts non-NULL values in the specified column
COUNT (DISTINCT (column_name) - - -- Counts unique non-NULL values
COUNT (1) - - -- Optimized version of COUNT(*)

Examples / Scenarios

Scenario 1:- Find the total number of employees in the employees table.

SELECT COUNT ( * ) AS total_employees
FROM employees ;

Scenario 2:- Returns the total number of rows in the orders table.

SELECT COUNT ( * ) AS total_orders
FROM orders ;

Scenario 3:- Find the number of employees with a salary.

SELECT COUNT ( salary ) AS employees_with_salary
FROM employees ;

Scenario 4:- Find the number of unique departments in which employees work.

SELECT COUNT (DISTINCT (department_id) ) AS unique_departments
FROM employees ;

Scenario 4:- (with GROUP BY) Counts the number of employees in each department.

SELECT department_id, COUNT ( * ) AS employee_count
FROM employees
GROUP BY department_id ;

Scenario 5:- (with HAVING) Count Departments with More Than 5 Employees

SELECT department_id, COUNT ( * ) AS employee_count
FROM employees
GROUP BY department_id
HAVING COUNT ( * ) > 5 ;

Scenario 6:- (with JOINs) Find the number of orders placed by each customer and include customers who haven't placed orders.

SELECT c.customer_id, c.customer_name,
    COUNT ( o.order_id ) AS total_orders
FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.customer_name
ORDER BY total_orders DESC ;

Scenario 7:- (with subqueries) Find how many employees in each department earn more than the department's average salary.

SELECT department_id,
    COUNT ( employee_id ) AS above_avg_salary_count
FROM employees e
WHERE salary > (
    SELECT AVG (salary)
    FROM employees
    WHERE department_id = e.department_id )
GROUP BY department_id ;

Scenario 8:- (with subqueries) Find the number of products that have a total sales quantity below the average sales per product.

SELECT COUNT ( product_id ) AS below_avg_sales_products
FROM ( SELECT product_id, SUM (quantity_sold) AS total_sales
    FROM Sales
    GROUP BY product_id )
WHERE total_sales < (
    SELECT AVG (salary)
    FROM employees (
      SELECT product_id,AVG (quantity_sold) AS total_sales
      FROM sales
      GROUP BY product_id ) ) ;

Scenario 8:- (with subqueries) Find the number of products that have a total sales quantity below the average sales per product.

SELECT COUNT ( * ) AS large_departments
FROM employees
WHERE department_id IN total_sales (
    SELECT department_id
    FROM employees
    GROUP BY department_id
    HAVING COUNT ( * ) > 10 ) ;

Scenario 10:- Find the number of employees who are managers (i.e., they have subordinates).

SELECT
    COUNT (DISTINCT (manager_id) ) AS total_managers
    FROM employees
    WHERE manager_id IS NOT NULL ;

Limitations of COUNT()

Limitation Description
NULL Handling COUNT(column_name) ignores NULL values, which may give misleading results.
Performance Overhead COUNT(*) on large tables can be slow without proper indexing or partitioning.
DISTINCT Impact COUNT(DISTINCT column) may have high execution cost.
GROUP BY Required When counting per group, GROUP BY must be used correctly.
Does not support multiple columns You cannot count multiple columns at once directly using COUNT().

Common Errors in COUNT()

Error Code Cause Solution
ORA-00904 Invalid column name in COUNT() Check column names in the query.
ORA-01722 Data type mismatch Ensure numeric columns are used in calculations.
ORA-00933 SQL command not properly ended Verify syntax correctness.
ORA-00979 Not a GROUP BY expression Ensure all selected columns (except aggregates) are in GROUP BY.

Do’s and Don’ts of COUNT()

Do’s Don’ts
Use COUNT(*) to count total rows. Don’t use COUNT(column_name) if NULL values are significant.
Use COUNT(DISTINCT column) for unique counts. Avoid unnecessary DISTINCT, as it increases processing time.
Optimize with indexes for performance. Don’t assume COUNT(*) is always fast; consider table size.
Use GROUP BY for category-wise counts. Don’t use COUNT() in correlated subqueries unless needed.
Use HAVING COUNT(*) to filter groups by count conditions. Don’t forget NULL handling in your COUNT conditions.
Optimize performance with indexes when using COUNT() on large tables. Avoid counting rows unnecessarily—use EXISTS if a boolean check is sufficient.



SUM() in Oracle SQL


The SUM() function in Oracle SQL is an aggregate function used to calculate the total sum of a numeric column.


It is commonly used with GROUP BY to compute totals for specific categories.


Used for financial reports, sales analysis, salary calculations, and other aggregations where summing values is required.


Syntax

SELECT SUM (column_name)
FROM table_name WHERE Condition ;

Key Features

  • Returns the sum of all values in a numeric column.
  • Ignores NULL values.
  • Can be used with GROUP BY to generate category-wise totals.
  • Supports DISTINCT to sum only unique values.
  • Can be used with HAVING to filter grouped results.

Examples / Scenarios

Scenario 1:- Returns the total sum of all salaries in the employees table.

SELECT SUM ( salary ) AS total_salary
FROM employees ;

Scenario 2:- Calculate the total revenue generated from all orders in the orders table.

SELECT CEIL ( order_amount ) AS total_revenue
FROM orders ;

Scenario 3:- Find the total sales revenue for each month.

SELECT TO_CHAR ( order_date, 'YYYY-MM' ) AS order_month,
    SUM ( order_amount ) AS monthly_revenue
GROUP BY TO_CHAR ( order_date, 'YYYY-MM' )
ORDER BY order_month ;

Scenario 4:- Calculate the total salary paid per department.

SELECT department_id, SUM (salary) AS total_salary
FROM employees
ORDER BY department_id ;

Scenario 5:- ( with HAVING ) A Find departments where the total salary is greater than 500,000.

SELECT department_id, SUM (salary) AS total_salary
FROM employees
ORDER BY department_id
HAVING SUM (salary) > 500000 ;

Scenario 6:- ( with DISTINCT ) Calculate the sum of distinct order amounts in the orders table.

SELECT department_id, SUM (DISTINCT order_amount) AS distinct_total_revenue
FROM orders
;

Scenario 7:- ( with JOIN ) Calculate total amount spent per customer.

SELECT c.customer_id, c.customer_name,
    SUM ( o.total_amount ) AS total_spent
FROM customers c
JOIN orders o ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.customer_name
;

Scenario 8:- ( with Subqueries ) Finds employees whose salary is above the average salary.

SELECT employee_id, salary
FROM customers c
WHERE salary > (
    SELECT SUM ( salary ) / COUNT (*) FROM employees
) ;

Scenario 9:- ( with CASE ) Retrieve total Salaries for Full-Time vs Part-Time Employees

SELECT
    SUM ( CASE WHEN job_type = 'Full-Time' THEN salary ELSE 0 END ) AS full_time_salary, SUM ( CASE WHEN job_type = 'Part-Time' THEN salary ELSE 0 END ) AS part_time_salary
FROM employees ;

Advantages & Disadvantages of SUM() in Oracle SQL

Advantages Disadvantages
Efficient way to calculate total values in large datasets. SUM() ignores NULL values, which may lead to incorrect calculations if not handled properly.
Can be used with GROUP BY to get category-wise totals. May have performance issues if used on large datasets without indexing.
Supports DISTINCT to sum only unique values. Cannot be used directly on VARCHAR columns without explicit conversion.
Works with HAVING to filter aggregated results. SUM() on large datasets may require optimization with indexing or partitioning.

Common Errors with SUM() in Oracle SQL

Error Code Cause Solution
ORA-01722 Invalid number if SUM() is applied on a non-numeric column. Ensure the column is numeric or use TO_NUMBER().
ORA-00937 Not a single-group function when used without GROUP BY in a multi-row query. Use GROUP BY or apply SUM() in a subquery.
ORA-01428 Argument out of range if SUM() exceeds numeric limits. Use NUMBER data type with sufficient precision.
ORA-00904 Invalid identifier when referencing a column incorrectly. Verify column name spelling and aliasing.

Limitations of SUM() in Oracle SQL

Limitation Description
Ignores NULL values If a column contains NULLs, SUM() ignores those rows.
Performance Issues on Large Tables Summing large datasets can slow queries; use indexes for optimization.
Does Not Support Non-Numeric Data Cannot be used on VARCHAR, DATE, or non-numeric columns.
Cannot Use in WHERE Clause SUM() must be used in SELECT, HAVING, or subqueries, not in WHERE.

Do's and Don'ts of SUM() in Oracle SQL

Do's Don'ts
Use SUM(NVL(column, 0)) to handle NULL values and avoid incorrect totals. Don't assume SUM() includes NULL values; it ignores them by default.
Use GROUP BY when aggregating data per category or group. Don't use SUM() without GROUP BY when selecting multiple non-aggregated columns.
Use HAVING to filter aggregated results after applying SUM(). Don't use WHERE to filter aggregated results, as it applies before aggregation.
Use materialized views to store precomputed SUM() results for large datasets. Don't use SUM() in queries without proper indexing on large tables, as it affects performance.
Ensure numeric data types (NUMBER, INTEGER, FLOAT) are used in SUM(). Don't apply SUM() on non-numeric columns without converting using TO_NUMBER().
Optimize performance using indexes on columns used in SUM() queries. Don't perform SUM() on large datasets in real-time queries without optimization.
Use DISTINCT in SUM() when required, but carefully, as it impacts performance.
Don't use SUM(DISTINCT column) unnecessarily, as it adds overhead.
Consider using SUM() as an analytic function (SUM() OVER()) for running totals. Don't use SUM() in subqueries unnecessarily if results can be derived more efficiently.


AVG() Function in Oracle SQL

The AVG() function in Oracle SQL calculates the average (mean) value of a numeric column.


It ignores NULL values and only considers non-null records while computing the average.


AVG() Syntax in Oracle

SELECT MIN (column_name)
FROM table_name WHERE Condition ;

using GROUP BY, MIN() Syntax

SELECT column_name, MIN (column_name)
FROM table_name GROUP BY column_name ;

using an analytic function, MIN() Syntax

SELECT column_name, MIN (column_name) OVER ( PARTITION BY column_name) FROM table_name ;

Key Features of MIN()

  • Works with numeric, date, and character data types.
  • Can be used with GROUP BY to find the minimum per category.
  • Ignores NULL values.
  • Can be used as an analytic function with OVER().

Examples / Scenarios

Scenario 1:- Find the Lowest Salary in Employees Table

SELECT MIN (salary) AS lowest_salary
FROM employees ;

Scenario 2:- Find the Earliest Hire Date

SELECT MIN (joining_date) AS earliest_joining
FROM employees ;

SELECT category_id, MIN (price) AS lowest_price
FROM products
GROUP BY category_id ;

Scenario 4:- Find the Minimum Order Amount for Each Customer in the Last Year

SELECT category_id, MIN (order_total) AS min_order_amount
FROM orders
WHERE order_date >= ADD_MONTHS ( SYSDATE, -12 )
GROUP BY customer_id ;

Scenario 5:- ( with HAVING ) Find departments with Minimum Salary Above 3000

SELECT department_id, MIN (salary) AS lowest_salary
FROM employees
ORDER BY department_id
HAVING MIN (salary) > 3000 ;

Scenario 6:- ( with JOIN ) Find the Earliest Order Date per Customer

SELECT c.customer_id, c.customer_name,
    MIN ( o.order_date ) AS first_order_date
FROM customers c
JOIN orders o ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.customer_name
;

Scenario 7:- ( with Subqueries ) Find Employees with the Lowest Salary

SELECT employee_id, employee_name, salary
FROM employees
WHERE salary = (
    SELECT MIN ( salary ) FROM employees
) ;

Scenario 8:- ( with Subqueries ) Find the Employee with the Minimum Salary in Each Department

SELECT department_id, employee_id, salary
FROM employees e
WHERE salary = (
    SELECT MIN ( salary )
    FROM employees
    WHERE department_id = e.department_id ) ;

Scenario 9:- ( with CASE ) Find the Employee with the Minimum Salary in Each Department

SELECT
    MIN ( CASE WHEN job_type = 'Full-Time' THEN salary ELSE NULL END ) AS min_full_time_salary, SUM ( CASE WHEN job_type = 'Part-Time' THEN salary ELSE NULL END ) AS min_part_time_salary
FROM employees

Scenario 10:- ( with CASE ) Find the Minimum Transaction Date per Account Using Analytic Function

SELECT account_id, transaction_date,
    MIN ( transaction_date ) OVER ( PARTITION BY account_id ) AS first_transaction
FROM transactions ;

Advantages and Disadvantages of MIN()

Advantages Disadvantages
Efficient for finding the smallest value in a dataset. MIN() ignores NULL values, which can affect results if NULLs represent missing data.
Works with multiple data types (numeric, date, and string). Can be slow on large datasets if proper indexing is not applied.
Supports GROUP BY and analytic functions for advanced calculations. When used with GROUP BY, improper grouping may lead to incorrect results.

Limitations of MIN()

Limitation Description
Ignores NULL values If a column contains NULLs, MIN() ignores those rows.
Performance Issues on Large Tables Finding the minimum in large datasets can slow down queries.
Cannot Use in WHERE Clause MIN() must be used in SELECT, HAVING, or subqueries, not in WHERE.
Slow Execution in Correlated Subqueries
  • When used in correlated subqueries, MIN() may run multiple times, affecting performance.
  • Use JOINs or analytic functions instead of correlated subqueries.

Common Errors in MIN()

Error Code Cause Solution
ORA-00937: not a single-group group function Using MIN() without GROUP BY when selecting multiple columns. Use GROUP BY or apply an aggregate function to all selected columns.
ORA-01722: invalid number Trying to find the MIN() of a non-numeric column where numeric data is expected. Ensure the column contains numeric values or convert using TO_NUMBER().
ORA-00904: invalid identifier Incorrect column name in the MIN() function. Verify that the column name exists in the table.
ORA-01427: single-row subquery returns more than one row Subquery using MIN() returns multiple results. Use DISTINCT or ROWNUM = 1 to ensure only one value is returned.

Do's and Don'ts of MIN()

Do's Don'ts
Use MIN() with GROUP BY for category-wise minimum values. Don't use MIN() on non-indexed columns in large datasets without performance optimization.
Ensure proper data types to avoid conversion issues. Avoid using MIN() in correlated subqueries if a better approach exists.
Use indexing on frequently searched columns to improve performance. Don't use MIN() without proper filtering conditions on large tables.
Use analytic functions (MIN() OVER()) for row-wise comparisons. Don't assume MIN() will include NULL values; it ignores them by default.

SELECT product_id, price, FLOOR (price / 100) * 100 AS discount_slab

ATAN2(y, x) Function in Oracle SQL

The ATAN2(y, x) function in Oracle SQL returns the angle (in radians) between the positive x-axis and the point (x, y) in a Cartesian coordinate system.


Unlike ATAN(n), which takes only one argument, ATAN2(y, x) requires two parameters (y and x).


It correctly determines the quadrant of the angle based on the signs of x and y.


Syntax

ATAN2 ( y, x )
- - y → Numerator (y-coordinate)
- - x → Denominator (x-coordinate)

Key difference from ATAN(y/x) & ATAN2(y, x)

  • ATAN2(y, x) considers all four quadrants, while ATAN(y/x) only considers the first and fourth quadrants.
  • Handles x = 0 correctly, returning π/2 or -π/2 instead of throwing an error.

Key Features of ATAN2(y, x) Function
