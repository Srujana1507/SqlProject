    SELECT DISTINCT

    The SELECT DISTINCT statement is used to retrieve unique values from a specified column or combination of columns, eliminating duplicate rows in the result set.


    • It ensures that only unique combinations of column values are returned.
    • This is particularly useful when you want to retrieve distinct values from one or more columns in a table.

    Syntax for SELECT DISTINCT

    SELECT column1, column2, ...
    FROM table_name
    [WHERE condition]
    [GROUP BY column]
    [HAVING condition]
    [ORDER BY column [ASC |DESC ] ] ;


    Features of SELECT DISTINCT

    Feature Description
    Removes Duplicates Eliminates duplicate rows in the result set.
    Applicable to Columns Works on one or more columns. Distinctness is determined by the combination of values in those columns.
    Improves Clarity Useful for fetching unique values in reporting or analysis.
    Order Support Can be used with ORDER BY to sort the unique rows.


    Scenarios

    Scenario 1:- Retrieve the list of unique countries from Customers table.

    SELECT DISTINCT job_title
    FROM employees ;

    Scenario 2:- Retrieve unique department IDs from the employees table

    SELECT DISTINCT department_id
    FROM employees ;

    Scenario 3:- Retrieve unique product categories from a products table.

    SELECT DISTINCT category
    FROM products ;

    Scenario 4:- Retrieve unique combinations of department ID and job title

    SELECT DISTINCT department_id, job_title
    FROM employees ;

    Scenario 5: Retrieve unique combinations of department and job titles.

    SELECT DISTINCT department_name , job_title
    FROM employees ;

    Scenario 6: Retrieve distinct customer names and their countries.

    SELECT DISTINCT customer_name , country
    FROM customers ;

    Scenario 7:- Retrieve unique department IDs where employees earn a salary greater than 5000.

    SELECT DISTINCT department_id
    FROM employees
      WHERE salary > 5000 ;

    Scenario 8:- Filtering with WHERE Clause: Retrieve unique product categories with prices above $50.

    SELECT DISTINCT Category
    FROM Products
      WHERE Price > 50 ;

    Scenario 9:- To count the number of unique departments.

    SELECT COUNT( DISTINCT department_name ) AS unique_departments
    FROM employees ;

    Scenario 10:- Count the total number of unique cities where orders have been placed.

    SELECT COUNT( DISTINCT city ) AS unique_cities
    FROM orders ;

    Scenario 11:- Retrieve distinct CustomerID values from the Orders table, and Ensure the count of distinct Country values is greater than or equal to 2

    SELECT DISTINCT CustomerID
    FROM Orders ;

    SELECT COUNT ( DISTINCT Country ) AS Country_Count
    FROM Orders
    HAVING COUNT ( DISTINCT Country ) >= 2 ;

    Optimized Single Query of above scenario (Scenario 11)

    WITH DistinctCountry AS (
      SELECT COUNT ( DISTINCT Country ) AS Country_Count
      FROM Orders
    )
    SELECT DISTINCT CustomerID
    FROM Orders
    WHERE ( SELECT Country_Count FROM DistinctCountry ) >= 2 ;

    Scenario 12:- Retrieve unique combinations of job title and department ID, sorted by department ID

    SELECT job_title, department_id
    FROM employees
      ORDER BY department_id ;

    Scenario 13:- (DISTINCT with Joins) Retrieve unique product categories ordered by customers.

    SELECT DISTINCT p.Category
    FROM Products p
    JOIN Orders o
    ON p.ProductID = o.ProductID ;

    Scenario 14:- Retrieve unique locations of employees by joining two tables (employees and departments)

    SELECT DISTINCT e.title, d.location
    FROM employees e
    JOIN departments d
    ON e.department_id = d.department_id ;

    Scenario 15:- Retrieve unique employee hire years (derived from the hire_date column)

    SELECT DISTINCT EXTRACT ( YEAR FROM hire_date ) AS hire_year
    FROM employees ;

    Scenario 16:- Retrieve unique salary ranges based on a custom range logic

    SELECT DISTINCT
      CASE
        WHENsalary BETWEEN 0 AND 3000 THEN 'Low'
        WHENsalary BETWEEN 3001 AND 7000 THEN 'Medium'
        ELSE 'High'
      END AS salary_range
    FROM employees ;


    Common Errors with SELECT DISTINCT

    Error Cause Solution
    ORA-00904 Specifying an invalid column name in the SELECT DISTINCT clause. Ensure column names are valid and spelled correctly.
    Performance Lag Using DISTINCT on large, non-indexed datasets with low cardinality. Use indexes or optimize the query by filtering data.
    Ambiguity in Joins Failing to use fully qualified column names in joins when using DISTINCT. Use table aliases to clarify which columns belong to which table.


    Best Practices

    Practice Description
    Filter Data First Use a WHERE clause to limit the dataset before applying DISTINCT.
    Avoid Overuse Use DISTINCT only when duplicates are problematic or affect the query’s intent.
    Index Usage Ensure indexed columns are included in the SELECT DISTINCT clause for better performance.
    Combine with Other Features Use in conjunction with ORDER BY, JOIN, and WHERE clauses to create efficient queries.

    Do's and Don'ts of SELECT DISTINCT

    Do's Don'ts
    Use DISTINCT to eliminate duplicates when the result set needs to contain unique rows. Avoid using DISTINCT unnecessarily, as it may increase query execution time.
    Use DISTINCT with indexed columns for better performance. Don’t use DISTINCT as a shortcut for fixing poorly designed queries or data models.
    Combine DISTINCT with filtering (WHERE) to reduce the number of rows processed. Don’t rely solely on DISTINCT to handle duplicates if they can be prevented at the source.


    Limitations of SELECT DISTINCT

    Limitation Description
    Impact on Performance Can be slow on large datasets due to the sorting operation.
    Not Scalable for Large Columns Applying DISTINCT on many columns increases the likelihood of duplicate combinations, reducing efficiency.
    Aggregate Functions Does not work directly with aggregate functions; must be combined with GROUP BY.


    Performance Considerations

    Performance Details
    Sorting Internally, Oracle SQL sorts the data to identify duplicates. This can impact performance on large datasets.
    Indexing Using indexes on the columns specified in SELECT DISTINCT can improve query performance.
    High Cardinality Columns Applying DISTINCT on high-cardinality columns (with many unique values) has less performance impact.
    Low Cardinality Columns Applying DISTINCT on low-cardinality columns (with few unique values) may require sorting a large number of rows.


    SELECT DISTINCT vs GROUP BY

    Scenario Query Using DISTINCT Query Using GROUP BY
    Behavior Eliminates duplicates but doesn’t allow aggregate functions like SUM or COUNT. Groups rows and can perform aggregate functions but may not always return a clean set of unique rows without aggregates.
    Retrieve unique departments SELECT DISTINCT department_id FROM employees; SELECT department_id FROM employees GROUP BY department_id;
    Count employees per department N/A (Not supported directly) SELECT department_id, COUNT(*) FROM employees GROUP BY department_id;
