CASE in Oracle SQL

The CASE statement in Oracle SQL is a conditional expression that allows you to perform logic-based evaluations and return results based on those conditions.


  • It is similar to an IF-THEN-ELSE construct in programming languages.
  • It evaluates a series of conditions and returns a value when the first condition is met. If no conditions are met, it returns a default value specified by an optional ELSE clause.


Key Features of CASE in Oracle SQL

Feature Description
Conditional Logic Evaluates conditions and returns a value when a condition is met.
Two Types
  • Simple CASE: Compares a single expression against multiple values.
  • Searched CASE: Evaluates multiple Boolean conditions.
Result Substitution Replaces values or performs calculations based on conditions.
Inline Conditionality Usable in SELECT, WHERE, ORDER BY, GROUP BY, and HAVING clauses.
NULL Handling Can explicitly handle or substitute NULL values in conditions and results.


Syntax

1. Simple CASE Expression

CASE expression
    WHEN value1 THEN result1
    WHEN value2 THEN result2
      .
      .
      .
    ELSE default_result
END
  • Expression : The column or calculation to evaluate.
  • WHEN value THEN result : Specifies the condition and its output.
  • ELSE: Specifies the default result if no conditions are met.
  • END: Marks the end of the CASE statement.

2. Searched CASE Expression

CASE
    WHEN condition1 THEN result1
    WHEN condition2 THEN result2
      .
      .
      .
    ELSE default_result
END
- - Condition : A logical condition that evaluates to TRUE or FALSE.

Examples / Scenarios

Scenario 1:- ( Categorizing Salaries ) Assign salary ranges to employees.

SELECT EmployeeID, salary,
    CASE
      WHEN salary < 3000 THEN 'Low'
      WHEN salary BETWEEN 3000 AND 7000 THEN 'Medium'
      ELSE 'High'
    END AS salary_category
FROM Employees ;

Scenario 2:- Categorize employees based on their job title.

SELECT EmployeeID,
job_title,
    CASE JobTitle
      WHEN 'Manager' THEN 'Leadership'
      WHEN 'Developer' THEN 'Technical'
      ELSE 'Support'
    END AS RoleCategory
FROM Employees ;

Scenario 3:- ( Handling NULL Values ) Replace NULL values in a column with a default value.

SELECT customer_id,
    CASE
      WHEN cont_number IS NULL THEN 'No Contact'
      ELSE cont_number
    END AS contact_info
FROM customers ;

Scenario 4:- Assign grades based on a score.

SELECT student_name, Scroe,
    CASE
      WHEN score >= 90 THEN 'A'
      WHEN score >= 80 THEN 'B'
      WHEN score >= 70 THEN 'C' ELSE 'F'
    END AS grade
FROM Students ;

Scenario 5:- ( Use in WHERE Clause ) Filter employees based on conditional criteria.

SELECT employee_id, name, salary
FROM employees
WHERE CASE
    WHEN department_name = 'HR' THEN salary > 40000
    WHEN department_name = 'IT' THEN salary > 60000
    ELSE salary > 30000
END ;

Scenario 5.1:- ( Use in WHERE Clause ) Retrieve orders placed in 2023, with a focus on "Priority" orders.

SELECT order_id, customer_id, order_date, priority
FROM orders
WHERE
    CASE
      WHEN priority = 'High' THEN 1
      WHEN order_date BETWEEN TO_DATE ( '2023-01-01', 'YYYY-MM-DD' )
        AND TO_DATE ( '2023-12-01', 'YYYY-MM-DD' ) THEN 1
      ELSE 0
END = 1 ;

Scenario 6:- ( Use in ORDER BY Clause ) Sort employees by salary category and within each category by last name.

SELECT employee_id, last_name, salary,
    CASE
      WHEN salary < 3000 THEN 'Low'
      WHEN salary BETWEEN 3000 AND 7000 THEN 'Medium'
      ELSE 'High'
    END AS salary_category
FROM employees
ORDER BY
    CASE
      WHEN salary < 3000 THEN 1
      WHEN salary BETWEEN 3000 AND 7000 THEN 2
      ELSE 3
    END , last_name ;

Scenario 7:- ( Use in GROUP BY Clause ) Group sales by dynamic ranges.

SELECT
    CASE
      WHEN total_sales < 500 THEN 'Low Sales'
      WHEN total_sales BETWEEN 500 AND 1000 THEN 'Medium Sales'
      ELSE 'High Sales'
    END AS sales_range, COUNT( * ) AS num_orders
FROM sales
GROUP BY
    CASE
      WHEN total_sales < 500 THEN 'Low Sales'
      WHEN total_sales BETWEEN 500 AND 1000 THEN 'Medium Sales'
      ELSE 'High Sales'
    END ;

Scenario 8:- ( how to use HAVING ) Filter aggregated results based on conditions.

SELECT department_id, avg_salary
    SELECT department_id, AVG( salary ) AS avg_salary ,
      CASE
        WHEN department_id = 1 THEN AVG( salary ) > 50000
        ELSE AVG(salary) > 30000
      END AS condition_met
    FROM employees
    GROUP BY department_id
WHERE condition_met = 1 ;

- - The CASE statement within the subquery determines if the average salary meets the condition based on the department_id.
- - The WHERE clause in the outer query then filters the results to include only those groups where the condition is met (i.e., condition_met = 1).

Scenario 9:- ( in UPDATE ) Update employee bonuses based on their department.

UPDATE employees
SET bonus = CASE
      WHEN department_name = 'HR' THEN salary * 0.1
      WHEN department_name = 'IT' THEN salary * 0.15
      ELSE salary * 0.05
    END ;

Scenario 10:- ( in DELETE ) Delete records based on dynamic criteria.

DELETE FROM employees
WHERE CASE
      WHEN department_name = 'Sales' THEN salary < 40000
      WHEN department_name = 'Marketing' THEN salary < 30000
      ELSE salary < 20000
    END ;

Scenario 11:- ( Using JOINs ) Retrieve employees and categorize their performance based on the number of completed projects.

SELECT e.employee_id, e.employee_name,
    CASE
      WHEN COUNT (p.project_id) >= 5 THEN 'Excellent'
      WHEN COUNT (p.project_id) BETWEEN 3 AND 4 THEN 'Good'
      ELSE 'Needs Improvement'
    END AS performance
FROM employees e
LEFT JOIN projects p ON e.employee_id = p.employee_id
GROUP BY e.employee_id, e.employee_name ;

Scenario 12:- ( Pivoting Data ) Transform rows into columns using CASE.

SELECT product_id,
      SUM( CASE WHEN region = 'North' THEN sales ELSE 0 END ) AS north_sales,
      SUM( CASE WHEN region = 'South' THEN sales ELSE 0 END ) AS south_sales
    FROM sales
    GROUP BY product_id ;

Scenario 13:- Create flags for conditional monitoring or reporting.

SELECT order_id,
    CASE
      WHEN delivery_date < CURRENT_DATE THEN 'Late'
      WHEN delivery_date = CURRENT_DATE THEN 'On Time'
      ELSE 'Scheduled'
    END AS delivery_status
FROM Orders ;



Limitations of CASE

Limitations Description
Not Usable for Table Constraints Cannot be used directly in constraints like CHECK.
Complexity in Nesting Deeply nested CASE statements can become hard to read and maintain.
Performance Impact Large or complex CASE expressions may slightly impact query speed.
NULL Handling Requires explicit handling of NULL values in conditions to avoid logical errors.


Common Errors with CASE Statement

Error Cause Solution
ORA-00905: Missing Keyword Missing END keyword to close the CASE statement. Ensure all CASE statements are closed with the END keyword.
ORA-00932: Inconsistent Datatypes Result expressions have incompatible data types. Ensure all result expressions have compatible data types.
Invalid Syntax in Nested CASE Incorrect nesting or unbalanced conditions. Validate each CASE block for correctness.
NULL Logic Errors Logical errors due to NULL values in conditions. Use IS NULL or NVL to explicitly handle NULL values.
Improper Default Handling Missing the ELSE clause when required. Always include an ELSE clause to cover all conditions unless it is safe to omit it.


Do's and Don'ts of CASE in Oracle SQL

Do's Don'ts
Use CASE for conditional logic in SELECT, WHERE, GROUP BY, and ORDER BY. Avoid excessive nesting; it reduces readability.
Use aliases for clarity when using CASE in SELECT statements. Avoid complex CASE logic that impacts performance.
Ensure compatibility of data types in THEN expressions. Don’t use CASE when simpler logic (like DECODE) suffices.
Combine CASE with aggregate functions for conditional aggregation. Don't forget the END keyword to properly close the CASE statement.
Test CASE expressions for handling NULL values appropriately. Don’t rely on implicit handling of NULL; use explicit checks when needed.
Use clear and concise conditions to enhance query readability. Avoid overly nested CASE statements, as they reduce readability and performance.
