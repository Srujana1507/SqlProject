Numeric Functions in Oracle SQL

Numeric functions are built-in functions that perform operations on numeric data. They allow manipulation, transformation, and computation of numeric values in a query.


These functions allow users to perform mathematical calculations, manipulations, and data conversions efficiently.



Key Features of Numeric Functions

Feature Description
Wide Range of Functions: Includes basic arithmetic, rounding, and advanced mathematical operations.
Supports Large Numbers Operates seamlessly with Oracle's robust numeric data types.
Comparison Flexibility Supports operators other than =, such as <,>, and BETWEEN.
Performance Optimization Efficiently processes numeric data for large datasets.
Flexible Applications Useful in financial analysis, data aggregation, and reporting.

Why Numeric Functions?

1. Perform Calculations:- Simplify arithmetic operations in SQL queries.


2. Data Transformation:- Modify numeric data into required formats or scales.


3. Conditional Logic:- Handle specific numeric conditions directly in queries.


4. Aggregations and Summaries:- Summarize and analyze data efficiently.


5. Precision and Rounding:- Ensure numerical accuracy for business use cases.



Commonly Used Numeric Functions

Function Description Usage
ABS(number) Returns the absolute value of a number. ABS(-10) → 10
CEIL(number) Returns the smallest integer greater than or equal to the number. CEIL(4.3) → 5
FLOOR(number) Returns the largest integer less than or equal to the number. FLOOR(4.7) → 4
ROUND(number) Rounds a number to n decimal places. ROUND(123.456, 2) → 123.46
TRUNC(number) Truncates a number to n decimal places without rounding. TRUNC(123.456, 2) → 123.45
MOD(m, n) Returns the remainder of m divided by n. MOD(10, 3) → 1
POWER(m, n) Returns m raised to the power of n. POWER(2, 3) → 8
SIGN(number) Returns the square root of a non-negative number. SQRT(16) → 4
EXP(number) Returns e (Euler's number) raised to the power of the given number. EXP(1) → 2.71828
LN(number) Returns the natural logarithm (base e) of a number. LN(2.71828) → 1
LOG(base, number) Returns the logarithm of a number to the specified base. LOG(10, 1000) → 3
SIN(n) Computes the sine of a number (in radians). SIN(PI()/2) → 1
COS(n) Computes the cosine of a number (in radians). COS(PI()) → 1
TAN(n) Computes the tangent of a number (in radians). TAN(PI()/4) → 1
ASIN(n) Returns the arcsine of a number, in radians, between -1 and 1. ASIN(1) → 1.57079632679 (π/2)
ACOS(n) Returns the arccosine of a number, in radians, between -1 and 1. ACOS(1) → 0
ATAN(n) Returns the arctangent of a number, in radians. ATAN(1) → 0.78539816339 (π/4)
ATAN2(x, y) Returns the arctangent of two numbers as a single operation (y, x). ATAN2(1, 1) → 0.78539816339 (π/4)
SINH(n) Computes the hyperbolic sine of a number. SINH(1) → 1.17520119364
COSH(n) Computes the hyperbolic cosine of a number. COSH(1) → 1.54308063482
TANH(n) Computes the hyperbolic tangent of a number. TANH(1) → 0.76159415596


Benefits of Numeric Functions

Benefit Description
Enhanced Query Efficiency Reduces the need for manual calculations outside the database.
Data Formatting Provides consistent numerical formatting within results.
Simplifies Complex Calculations Handles complex numeric operations directly in SQL queries.
Improves Data Analysis Useful for aggregations, summarizations, and comparisons.


Limitations of Numeric Functions

Limitation Description
Performance Numeric functions can slow down queries for very large datasets.
Data Type Compatibility Requires careful handling of incompatible data types (e.g., VARCHAR2 instead of NUMBER).
Error Handling Certain functions (e.g., LOG, SQRT) throw errors if invalid input (e.g., negative values) is provided.


Common Errors and Solutions

Error Code Cause Solution
ORA-01722 Invalid number if non-numeric data is passed to numeric functions. Ensure data types match function requirements or use conversion functions like TO_NUMBER.
ORA-01428 Argument out of range for mathematical functions like SQRT. Validate input data before applying functions.
Performance Lag Numeric functions slowing down queries on large datasets. Use indexes or pre-calculate values in materialized views.


Do's and Don'ts for Numeric Functions

Do's Don'ts
Use appropriate rounding functions for accuracy. Avoid using MOD or other functions with NULL inputs without handling them explicitly.
Use functions like ROUND or TRUNC for consistent formatting. Avoid applying numeric functions unnecessarily to large datasets.
Optimize queries for large datasets with indexes. Don't perform unnecessary calculations in SELECT clauses if they can be simplified.
Validate inputs to prevent runtime errors. Avoid hardcoding numeric constants without proper documentation.
Ensure input data is valid for mathematical functions. Don’t mix data types without explicit type conversions.
Use aliases for calculated columns for better readability. Avoid chaining multiple numeric functions in one statement.


ABS Function in Oracle SQL

The ABS function returns the absolute (positive) value of a numeric expression, removing any negative sign.


Syntax

ABS (number)

Examples / Scenarios

Scenario 1:- Calculate the absolute difference between the actual and expected profit margins.

SELECT product_id, ABS ( actual_profit - expected_profit ) AS profit_difference
FROM products ;

Scenario 2:- Display absolute sales figures, even if some are recorded as negative due to adjustments.

SELECT sale_id, sale_amount, ABS ( sale_amount ) AS abs_sales
FROM Sales ;

Scenario 3:- Rank candidates based on their deviation from the average score.

SELECT candidate_id, ABS ( score - AVG (score) OVER () ) AS deviation
FROM exam_scores ;

Scenario 4:- Apply discounts only when the absolute value of price changes exceeds $50.

SELECT order_id, ABS (original_price - discounted_price) AS price_change
FROM orders
WHERE ABS (original_price - discounted_price) > 50 ;

Scenario 5:- ( Distance From Average ) Calculate how far each salary is from the average salary (absolute value).

SELECT emp_id, salary,
    ABS (salary - ( SELECT AVG (salary) FROM Employees)) AS deviation_from_avg
FROM Employees ;

Advantages and Disadvantages of ABS Function

Advantages Disadvantages
Simplifies calculations involving differences or deviations. Only works with numeric data types.
Helps in ranking or grouping data based on absolute deviations. Cannot be used directly on non-numeric data without conversions.
Useful in financial and scientific computations. Overuse in queries may slightly degrade performance on large datasets.

Common Errors for ABS Function

Error Code Cause Solution
ORA-01722 Invalid number error when passing non-numeric values. Ensure only numeric inputs are used, or convert values with TO_NUMBER.
NULL result Using NULL inputs returns NULL instead of a valid number. Handle NULLs using NVL or COALESCE before applying ABS.


CEIL Function in Oracle SQL

The CEIL function rounds a numeric value up to the nearest whole number.


Syntax

CEIL (number)

Examples / Scenarios

Scenario 1:- Calculate the total sales price by adding a rounded-up tax amount to the product price.

SELECT product_id, price, CEIL ( price * tax_rate ) AS rounded_tax
FROM products ;

Scenario 2:- Calculate the number of full containers required to pack a given number of items.

SELECT item_id, CEIL ( quantity / container_capacity ) AS containers_needed
FROM inventory ;

Scenario 3:- Round up discount percentages to whole numbers for display purposes.

SELECT product_id, discount, CEIL ( discount ) AS rounded_discount
FROM Products ;

Scenario 4:- Estimate project completion times in days, always rounding up to ensure ample time.

SELECT project_id, estimated_hours, CEIL ( estimated_hours / 8 ) AS estimated_days
FROM Projects ;

Scenario 5:- A company is managing a multi-team project, and tasks need to be evenly distributed across all teams. If the total number of tasks cannot be divided equally among teams, an additional task is assigned to some teams. The goal is to determine how many tasks each team will handle, ensuring no team is overloaded.

WITH project_tasks AS (
    SELECT project_id, total_tasks, team_count
    FROM projects
) SELECT
    project_id,
    total_tasks,
    team_count,
    CEIL (total_tasks / team_count) AS tasks_per_team
FROM project_tasks ;

Advantages and Disadvantages of CEIL Function

Advantages Disadvantages
Ensures precise rounding up for business-critical calculations. Limited to numeric data types only.
Ideal for computations involving minimum requirements, like quotas. Might result in overestimation in scenarios requiring exact values.
Supports fractional and decimal inputs seamlessly. Performance impact when used excessively on large datasets.

Common Errors for CEIL Function

Error Code Cause Solution
ORA-01722 Invalid number error when non-numeric input is provided. Ensure input is numeric or cast non-numeric types using TO_NUMBER.
NULL result Input value is NULL, returning NULL as output. Use NVL or COALESCE to handle NULL values gracefully.


FLOOR Function in Oracle SQL

The FLOOR function in Oracle SQL returns the largest integer less than or equal to a given numeric value.


It is useful when you need to truncate a number down to the nearest whole number without rounding up.


Syntax

FLOOR (number)

Key Features of FLOOR

  • Always rounds down, regardless of the fractional part.
  • Works on both positive and negative numbers.
  • Supports floating-point and integer inputs.
  • Compatible with arithmetic expressions and column values.

Examples / Scenarios

Scenario 1:- Determine the number of complete work units processed when each unit requires 2.5 hours.

SELECT work_id, hours_worked, FLOOR ( hours_worked / 2.5 ) AS completed_units
FROM Work_Log ;

Scenario 2:- Determine the discount slab (rounded down) for product prices.

SELECT product_id, price, FLOOR (price / 100) * 100 AS discount_slab
FROM products ;

Scenario 3:- Calculate the number of full pallets needed to store items, considering each pallet can hold up to 50 items.

SELECT item_id, quantity, FLOOR ( quantity / 50 ) AS full_pallets
FROM inventory ;

Scenario 4:- Calculate the maximum number of products fitting into a fixed budget without exceeding it.

SELECT budget, product_price,
    FLOOR (budget / product_price) AS max_products
FROM Product_Pricing ;

Scenario 5:- Display the rounded-down total sales per region.

SELECT region_id,
    SUM (sales_amount) AS total_sales,
    FLOOR ( SUM (sales_amount) ) AS rounded_sales
FROM Sales
GROUP BY region_id ;

Scenario 6:- Group individuals into age brackets of 10 years, starting from the lowest decade.

SELECT
    FLOOR (age / 10) * 10 AS age_group,
    COUNT (*) AS num_people
FROM customers
GROUP BY FLOOR (age / 10) ;

Advantages and Disadvantages of FLOOR Function

Advantages Disadvantages
Ensures predictable results by always rounding down. Limited to numeric values; does not handle non-numeric data types.
Useful for creating ranges or slabs in data analysis. Can result in underestimation in some financial computations.
Works well with both positive and negative numbers. Performance might be impacted if used on large datasets frequently.

Common Errors for CEIL Function

Error Code Cause Solution
ORA-01722 "Invalid number" when non-numeric data is passed. Ensure input data is numeric or cast using TO_NUMBER.
NULL result When the input is NULL, the function returns NULL. Handle NULLs with NVL or COALESCE.


ROUND Function in Oracle SQL

The ROUND function rounds a number to a specified number of decimal places or the nearest integer if no precision is provided.


It is versatile, allowing rounding to both decimal and integer levels.


Syntax

ROUND (n [, precision])
- - precision (optional): Specifies the number of decimal places to which the value should be rounded.

Key Features of ROUND

  • Supports rounding both up and down based on standard mathematical rules.
  • Handles both positive and negative precision values.
  • Can be used with floating-point, decimal, and integer values.
  • Helps in formatting numerical results for reporting and financial calculations.

Examples / Scenarios

Scenario 1:- Format sales amounts to two decimal places for reporting purposes.

SELECT sale_id, sale_amount, ROUND ( sale_amount, 2 ) AS rounded_sales
FROM sales_data ;

Scenario 2:- Round all product prices to two decimal places for consistent display.

SELECT product_id, price, ROUND (price , 2) AS rounded_price
FROM products ;

Scenario 3:- Round tax amounts to the nearest integer for billing purposes.

SELECT bill_id, tax_amount, ROUND ( tax_amount ) AS rounded_tax
FROM Billing ;

Scenario 4:- Round employee ratings to one decimal place for appraisal purposes.

SELECT emp_id,
    AVG (rating) AS average_rating
    ROUND ( AVG (rating), 1 ) AS rounded_rating
FROM Employee_Reviews
GROUP BY emp_id ;

Scenario 5:- Round total expenses for each department to zero decimal places.

SELECT department_id,
    SUM (expense) AS total_expense,
    ROUND ( SUM (expense) , 0 ) AS rounded_expense
FROM Expenses
GROUP BY department_id ;

Scenario 6:- Round converted currency values to two decimal places.

SELECT transaction_id, amount_usd,
    ROUND ( amount_usd * 0.85, 2 ) AS amount_eur
FROM Transactions ;

Advantages and Disadvantages of FLOOR Function

Advantages Disadvantages
Offers flexibility in rounding to any decimal or integer position. Rounding might introduce minor inaccuracies in precise calculations.
Ideal for formatting numerical results in reports. Cannot handle non-numeric data directly, causing errors if used.
Useful for handling both positive and negative precision values. May round in an unintended way if precision is not explicitly defined.

Common Errors for CEIL Function

Error Code Cause Solution
ORA-01722 "Invalid number" when non-numeric data is passed. Ensure the column or value is numeric before applying ROUND.
NULL result Returns NULL if the input value is NULL. Handle NULLs using NVL or COALESCE before applying ROUND.


TRUNC Function in Oracle SQL

The TRUNC function is used to truncate a numeric value or a date to a specified level of precision.


it removes the fractional part without rounding, and for dates, it truncates the date to the specified unit (e.g., year, month, day).


Syntax

Numeric Truncation:

TRUNC (number, decimal_places)
- - precision (optional): Specifies the number of decimal places to retain. Defaults to 0 if not provided.

Date Truncation:

TRUNC (date, format)
- - date: The date value to truncate.
format (optional): Specifies the unit for truncation (e.g., 'YEAR', 'MONTH').

Key Features of TRUNC

  • Removes fractional parts of numbers without rounding.
  • Enables precise date truncation for analytics and reporting.
  • Supports various date formats like 'YEAR', 'MONTH', 'DAY', etc.
  • Useful for data cleansing, grouping, and standardization.

Examples / Scenarios

Numeric Scenarios:-

Scenario 1:- Display product prices truncated to two decimal places without rounding.

SELECT product_id, price, TRUNC ( price, 2 ) AS truncated_price
FROM Products ;

Scenario 2:- ( Truncate Prices to Whole Numbers ) Remove fractional parts of product prices for simplified pricing.

SELECT product_id, price, ROUND (price) AS truncated_price
FROM products ;

Scenario 3:- ( Truncation to Nearest Thousand ) Truncate department budgets to the nearest thousand for financial analysis.

SELECT department_id, budget, TRUNC ( budget, -3 ) AS truncated_budget
FROM departments ;

Scenario 4:- Show employee salaries without cents for administrative records.

SELECT emp_id, salary,
    TRUNC (salary, 0 ) AS salary_no_cents
FROM Employees ;

Date Scenarios: -

Scenario 5:- ( Truncate Dates to the Start of the Month ) Find all transactions grouped by the start of the month.

SELECT department_id,
    TRUNC (transaction_date, 'MONTH' ) AS start_of_month,
    COUNT (*)
FROM transactions
GROUP BY TRUNC (transaction_date, 'MONTH' ) ;

Scenario 6:- ( Analyze Daily Activity Without Time ) Group login activity by date, ignoring the time.

SELECT
    TRUNC ( login_time ) AS login_date
    COUNT (*)
FROM user_logins
GROUP BY TRUNC ( login_time ) ;

Scenario 7:- ( Truncate to Start of Year ) Find total sales grouped by the start of the year.

SELECT
    TRUNC (sale_date, 'YEAR' ) AS start_of_year
    SUM ( sale_amount ) AS total_sales
FROM sales
GROUP BY TRUNC (sale_date, 'YEAR' ) ;

Scenario 8:- Truncate the difference in days between two dates to integers.

SELECT order_id, delivery_date - order_date AS days_difference,
    TRUNC ( delivery_date - order_date ) AS truncated_days
FROM Orders ;

Advantages and Disadvantages of TRUNC Function

Advantages Disadvantages
Prevents rounding errors by removing fractions. Cannot round numbers, only truncates.
Simplifies date and number grouping in analytics. For large datasets, can add overhead if used frequently in queries.
Highly flexible for both numeric and date-related operations. Does not handle NULL values, returning NULL instead.

Common Errors for TRUNC Function

Error Code Cause Solution
ORA-01722 "Invalid number" when applied to non-numeric data. Ensure the input column or value is numeric before using TRUNC.
NULL result Returns NULL when applied to NULL values. Use NVL or COALESCE to handle NULLs before applying TRUNC.


MOD Function in Oracle SQL

The MOD function in Oracle SQL returns the remainder of a division operation between two numbers.


It is commonly used for mathematical operations, data grouping, and validations.


Syntax

TRUNC (dividend, divisor)
-- The dividend (the number to be divided).
-- The divisor (the number by which the dividend is divided).

Key Features of MOD Function

  • Helps in identifying divisibility and remainders.
  • Works with both positive and negative numbers.
  • Useful in grouping or categorizing data based on numeric properties.
  • Handles edge cases like division by 0 gracefully, returning NULL.

Examples / Scenarios

Numeric Scenarios:-

Scenario 1:- ( Identify Odd and Even Numbers ) List all even numbers in an employee table based on employee ID.

SELECT employee_id, name
FROM employees WHERE MOD ( employee_id, 2) = 0 ;

( OR )

SELECT number,
    CASE
      WHEN MOD ( number, 2) = 0 THEN 'Even'
      ELSE 'Odd'
    END AS number_type
FROM ;

Scenario 2:- Assign employees into 3 rotating teams based on their employee ID.

SELECT emp_id, MOD ( emp_id, 3 ) AS team_id
FROM Employees ;

Scenario 3:- ( Group Products by Box Packing ) Identify products that do not fully fit into boxes of size 10.

SELECT product_id, total_quantity, MOD ( total_quantity, 10 ) AS leftover_items
FROM inventory
WHERE MOD ( total_quantity, 10 ) > 0 ;

Scenario 4:- ( Validate Account Numbers ) Flag accounts where the account number is not divisible by 7.

SELECT account_id,
    MOD ( account_number, 7 ) AS remainder
FROM accounts
WHERE MOD ( account_number, 7 ) <> 0 ;

Scenario 5:- ( Group Orders by Weekday ) Group order dates into days of the week (Sunday = 0, Monday = 1, etc.).

SELECT order_id, order_date,
    MOD ( TO_NUMBER ( TO_CHAR (order_date, 'J' ) ), 7 ) AS weekday
FROM Orders ;

Scenario 6:- Identify batch numbers where the remainder is 3 when divided by 7.

SELECT batch_id FROM Batches
WHERE MOD (batch_id, 7) = 3 ;

Scenario 7:- Assign records to pages, displaying 10 records per page.

SELECT record_id,
    MOD ( ROWNUM - 1, 10 ) + 1 AS page_number
FROM Records ;

Advantages and Disadvantages of MOD Function

Advantages Disadvantages
Useful for categorization and grouping in mathematical problems. Returns NULL when the divisor is 0, which might require handling.
Easy to implement for divisibility checks. Does not directly support non-numeric data.
Can handle both positive and negative numbers. May cause performance overhead in large datasets if used in WHERE clauses.

Common Errors in MOD Function

Error Code Cause Solution
ORA-01722 "Invalid number" for non-numeric inputs. Ensure the input columns are numeric before using the MOD.
NULL result Division by zero in the divisor (n2). Add a condition to ensure the divisor is not zero.


POWER Function in Oracle SQL

The POWER function in Oracle SQL is used to raise a number to the power of a specified exponent.


It is particularly useful in mathematical calculations involving exponential growth, scientific computations, and finance-related queries.


Syntax

TRUNC (base, exponent)
- - base: The numeric value that you want to raise to a power.
- - exponent: The power to which the base is raised.

Key Features of POWER Function

  • Works with both positive and negative bases and exponents.
  • Supports fractional exponents to compute roots (e.g., square roots, cube roots).
  • Suitable for complex mathematical and scientific operations.
  • Compatible with other numeric and aggregate functions in Oracle SQL.

Examples / Scenarios

Numeric Scenarios:-

Scenario 1:- Calculate the future value of an investment with compound interest.

SELECT principal_amount, rate_of_interest, years,
    principal_amount * POWER (1 + rate_of_interest / 100, years) AS future_value
FROM investments ;

Scenario 2:- Calculate the area of circles given their radii.

SELECT radius, POWER ( radius, 2 ) * 3.14159 AS area
FROM circles ;

Scenario 3:- Calculate the exponential growth of a population over time.

SELECT year, initial_population, growth_rate,
    POWER ((1 + growth_rate), year) * initial_population AS population
FROM Population_Growth ;

Scenario 4:- ( Power of Negative Exponent ) Calculate reciprocals by raising numbers to the power of -1.

SELECT number,
    POWER ( number, -1 ) AS reciprocal
FROM Numeric_Data ;

Scenario 5:- ( Compute Cube of Numbers ) Find the cube of given numbers in a dataset.

SELECT number,
    POWER (number, 3) AS cube
FROM numbers_table ;

Scenario 6:- Predict stock values using a growth factor over a number of years.

SELECT stock_id, initial_price, growth_rate, years,
    POWER ((1 + growth_rate / 100), years) * initial_price AS future_price
FROM Stock_Data ;

Scenario 7:- Compute the hypotenuse of a right triangle using the Pythagorean theorem.

SELECT side_a, side_b,
    POWER ( POWER (side_a, 2) + POWER (side_b, 2), 0.5 ) AS hypotenuse
FROM triangles ;

Scenario 8:- ( Fractional Powers for Roots ) Find the cube root of various numbers.

SELECT number,
    POWER ( number, 1/3 ) AS cube_root
FROM numbers_table ;

Advantages and Disadvantages of POWER Function

Advantages Disadvantages
Handles a wide range of mathematical operations effectively. Cannot process NULL values; results in NULL output for NULL inputs.
Supports fractional and negative exponents for versatile usage. May cause performance issues in large datasets when used in complex queries.
Compatible with numeric data types, enabling scientific calculations. Errors occur if inputs are non-numeric or incompatible data types.

Common Errors in POWER Function

Error Code Cause Solution
ORA-01722 "Invalid number" when using non-numeric values as input. Ensure the base and exponent are numeric.
NULL result NULL input for either the base or exponent. Use NVL or COALESCE to handle NULL values.
ORA-01476 Division by zero when using fractional exponents with a zero base. Validate inputs to avoid zero base with fractional exponents.


SIGN Function in Oracle SQL

The SIGN function in Oracle SQL returns the sign of a given number. It indicates whether a number is positive, negative, or zero.


Syntax

SIGN (number)
- - number: A numeric value whose sign needs to be determined.

Return Values of SIGN Function

Input Output Description
> 0 1 The Number is positive
= 0 0 The number is zero.
< 0 -1 The number is negative.

Key Features of SIGN Function

  • Identifies whether a number is positive, negative, or zero.
  • Helps in conditional logic and comparisons.
  • Can be combined with other functions for complex calculations.
  • Works with both integer and decimal values.

Examples / Scenarios

Numeric Scenarios:-

Scenario 1:- Identify if a transaction results in a profit (1), loss (-1), or no change (0).

SELECT transaction_id, amount,
    SIGN (amount) AS profit_or_loss
FROM transactions ;

Scenario 2:- Categorize employees based on their bonus received.

SELECT employee_id, name, bonus,
    CASE SIGN (bonus)
      WHEN 1 THEN 'High Performer'
      WHEN 0 THEN 'No Bonus'
      WHEN -1 THEN 'Penalty Applied'
    END AS performance_category
FROM employees ;

Scenario 3:- Sort all transactions based on whether the amount is positive, zero, or negative.

SELECT transaction_id, amount,
    SIGN (amount) AS sign_value
FROM Transactions
ORDER BY SIGN (amount) DESC ;

Scenario 4:- Categorize salary changes as an increase, decrease, or no change.

SELECT order_id, return_amount,
    CASE
      WHEN SIGN (return_amount) = -1 THEN return_amount * 0.1
      ELSE 0
    END AS penalty
FROM Order_Returns ;

Scenario 5:- Count how many transactions are positive, zero, or negative.

SELECT SIGN (amount) transaction_type , COUNT ( * ) AS count FROM transactions
GROUP BY SIGN (amount) ;

Scenario 6:- Retrieve only negative balances from an account table.

SELECT account_id, balance FROM Accounts
WHERE SIGN (balance) = -1 ;

Advantages and Disadvantages of SIGN Function

Advantages Disadvantages
Simple and efficient for checking positive/negative values. Does not provide the absolute magnitude of a number.
Works well with CASE and conditional statements. NULL values return NULL, which may need handling.
Helps in sorting and categorizing numerical data. Cannot be used on non-numeric columns.

Common Errors in SIGN Function

Error Code Cause Solution
ORA-01722 "Invalid number" if applied to non-numeric columns. Ensure input column contains only numeric values.
NULL result If input value is NULL. Use NVL(number, 0) to handle NULL values.
ORA-01476 Division by zero when using fractional exponents with a zero base. Validate inputs to avoid zero base with fractional exponents.


EXP (Exponential) Function in Oracle SQL

The EXP function in Oracle SQL returns the mathematical constant e (Euler's number, approximately 2.718) raised to the power of a given number.


It is commonly used in exponential growth models, logarithmic transformations, and scientific calculations.


Purpose of EXP Function

  • Computes the exponential growth of a number.

    MOD ( ATAN2 (wind_v, wind_u) * (180/ ACOS (-1) ) + 360, 360) AS wind_direction
FROM weather_data ;

Scenario 3:- Find the rotation angle of a satellite antenna based on x and y offsets.

SELECT satellite_id, offset_x, offset_y,
    ATAN2 (offset_y, offset_x) * (180/ ACOS (-1) ) AS antenna_rotation_angle
FROM satellite_positions ;

Scenario 4:- Find the slope angle of a construction site given rise (y) and run (x).

SELECT slope_id, rise, run,
    ATAN2 (rise, run) * (180/ ACOS (-1) ) AS slope_angle
FROM construction_slopes ;

Scenario 5:- Given two GPS points (lat1, lon1 and lat2, lon2), compute the bearing angle between them.

SELECT point_id, lat1, lon1, lat2, lon2,
    MOD ( ATAN2 ( SIN (lon2 - lon1) * COS (lat2),
      COS (lat1) * SIN (lat2) - SIN (lat1) * COS (lat2) * COS (lon2 - lon1)) * (180/ ACOS (-1)) + 360, 360 )
    AS bearing_angle
FROM gps_coordinates ;

Limitations of ATAN2(y, x) Function

Limitation Description
Returns Radians by Default Must convert to degrees using 180/π

SINH(n) Function in Oracle SQL

The SINH(n) function in Oracle SQL returns the hyperbolic sine of a given numeric value n.


  • It is similar to the SIN(n) function but applies to hyperbolic trigonometry.
  • The function is useful in engineering, physics, and scientific calculations.

Syntax

SINH ( n )
- -n → Numeric input (in radians)

SELECT SINH ( 1 ) FROM dual ; - -Output: 1.1752011936

Key Features of SINH(n) Function

Feature Description
Returns Hyperbolic Sine Value Computes sinh(n), unlike SIN(n) which gives the standard sine value
Supports Positive & Negative Values Works with positive, negative, and zero inputs
Used in Scientific & Engineering Fields Applied in wave equations, electrical engineering, and fluid mechanics

Examples / Scenarios

Scenario 1:- Calculate the expansion rate of a metal rod using the hyperbolic sine function.

SELECT material_id, temperature_change,
    SINH (temperature_change) AS expansion_rate
FROM thermal_expansion ;

SELECT signal_id, resistance_value,
    SINH (resistance_value) AS voltage_fluctuation
FROM circuit_signals ;

    SINH (growth_factor) AS estimated_population
FROM population_growth ;

Scenario 4:- Compute fluid pressure differences in an industrial pipeline.

    SINH (pressure_difference) AS pressure_ratio
FROM fluid_dynamics ;

Scenario 5:- Electrical engineers use SINH(n) to model impedance in AC circuits.

    SINH (resistance * capacitance) AS impedance_factor
FROM Circuit_Analysis ;

Scenario 6:- SINH(n) is used in heat transfer calculations for temperature variations in an object.

    SINH (temperature / reference_temperature) AS heat_distribution
FROM Thermal_Analysis ;

Limitations of SINH(n) Function

Limitation Description
Works only with numeric values Input must be a valid number, otherwise it raises an error.
Precision issues for large values For very large numbers, floating-point precision errors may occur.
Not applicable for degrees SINH(n) requires radians, not degrees.

Common Errors with ACOS()

Error Code Cause Solution
ORA-01722 Non-numeric input Ensure n is a valid number
ORA-01428 Overflow error Use smaller values if results grow too large


Do’s and Don’ts

Do's Don'ts

Handle large values carefully using ROUND(). Don't use non-numeric inputs.
Use CAST() for precision control. Avoid unnecessary calculations when simple math suffices.

  • The hyperbolic equivalent of the standard TAN(n).

Syntax

TANH ( n )
- -n → Numeric input (in radians)

SELECT TANH ( 1 ) FROM dual ; - -Output: 0.761594156

Feature Description
Returns Hyperbolic Tangent Value Computes tanh(n), which is the ratio of sinh(n) and cosh(n)
