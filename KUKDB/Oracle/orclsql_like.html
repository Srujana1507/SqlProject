    LIKE Operator in Oracle SQL

    The LIKE operator in Oracle SQL is used to search for a specified pattern in a column.


    • It is particularly useful for performing pattern-matching searches with wildcard characters.
    • The LIKE operator supports the use of two wildcards:
      • %: Represents zero, one, or multiple characters.
      • _: Represents a single character.

    Purpose of LIKE Operator

    • To perform pattern-based searches on text data.
    • Retrieve rows where column values match a specific pattern.
    • To handle cases where exact matches (=) are not practical.

    Wildcard Characters in LIKE

    Wildcard Description
    % Represents zero or more characters.
    _ Represents a single character.
    ESCAPE Allows escaping special characters (%, _) if they are part of the search.

    Syntax

    SELECT column1, column2
    FROM table_name
    WHERE column_name LIKE pattern ;

    Using NOT LIKE:

    SELECT column1, column2
    FROM table_name
    WHERE column_name NOT LIKE pattern ;

    Key Points

    Key Point Description
    Case Sensitivity By default, the LIKE operator is case-sensitive.
    Wildcards Usage
    • % for multiple characters.
    • _ for single character.
    Pattern Matching Allows flexible search options with custom patterns.
    Works with Strings Only Typically applied to columns with string data types like VARCHAR, CHAR, etc.


    Examples / Scenarios

    Scenario 1:- Find customers whose names start with "U".

    SELECT customer_id, customer_name
    FROM customers
      WHERE customer_name LIKE 'U%' ;

    Scenario 2:- Find all products whose names end with "phone".

    SELECT product_id, product_name
    FROM products
      WHERE product_name LIKE ' %Phone %Phone' ;

    Scenario 3:- Retrieve all orders where the order description contains "urgent".

    SELECT order_id, order_description
    FROM Orders
      WHERE order_description LIKE ' %urgent% ' ;

    Scenario 4:- ( Single Character Wildcard ) Find all vendors whose names start with "T" and have "a" as the third character.

    SELECT vendor_id, vendor_name
    FROM vendors
      WHERE vendor_name LIKE ' T_a% T_a%' ;

    Scenario 5:- ( LIKE with NOT Operator ) Find customers whose names do not start with "A".

    SELECT customer_id, customer_name
    FROM customers
      WHERE customer_name NOT LIKE ' 'A% ' ;

    Scenario 6:- ( Case-Insensitive Search with UPPER ) Find products whose names contain the word "Tablet", ignoring case sensitivity.

    SELECT product_id, product_name
    FROM products
      WHERE UPPER (product_name) LIKE ' '%TABLET% ' ;

    Scenario 7:- ( LIKE with Numeric Strings ) Find transactions with IDs that start with "2023".

    SELECT transaction_id, transaction_date
    FROM transactions
      WHERE transaction_id LIKE ' _a% ' ;

    Scenario 8:- ( LIKE with ESCAPE Clause ) Find users with usernames containing "100%".

    SELECT user_id, username
    FROM users
      WHERE username LIKE ' %100\%% ' ;

    Scenario 9:- Retrieve all employee names with exactly 5 characters.

    SELECT employee_id, first_name
    FROM employees
      WHERE first_name LIKE '_ _ _ _ _' ;

    Scenario 10:- Retrieve all employee names with exactly 5 characters.

    SELECT *
    FROM files
      WHERE file_name LIKE '%.pdf' ;

    Scenario 11:- Find all users visiting URLs from a specific domain.

    SELECT *
    FROM web_logs
      WHERE visit_url LIKE 'https://www.example.com%' ;

    Scenario 12:- ( LIKE in DELETE )Delete products whose names include "Demo".

    DELETE FROM products
      WHERE product_name LIKE '%Demo%' ;

    Scenario 13:- ( LIKE in UPDATE )Update the status of inactive customers whose names start with "Test".

    UPDATE customers
    SET status = 'Inactive'
      WHERE product_name LIKE '%Demo%' ;

    Scenario 13:- ( LIKE in Subqueries )Find customers who purchased products with names containing "luxury".

      SELECT CustomerID , CustomerName
      FROM Customers
      WHERE CustomerID IN (
        SELECT CustomerID
        FROM Orders
        WHERE ProductName LIKE '%luxury%'
      ) ;

    Limitations of LIKE Operator

    Limitations Description
    Case Sensitivity LIKE is case-sensitive by default. To ignore case, functions like UPPER or LOWER are needed.
    Performance Can be slow on large datasets, especially with leading %.
    Limited Pattern Matching Cannot perform advanced pattern matching like regular expressions.
    Works Only with String Data Does not work with non-string data types unless explicitly cast.


    Common Errors with LIKE Operator

    Error Cause Solution
    ORA-01722: Invalid Number Using LIKE on a numeric column without converting it to a string. Use TO_CHAR(column) for numeric columns.
    No Rows Returned Incorrect or overly restrictive pattern specified. Verify the pattern and adjust wildcards accordingly.
    Performance Issues Using LIKE with leading % in large datasets. Use indexes or avoid leading % where possible.
