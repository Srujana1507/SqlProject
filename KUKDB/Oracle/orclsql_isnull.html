IS NULL / IS NOT NULL

NULL in Oracle SQL


NULL in Oracle SQL represents a missing, undefined, or unknown value in a column. It is not the same as zero, an empty string, or a blank space.


  • A NULL value is a placeholder for data that is unavailable or not applicable.
  • It is not equivalent to zero, an empty string, or any other default value—it is a state of "absence."

Key Features of NULL

Feature Description
Represents Missing Values Acts as a placeholder for unknown or inapplicable data.
Not Equal to Zero/Empty A NULL value is distinct from 0, an empty string, or a blank space.
Affects Comparisons Any operation involving NULL generally results in NULL or unknown.
Requires Special Handling Use functions like NVL, COALESCE, or conditions like IS NULL to manage NULL values.
Propagation in Calculations Any arithmetic operation involving NULL results in NULL.


Syntax

SELECT column_name
FROM table_name
WHERE column_name IS NULL ;


Check if a value is NOT NULL

SELECT column_name
FROM table_name
WHERE column_name IS NOT NULL ;


Examples / Scenarios Using NULL

Scenario 1:- Find employees whose email address is not provided.

SELECT employee_id , name
FROM employees
    WHERE email IS NULL ;

Scenario 2:- Find all rows where the address column is NULL.

SELECT Cust_id , name FROM customers
WHERE address IS NULL ;

Scenario 3:- Retrieve all products where the price is missing.

SELECT product_id , product_name
FROM products
WHERE price IS NULL ;

Scenario 4:- Retrieve all employee details who are having salary.

SELECT employee_id , name , salary FROM employee
WHERE salary IS NOT NULL ;

Scenario 5:- NULL cannot be compared using regular operators like = or !=.

SELECT * FROM employee
WHERE salary = NULL ;

-- Always returns no rows


Behavior of NULL in Different Contexts

Context Behavior
Arithmetic Operations Any operation with NULL results in NULL (e.g., 10 + NULL = NULL).
String Concatenation Concatenating NULL with any string results in the original string (e.g., `'Hello'
Logical Conditions Comparisons with NULL are UNKNOWN and never TRUE or FALSE.
Aggregates Aggregate functions like SUM, AVG, or COUNT ignore NULL values.


Functions to Handle NULL

Function Description Example
NVL(expr1, expr2) Replaces NULL in expr1 with expr2. NVL(salary, 0) replaces NULL salary values with 0.
NVL2(expr1, expr2, expr3) Returns expr2 if expr1 is not NULL; otherwise returns expr3. NVL2(salary, 'Has Salary', 'No Salary') checks salary and returns corresponding string.
NULLIF(expr1, expr2) Returns NULL if expr1 = expr2; otherwise returns expr1. NULLIF(salary, 0) returns NULL if salary equals 0.
COALESCE(expr1, expr2, ...) Returns the first non-NULL expression from the list. COALESCE(address1, address2, address3) provides the first available address.


Scenario 6:- Arithmetic with NULL results in NULL.

SELECT COUNT ( email )
FROM employees
    WHERE email IS NOT NULL ;

Scenario 7:- Display salaries, replacing NULL values with the minimum salary in the department.

SELECT employee_id ,
NVL ( salary, MIN (salary) OVER ( PARTITION BY epartment_id ) ) AS adjusted_salary
FROM employees
;

Scenario 8:- ( Sort Data Including NULLs ) Retrieve employees sorted by hire date, placing NULL values last.

SELECT employee_id , hire_date
FROM employees
ORDER BY hire_date NULLS LAST ;

Scenario 9:- ( NULL with Default Value ) Display product prices, replacing missing values with "Not Available."

SELECT product_id , NVL ( price, 'Not Available' ) AS price
FROM products ;

Handling NULL with Functions

Scenario 10:- ( with COALESCE ) Retrieve the first non-NULL value among alternative contact numbers.

SELECT customer_id , COALESCE ( phone1, phone2, 'No Contact Available' ) AS contact_number
FROM customers ;

Scenario 10:- ( with NVL ) Find the total sales, including orders with no discount as 0.

SELECT customer_id , SUM ( NVL ( discount, 0) ) AS total_discount
FROM orders ;

Scenario 11:- ( NVL with CASE ) Classify employees as "Active" or "Inactive" based on the last_login field.

SELECT employee_id ,
    CASE
      WHEN last_login IS NULL THEN 'Inactive'
      ELSE 'Active'
    END AS status
FROM employees ;

Scenario 12:- ( Conditional Replacement Using NVL2 ) Display the contact information of customers. If a customer has a primary phone number, display "Primary Phone Available"; otherwise, display "No Phone Available."

SELECT customer_id , NVL2 ( primary_phone 'Primary Phone Available' , 'No Phone Available' ) AS contact_status
FROM customers ;

Common Errors with NULL

Error Description Resolution
Misusing = with NULL Comparing NULL with = always returns FALSE. Use IS NULL or IS NOT NULL instead.
NULL in Aggregates Ignoring the impact of NULL values on aggregate functions. Use NVL or similar functions to handle NULL values in calculations.
NULL in Logical Operations Logical operations involving NULL result in UNKNOWN. Handle NULL explicitly in the query logic.
NULL in Joins NULL values can lead to unexpected results in join conditions. Use NVL or COALESCE to ensure consistency.


Do's and Don'ts of NULL

Do's Don'ts
Use IS NULL and IS NOT NULL for checking NULL values. Don’t use = or <> to compare NULL values.
Replace NULL with meaningful defaults using NVL or COALESCE. Don’t ignore the potential impact of NULL in aggregate functions.
Handle NULL explicitly in joins and subqueries. Don’t assume NULL equals 0, an empty string, or a blank space.
Use functions like NVL2 for conditional replacements. Avoid complex queries without accounting for NULL handling.


Benefits of Handling NULL

  • Improved Data Integrity:- Helps identify missing or incomplete data.
  • Accurate Reporting:- Ensures calculations and aggregations are meaningful.
  • Better Application Logic:- Provides consistent handling of missing values across the application.
  • Clear Query Logic:- Reduces ambiguity and improves query readability.
