UPDATE Statement in Oracle SQL

The UPDATE statement in Oracle SQL is used to modify existing records in a table. It allows updating one or multiple columns based on a condition.


This is one of the DML (Data Manipulation Language) commands, meaning it modifies the data in the database.


Syntax of UPDATE Statement

UPDATE table_name SET column1 = value1,
    column2 = value2,
    ...
[WHERE condition] ;
  • If the WHERE clause is omitted, all rows in the table will be updated!.
  • Always use WHERE carefully to avoid accidental updates.
  • table_name → The table where data needs to be updated.
  • SET column = value → Specifies the column(s) to be updated and their new values.
  • WHERE condition → Defines which rows should be updated. If omitted, all rows are updated .

Key Features of UPDATE Statement

Feature Description
Can Update Multiple Columns Allows updating one or more columns in a single query.
Can Update Multiple Rows If the WHERE condition matches multiple rows, all are updated.
Can Use Subqueries The new value for a column can be derived from a subquery.
Can Use Joins (UPDATE with JOIN) Possible to update a table based on data from another table.
Supports Transactions Changes can be committed or rolled back for data integrity.

Examples of UPDATE Statement

1. Updating a Single Column:- Updates the salary of employee with ID 101 by 10%.

UPDATE employees
SET salary = salary * 1.10
WHERE employee_id = 101 ;

2. Updating Multiple Columns:- Increases salary by 10% and changes the department for all Software Engineers.

UPDATE employees
SET salary = salary * 1.10, department_id = 5
WHERE job_title = 'Software Engineer' ;

3. Updating Data Using a Subquery:- Sets interns' salary to the company's average salary.


UPDATE employees
SET salary = ( SELECT AVG (salary) FROM employees)
WHERE job_title = 'Intern' ;

4. Updating Using a JOIN (Correlated Update):- Increases salary based on the bonus amount from another table.

UPDATE employees e
SET e.salary = e.salary + ( SELECT bonus FROM bonuses b WHERE e.employee_id = b.employee_id)
WHERE EXISTS (SELECT 1 FROM bonuses b WHERE e.employee_id = b.employee_id) ;

5. Updating All Rows:- Sets salary for all employees to 50,000.

UPDATE employees SET salary = 50000 ;
  • If a WHERE condition is missing, it updates every row in the table.(high Risk)

6. Conditional Logic using CASE:- Dynamically updates salary based on department.

UPDATE employees e
SET salary = salary + CASE
      WHEN dept_id = 10 THEN 1000
      WHEN dept_id = 20 THEN 500
      ELSE 200
    END ;

Common Clauses Used

  • WHERE - Filters rows to update.
  • RETURNING - Returns updated values to the client (useful in PL/SQL).
  • SET - Assigns new values to columns.

Example with RETURNING INTO in PL/SQL

Business Case: A company wants to give a salary raise of ₹1000 to a specific employee (with emp_id = 101). After updating the salary, they need to retrieve and display the new salary immediately.

DECLARE
    v_new_salary NUMBER ;
BEGIN
    UPDATE employees
    SET salary = salary + 1000
    WHERE emp_id = 101
    RETURNING salary INTO v_new_salary ;

DBMS_OUTPUT.PUT_LINE('New Salary: ' || v_new_salary) ;
END ;

Locking Behavior

  • The UPDATE statement implicitly locks the rows it modifies (ROW-LEVEL EXCLUSIVE locks).
  • If another transaction tries to update the same rows, it will wait or raise ORA-00054: resource busy.

Performance Considerations

  • Updates can block reads in non-committed transactions.
  • Index usage: If updating indexed columns frequently, consider the performance impact.
  • Batch updates: When dealing with large datasets, consider chunking the update (e.g., by rownum ranges or using ROWID).

Updating with MERGE for UPSERT Logic

MERGE is often used instead of UPDATE + INSERT for "update-if-exists, insert-if-not" scenarios.


Business Case: A company maintains an employees table with existing employee records. A new batch of employee data (new_employees) arrives from a recruitment system. The goal is to:

  • Update salaries if the employee already exists.
  • Insert new employees if they are not in the employees table.
MERGE INTO employees e
    USING new_employees n
    ON (e.emp_id = n.emp_id)
WHEN MATCHED THEN
    UPDATE SET e.salary = n.salary
WHEN NOT MATCHED THEN
    INSERT (emp_id, emp_name, salary) VALUES (n.emp_id, n.emp_name, n.salary) ;

Common Errors in UPDATE Statement

Error Code Cause Solution
ORA-00942:Table or view does not exist Table name is incorrect or user lacks privileges. Verify table name and UPDATE privileges.
ORA-01747:Invalid user.table.column, table.column, or column specification Trying to update a computed column or using an alias in SET. Use actual column names without alias.
ORA-02292:Integrity constraint violated - child record found Foreign key constraint prevents update Ensure related records are updated first or use CASCADE option
ORA-01407: Cannot update to NULL Column is NOT NULL but trying to set NULL value Provide a valid value instead of NULL.
ORA-12899: Value too large for column Trying to update a column with a value exceeding its size limit. Ensure value length matches column definition.

Limitations of UPDATE Statement

Limitation Description
Cannot Update Primary Key Without Foreign Key Handling If a column is a primary key referenced by another table, updating it may fail unless proper constraints (CASCADE) are used.
Cannot Use Aliases in SET Clause Column aliases cannot be used in the SET clause. The actual column name must be used.
Updates Can Cause Performance Issues Updating a large number of records at once can slow down performance. Consider using BULK UPDATE or indexing.
Triggers May Cause Unexpected Results If triggers exist on the table, an UPDATE operation may fire automatically, causing side effects.
Cannot Directly Update a View If a view is based on multiple tables, you cannot update it unless it has an INSTEAD OF trigger.

Do's and Don'ts of UPDATE

Do's Don'ts
Use a WHERE condition to avoid updating all rows accidentally. Do not update without a WHERE clause unless required.
Use indexes to improve performance when updating large datasets. Avoid updating indexed columns frequently, as it can impact performance.
Use transactions (COMMIT/ROLLBACK) for data consistency. Do not update without checking constraints, as it may cause errors.
Use subqueries when updating based on another table. Do not assume that updates will not affect related data—always verify foreign key constraints.
