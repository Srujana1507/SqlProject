BETWEEN Operator in Oracle SQL

The BETWEEN operator in Oracle SQL is used to filter the rows that fall within a specified range.


  • It is inclusive, meaning it includes the boundary values specified in the range.
  • It is a logical operator and is commonly used in the WHERE clause or HAVING clause.
  • The range specified with BETWEEN is inclusive, meaning the start and end values are part of the result.

Purpose of the BETWEEN Operator

  • To simplify range-based filtering conditions.
  • Commonly used with numbers, dates, and text (in alphabetical order).

Syntax

Basic Syntax:

SELECT column1, column2
FROM table_name
WHERE column_name BETWEEN < lower_bound > AND < upper_bound > ;

Using NOT BETWEEN:

SELECT column1, column2
FROM table_name
WHERE column_name NOT BETWEEN < lower_bound > AND < upper_bound > ;

  • column_name: The column being tested.
  • lower_bound: The starting value of the range.
  • upper_bound: The ending value of the range.

Key Points About the BETWEEN Operator

Feature Description
Simplifies Range Conditions Eliminates the need for combining conditions with >= and <=.< /td>
Inclusive of Boundaries Includes the lower and upper bounds of the specified range.
Works with Numbers, Dates, Text Can be used with numeric data, date/time data, and text values for filtering.
Case Sensitivity When used with text, it respects case sensitivity depending on the database's collation settings.

Examples / Scenarios

Scenario 1:- ( Numerical Range ) Retrieve employees with salaries between $50,000 and $80,000.

SELECT employee_id, first_name, salary
FROM employees
    WHERE salary BETWEEN 50000 AND 80000 ;


- - Equivalent Query
SELECT employee_id, first_name, salary
FROM employees
    WHERE salary >= 30000 AND salary <= 60000 ;

Scenario 2:- ( Date Range ) Find orders placed between January 1, 2024, and December 31, 2024.

SELECT order_id, order_date, total_amount
FROM orders
    WHERE order_date BETWEEN TO_DATE ( '2024-01-01' , 'YYYY-MM-DD' ) AND TO_DATE ( '2024-12-31' , 'YYYY-MM-DD' ) ;

Scenario 3:- ( Character Range ) List products with names alphabetically between 'Apple' and 'Mango'.

SELECT product_id, product_name
FROM Products
    WHERE product_name BETWEEN 'Apple' AND 'Mango' ;

Scenario 4:- ( NOT BETWEEN ) Retrieve customers whose credit limits are not between 5000 and 20000.

SELECT customer_id, customer_name, credit_limit
FROM customers
WHERE credit_limit NOT BETWEEN 5000 AND 20000 ;

Scenario 5:- ( BETWEEN with Dates and Times ) Retrieve events scheduled between '01-11-2024 08:00:00' and '15-11-2024 18:00:00'.

SELECT event_id, event_name, event_datetime
FROM events
WHERE event_datetime BETWEEN '01-11-2024 08:00:00' AND '15-11-2024 18:00:00' ;

Scenario 6:- ( BETWEEN with AND ) Find employees whose salaries are between $60,000 and $90,000 and work in department 101.

SELECT employee_id, name, salary, department_id
FROM employees
WHERE salary BETWEEN 60000 AND 90000
    AND department_id = 101 ;

Scenario 7:- ( BETWEEN in HAVING ) Retrieve departments where the average salary of employees is between $50,000 and $75,000.

SELECT department_id AVG (Salary) AS avg_salary
FROM employees
GROUP BY department_id
    HAVING AVG (Salary)
    BETWEEN 50000 AND 75000 ;

Scenario 8:- ( with Subqueries ) Retrieve products with prices within the range of the minimum and maximum prices of a specific category.

SELECT product_id, product_name, price
FROM products
WHERE price BETWEEN
    ( SELECT MIN(price)
    FROM products
      WHERE category_id = 1 )
      AND
      ( SELECT MAX(price) FROM products WHERE category_id = 1 ) ;

Scenario 9:- ( with Negative Numbers ) Retrieve employees whose performance scores are between -10 and 10.

SELECT employee_id, first_name, performance_score
FROM employees
WHERE performance_score BETWEEN -10 AND 10 ;

Scenario 10:- ( BETWEEN with UPDATE ) Update customer statuses based on credit limits within a range.

UPDATE customers
SET status = 'Preferred'
WHERE credit_limit BETWEEN 10000 AND 50000 ;

Scenario 11:- ( BETWEEN with DELETE ) Delete orders placed within a specific date range.

DELETE FROM orders
WHERE order_date BETWEEN '01-01-2024' AND '30-06-2024' ;

Scenario 12:- ( BETWEEN in INSERT INTO SELECT ) Insert sales records from a specific period into a historical archive table.

INSERT INTO sales_archive ( sale_id, sale_date, amount )
SELECT sale_id, sale_date, amount
FROM sales
WHERE sale_date BETWEEN '01-01-2024' AND '31-12-2024' ;

Scenario 13:- ( BETWEEN in CASE ) Assign rating tiers based on sales revenue ranges.

SELECT sale_id, revenue,
    SELECT
      WHEN revenue BETWEEN 0 AND 1000 THEN 'Low'
      WHEN revenue BETWEEN 1001 AND 5000 THEN 'Medium'
      WHEN revenue BETWEEN 5001 AND 10000 THEN 'High'
      ELSE 'Very High'
    END AS revenue_tier
FROM sales ;

Scenario 14:- ( BETWEEN in JOIN ) Retrieve overlapping bookings between two tables.

SELECT b1.booking_id, b2.booking_id
FROM bookings b1
JOIN bookings b2 ON b1.start_date BETWEEN b2.start_date AND b2.end_date
WHERE b1.booking_id != b2.booking_id ;

Scenario 15:- ( BETWEEN with Window Functions ) Retrieve sales transactions within the middle 50% (quartiles) of total sales.

WITH SalesRank AS (
    SELECT TransactionID, Amount,
      PERCENT_RANK () OVER ( OVER (ORDER BY Amount ) ASPercentRank
    FROM Sales
)
SELECT TransactionID, Amount
FROM SalesRank
WHERE PercentRank BETWEEN 0.25 AND 0.75 ;


Common Errors with BETWEEN Operator

Error Description Resolution
Reversed Bounds Using a larger lower bound and a smaller upper bound leads to no matching rows. Ensure the lower bound is smaller than the upper bound.
NULL Values Rows with NULL values in the column are not included in the result. Handle NULL explicitly using IS NULL or COALESCE.
Incorrect Data Type Comparing incompatible data types (e.g., numeric and string). Ensure column and bounds have matching data types.
Non-Inclusive Ranges Misunderstood Forgetting that BETWEEN includes the boundaries. Use < and> operators if exclusive bounds are required.


Limitations of BETWEEN Operator

Limitations Description
Inclusive Only Always includes boundary values; cannot create exclusive ranges directly.
Static Ranges Cannot handle dynamic ranges unless explicitly coded.
No OR Combination Cannot directly specify multiple BETWEEN conditions in a single operator.
Null Ignorance Skips rows where the value being compared is NULL.


Do's and Don'ts of BETWEEN Operator

Do's Don'ts
Use BETWEEN for simple and readable range filtering. Avoid using BETWEEN with non-inclusive requirements (e.g., excluding boundaries).
Ensure the lower and upper bounds are provided in the correct order. Do not use BETWEEN if the range involves NULL values without proper handling.
Use functions like TO_DATE for date ranges to ensure consistent formatting. Avoid using BETWEEN for overlapping ranges without careful design.
