TRUNCATE TABLE Statement in Oracle SQL

The TRUNCATE TABLE statement in Oracle SQL is used to quickly remove all rows from a table without logging individual row deletions in the undo tablespace.


Unlike DELETE, TRUNCATE is a DDL (Data Definition Language) operation, not a DML operation, which means it cannot be rolled back and releases storage space back to the tablespace immediately.


How TRUNCATE Works

  • Removes all rows from a table instantly.
  • Resets the High Water Mark (HWM) — which defines the boundary between used and unused space.
  • Auto-commits the transaction after execution.
  • Resets the identity column sequence to the starting value (if specified).
  • TRUNCATE does NOT remove table structure or dependent objects like indexes, constraints, and grants.
  • Does not fire triggers because it does not generate individual row deletes.
  • No undo or redo is generated for individual rows, which makes it faster than DELETE.

Syntax

Basic Syntax

TRUNCATE TABLE table_name ;

Truncate Table with DROP STORAGE

TRUNCATE TABLE table_name DROP STORAGE ;
  • DROP STORAGE – Releases storage back to the tablespace.
  • REUSE STORAGE – Retains storage for future use (default behavior).

Example

1. Truncate a Table:- This will remove all rows from the table:

TRUNCATE TABLE employees ;
  • All rows in the employees table are deleted.
  • No undo or redo entries are logged.
  • High Water Mark is reset.

2. Truncate and Release Storage:- This will free the storage space back to the tablespace.

TRUNCATE TABLE employees DROP STORAGE ;
  • Frees up allocated storage.
  • Helps reclaim unused space in large tables.

3. Truncate and Retain Storage:- This will delete data but retain the allocated storage.

TRUNCATE TABLE employees REUSE STORAGE ;
  • Retains storage for future inserts.
  • Improves performance when the table is expected to be populated again.

4. Truncate a Partitioned Table:- You can truncate specific partitions in a table.

ALTER TABLE sales_data TRUNCATE PARTITION jan_sales ;
  • Only the jan_sales partition is truncated.
  • Other partitions remain intact.

5. Truncate with Foreign Key References:- If a table has foreign key references, you cannot truncate it unless the referencing table is dropped or the foreign key is disabled.

ALTER TABLE orders DISABLE CONSTRAINT fk_orders_customers ;
TRUNCATE TABLE customers ;
ALTER TABLE orders ENABLE CONSTRAINT fk_orders_customers ;
  • Disables the foreign key.
  • Truncates the customers table.
  • Enables the foreign key again.

Differences Between DELETE and TRUNCATE

Feature TRUNCATE DELETE
Operation Type DDL (Data Definition Language) DML (Data Manipulation Language)
Rollback Possible No (Auto-commits) Yes (Can be rolled back)
Speed Fast (Does not generate undo/redo) Slower (Generates undo/redo)
Triggers Not fired Fired
WHERE Clause Not allowed Allowed
High Water Mark Reset Yes No
Identity Reset Yes (Resets to starting value) No
Foreign Key References Cannot truncate with active FK Can delete even with FK
Space Reuse Frees up space with DROP STORAGE Space is not reclaimed immediately

When to Use TRUNCATE vs DELETE

When to use TRUNCATE When to use DELETE
You want to quickly delete all rows in a table. You want to delete specific rows based on a condition.
You don’t need to retain rollback information. You need the ability to roll back the operation.
The table is large, and performance is critical. You need to fire row-level triggers.
You need to free up storage space. You need to retain the table's current storage allocation.
The table is not referenced by other tables through foreign keys. The table is referenced by other tables through foreign keys.

Advantages of TRUNCATE

Advantage Description
Fast Performance Much faster than DELETE because it does not generate undo or redo logs for individual rows.
Resets High Water Mark Improves performance for future inserts by resetting the high water mark.
No Locking Issues Does not generate row-level locks, reducing contention.
Space Reuse Frees up storage space when using DROP STORAGE.
Identity Column Reset Resets sequence-based identity columns to starting value.

Disadvantages of TRUNCATE

Disadvantage Description
Cannot be Rolled Back TRUNCATE is a DDL operation and commits immediately.
No WHERE Clause Cannot use a WHERE clause to selectively truncate rows.
Foreign Key Constraint Issue Cannot truncate a table with active foreign key references.
Cannot Be Used on Indexed Views Indexed views and materialized views cannot be truncated directly.

Limitations of TRUNCATE

Limitation Description
Cannot Truncate Synonyms You cannot truncate a synonym directly.
Partitioned Tables TRUNCATE can be used only on individual partitions, not on the whole table unless explicitly allowed.
Foreign Key Dependencies Tables with active foreign key constraints cannot be truncated.
Transaction Handling TRUNCATE cannot be rolled back after execution.
Materialized Views Cannot truncate a table if it’s part of a materialized view.

Common Errors and Solutions

Error Code Cause Solution
ORA-02266: unique/primary keys in table referenced by foreign keys Table is referenced by a foreign key. Disable the foreign key or drop the referencing table.
ORA-01466: unable to read data – table definition has changed Attempt to flashback a truncated table. TRUNCATE cannot be reversed using flashback.
ORA-03291: invalid truncate option - missing storage clause Invalid use of DROP STORAGE or REUSE STORAGE. Use correct syntax.
ORA-00942: table or view does not exist Table does not exist. Verify table name.
ORA-01722: invalid number Attempt to truncate a table with invalid column data. Ensure valid column data.

Do’s and Don’ts of TRUNCATE TABLE

Do's Don'ts
Use TRUNCATE for performance when removing large data sets. Don’t truncate tables with active foreign key references.
Use DROP STORAGE to reclaim space when needed. Don’t truncate tables with audit requirements.
Use REUSE STORAGE to retain existing table storage. Don’t expect rollback — TRUNCATE cannot be undone.
Use for partitioned tables when allowed. Don’t use TRUNCATE if triggers are required to fire.

Best Practices

  • Use TRUNCATE for large tables to improve performance.
  • If you need to rollback, use DELETE instead of TRUNCATE.
  • Avoid TRUNCATE when foreign keys are involved.
  • Use DROP STORAGE only when storage reclamation is necessary.
