Date Functions in Oracle SQL

Oracle SQL provides various Date Functions to perform operations like date addition, subtraction, formatting, and conversion.


These functions help in handling DATE, TIMESTAMP, and INTERVAL data types efficiently.


These functions help in extracting, formatting, and performing arithmetic operations on DATE, TIMESTAMP, and INTERVAL data types.


Date Functions offer great flexibility in handling dates and timestamps, but they come with performance considerations and format dependencies.


Key Features of Date Functions

Feature Description
Works with DATE & TIMESTAMP Oracle provides functions for both date and timestamp operations
Supports Arithmetic Operations Allows adding/subtracting days and intervals
Format Conversions Converts dates to different formats (TO_DATE, TO_CHAR)
Extracts Components Extracts Year, Month, Day, Hour, etc.
Supports Time Zone Handling Functions like CURRENT_TIMESTAMP, SESSIONTIMEZONE

Why we need to Use Date Functions

  • Date Arithmetic :- Functions like ADD_MONTHS and MONTHS_BETWEEN simplify date calculations.
  • Extracting Components :- EXTRACT(YEAR FROM SYSDATE) makes retrieving year, month, and day easy.
  • Formatting Dates :- TO_CHAR(SYSDATE, 'DD-MON-YYYY HH24:MI:SS') helps in report generation.
  • Comparing & Filtering :- WHERE TRUNC(SYSDATE) = TRUNC(order_date) is used in queries for accurate filtering.
  • Working with Time Zones :- SYSTIMESTAMP and TO_TIMESTAMP_TZ help in handling global applications.
  • Handling End-of-Month Scenarios :- LAST_DAY(SYSDATE) is useful for financial reporting.
  • Scheduling & Recurring Events :- NEXT_DAY(SYSDATE, 'MONDAY') helps in automating task scheduling.

List of Date Functions in Oracle SQL

Function Description
SYSDATE Returns the current system date and time
CURRENT_DATE Returns the current date in the session’s time zone
SYSTIMESTAMP Returns the system's date and time with fractional seconds
CURRENT_TIMESTAMP Returns the current timestamp in the session’s time zone
SESSIONTIMEZONE Returns the time zone of the current session
DBTIMEZONE Returns the database time zone
TO_DATE() Converts a string into a DATE data type
TO_CHAR() Converts a DATE to a formatted string
EXTRACT() Extracts Year, Month, Day, etc., from a date
ADD_MONTHS() Adds a specified number of months to a date
LAST_DAY() Returns the last day of the month for a given date
NEXT_DAY() Returns the next specified weekday after a given date
MONTHS_BETWEEN() Finds the number of months between two dates
ROUND() Rounds a date to the nearest unit (e.g., month, year)
TRUNC() Truncates a date to a specific unit (e.g., month, year)
NEW_TIME() Converts a date from one time zone to another
FROM_TZ() Converts a timestamp to a different time zone
TZ_OFFSET() Returns the time zone offset for a given time zone

Advantages of Date Functions

Advantage Description
Simplifies Date Calculations Functions like ADD_MONTHS, MONTHS_BETWEEN, and NEXT_DAY make date calculations easy.
Handles Leap Years Automatically Functions adjust correctly for leap years (e.g., ADD_MONTHS('2024-01-31', 1) returns 2024-02-29).
Supports Multiple Time Zones Functions like SYSTIMESTAMP, CURRENT_TIMESTAMP, and TO_TIMESTAMP_TZ help in handling global applications.
Flexible Formatting TO_CHAR allows conversion of dates into various formats (e.g., 'DD-MON-YYYY').
Extracts Specific Date Parts EXTRACT(YEAR FROM SYSDATE) allows retrieving year, month, or day without extra processing.
Works with INTERVAL and TIMESTAMP Functions can manipulate both DATE and TIMESTAMP data types.
Compatible with Comparisons & Filtering Date functions can be used in WHERE, GROUP BY, and ORDER BY clauses effectively.

Disadvantages of Date Functions

Disadvantage Description
Performance Overhead Functions like TO_DATE, TO_CHAR, and EXTRACT can slow down queries if used on indexed date columns.
Time Zone Complexity Functions like NEW_TIME and TO_TIMESTAMP_TZ require proper time zone handling.
Format Dependency TO_DATE requires an exact format match, or it may result in errors.
Limited Precision for SYSDATE SYSDATE returns date and time but lacks fractional seconds (use SYSTIMESTAMP instead).
Locale-Sensitive Output TO_CHAR(SYSDATE, 'DAY') depends on NLS_LANGUAGE, leading to different outputs across users.
Complexity in Interval Calculations Functions like MONTHS_BETWEEN return decimals, which may require additional rounding logic.
Ambiguity in Some Conversions TO_DATE('20250309', 'YYYYMMDD') works, but lacks explicit separators, causing possible confusion.

Limitations of Date Functions

Limitation Description
Date Format Must Match Exactly TO_DATE('2025-03-09', 'DD-MM-YYYY') will fail if format mismatches.
Limited Support for Time Zones in Some Functions NEW_TIME only supports a limited set of time zone abbreviations.
SYSDATE is Not Precise Enough SYSDATE does not store fractional seconds (use SYSTIMESTAMP).
Intervals Require Manual Handling Functions like MONTHS_BETWEEN return decimals instead of full months and days.
Performance Issues on Large Datasets Using TRUNC(SYSDATE) in WHERE conditions can prevent index usage, slowing queries.
No Direct Support for Business Days Oracle does not have a built-in function for skipping weekends/holidays.
Locale & NLS Dependencies Functions like TO_CHAR(SYSDATE, 'DAY') depend on session settings and can produce different outputs.



SYSDATE in Oracle SQL

SYSDATE is a built-in date function in Oracle SQL that returns the current system date and time based on the database server's operating system time.


  • The returned value is of the DATE data type, which includes both date and time components.
  • It does not include fractional seconds. If you need them, use SYSTIMESTAMP instead.

SYSDATE Syntax

SELECT SYSDATE FROM dual ;
  • DUAL is a special dummy table used for evaluating expressions.
  • This query returns the current date and time from the database server.

Key Features of SYSDATE

Feature Description
Returns Current Date and Time Provides the system’s current date and time.
No Parameters Required Directly used without any arguments.
Format Depends on NLS Settings Default format is based on NLS_DATE_FORMAT.
Supports Arithmetic Operations Can be used for date calculations (e.g., adding/subtracting days).
Independent of Session Time Zone It reflects server time, not the client’s or session’s time zone.

Examples

Scenario 1:- Find the current age of employees based on their date of birth (dob column).

SELECT emp_id, emp_name, dob,
    FLOOR (MONTHS_BETWEEN (SYSDATE, dob) / 12) AS age
FROM employees ;

Scenario 2:- A retail store wants to retrieve a list of orders placed today.

SELECT order_id, customer_name, order_date
FROM orders
    WHERE TRUNC (order_date) = TRUNC (SYSDATE)
;

Scenario 3:- A subscription-based company gives users a 1-year membership from the date they sign up.

SELECT user_id, signup_date,
    ADD_MONTHS (SYSDATE, 12) AS membership_expiry_date
FROM users ;

Scenario 4:- A logistics company wants to find orders that should have been delivered before today but are still pending.

SELECT order_id, customer_id, delivery_date, status
FROM shipments
WHERE delivery_date < SYSDATE
AND status != 'Delivered' ;

Scenario 5:- Scheduling a Report to Run at Midnight ( A finance team needs a daily revenue report that includes yesterday’s transactions. )

SELECT SUM (amount)
AS total_revenue
FROM transactions
WHERE transaction_date
BETWEEN TRUNC (SYSDATE - 1) AND TRUNC (SYSDATE - 1) - INTERVAL '1' SECOND ;

SYSDATE with Arithmetic Operations

Operation Description Example
SYSDATE + n Adds n days SYSDATE + 7 (Next week’s date)
SYSDATE - n Subtracts n days SYSDATE - 30 (Last month’s date)
SYSDATE + INTERVAL 'n' HOUR Adds n hours SYSDATE + INTERVAL '5' HOUR
SYSDATE - INTERVAL 'n' MINUTE Subtracts n minutes SYSDATE - INTERVAL '15' MINUTE

Limitations of SYSDATE

Limitation Description
Depends on Server Clock If the database server time is incorrect, SYSDATE will also be incorrect.
Lacks Time Zone Support Returns time based on server settings; does not consider session time zone.
No Fractional Seconds Does not return milliseconds; use SYSTIMESTAMP for that.
Fixed in Queries The value of SYSDATE remains constant throughout a query execution.

Common Errors with SYSDATE

Error Code Error Message Cause Solution
ORA-01843 Not a valid month Incorrect date format used in TO_DATE() Use correct format like 'DD-MON-YYYY'
ORA-01830 Date format picture ends before converting entire input string Format mismatch in TO_CHAR(SYSDATE, format) Ensure format covers full date
ORA-01850 Hour must be between 1 and 12 Wrong hour format used in conversion Use HH24 for 24-hour format

SYSTIMESTAMP in Oracle SQL

SYSTIMESTAMP is a built-in date-time function in Oracle SQL that returns the current system timestamp (date and time) with fractional seconds and time zone information.


It is similar to SYSDATE but provides higher precision and time zone support.

  • The returned value is of TIMESTAMP WITH TIME ZONE data type.
  • Includes fractional seconds (up to 6 decimal places).
  • Includes time zone offset from UTC.

SYSDATE Syntax

SELECT SYSTIMESTAMP FROM dual ;
output: 06-FEB-2025 14:45:30.123456 +05:30
  • The first part is the date and time.
  • The decimal part represents fractional seconds.
  • The +05:30 indicates the time zone offset from UTC.

Key Differences: SYSDATE vs. SYSTIMESTAMP

Feature SYSDATE SYSTIMESTAMP
Returns Date and time Date, time, fractional seconds, time zone
Data Type DATE TIMESTAMP WITH TIME ZONE
Fractional Seconds No Yes (up to 6 decimal places)
Time Zone No Yes
Precision Seconds Microseconds

Examples

Scenario 1:- Logging User Login Timestamps (A company wants to log the exact time (including microseconds) when users log in.)

CREATE TABLE user_logins (
    user_id NUMBER,
    login_time TIMESTAMP WITH TIME ZONE DEFAULT SYSTIMESTAMP
) ;

INSERT INTO user_logins (user_id) VALUES (101) ;
SELECT * FROM user_logins ;
  • The login_time column stores the precise timestamp of when a user logs in.
  • SYSTIMESTAMP ensures high precision logging.

Scenario 2:- Comparing Execution Times of SQL Queries ( A database administrator (DBA) wants to measure query execution time).

DECLARE
    v_start_time TIMESTAMP WITH TIME ZONE := SYSTIMESTAMP ; v_end_time TIMESTAMP WITH TIME ZONE ;
BEGIN
    SELECT COUNT (*) INTO v_end_time FROM large_table ;

v_end_time := SYSTIMESTAMP ;
    DBMS_OUTPUT.PUT_LINE( 'Execution Time: ' ||
      TO_CHAR (v_end_time - v_start_time, 'SS.FF6' ) || 'seconds' ) ;
END ;
/

Scenario 3:- Storing Order Processing Times with Time Zone (An e-commerce company operates in multiple time zones and wants to store the exact order processing time.)

CREATE TABLE orders (
    order_id NUMBER,
    order_time TIME ZONE WITH TIME ZONE DEFAULT SYSTIMESTAMP
) ;

INSERT INTO orders (order_id) VALUES (1001) ;
SELECT order_id, order_time FROM orders ;
  • The login_time column stores the precise timestamp of when a user logs in.
  • SYSTIMESTAMP ensures high precision logging.

Scenario 4:- Adjusting Timestamps to Different Time Zones (A company has offices in New York (EST) and London (GMT). They need to convert timestamps between time zones.)

SELECT SYSTIMESTAMP AT TIMEZONE 'America/New_York' AS ny_time ,
    SYSTIMESTAMP AT TIMESTAMP 'Europe/London' AS london_time
FROM dual ;

Scenario 5:- Generating Unique IDs Using Timestamps ( A company wants to create unique transaction IDs using timestamps. )

SELECT 'TXN_' || TO_CHAR ( SYSTIMESTAMP , 'YYYYMMDDHH24MISSFF6' ) AS unique_txn_id FROM dual ;

SYSTIMESTAMP with Arithmetic Operations

Operation Description Example
SYSTIMESTAMP + INTERVAL '1' DAY Adds 1 day SYSTIMESTAMP + INTERVAL '1' DAY
SYSTIMESTAMP - INTERVAL '1' HOUR Subtracts 1 hour SYSTIMESTAMP - INTERVAL '1' HOUR
SYSTIMESTAMP + INTERVAL '30' MINUTE Adds 30 minutes SYSTIMESTAMP + INTERVAL '30' MINUTE
SYSTIMESTAMP - INTERVAL '10' SECOND Subtracts 10 seconds SYSTIMESTAMP - INTERVAL '10' SECOND

Limitations of SYSTIMESTAMP

Limitation Description

Time Zone Awareness Needed The returned time is based on the database server's time zone, not necessarily the client’s.
More Storage Space Since it includes fractional seconds and time zone, it requires more storage than SYSDATE.

ORA-01850 Hour must be between 1 and 12 Incorrect hour format used Use HH24 for a 24-hour format



CURRENT_DATE in Oracle SQL

CURRENT_DATE is a built-in date function in Oracle SQL that returns the current date and time based on the session's time zone.


CURRENT_DATE is session-based, meaning it adjusts to the user’s time zone.


It is useful for global applications, reporting, scheduling, and time zone-based calculations.


It lacks fractional seconds, so use SYSTIMESTAMP for higher precision.


Key Points

  • Unlike SYSDATE, which returns the database server's date and time, CURRENT_DATE adapts to the user session's time zone.
  • It returns a DATE data type, meaning it does not include fractional seconds (unlike SYSTIMESTAMP).
  • If a user in New York queries CURRENT_DATE, they get New York time, while a user in London gets London time.

CURRENT_DATE Syntax

SELECT CURRENT_DATE FROM dual ;
output: 06-FEB-2025 14:30:00
  • Returns date and time according to the session time zone.

CURRENT_DATE vs. SYSDATE vs. SYSTIMESTAMP

Feature CURRENT_DATE SYSDATE SYSTIMESTAMP
Returns Current date & time based on session time zone Current date & time of the database server Current date & time with fractional seconds & time zone
Data Type DATE DATE TIMESTAMP WITH TIME ZONE
Fractional Seconds No No Yes (up to 6 decimals )
Time Zone Support Yes (session-dependent) No Yes
Usage User-specific date/time General system date/time High-precision timestamps

Examples

Scenario 1:- Displaying Local Time for Users in Different Time Zones.

SELECT user_id,
    CURRENT_DATE AS local_time
FROM users ;

Scenario 2:- Fetch all orders placed "today" based on the user’s time zone.

SELECT order_id, customer_id, order_date
FROM orders
    WHERE TRUNC (order_date) = TRUNC (CURRENT_DATE )
;

Scenario 3:- Scheduling Automated Reports at Midnight Based on User's Time Zone.

SELECT customer_id, balance,
    CURRENT_DATE AS report_time
FROM bank_accounts
    WHERE CURRENT_DATE = TRUNC (CURRENT_DATE )
;

Scenario 4:- Comparing Two Time Zones in a Multi-Region Application.

SELECT
    CURRENT_DATE AT TIME ZONE 'America/New_York' AS my_time,
    CURRENT_DATE AT TIME ZONE 'Asia/Tokyo' AS tokyo_time
FROM dual ;

Scenario 5:- Generating a Unique Daily Report ID.

SELECT 'REPORT_' || TO_CHAR ( CURRENT_DATE , 'YYYYMMDD' ) AS report_ide FROM dual ;

CURRENT_DATE with Arithmetic Operations

Operation Description Example
CURRENT_DATE + 1 Adds 1 day SELECT CURRENT_DATE + 1 FROM dual;
CURRENT_DATE - 7 Subtracts 7 days SELECT CURRENT_DATE - 7 FROM dual;
CURRENT_DATE + INTERVAL '1' HOUR Adds 1 hour SELECT CURRENT_DATE + INTERVAL '1' HOUR FROM dual;
CURRENT_DATE - INTERVAL '10' MINUTE Subtracts 10 minutes SELECT CURRENT_DATE - INTERVAL '10' MINUTE FROM dual;

Limitations of CURRENT_DATE

Limitation Description
Depends on User Session Time Zone If users don’t set their session time zone, results may be unexpected.
Less Precision It doesn’t include fractional seconds, unlike SYSTIMESTAMP.
Changes with Session Settings If a user changes their time zone using ALTER SESSION SET TIME_ZONE, the result of CURRENT_DATE changes accordingly.

Common Errors with CURRENT_DATE

Error Code Error Message Cause Solution
ORA-01843 Not a valid month Incorrect format in TO_DATE() Use correct format 'YYYY-MM-DD HH24:MI:SS'
ORA-01830 Date format picture ends before converting entire input string Incorrect usage of TO_CHAR(CURRENT_DATE, format) Ensure format matches timestamp length
ORA-01850 Hour must be between 1 and 12 Incorrect hour format used Use HH24 for a 24-hour format



NEXT_DAY(date, day) in Oracle SQL

NEXT_DAY(date, day) is a date function in Oracle SQL that returns the next occurrence of a specified weekday after a given date.


NEXT_DAY(date, day) returns the next occurrence of a weekday from a given date.


It is useful for scheduling, business processes, and automation.


It lacks fractional seconds, so use SYSTIMESTAMP for higher precision.


Considers session NLS settings, so always ensure correct language settings.


Key Points

  • It helps find the next Monday, Tuesday, etc., from a given date.
  • The function considers session NLS settings for day names (Monday, Tuesday, etc.).
  • It returns a DATE data type.

NEXT_DAY Syntax

SELECT NEXT_DAY (date, day) FROM dual ;
  • date → The starting date.
  • day → The weekday name or number (Sunday = 1, Monday = 2, etc.).
If today is 6-Feb-2025 (Wednesday), the next Monday is 12-Feb-2025.

NEXT_DAY with Numeric Day Representation

Number Weekday
1 Sunday
2 Monday
3 Tuesday
4 Wednesday
5 Thursday
6 Friday

Examples

Scenario 1:- Finding the Next Friday for Payroll Processing.

SELECT
    NEXT_DAY ( SYSDATE, 'Friday' ) AS next_payroll_day
FROM dual ;

Scenario 2:- Booking an Appointment for the Next Monday.

SELECT patient_id,
    NEXT_DAY ( appointment_date, 'Monday' ) AS next_available_monday
FROM appointments ;

Scenario 3:- Finding the Next Business Day (A company wants to process refunds only on weekdays (Monday–Friday).)

SELECT
    order_id, refund_request_date,
    CASE
      WHEN TO_CHAR (refund_request_date, 'D' ) IN (6, 7) THEN NEXT_DAY ( refund_request_date, 'Monday' )
      ELSE NEXT_DAY (refund_request_date, 'Friday')
    END AS next_refund_processing_day
FROM refunds ;

Scenario 4:- Finding the Next Delivery Date Based on Custom Schedule.

SELECT
    order_id, order_date, ,
    LEAST ( NEXT_DAY (order_date, 'Wednesday' ), NEXT_DAY (order_date, 'Saturday' )) AS next_delivery_date
FROM orders ;

Scenario 5:- Scheduling an Automated Report for the Next Sunday.

SELECT 'Weekly Report Date: ' || TO_CHAR ( NEXT_DAY (SYSDATE, 'Sunday' ), 'DD-MON-YYYY' AS report_date FROM dual ;

Limitations of NEXT_DAY

Limitation Description
NLS Settings Dependent The function depends on the NLS_DATE_LANGUAGE setting. A mismatch can cause errors.
Day Name Case Sensitivity Some Oracle versions require exact case-sensitive day names.
Time Component Retention The returned date retains the original time, which might be unexpected in some scenarios.

Common Errors with NEXT_DAY

Error Code Error Message Cause Solution
ORA-01846 Not a valid day of the week Using an incorrect or misspelled day name Use correct names (Monday, Tuesday, etc.)
ORA-01849 Badly formed date Incorrect format in TO_DATE() Ensure the date format matches DD-MON-YYYY
ORA-01843 Not a valid month Mismatch in date formats Use TO_DATE('06-FEB-2025', 'DD-MON-YYYY')



LAST_DAY(date) in Oracle SQL

LAST_DAY(date) is a date function in Oracle SQL that returns the last day of the month for a given date.


LAST_DAY(date) returns the last day of the month for a given date.


It is useful for financial reports, payroll processing, and scheduling.


Works well with other date functions like NEXT_DAY() and ADD_MONTHS().


Retains time components, so use TRUNC() if needed.


Key Points

  • It is useful for end-of-month processing, billing, and reporting.
  • The function returns a DATE data type.
  • The time component remains unchanged from the input date.

LAST_DAY Syntax

SELECT LAST_DAY (date) FROM dual ;
  • date → Any DATE or TIMESTAMP value.

Examples

Scenario 1:- Find last day of current month

SELECT
    LAST_DAY ( SYSDATE) AS last_day_of_month
FROM dual ;
If today is 15-Mar-2025 the last_day_of_month: 31-Mar-2025

Scenario 2:- Finding the Last Day of the Current Month.

SELECT employee_id, salary,
    LAST_DAY ( SYSDATE) AS payroll_cutoff
FROM employees ;

Scenario 3:- Getting the Last Day of a Specific Month (A sales department wants to analyze data for the entire month and needs the last day of a given date.)

SELECT
    LAST_DAY ( TO_DAY ( '15-MAY-2025', 'DD-MON-YYYY' )) AS last_day_may
FROM dual ;

Scenario 4:- Finding the Last Working Day of a Month (A company processes invoices only on weekdays. If the last day is a Saturday or Sunday, they move it to the previous Friday.)

SELECT
    invoice_id,
    invoice_date,
    CASE
      WHEN TO_CHAR ( LAST_DAY ( invoice_date), 'DY' ) IN ('SAT', 'SUN' ) THEN NEXT_DAY (LAST_DAY ( invoice_date) -7, 'FRIDAY' ) ELSE LAST_DAY (invoice_date)
    END AS last_working_day
FROM invoices ;

Scenario 4:- Generating Reports for the Last Day of Every Quarter (A company needs to generate quarterly financial reports for the last day of March, June, September, and December.)

SELECT
    quarter,
    NEXT_DAY (TO_DATE ('01-' || quarter || '-2025', 'DD-MON-YYYY' )) AS quarter_end_date
FROM (
    SELECT 'MAR' AS quarter FROM dual
    UNION ALL
    SELECT 'JUN' FROM dual
    UNION ALL
    SELECT 'SEP' FROM dual
    UNION ALL
    SELECT 'DEC' FROM dual
) ;

Scenario 5:- Calculating the Last Day of a Customer’s Subscription.

SELECT
    customer_id,
    subscription_start,
    NEXT_DAY (subscription_start) AS subscription_end
FROM customers ;

Limitations of LAST_DAY

Limitation Description
Time Component Retention The returned date retains the original time, which might be unexpected.
Only Works with Valid Dates The function does not handle invalid dates like 31-Feb-2025.
Does Not Consider Holidays It only finds the last day of the month, not business days or holidays.

Common Errors with LAST_DAY

Error Code Error Message Cause Solution
ORA-01843 Not a valid month Invalid month name Ensure month format is correct ('DD-MON-YYYY')
ORA-01858 Not a valid number Using a string instead of a date Convert strings using TO_DATE()
ORA-01830 Date format picture ends before converting entire input string Using incomplete date format Use correct format (DD-MON-YYYY HH24:MI:SS)



ADD_MONTHS(date, n) in Oracle SQL

ADD_MONTHS(date, n) is a date function in Oracle SQL that adds or subtracts months from a given date.


ADD_MONTHS(date, n) adds or subtracts months from a given date.


It is used in subscription management, payroll, forecasting, and billing.


Handles leap years and end-of-month dates automatically.


Works well with LAST_DAY(), TRUNC(), and NEXT_DAY() for better date handling.


Key Points

  • If n is positive, it adds months to the date.
  • If n is negative, it subtracts months from the date.
  • It maintains the day portion, but if the resulting month has fewer days, it adjusts to the last valid day.
  • Works with both DATE and TIMESTAMP data types.

ADD_MONTHS Syntax

SELECT ADD_MONTHS (date, n) FROM dual ;
  • date → Any DATE or TIMESTAMP value.
  • n → Number of months to add (positive) or subtract (negative).

Examples

Scenario 1:- Finding the Expiry Date of a Subscription.

SELECT customer_id, plan_start_date,
    ADD_MONTHS ( plan_start_date, 6 ) AS expiry_date
FROM subscriptions ;

Scenario 2:- Calculating a Credit Card Due Date (A bank needs to calculate the billing due date for customers, which is 1 month from the statement date.)

SELECT account_id, statement_date,
    ADD_MONTHS ( statement_date, 1) AS due_date
FROM credit_card_bills ;

Scenario 3:- Handling End-of-Month Adjustments ( An employee joined on 31-JAN-2025, and the HR system calculates probation period of 3 months. )

SELECT employee_id, hire_date,
    ADD_MONTHS ( hire_date, 3 ) AS probation_end_date
FROM employees ;

Scenario 4:- Handling End-of-Month Adjustments ( An employee joined on 31-JAN-2025, and the HR system calculates probation period of 3 months. )

SELECT employee_id, hire_date,
    LAST_DAY (ADD_MONTHS ( hire_date, 3 ) ) AS probation_end_date
FROM employees ;

Scenario 5:- Forecasting Future Sales ( A company wants to predict sales for the next 6 months.)

SELECT product_id, sales_date,
    ADD_MONTHS (sales_date, 6 ) AS future_sales_period

Syntax

  • date1 - The first date (end date).
  • date2 - The second date (start date).

How It Works:

  • The function returns the number of full and fractional months between date1 and date2.
  • A positive result indicates that date1 is after date2.
  • A negative result indicates that date1 is before date2.

  • Fractional values represent partial months.

Behavior on Day Differences:

  • If the day of date1 is later than date2 → Adjusts to the last day of the month.
  • Leap year impact is automatically handled.

FROM_TZ() Date Function in Oracle SQL

The FROM_TZ() function in Oracle SQL converts a TIMESTAMP value (without a time zone) to a TIMESTAMP WITH TIME ZONE value by assigning a specified time zone to the timestamp.


Purpose of FROM_TZ() Date Function

  • Converts a TIMESTAMP value into a TIMESTAMP WITH TIME ZONE.
  • Allows time zone conversion and manipulation in date-time calculations.
  • Helps standardize date-time values across different time zones for consistent reporting and processing.

Syntax

FROM_TZ (timestamp_value, time_zone)

Parameters

  • timestamp_value :- A TIMESTAMP value that does not have any time zone information.
  • A valid time zone value or a numeric offset (e.g., '-08:00' for PST).

Key Features

  • Converts TIMESTAMP to TIMESTAMP WITH TIME ZONE.
  • Time zone can be specified using both region names and numeric offsets.
  • Handles daylight saving time (DST) adjustments automatically.
  • Returns output in TIMESTAMP WITH TIME ZONE format.
  • Can be used with other time zone functions like CAST(), SYS_EXTRACT_UTC(), etc.

Key Points

  • The time_zone parameter can be a time zone region name (like 'America/New_York') or a numeric offset (like '-08:00').
  • If the timestamp_value is NULL, the function returns NULL.
  • The time_zone must be a valid time zone or offset; otherwise, Oracle raises an error.
  • The result is stored in the TIMESTAMP WITH TIME ZONE format.

How FROM_TZ() Works

  • Takes a TIMESTAMP value.
  • Applies the specified time zone to the TIMESTAMP.
  • Returns the result as a TIMESTAMP WITH TIME ZONE value.

Examples

Scenario 1:- Convert a TIMESTAMP to TIMESTAMP WITH TIME ZONE using a numeric offset.

SELECT
    FROM_TZ ( TIMESTAMP '2025-02-20 15:30:00' , '-08:00' ) AS converted_time
FROM dual ;
Output: 20-FEB-25 03.30.00.000000 PM -08:00
  • TIMESTAMP value is 2025-02-20 15:30:00.
  • Time zone offset -08:00 corresponds to Pacific Standard Time (PST).

Scenario 2:- Convert a TIMESTAMP value using a named time zone (America/New_York).

SELECT
    FROM_TZ ( TIMESTAMP '2025-04-09 09:00:00' , 'America/New_York' ) AS converted_time
FROM dual ;
Output: 10-MAR-25 09.00.00.000000 AM AMERICA/NEW_YORK
  • 09:00 AM in America/New_York time zone is correctly converted.

Scenario 3:- Convert a timestamp from GMT to Indian Standard Time (IST).

SELECT
    FROM_TZ ( TIMESTAMP '2025-07-10 12:00:00' , '+05:30' ) AS converted_time
FROM dual ;
Output: 10-JUL-25 12.00.00.000000 PM +05:30
  • GMT +5:30 is Indian Standard Time (IST).

Scenario 4:- Use CAST() with FROM_TZ() (Convert a TIMESTAMP WITH TIME ZONE to a DATE value.)

SELECT
    CAST (
      FROM_TZ ( TIMESTAMP '2025-04-20 10:00:00' , '-05:00' ) AS DATE)
    AS converted_date
FROM dual ;
Output: 20-APR-25
  • CAST() removes the time zone information, returning only the DATE

Scenario 5:- Combine FROM_TZ() with SYS_EXTRACT_UTC() - Convert a local timestamp to UTC time using FROM_TZ() and SYS_EXTRACT_UTC().

SELECT
    SYS_EXTRACT_UTC (
      FROM_TZ ( TIMESTAMP '2025-05-15 18:30:00' , '+05:30' )) AS utc_time
FROM dual ;
Output: 15-MAY-25 13:00:00
  • +05:30 is Indian Standard Time (IST)
  • Converted to UTC by subtracting 5 hours and 30 minutes.

Scenario 6:- Store and convert user activity timestamps to a consistent time zone.

INSERT INTO user_activity_log (user_id, activity_time)
VALUES (
    101,
    FROM_TZ ( TIMESTAMP '2025-08-10 14:30:00' , 'America/New_York' )
) ;
  • Stores user activity in the America/New_York time zone.
  • Ensures consistent handling of time zone information.

Scenario 7:- Find Total Working Hours Across Time Zones - Convert working hours from PST to UTC.

SELECT employee_id
    FROM_TZ ( start_time, 'PST' ) AS start_time,
    FROM_TZ ( end_time, 'PST' ) AS end_time,
    SYS_EXTRACT_UTC ( FROM_TZ (end_time, 'PST' )) - SYS_EXTRACT_UTC ( FROM_TZ (start_time, 'PST' )) AS working_hours
FROM employee_hours ;

Scenario 8:- Convert flight departure times to a specific time zone.

SELECT flight_id,
    departure_time,
    FROM_TZ ( departure_time, 'GMT' ) AS departure_in_gmt
FROM flights ;

TZ_OFFSET() Date Function in Oracle SQL

The TZ_OFFSET() function in Oracle SQL returns the time zone offset for a specified time zone.


The offset is the difference (in hours and minutes) between the specified time zone and Coordinated Universal Time (UTC).


Purpose of TZ_OFFSET() Date Function

  • Returns the offset of a time zone from UTC.
  • Can be used to convert local times to UTC or vice versa.
  • Helps in adjusting or aligning timestamps across different time zones.
  • Handles daylight saving time (DST) automatically when a named time zone is used.

Syntax

TZ_OFFSET ( time_zone)
time_zone - A valid time zone name (e.g., 'America/New_York') or time zone abbreviation (e.g., 'PST').

Key Features

  • Returns offset in the format [+|-]HH:MI (hours and minutes).
  • Supports both numeric offsets and time zone names.
  • Adjusts for daylight saving time (DST) automatically.
  • Can be combined with other date functions to modify timestamps.
  • Works well with FROM_TZ(), CAST(), and EXTRACT() functions.

Key Points

  • If a valid time zone is not specified, Oracle raises an error.
  • TZ_OFFSET() returns the offset as a string value in VARCHAR2 format.
  • If the input is NULL, the function returns NULL.
  • The output includes the sign (+ or -) to indicate the direction of the offset from UTC.
  • The function does NOT consider fractional seconds.

How TZ_OFFSET() Works

  • Takes a valid time zone name or abbreviation.
  • Checks the current offset of the time zone from UTC.
  • Returns the result as a VARCHAR2 value in [+|-]HH:MI format.

Examples

Scenario 1:- Get the time zone offset for 'America/New_York'.

SELECT
    TZ_OFFSET ( 'America/New_York' ) AS offset
FROM dual ;
Output: -05:00 --America/New_York is 5 hours behind UTC (during standard time).

Scenario 2:- Get the offset for 'America/Los_Angeles' (which observes DST).

SELECT
    TZ_OFFSET ( 'America/Los_Angeles' ) AS offset
FROM dual ;
Output: -08:00 -- Oracle adjusts the offset automatically based on whether DST is in effect.

Scenario 3:- Get the offset for a numeric time zone +05:30 (Indian Standard Time).

SELECT
    TZ_OFFSET ( '+05:30' ) AS offset
FROM dual ;
+05:30 corresponds to Indian Standard Time (IST).

Scenario 4:- Get Offset for UTC Time Zone.

SELECT
    TZ_OFFSET ( 'UTC' ) AS offset
FROM dual ;
UTC is the reference point; therefore, the offset is +00:00.

Scenario 5:- Use TZ_OFFSET() with FROM_TZ() ( Convert a timestamp to a specific time zone using TZ_OFFSET() with FROM_TZ(). )

SELECT
    FROM_TZ ( TIMESTAMP, '2025-05-10 14:30:00' , TZ_OFFSET ( TIMESTAMP, 'America/Los_Angeles' ) ) AS adjusted_time
FROM dual ;
Output: 10-MAY-25 02.30.00.000000 PM -07:00
  • FROM_TZ() assigns the offset returned by TZ_OFFSET() to the TIMESTAMP.

Scenario 6:- Convert employee working hours from local time zones to UTC.

SELECT employee_id,
    start_time,
    FROM_TZ ( start_time, TZ_OFFSET ( '2025-05-10 14:30:00' , ) ) AS utc_start_time
FROM employee_schedule ;
  • TZ_OFFSET() provides the offset for America/New_York.
  • FROM_TZ() adjusts the timestamp to UTC.

Scenario 7:- Store the offset based on the user's location.

INSERT INTO user_time_log (user_id, login_time, timezone_offset)
VALUES (
    101,
    SYSTIMESTAMP ( TZ_OFFSET 'Europe/London' )
) ;
  • Stores the user's login time along with the correct offset based on their location.

Scenario 8:- Calculate the difference in flight departure times using time zone offsets.

SELECT flight_id,
    TZ_OFFSET 'America/New_York' ) AS ny_offset,
    TZ_OFFSET 'Europe/London' ) AS london_offset,
    TZ_OFFSET 'Asia/Tokyo' ) AS tokyo_offset
FROM flight_schedule ;
  • Provides offsets for different flight departure locations.
  • Helps in calculating flight durations accurately.
