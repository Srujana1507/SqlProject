Arithmetic Operators in Oracle SQL

Arithmetic operations are mathematical computations that manipulate numeric values in SQL queries.


These operations are performed on numerical columns, constants, or expressions to derive meaningful insights.


These operators can be used in SELECT queries, WHERE conditions, GROUP BY, ORDER BY, and expressions.


Works with both integer and decimal values.


List of Arithmetic Operators in Oracle SQL

Operator Description Example
+ (Addition) Adds two numbers. 10+5
- (Subtraction) Subtracts second number from first. 10 - 5
* (Multiplication) Multiplies two numbers. 10 * 5
/ (Division) Divides first number by second. 10 / 2
MOD() (Modulo) Returns the remainder of division. MOD(10,3)

Key Features of Arithmetic Operations in Oracle SQL

  • Performed on Numeric Data Types - Arithmetic operations can only be executed on numeric data types (NUMBER, INTEGER, FLOAT, etc.).
  • Supports Column, Constants, and Expressions – Operations can be performed on table columns, constants, and expressions in SQL queries.
  • Works with Functions – Can be used with aggregate functions like SUM(), AVG(), etc.
  • NULL Handling – If any operand in an arithmetic operation is NULL, the result will also be NULL.
  • Supports Order of Operations – Follows standard mathematical precedence rules (BODMAS/PEMDAS).

Common Errors with Arithmetic Operators

Error Cause Solution
ORA-01722: invalid number Using arithmetic operations on non-numeric columns. Ensure the column contains only numeric values.
ORA-01476: divisor is equal to zero Dividing by zero in a calculation. Use CASE WHEN column != 0 THEN column1 / column2 END.
NULL result Performing arithmetic on a NULL value. Use NVL(column, 0) to replace NULLs.

Limitations of Arithmetic Operators

Limitation Description Example Workaround
Division by Zero Error Division by zero causes an error in Oracle SQL. 10 / 0 causes an error→ ORA-01476: divisor is equal to zero Use CASE or NULLIF() to avoid division by zero: SELECT 10 / NULLIF(0, 0) FROM dual;
NULL Values Impact Any arithmetic operation involving NULL results in NULL. SELECT 10 + NULL FROM dual; → Result: NULL Use NVL() to replace NULL with a default value: SELECT 10 + NVL(NULL, 0) FROM dual;
Implicit Data Type Conversion Arithmetic operations on non-numeric values may cause conversion errors. SELECT 'ABC' + 10 FROM dual; → ORA-01722: invalid number Ensure the column is numeric before performing calculations.
Precision Loss in Division Integer division may lead to precision loss if not handled correctly. SELECT 10 / 3 FROM dual; → Result: 3 (instead of 3.3333) Use CAST() to ensure decimal precision: SELECT CAST(10 AS NUMBER(10,2)) / 3 FROM dual;
Operator Precedence Issues Wrong precedence can lead to unexpected results. SELECT 10 + 5 * 2 FROM dual; → Result: 20 (instead of 30) Use parentheses () to enforce correct evaluation: SELECT (10 + 5) * 2 FROM dual;
Performance Overhead Using arithmetic operations on indexed columns can degrade performance. SELECT * FROM employees WHERE salary * 1.1 > 50000; Perform calculations outside conditions or use computed columns.

Do's and Don'ts of Arithmetic Operators

Do's Don'ts
Use NVL(column, 0) to handle NULL values. Don’t divide by zero—handle it using CASE or NULLIF().
Use parentheses () to control order of execution. Don’t use arithmetic operators on non-numeric columns.
Use MOD() for remainder calculations. Don’t assume division will always return an integer—handle decimals properly.


+ Operator in Oracle SQL

  • The + operator is a basic arithmetic operator in Oracle SQL used to add two numeric values together.
  • It is commonly used in queries to compute totals, sums, or combined values in SELECT statements, or within expressions in the SELECT, WHERE, or HAVING clauses.

Purpose of + Addition Operator

Purpose Description
Perform Addition Adds two numeric values, either from columns, literals (constants), or expressions.
Combine Numeric Data Useful for computing total amounts, combining salaries and bonuses, or adding quantities and adjustments.
Support in Expressions Works seamlessly with numeric functions, CASE expressions, and subqueries.

Syntax

SELECT column1 + column2 AS result
FROM table_name ;

Key Features

  • Works only with numeric data types (NUMBER, INTEGER, FLOAT, etc.).
  • Returns NULL if either operand is NULL (unless handled using NVL() or COALESCE()).
  • Supports addition of column values, literals, and expressions.
  • Standard arithmetic precedence applies when combined with other operators.

Examples

Scenario 1:- Calculate the total salary of employees, including their bonuses.

SELECT employee_id, first_name, salary, bonus, salary + bonus AS total_salary
FROM employees ;

Scenario 2:- Add 1000 to each employee’s salary.

SELECT employee_id, salary, salary + 1000 AS increased_salary
FROM employees ;

Scenario 3:- Find the discount amount applied on each product.

SELECT product_id, product_name, price, discount, price - discount AS final_price
FROM products ;

Scenario 4:- Calculate total price after adding a fixed service fee.

SELECT order_id, product_id, total_price, total_price + 50 AS price_with_service_fee
FROM orders ;

Scenario 5:- Calculate annual compensation including bonus.

SELECT employee_id, (salary * 12) + bonus AS annual_compensation
FROM employees ;

Scenario 6:- Combine results from two different subqueries — calculate overall inventory (from two warehouses).

SELECT p.product_id,
( SELECT SUM (quantity) FROM warehouse_a WHERE product_id = p.product_id) +
(SELECT SUM (quantity) FROM warehouse_b WHERE product_id = p.product_id) AS total_inventory
FROM products p ;

Scenario 7:- ( Handling NULL Values ) Safely compute salary + bonus even if bonus is NULL.

SELECT employee_id, first_name, salary,
NVL (bonus, 0), salary + NVL (bonus, 0) AS total_compensation
FROM employees ;

Scenario 8:- ( CASE Expressions ) Add extra bonus for employees based on their department.

SELECT employee_id, salary, bonus,
    salary + bonus +
    CASE
      WHERE department = 'SALES' THEN 1000
      WHERE department = 'IT' THEN 500
      ELSE 0
    END AS total_salary_with_bonus
FROM employees ;

Limitations of + Addition Operator in Oracle SQL

Limitation Description
NULL Propagation If any operand is NULL, the result will be NULL.
Data Type Restrictions Only works on numeric columns; applying on non-numeric columns causes errors.
Type Conversion Issues Implicit conversion from VARCHAR to NUMBER can fail if the data is not numeric.
Overflows Adding very large numbers can lead to overflow errors if the column data type has restricted precision.

Common Errors in + Addition Operator

Error Code Cause Solution
ORA-01722 Invalid number when trying to add numeric and non-numeric values. Ensure both operands are numeric.
ORA-01476 Division by zero when division is part of a combined expression. Validate denominator in expressions.
ORA-01438 Value larger than precision allowed for the column. Use larger numeric data types (NUMBER(p,s)).

Do’s and Don’ts for + Operator in Oracle SQL

Do's Don'ts
Use with numeric columns or constants only. Don’t apply directly to non-numeric columns like VARCHAR.
Handle NULL using NVL() or COALESCE(). Don’t assume NULL is treated as zero — it’s not.
Use in combination with CASE for conditional addition. Don’t rely on implicit type conversion from VARCHAR to NUMBER.
Consider data type precision in addition-heavy calculations. Don’t apply addition in indexed columns within WHERE clause (impacts performance).
Use parentheses to enforce precedence if combining with other operators. Don’t write complex expressions without proper clarity (use comments or split logic).


- Operator in Oracle SQL

  • The - operator is a basic arithmetic operator in Oracle SQL used to subtract one numeric value from another.
  • It is used to calculate differences between columns, literals, or expressions.

Purpose of + Addition Operator

Purpose Description
Perform Subtraction Subtracts the right operand from the left operand.
Calculate Differences Useful in financial reports, inventory adjustments, and date calculations.
Combine with Expressions Works well with numeric functions and analytical calculations.

Syntax

SELECT column1 - column2 AS result
FROM table_name ;

Key Features

  • Operates on numeric data types (NUMBER, FLOAT, INTEGER).
  • Returns NULL if any operand is NULL, unless handled by NVL() or COALESCE().
  • Used in SELECT, WHERE, HAVING, ORDER BY, and GROUP BY clauses.
  • Can also work with dates, returning the difference in days.

Examples

Scenario 1:- Calculate net profit after subtracting expenses from revenue.

SELECT revenue, expenses, revenue - expenses AS net_profit
FROM financials ;

Scenario 2:- Calculate discount amount by subtracting the discounted price from the regular price.

SELECT product_id, price,
price - 100 AS discounted_price
FROM products ;

Scenario 3:- Find how many days have passed since the order date.

SELECT order_id, order_date,
SYSDATE - order_date AS days_since_order
FROM orders ;

Scenario 4:- Calculate net monthly income after tax deduction (20% of salary) and standard deductions.

SELECT employee_id, salary,
salary - (salary * 0.20) - 500 AS net_income
FROM employees ;

Scenario 5:- Find the difference between max and min salary within each department.

SELECT department_id,
MAX (salary) - MIN (salary) AS salary_difference
FROM employees
GROUP BY department_id ;

Scenario 6:- Calculate stock shortage by subtracting available stock from required stock.

SELECT p.product_id,
( SELECT required_quantity FROM orders o WHERE o.product_id = p.product_id AND order_id = 1001) -
(SELECT SUM (quantity) FROM warehouse_stock ws WHERE ws.product_id = p.product_id) AS shortage
FROM products p
WHERE p.product_id IN ( SELECT product_id FROM orders WHERE order_id = 1001 ) ;

Scenario 7:- ( CASE Expressions ) Deduct penalty from salary for late joiners (joining date after 1st day of month).

SELECT employee_id, salary,
    salary + bonus +
    CASE
      WHERE EXTRACT ( DAY FROM hire_date) > 1 THEN salary - 1000
      ELSE salary
    END AS salary_after_penalty
FROM employees ;

Limitations of - Subtraction Operator in Oracle SQL

Limitation Description
NULL Propagation Any subtraction involving NULL results in NULL.
Non-Numeric Data Can’t directly subtract non-numeric columns (e.g., VARCHAR).
Type Conversion Issues Implicit conversion might cause errors if non-numeric data is involved.
Date Arithmetic Specificity Subtracting dates returns days, not time components (hours, minutes).

Common Errors in - Subtraction Operator

Error Code Cause Solution
ORA-01722 Invalid number error when trying to subtract numeric and non-numeric values. Ensure both operands are numeric.
ORA-01476 Division by zero in expressions that use division after subtraction. Validate divisor before operation.
ORA-01438 Value larger than column precision after subtraction. Use larger numeric data types or handle overflow cases.

Do’s and Don’ts for - Subtraction Operator in Oracle SQL

Do's Don'ts
Use with numeric columns, constants, or date columns. Don’t use on non-numeric columns directly.
Handle NULL values using NVL() or COALESCE(). Don’t assume NULL is zero — subtraction with NULL returns NULL.
Use parentheses for clear precedence when combining with other operations. Don’t perform unnecessary nested calculations — flatten where possible.
Use with date columns to calculate day differences. Don’t rely on - to compute time differences; use INTERVAL for that.
Use subtraction in CASE to implement conditional adjustments. Don’t perform subtraction in filter conditions without understanding NULL behavior.


* (Multiplication) Operator in Oracle SQL

  • The * (Multiplication) operator in Oracle SQL is used to multiply two numeric values, which can be:
    • Columns
    • Constants
    • Expressions
    • Results of functions

Purpose of * Multiplication Operator

Purpose Description
Perform Multiplication Multiplies two numeric operands.
Calculations Used for price calculations, revenue estimations, or financial projections.
Works with Aggregations Can be combined with SUM(), AVG(), etc.
Used in Expressions Works in SELECT, WHERE, GROUP BY, HAVING, and ORDER BY clauses.

Syntax

SELECT column1 * column2 AS result
FROM table_name ;

Key Features

  • Works only with numeric types (NUMBER, FLOAT, etc.).
  • Propagates NULL — if any operand is NULL, result is NULL.
  • Can be used in expressions, comparisons, and joins.
  • Supports arithmetic precedence, so it can be combined with +, -, /.

Examples

Scenario 1:- Calculate total cost for each product by multiplying price and quantity.

SELECT product_id, quantity, price,
quantity * price AS total_cost
FROM products ;

Scenario 2:- Calculate total salary including a 10% bonus.

SELECT employee_id, salary,
salary * 1.10 AS salary_with_bonus
FROM employees ;

Scenario 3:- Calculate fine for delayed orders at $5 per day.

SELECT order_id, SYSDATE - delivery_due_date AS delay_days,
    (SYSDATE - delivery_due_date) * 5 AS fine_amount
FROM orders
WHERE SYSDATE > delivery_due_date ;

Scenario 4:- Calculate department-level projected budget by multiplying average salary with estimated new hires.

SELECT department_id,
    AVG (salary) * ( COUNT (employee_id) + 5) AS projected_budget
FROM employees
GROUP BY department_id ;

Scenario 5:- Apply different salary multipliers based on department.

SELECT employee_id, department_id, salary,
    CASE
      WHEN department_id = 10 THEN salary * 1.15
      WHEN department_id = 20 THEN salary * 1.10
      ELSE salary * 1.05
    END AS adjusted_salary
FROM employees ;

Scenario 6:- Calculate total cost per order by multiplying order quantity with the product price from the product table.

SELECT o.order_id, o.product_id, o.quantity,
o.quantity * ( SELECT p.price FROM products p WHERE p.product_id = o.product_id) AS order_cost FROM order_details o ;

Scenario 7:- Rank employees by total sales value (quantity * price) within each department.

SELECT employee_id, department_id, product_id,
    quantity * price AS sales_value,
    RANK() OVER ( PARTITION BY department_id ORDER BY quantity * price DESC ) AS sales_rank
FROM sales ;

Limitations of * Multiplication Operator in Oracle SQL

Limitation Description
NULL Propagation Multiplication with NULL returns NULL.
Non-Numeric Data Cannot multiply non-numeric columns directly.
Overflow Risk Large multiplications may exceed column precision.
Implicit Type Conversion May cause errors if strings or incompatible data types are involved.

Common Errors in - Subtraction Operator

Error Code Cause Solution
ORA-01722 Invalid number when non-numeric data is involved. Ensure both operands are numeric.
ORA-01476 Division by zero in later calculations when using multiplication results in further expressions. Check divisor before dividing.
ORA-01438 Value larger than column precision after multiplication. Use larger data types (NUMBER(20, 5) etc.).
ORA-06502 Numeric or value error (overflow). Review value ranges and calculations.

Do’s and Don’ts for * Multiplication Operator in Oracle SQL

Do's Don'ts
Use with numeric columns and constants. Don’t use with non-numeric columns.
Handle potential NULL values using NVL() or COALESCE(). Don’t assume NULL equals 0.
Use for quantity-price calculations, financial projections, etc. Don’t use with unvalidated data, especially if type conversions are possible.
Use parentheses to ensure proper order of operations. Don’t mix with string concatenation operators accidentally.
Use for calculating percentages, ratios, and projections. Don’t perform unnecessary nested multiplications; flatten logic where possible.


/ (Division) Operator in Oracle SQL

  • The / (Division) operator divides one numeric value by another. It’s primarily used to compute:
    • Ratios
    • Averages
    • Percentages
    • Per-unit costs

Purpose of / Division Operator

Purpose Description
Divide Numeric Values Divides the numerator by the denominator.
Financial Calculations Used to calculate per-unit costs, cost per employee, etc.
Percentage/Ratio Computation Easily calculate percentages or proportions.
Data Analysis Useful in analytical and statistical calculations.

Syntax

SELECT column1 / column2 AS result
FROM table_name ;

Key Features

  • Works only on numeric columns (NUMBER, FLOAT, etc.).
  • NULL propagation — if any operand is NULL, the result is NULL.
  • Division by Zero is NOT allowed, and causes ORA-01476 error.
  • Can be used in SELECT, WHERE, HAVING, ORDER BY clauses.
  • Supports combination with other arithmetic operators.

Examples

Scenario 1:- Calculate per-unit cost by dividing total price by quantity.

SELECT product_id, total_price, quantity,
total_price / quantity AS unit_price
FROM product_sales
WHERE quantity > 0 ;

Scenario 2:- Calculate each product's contribution to total revenue.

SELECT product_id, total_revenue,
    (total_revenue / ( SELECT SUM (total_revenue) FROM product_sales)) * 100 AS revenue_percentage
FROM product_sales ;

Scenario 3:- Calculate employee performance score, but handle cases where targets are zero.

SELECT employee_id, achieved_target, target,
    CASE
      WHEN target = 0 THEN 0
      ELSE (achieved_target / target) * 100
    END AS performance_score
FROM employee_targets ;

Scenario 4:- Calculate turnover ratio per product category.

SELECT category_id,
    SUM (total_sales) / NULLIF ( SUM (average_inventory), 0) AS turnover_ratio
FROM product_inventory
GROUP BY category_id ;

Scenario 5:- For each order, calculate price-to-quantity ratio and rank by ratio

SELECT order_id, product_id, price, quantity,
    price / NULLIF (quantity, 0) AS price_quantity_ratio,
    RANK () OVER ( ORDER BY price / NULLIF (quantity, 0) DESC ) AS rank_by_ratio
FROM order_details ;

Scenario 6:- Calculate profit margin for products across multiple categories.

SELECT product_id, category_id,
    (selling_price - cost_price) / NULLIF (selling_price, 0) AS profit_margin
FROM product_pricing ;

Scenario 7:- Calculate average lifetime value per order for customers over multiple years.

SELECT customer_id
    SUM (total_spent) / NULLIF ( COUNT ( DISTINCT order_id ), 0 ) AS lifetime_value_per_order
FROM customer_orders
GROUP BY customer_id ;

Limitations of / Division Operator in Oracle SQL

Limitation Description
Division by Zero Direct division by zero throws error ORA-01476.
NULL Propagation Division with NULL operands results in NULL.
Non-Numeric Data Can’t divide non-numeric data directly.
Precision Loss Divisions of large or small numbers might suffer precision loss.
Implicit Conversion Risk If columns are different types, implicit conversion may happen and cause errors.

Common Errors in / Division Operator

Error Code Cause Solution
ORA-01476 Division by zero error. Use NULLIF() to prevent division by zero.
ORA-01722 Invalid number when non-numeric data is involved. Ensure both operands are numeric.
ORA-01438 Value exceeds column precision after division. Use larger numeric data types.
ORA-06502 Numeric or value error due to overflow. Review numeric data type sizes.

Do’s and Don’ts for / Division Operator in Oracle SQL

Do's Don'ts
Use only with numeric columns or expressions. Don’t divide non-numeric columns directly.
Handle division by zero using NULLIF() or CASE. Don’t assume all denominators are greater than zero.
Combine with aggregates for ratio/percentage calculations. Don’t divide directly in poorly controlled data sets.
Use parentheses to ensure proper order of operations. Don’t nest divisions unnecessarily — flatten calculations where possible.
Validate data ranges to avoid precision overflow. Don’t expect integer division when working with floats.
