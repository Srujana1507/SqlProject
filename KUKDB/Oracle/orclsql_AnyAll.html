    ALL Operator in Oracle SQL

    The ALL operator in Oracle SQL is used to compare a value against all the values in a list or the result set of a subquery.


    • It ensures that the condition must be true for all values in the list or subquery.
    • It returns TRUE only if the comparison condition holds true for every value in the list or subquery.


    Purpose of ALL Operator

    Purpose Description
    Comparison Tests whether a condition holds true when compared with all values in a list or subquery.
    Logical Evaluation Ensures that the comparison satisfies all elements in the specified set or subquery.
    Subquery Filtering Allows comparison of a value with every value returned by a subquery.

    Basic Syntax

    SELECT column1, column2
    FROM table_name
    WHERE expression operator ALL ( subquery or list ) ;
    • expression:- The column or value being compared.
    • operator:- A comparison operator (=, <,>, <=,>=, !=, etc.).
    • subquery:- A query that returns a result set to compare against.

    Key Points About ALL Operator

    Key Point Description
    Universal Comparison The condition must be true for every value in the list or subquery.
    Requires Subquery or List The ALL operator is always used with a list of values or the output of a subquery.
    Logical Negation Can be negated using NOT, e.g., NOT > ALL.
    Combination with Operators Commonly used with comparison operators like >, <,>=, or <=.< /td>
    Performance Considerations Performance can be slower with large datasets if the subquery or list is not optimized.


    Examples of Logical Meaning

    Operator with ALL Meaning
    x > ALL (subquery) The value x is greater than every value returned by the subquery.
    x < ALL (subquery) The value x is less than every value returned by the subquery.
    x = ALL (subquery) The value x is equal to every value in the list or subquery (rarely used).
    x != ALL (subquery) The value x is not equal to any value in the list or subquery (equivalent to NOT IN).


    Examples / Scenarios

    Scenario 1:- ( with Greater Than ALL ) Find products that have a price greater than all prices in the discounted_products table.

    SELECT ProductID, ProductName, Price
    FROM Products
    WHERE Price > ALL (
      SELECT Price
      FROM discounted_products
      ) ;

    Scenario 2:- ( Less Than ALL ) Retrieve employees whose salary is less than all salaries of managers in the managers table.

    SELECT EmployeeID, Name, Salary
    FROM Employees
    WHERE Salary < ALL (
        SELECT Salary
        FROM managers
        ) ;

    Scenario 3:- ( Less Than or Equal to All ) Retrieve students who scored less than or equal to the lowest score among all students.

    SELECT StudentID, Name, Score
    FROM Students
    WHERE Score <= ALL (
        SELECT Score
        FROM Students
        ) ;

    Scenario 4:- ( Greater Than ALL ) List products whose price is greater than or equal to all products in the "Discounted" category.

    SELECT product_id, product_name
    FROM products
    WHERE price >= ALL (
        SELECT price
        FROM products
          WHERE status = 'Discounted'
          ) ;

    Scenario 5:- ( with Greater Than ALL and Aggregation ) Find employees whose salaries are greater than the average salary of all departments.

    SELECT employee_id, employee_name, salary
    FROM employees
    WHERE salary > ALL (
        SELECT AVG (salary)
        FROM departments
          GROUP BY department_id
          ) ;

    Scenario 6:- ( ALL with NOT IN ) Find products that are not included in all orders placed by customers from the customers table.

    SELECT ProductID, ProductName, Price
    FROM Products
    WHERE product_id NOT IN ALL (
        SELECT product_id
        FROM Orders
        ) ;

    Scenario 6.1:- ( ALL with NOT IN ) Find products not sold in all regions.

    SELECT ProductID, ProductName, Price
    FROM Products
    WHERE product_id NOT IN (
        SELECT product_id
        FROM Orders
        WHERE region_id = ALL (
          SELECT region_id FROM regions
        )
      ) ;

    Scenario 7:- ( ALL with Subquery on Aggregated Data ) Find stores where the total sales are greater than the total sales of all regions.

    SELECT store_id, store_name, total_sales
    FROM stores
    WHERE total_sales > ALL (
        SELECT SUM ( sales )
        FROM regions
          WHERE Region = 'North'
            GROUP BY region_id ) ;

    Scenario 8:- Find products priced higher than all average prices in their respective categories.

    SELECT ProductID, ProductName, Price
    FROM Products p
      WHERE Price > ALL (
          SELECT AVG ( Price )
          FROM Products
            WHERE p.Category = Category
              GROUP BY Category
              ) ;

    Scenario 9:- ( ALL with Explicit List ) Retrieve employees whose salary is greater than all listed values.

    SELECT EmployeeID, Name, Salary
    FROM Employees
      WHERE Salary > ALL (20000, 30000, 40000 ) ;

    Scenario 10:- ( ALL in the HAVING ) Find departments where the maximum salary is greater than the maximum salary of all employees in the "Sales" department.

    SELECT department, MAX ( salary ) AS max_salary
    FROM employees
      GROUP BY department
        HAVING MAX ( salary ) > ALL (
            SELECT MAX ( salary )
              FROM employees
                WHERE department = 'Sales'
                ) ;

    Scenario 11:- ( ALL with Correlated Subqueries ) Find employees whose salary is greater than the average salary of all employees in their respective departments.

    SELECT e1.employee_id, e1.name, e1.salary
    FROM employees e1
    WHERE e1.salary > ALL (
        SELECT AVG ( e2.salary )
        FROM employees e2
          WHERE e2.department = e1.department
          ) ;

    Scenario 12:- ( ALL with Multiple Conditions in Subquery ) Find orders where the order amount is higher than all orders placed in the international_orders table for the same customer.

    SELECT order_id, customer_id, order_amount
    FROM orders o
    WHERE order_amount ALL (
        SELECT order_amount
        FROM international_orders io
          WHERE io.customer_id = o.customer_id
          ) ;

    Scenario 13:- ( ALL with Subquery ) Retrieve employees whose salary is greater than all the salaries of employees in the Sales department.

    SELECT employee_id, first_name, salary
    FROM employees
    WHERE salary > ALL (
        SELECT salary
        FROM employees
          WHERE department_id = (
            SELECT department_id
            FROM departments
              WHERE department_name = 'Sales'
            )

          ) ;

    Common Errors of ALL Operator

    CauseSolution
    Error
    ORA-00913: Too Many Values Subquery in ALL returns multiple columns instead of one. Ensure the subquery returns only a single column. Example: SELECT column FROM table.
    ORA-01722: Invalid Number Data type mismatch between the value and the subquery results. Ensure the data types being compared are compatible. Use type conversion functions if needed.
    NULL Results Subquery contains NULL, which affects the evaluation of the ALL operator. Use NVL or explicitly filter out NULL values in the subquery.
    Performance Degradation Subquery in ALL is poorly optimized, leading to slow execution. Optimize the subquery with indexes or simplified logic.


    Limitations of ALL Operator

    Limitations Description
    Performance Issues When used with large datasets, ALL may lead to slower query performance.
    Requires Single-Column Subqueries The subquery in ALL must return only one column; otherwise, it causes an error.
    Complexity Queries with ALL can be harder to read and debug compared to simpler alternatives.
    Complex Logic Harder to understand for beginners compared to alternatives like EXISTS or MAX.
    NULL Handling If the subquery includes NULL, the ALL operator may return unexpected results.
    Dependence on Subquery Requires a subquery or list, making it less flexible than other operators.


    Do's and Don'ts of ALL Operator

    Do's Don'ts
    Use ALL with properly optimized subqueries or small lists. Don’t use ALL with large unindexed subqueries; it may lead to performance issues.
    Combine ALL with operators like <,>, or >= for clarity. Avoid using ALL if a more concise equivalent, like MAX, can be used for comparison.
    Ensure subqueries return consistent and relevant data. Don’t forget to handle NULL values in the subquery to avoid logical errors.
    Test the query logic thoroughly to ensure correct results. Avoid relying on ALL for complex comparisons where EXISTS or IN might be more efficient.
