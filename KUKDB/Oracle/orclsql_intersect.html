INTERSECT Operator in Oracle SQL

INTERSECT is a set operator in Oracle SQL used to return only the common rows between two SELECT queries.


  • It removes duplicates from the final result.
  • All SELECT statements must have:
    • The same number of columns
    • Compatible data types
    • Typically no ORDER BY except at the end

Key Features of UNION ALL

  • Retrieves only rows that exist in both result sets (intersection).
  • Automatically removes duplicate rows from the final output.
  • Both SELECT statements must have equal number of columns.
  • Corresponding columns in both queries must have compatible data types.
  • Output column names are taken from the first SELECT query.
  • Like other set operators, INTERSECT is used for querying only, not modifying data.
  • The output is not ordered unless an explicit ORDER BY clause is used at the end.
  • Useful when comparing and filtering data between two different sources/tables.
  • You can use standard clauses within each SELECT before applying INTERSECT.
  • Supported in Oracle, but not universally supported or behaves differently in some RDBMS like MySQL (without workarounds).

Syntax of UNION ALL

SELECT column1, column2, ... FROM table1
INTERSECT SELECT column1, column2, ... FROM table2 ;

Examples of INTERSECT Statement

1. Identify Customers Who Bought Both Online and In-Store.

SELECT customer_id, customer_name FROM online_orders
INTERSECT SELECT customer_id, customer_name FROM store_orders
ORDER BY customer_id ;

2. Using WHERE with INTERSECT:- Filters data before merging the results.

  • Retrieve IDs and names of employees who work in both HR and Finance departments.
SELECT emp_id, emp_name FROM hr_employees
WHERE job_role = 'Analyst'
INTERSECT SELECT emp_id, emp_name FROM finance_employees
WHERE job_role = 'Analyst' ;

3. HR wants to find applicants who applied for both Developer and Tester roles.

SELECT candidate_id, email FROM job_applications
WHERE position_applied = 'Developer' INTERSECT SELECT candidate_id, email FROM job_applications
WHERE position_applied = 'Tester' ;

4. Using GROUP BY with INTERSECT:- Identify Customers with High Purchases in Both Online and In-Store Channels

  • The Marketing and Sales teams want to identify customers who have spent more than $5000 in both the online store and the physical store. This helps them create a premium loyalty program targeting consistent high spenders across both channels.
SELECT customer_id
FROM online_orders
GROUP BY customer_id
HAVING SUM (order_amount) > 5000
INTERSECT SELECT customer_id
FROM store_orders
GROUP BY customer_id
HAVING SUM (order_amount) > 5000 ;

5. Using INTERSECT with Aggregate Functions:- Identify Vendors with High Total Sales and Shipments.

Business Case: The Sales & Finance departments want to identify customers who:

  • The Procurement Team wants to find vendors who have: On average, purchase high-value orders (avg order > $5,000), and On average, make high-value payments (avg payment > $5,000).
SELECT customer_id
FROM orders
GROUP BY customer_id
HAVING AVG (order_total) > 5000
INTERSECT SELECT customer_id
FROM payments
GROUP BY customer_id
HAVING AVG (payment_amount) > 5000 ;

5. Using INTERSECT with Joins:- Retrieve employee and customer names who belong to the same region as their respective departments or stores

SELECT e.emp_name, d.region
FROM employees e
JOIN departments d ON e.dept_id = d.dept_id
UNION ALL SELECT c.cust_name, s.region
FROM customers c
JOIN stores s
ON c.store_id = s.store_id ;

Limitations of UNION ALL

Limitation Description
Column Compatibility All queries must have the same number of columns with compatible data types.
ORDER BY Restriction The ORDER BY clause can only be applied at the end of the last SELECT.
Data Duplication Since duplicates are not removed, it can lead to redundancy in reports.
Larger Result Sets If source tables contain many duplicates, result sets can be significantly larger.

Common Errors in INTERSECT

Error Cause Solution
ORA-01790: Expression must have same datatype Column types in SELECTs don't match Use type conversion (e.g., TO_CHAR, CAST)
ORA-00933: SQL command not properly ended Misuse of ORDER BY inside subqueries Place ORDER BY only at the end
ORA-00904: Invalid identifier Column name mismatch Ensure all columns are correctly named and aliased

Do’s and Don’ts of INTERSECT in Oracle SQL

Do's Don'ts
Use INTERSECT when you need to find common rows between two datasets. Don’t use INTERSECT if the two queries return different numbers of columns.
Ensure both SELECT statements have the same number of columns. Don’t mix incompatible data types across the SELECT columns.
Confirm corresponding columns are of compatible data types. Don’t use ORDER BY inside individual SELECT queries—only apply at the end.
Use INTERSECT for data comparison across systems or data sync checks. Don’t assume results will be sorted—sorting must be done explicitly.
Aliases in first SELECT will be used in final output—name them clearly. Don’t rely on INTERSECT if duplicates matter—distinct rows only are returned.
Apply filters (WHERE, JOIN, GROUP BY) within each SELECT as needed. Don’t apply WHERE after INTERSECT—use it inside each SELECT.
Use in reporting to cross-check integrity between systems or logs. Don’t expect INTERSECT to perform well on very large data sets without indexing.
