UNION Set Operator in Oracle SQL

The UNION set operator in Oracle SQL is used to combine the result sets of two or more SELECT queries while eliminating duplicate rows.


It merges the outputs into a single result set and performs an implicit DISTINCT operation.


Key Features of UNION

  • Combines result sets from multiple SELECT queries.
  • Removes duplicate rows by default.
  • Ensures all SELECT statements within the UNION have the same number of columns.
  • The columns must have compatible data types.

Syntax of UNION

SELECT column1, column2, ... FROM table1
UNION SELECT column1, column2, ... FROM table2 ;

Examples of UNION Statement

1. Using ORDER BY with UNION:-

  • The HR department wants to list employees who:
    • Earn a salary greater than 5000
    • Belong to department 10
SELECT emp_name, emp_salary FROM employees
UNION SELECT cust_name, cust_income FROM customers
ORDER BY emp_name ;
  • The ORDER BY clause is applied only at the end of the last SELECT statement.
  • It sorts the final result set.

2. Using UNION with WHERE Clause:- Filters data from both queries before combining.

  • A company wants to identify and analyze high-earning individuals, including:
    • Employees with a salary greater than ₹50,000
    • Customers with an income greater than ₹50,000
SELECT emp_id, emp_name FROM employees
WHERE emp_salary > 50000
UNION SELECT cust_id, cust_name FROM customers
WHERE cust_income > 50000 ;

3. Using UNION with GROUP BY:- Groups data before applying the UNION.

  • To analyze the distribution of Employees across different departments, Customers across different regions.
SELECT department, COUNT (*) FROM employees
GROUP BY department
UNION SELECT region, COUNT (*) FROM customers
GROUP BY region ;

4. Using UNION with Aggregate Functions:- Allows aggregation before merging result sets.

  • The company wants to compare the average earnings of
    • Employees' salaries across different departments.
    • Customers' incomes across different regions.
SELECT department, AVG (emp_salary) AS avg_salary FROM employees
GROUP BY department
UNION SELECT region, AVG (cust_income) AS avg_income FROM customers
GROUP BY region ;

5. Using UNION with Joins:- Can combine results from queries with different joins.

  • The company wants to link employees with their departments and customers with their regions in a single report to:
    • Understand how employees are distributed across departments.
    • Identify where customers are located based on regions.
    • Generate a unified report for business analysis and decision-making.
SELECT e.emp_id, e.emp_name, d.dept_name FROM employees e JOIN departments d ON e.dept_id = d.dept_id
UNION SELECT c.cust_id, c.cust_name, r.region_name FROM customers c
JOIN regions r ON c.region_id = r.region_id ;

6. A company maintains separate records for employees and contractors. The HR team wants a complete list of all personnel, including duplicate names.

SELECT emp_id, emp_name, 'Employee' AS type FROM employees
UNION SELECT contractor_id, contractor_name, 'Employee' AS type FROM contractors ;

7. A retailer stores product information in separate warehouse tables. To generate a complete product catalog.

SELECT product_id, product_name, 'Warehouse A' AS source FROM warehouse_a
UNION SELECT product_id, product_name, 'Warehouse B' AS source FROM warehouse_b ;

8. A bank wants a list of all customers, categorizing them as active or inactive.

SELECT cust_id, cust_name, 'Active' AS status FROM active_customers
UNION SELECT cust_id, cust_name, 'Inactive' AS status FROM inactive_customers ;

9. A retail company wants to merge sales and return data for reporting.

SELECT order_id, product_id, quantity, 'Sale' AS transaction_type FROM sales
UNION SELECT return_id, product_id, quantity, 'Return' AS transaction_type FROM returns ;

Limitations of UNION

Limitation Description
Performance Overhead Since UNION removes duplicates (DISTINCT operation), it can be slower than UNION ALL.
Column Data Type Compatibility All SELECT statements must have the same number of columns and compatible data types.
ORDER BY Restriction The ORDER BY clause applies only to the final result set.
Cannot Use in INSERT INTO UNION cannot be directly used in INSERT INTO unless wrapped in a subquery.

Common Errors in UNION (with Error Codes)

Error Cause Solution
ORA-01790: Expression must have same datatype Mismatched column data types between queries Ensure all SELECT statements return columns with the same data type
ORA-00904: Invalid identifier Using incorrect column names in ORDER BY Use column aliases if needed
ORA-00933: SQL command not properly ended Incorrect syntax in UNION query Ensure ORDER BY is only at the last SELECT

Do's and Don'ts of UNION in Oracle SQL

Do's Don'ts
Use UNION when you need to remove duplicate rows across the combined datasets Don’t use UNION if duplicates are acceptable — it will add overhead unnecessarily
Make sure each SELECT query has the same number of columns Don’t mismatch column count — leads to ORA-01789: query block has incorrect number of result columns
Ensure compatible data types in corresponding columns across queries Don’t try to union columns with incompatible data types (e.g., VARCHAR with DATE)
Use UNION when working with normalized reporting or consolidated outputs Don’t assume UNION will preserve all rows — duplicates will be removed
Use ORDER BY only after the final SELECT Don’t place ORDER BY inside individual SELECTs — it will throw an ORA-00933 error
Use UNION for final outputs where deduplication matters, like dashboards or reports Don’t use UNION blindly in large datasets — performance can degrade due to sorting
Apply WHERE clause individually in each SELECT to optimize performance Don’t rely on WHERE clause after UNION to filter individual parts
Use column aliases in the final SELECT to control output column names Don’t assume aliases from the first SELECT will carry through automatically
Use UNION when accuracy > performance Don’t use UNION if your data is already unique — prefer UNION ALL for better speed
