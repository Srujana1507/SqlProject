NOT Operator in Oracle SQL

The NOT operator in SQL is a logical operator used to negate a condition. It is often combined with other operators (IN, BETWEEN, LIKE, etc.) to filter results that do not meet certain criteria.

  • It reverses the result of a condition, returning TRUE if the condition evaluates to FALSE and vice versa.
  • Combine with other logical operators (AND, OR, IN, LIKE, etc.) to form complex conditions.

Purpose of NOT in SQL

  • Negate Conditions:- Used to exclude rows that meet specific conditions by inverting their truth value.
  • Combining with Other Operators:- Works well in combination with AND, OR, and parentheses for complex conditions.
  • Common Usage:- Used with operators like IN, LIKE, BETWEEN, and subqueries.
  • Filter Data:- Helps filter data by excluding certain records from the result set.

Basic Syntax

SELECT column1, column2, . . . .
FROM table_name
WHERE NOT condition ;

Examples / Scenarios

Scenario 1:- ( NOT with Equality ) Find products that are not in the "Electronics" category.

SELECT product_id , product_name , category
FROM products
    WHERE NOT category = 'Electronics' ;

Scenario 2:- ( NOT with BETWEEN ) Retrieve orders where the total amount is not between $500 and $1000.

SELECT order_id , total_amount
FROM orders
    WHERE total_amount NOT BETWEEN 500 AND 1000 ;

Scenario 3:- ( NOT with LIKE ) Retrieves customers whose email addresses are not hosted by Gmail.

SELECT CustomerName, email
FROM Customers
    WHERE NOT Email LIKE '@gmail' ;

Scenario 4:- ( NOT with Comparison Operators ) Exclude employees with a salary greater than 5000.

SELECT employee_id, name, salary
FROM employees
    WHERE NOT salary > 5000 ;

Scenario 5:- ( NOT with Multiple Conditions ) Find employees who are not in department 10 or do not have a salary greater than 5000.

SELECT employee_id , employee_name , salary , department_id
FROM employees
    WHERE NOT ( department_id = 10 AND salary > 5000 ) ;

Scenario 6:- ( NOT with Logical Operator (AND) ) Exclude employees in the "Sales" department who also earn less than 3000.

SELECT employee_id, name, department, salary
FROM employees
    WHERE NOT ( department = 'Sales' AND salary < 3000 ) ;

Scenario 7:- ( NOT with OR ) Retrieve users who are neither admins nor moderators.

SELECT user_id , username , role
FROM users
      WHERE NOT ( department = ' Admin ' AND ' Moderator ') ;

Scenario 8:- ( NOT with IN ) Find employees whose roles are not "Manager" or "Clerk".

SELECT employee_id, name, role
FROM employees
    WHERE role NOT IN ( 'Manager' , 'Clerk ' ) ;

Scenario 9:- ( NOT with IS NULL ) Retrieve records where the email column is not null.

SELECT customer_id, name, email
FROM customers
    WHERE email IS NOT NULL ;

Scenario 10:- Exclude products that are either out of stock or discontinued.

SELECT product_id, product_name, stock, status
FROM products
WHERE NOT ( stock = 0 OR status = 'Discontinued' ) ;

Scenario 11:- ( NOT with AND/OR ) Find employees who are not in the list of managers.

SELECT employee_id, name
FROM employees
WHERE employee_id NOT IN (
    SELECT manager_id
    FROM managers
) ;

Scenario 12:- ( Negating Nested Conditions ) Retrieve orders not placed within a specific date range or not for a specific product category.

SELECT OrderID, OrderDate, Category
FROM Orders
WHERE NOT ( OrderDate BETWEEN '01-01-2024' AND '30-07-2024' Category = ' Electronics' ) ;

Scenario 13:- ( NOT with EXISTS ) Retrieve customers who have not placed any orders.

SELECT CustomerID, CustomerName
FROM Customers c
WHERE NOT EXISTS (
    SELECT 1
    FROM Orders o
    WHERE o.CustomerID = c.CustomerID
) ;

Scenario 14:- ( NOT with Subqueries ) Retrieve employees whose salaries are not in the top 10 highest salaries.

SELECT EmployeeID, Name, Salary
FROM Employees
WHERE NOT Salary IN (
    SELECT DISTINCT TOP 10 Salary
    FROM Employees
    ORDER BY Salary DESC
) ;

Scenario 15:- ( NOT with CASE ) Exclude students whose scores do not fall in the "Pass" range.

SELECT StudentID, Score,
      CASE
        WHERE Score BETWEEN 50 AND 100 THEN 'Pass'
        ELSE 'Fail'
      END AS Result
FROM Students
    WHERE NOT ( Score BETWEEN 50 AND 100 ) ;

Scenario 16:- ( NOT with UPDATE ) Update salaries to include a bonus for employees not in the 'Sales' department and who have been with the company for more than 5 years.

UPDATE Employees
SET Salary = Salary + 5000
WHERE NOT Department = 'Sales' AND YearsWithCompany > 5 ;

Scenario 17:- ( NOT with DELETE ) Delete products that do not start with 'Eco'.

DELETE FROM Products
WHERE NOT ProductName LIKE 'Sales' ;

Scenario 18:- ( NOT with All clauses ) Retrieve orders that are not in "Pending" or "Shipped" status and group them by customer, displaying only those customers who have at least 3 such orders.

SELECT customer_id , COUNT (order_id) AS total_orders
FROM orders
    WHERE NOT order_status IN ( 'Pending', 'Shipped' )
      GROUP BY customer_id
        HAVING COUNT (order_id) >= 3
          ORDER BY total_orders DESC ;

Common Errors of NOT Operator

Error Cause Solution
Unintended Results Negating a condition without using parentheses in compound conditions. Use parentheses to ensure correct precedence. Example: NOT (condition1 OR condition2).
Syntax Errors Using NOT in an unsupported context. Verify that NOT is used correctly in conditions.
Performance Degradation Using NOT with large subqueries or datasets without optimization. Ensure proper indexing and query optimization.
Incorrect NULL Handling Failing to handle NULL explicitly when using NOT. Use IS NOT NULL for NULL values instead of relying on NOT.


Limitations of NOT Operator

Limitations Description
Performance Issues Negating conditions can lead to inefficient query execution on large datasets.
Misinterpretation of Logic Complex negated conditions can be difficult to read and understand.
Index Usage Negating conditions might prevent the database from using indexes, slowing down query performance.
NULL Handling NOT IN fails if the subquery or list contains NULL values.


Performance Tips

  • Use Indexed Columns:- Ensure the column being negated is indexed for better performance.
  • Simplify Negations:- Where possible, rewrite negated conditions to improve readability and performance.
  • Combine with Other Filters:- Use additional filters to reduce the dataset size before applying NOT.
  • Replace NOT IN with NOT EXISTS:- NOT EXISTS handles NULLs more effectively and is often faster.
