ALTER TABLE Statement in Oracle SQL

The ALTER TABLE statement in Oracle SQL is used to modify the structure of an existing table.


It allows you to:

  • Add, modify, or drop columns.
  • Rename a table or column.
  • Add or remove constraints.
  • Enable or disable constraints.
  • Add or drop indexes.
  • Modify storage properties and tablespace.

Syntax

Adding a New Column

ALTER TABLE table_name
ADD (
    column_name datatype [DEFAULT value ]
    [CONSTRAINT constraint_name ]
) ;

Example

Adds a new column email to the employees table.

ALTER TABLE employees
ADD (email VARCHAR2(100)) ;

Modifying an Existing Column

You can change the datatype, size, or default value of a column using the MODIFY clause.

ALTER TABLE table_name
MODIFY (
    column_name datatype [DEFAULT value ]
    ) ;

Example

Increases the size of the email column from 100 to 150 characters.

ALTER TABLE employees
MODIFY (email VARCHAR2(150)) ;

Changing the Default Value - Sets the default value of department_id to 1.

ALTER TABLE employees
MODIFY (department_id DEFAULT 1) ;

Dropping a Column

You can remove an existing column using the DROP COLUMN clause.

ALTER TABLE table_name
DROP (
    column_name
    ) ;

Example

Deletes the email column from the employees table.

ALTER TABLE employees
DROP COLUMN email ;

Renaming a Table

You can rename an existing table using the RENAME clause.

ALTER TABLE table_name
RENAME TO (
    new_table_name
    ) ;

Example

Renames the employees table to staff.

ALTER TABLE employees
RENAME TO staff ;

Renaming a Column

You can rename an existing column using the RENAME COLUMN clause.

ALTER TABLE table_name
RENAME COLUMN
    Old_Column_Name TO New_Column_Name ;

Example

Renames the hire_date column to joining_date.

ALTER TABLE employees
RENAME COLUMN
    hire_date TO joining_date ;

Adding a Constraint

You can add a primary key, unique key, check, or foreign key constraint to a table using the ADD CONSTRAINT clause.

ALTER TABLE table_name
ADD CONSTRAINT (
    constraint_name CONSTRAINT Column_Name
    ) ;

Example

Adds a unique constraint on the email column.

ALTER TABLE employees
ADD CONSTRAINT emp_email_uk UNIQUE Column_Name (email) ;

Dropping a Constraint

You can remove a constraint using the DROP CONSTRAINT clause.

ALTER TABLE table_name
DROP CONSTRAINT
    constraint_name CONSTRAINT (Column_Name)
    ;

Example

Removes the emp_email_uk constraint.

ALTER TABLE employees
DROP CONSTRAINT emp_email_uk ;

Enabling a Constraint

You can enable a disabled constraint using the ENABLE clause.


Enables the unique constraint on email.

ALTER TABLE employees
ENABLE CONSTRAINT emp_email_uk ;

Disabling a Constraint

You can disable a constraint using the DISABLE clause.


Example:- Disables the unique constraint on email.

ALTER TABLE employees
DISABLE CONSTRAINT emp_email_uk ;

Changing Table Storage

You can modify the storage properties or move the table to a different tablespace using MOVE.


Example:- Moves the employees table to a new tablespace.

ALTER TABLE employees
MOVE TABLESPACE new_tablespace ;

Adding a Virtual Column

You can create a virtual column based on an expression using ADD.


Example:- Adds a virtual column full_name that concatenates first_name and last_name.

ALTER TABLE employees
ADD ( full_name AS (first_name || ' ' || last_name)) ;

Dropping a Partition

You can drop a partition from a partitioned table.


Example:- Removes the partition sales_q1 from the sales table.

ALTER TABLE sales
DROP PARTITION ( full_name AS sales_q1 ;

Common Errors and Solutions

Error Code Cause Solution
ORA-00942: table or view does not exist Table doesn't exist or you lack privileges. Ensure the table exists and you have the necessary privileges.
ORA-01430: column being added already exists Trying to add a column with an existing name. Use a unique column name.
ORA-02275: such a referential constraint already exists Attempt to add an existing constraint. Ensure that the constraint doesn't already exist.
ORA-02298: cannot validate constraint - parent keys not found Foreign key violation. Ensure referenced data exists before adding a foreign key.
ORA-01735: invalid ALTER TABLE option Wrong syntax or unsupported option. Review the syntax and options used.
ORA-02443: Cannot drop constraint - nonexistent constraint Attempt to drop a non-existing constraint. Verify the constraint name.

Advantages and Disadvantages of ALTER TABLE

Advantages Disadvantages
Allows dynamic modification of table structure without data loss. Dropping a column or constraint may lead to data loss.
Allows adding new business logic through constraints and triggers. Modifying data types of existing columns may cause data corruption.
Can improve performance by adding indexes. Frequent alterations can fragment tables and degrade performance.
Useful for adding partitioning or moving tablespaces for better storage management. Changing primary keys and constraints on large tables may cause table locking and downtime.
Allows table structure to adapt to business changes. Complex alterations may require significant rework of dependent objects like views, triggers, and procedures.

Do's and Don'ts of ALTER TABLE

Do's Don'ts
Use ADD to create new columns or constraints carefully. Don’t drop columns containing important historical data without backup.
Test changes in a development environment first. Don’t modify primary keys or constraints directly on large production tables during business hours.
Use MODIFY to increase column size, but verify existing data first. Don’t shrink column size if data already exceeds the new size.
Use ENABLE and DISABLE for maintaining constraints without dropping them. Don’t disable essential constraints unless necessary — it may lead to data integrity issues.
Rename columns and tables carefully to avoid breaking dependent objects. Don’t change storage properties frequently — it can degrade performance.

Best Practices

  • Always back up your table before making structural changes.
  • Test your ALTER TABLE statements in a test environment first.
  • Ensure that no active sessions are using the table before performing complex changes.
  • Avoid modifying or dropping primary keys unless absolutely necessary.
