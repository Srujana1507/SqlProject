COALESCE Function in Oracle SQL

The COALESCE function in Oracle SQL returns the first non-null value from a list of expressions.


  • It evaluates each expression from left to right, and as soon as it finds a non-null value, it returns that value.
  • If all expressions evaluate to NULL, then COALESCE returns NULL.

Syntax

COALESCE (expression1, expression2, ..., expressionN)
  • expression1, expression2, ..., expressionN → A list of expressions to evaluate in order.
  • Returns the first non-null expression.
  • If all expressions are NULL, it returns NULL.

Key Features of COALESCE

Feature Description
Handles Multiple Values Can take multiple expressions as input
Returns First Non-NULL Value Searches the list and returns the first non-null value
Prevents NULL Issues Avoids NULL-related problems in queries
Works with Different Data Types Prevents NULL from affecting computations.
Works on Any Data Type Supports VARCHAR2, NUMBER, DATE, etc.
Shorter Alternative to CASE Can replace CASE statements with simpler syntax

Why COALESCE in Oracle SQL?

  • To replace NULL values with a fallback value, such as a default or user-provided value.
  • To handle multiple NULLable columns and choose the first available value.
  • Unlike NVL, which only works with two expressions, COALESCE provides the flexibility to work with multiple fallback values.

Comparison of COALESCE with Other Functions

Function Purpose NULL Handling
COALESCE Returns the first non-null expression. Returns first non-null value in a list.
NVL Replaces NULL with a specified value. Works only with two arguments.
NVL2 Returns different values for NULL and NOT NULL cases. Provides different behavior for NULL and non-null cases.
CASE Conditional logic for multiple conditions. Can handle more complex NULL handling.

Scenario 1:- If home_phone is NULL, use work_phone; if work_phone is also NULL, use mobile_phone.

SELECT customer_id, name,
    COALESCE (home_phone, work_phone, mobile_phone, 'No Phone Available') AS contact_number
FROM customers ;
  • Returns home_phone if available.
  • Else, returns work_phone.
  • Else, returns mobile_phone.
  • If all are NULL, returns 'No Phone Available'.

Scenario 2:- If an employee's salary is NULL, set it to the department average salary. If the department average is also NULL, set it to 50000.

SELECT emp_id, name, salary,
    COALESCE (salary, ( SELECT AVG (salary) FROM employees e2 WHERE e1.dept_id = e2.dept_id), 50000) AS adjusted_salary
FROM employees e1 ;
  • Uses COALESCE to replace NULL salaries with the department average salary.
  • If department average is also NULL, it defaults to 50000.

Scenario 3:- If order_status is NULL, set it to "Pending".

SELECT order_id, customer_id,
    COALESCE (order_status, 'Pending' ) AS final_status
FROM orders ;

Scenario 4:- If bonus is NULL, take performance_bonus; if that is also NULL, set it to 0.

SELECT emp_id, name, salary,
    COALESCE (bonus, performance_bonus, 0 ) AS final_bonus
FROM employees ;

Scenario 5:- If actual_delivery_date is NULL, take expected_delivery_date; If expected_delivery_date is also NULL, take order_date + 7 days.

SELECT shipment_id, order_date,
    COALESCE ( actual_delivery_date, expected_delivery_date, order_date + INTERVAL '7' day ) AS final_delivery_date
FROM shipments ;

Scenario 6:- If personal_email is NULL, use work_email; if work_email is NULL, use alternate_email.

SELECT customer_id,
    COALESCE ( personal_email, work_email, alternate_email, 'No Email Available' as ) AS contact_email
FROM customers ;

Scenario 6:- An e-commerce system allows customers to pay using (Wallet balance, Gift card, Credit card ), And Conditions are : If wallet_balance is sufficient, use it, If wallet_balance is NULL or insufficient, use gift_card, If both are unavailable, charge the credit card.

SELECT order_id,
customer_id,
    COALESCE (
      CASE WHEN wallet_balance >= order_total THEN 'Wallet' END ,
      CASE WHEN gift_card >= order_total THEN 'Gift Card' END ,
      'Credit Card'
    ) AS payment_method
FROM orders ;

Limitations of COALESCE

Limitation Description
Evaluates All Arguments Even if the first value is found, Oracle checks all expressions (unlike CASE).
Works Best with Same Data Type All arguments should be implicitly convertible to a single type.
Returns NULL if All are NULL Unlike NVL, COALESCE doesn’t provide a guaranteed fallback.
Performance Issue in Large Data Sets Multiple subqueries inside COALESCE can slow down queries.

Common Errors with COALESCE

Error Code Cause Solution
ORA-00932 Inconsistent data types (e.g., COALESCE(100, 'text')) Ensure all values have compatible types.
ORA-01476 Division by zero Use COALESCE(value, 1) to prevent zero values.
ORA-00904 Invalid column reference Check column names in COALESCE().

Do’s and Don’ts of COALESCE

Do's Don'ts
Use COALESCE to replace NULL values Don’t use it for boolean conditions (use CASE)
Ensure all expressions are of compatible types Don’t assume it stops evaluating after finding the first match
Use it in SELECT, WHERE, GROUP BY, ORDER BY Avoid nesting multiple COALESCE calls in a query
Prefer it over NVL when dealing with multiple values Don’t use it with huge subqueries inside
