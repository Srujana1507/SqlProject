Analytical Functions in Oracle SQL

Analytical (or Window) functions perform calculations across a set of rows that are related to the current row, without collapsing the result set like aggregate functions do.


Analytical functions perform calculations across a set of rows that are somehow related to the current row — but unlike aggregate functions, they do not group the result into a single row.


They give you row-by-row results with reference to a group (also called a window).


They retain row-level detail while still providing calculations like running totals, rankings, moving averages, etc.


Key Components of Analytical Functions

Most analytical functions follow this pattern:

function_name (expression)
OVER (
    [PARTITION BY column_name ]
    [ORDER BY column_name ]
    [ ROWS BETWEEN ...]
)

Key Components

  • Function Name: The analytical function you want to use (e.g., RANK, DENSE_RANK, SUM, etc.).
  • Expression: The column or calculation you want to perform the function on.
  • OVER: Indicates that this is an analytical function.
  • PARTITION BY: Divides the result set into partitions to apply the function independently within each partition.
  • ORDER BY: Specifies the order of rows within each partition for the function to operate on.
  • ROWS BETWEEN: Defines a specific range of rows to consider for the calculation.

Common Analytical Functions

Here are some commonly used analytical functions in Oracle SQL:

Function Description
ROW_NUMBER() Gives a unique row number to each row within a partition.
RANK() Assigns a rank to each row within a partition, with gaps in ranking for ties.
DENSE_RANK() Assigns a rank to each row within a partition, without gaps in ranking for ties.
PERCENT_RANK() Calculates the relative rank of a row within a partition as a percentage.
CUME_DIST() Calculates the cumulative distribution of a value within a partition.
NTILE(n) Divides the result set into 'n' buckets and assigns a bucket number to each row.
LAG(expr, n) Accesses data from a previous row in the same result set.
LEAD(expr, n) Accesses data from a subsequent row in the same result set.
FIRST_VALUE() Returns the first value in an ordered set of values.
LAST_VALUE() Returns the last value in an ordered set of values.
RATIO_TO_REPORT() Calculates the ratio of a value to the sum of values in a partition.
NTH_VALUE() Return the n-th row's value in an ordered window of rows based on a given position.

What Makes Analytical Functions Special

Analytical functions are unique because they:

Feature Description
Works row-by-row They perform calculations on each row while still considering the context of other rows in the result set.
Can compare rows easily They allow you to compare a row with other rows in the same partition or window.
Powerful in reports They are particularly useful in generating reports where you need to show detailed data along with aggregated calculations.
Maintain row-level detail They retain the original row-level detail while providing aggregated results.
Better performance They can be more efficient than using subqueries or joins for certain calculations, as they operate on the result set directly.

Important Notes

  • Analytical functions do not change the number of rows returned; they simply add calculations to each row.
  • They are often used in reporting and data analysis tasks to provide insights into data
  • Not valid in WHERE, GROUP BY directly. They can be used in conjunction with other SQL clauses like WHERE, GROUP BY, and ORDER BY.
    • patterns and trends.
  • Analytical functions can be nested, allowing for complex calculations across multiple dimensions.
  • Used only with SELECT statements.

Best Practices

Best Practice Description
Use PARTITION BY Always use PARTITION BY to define the scope of your calculations.
Order Matters Pay attention to the ORDER BY clause, as it determines how rows are processed.
Use ROWS BETWEEN Use ROWS BETWEEN to specify the range of rows for calculations when needed.
Test Performance Test the performance of your queries, as analytical functions can be resource-intensive on large datasets.
Avoid OVERUSE Use analytical functions judiciously; overusing them can lead to complex queries that are hard to maintain.




ROW_NUMBER() in Oracle SQL

ROW_NUMBER() is an analytical function that assigns a unique, sequential number to each row within a partition of a result set. The numbering is based on the order specified in the ORDER BY clause.


It’s often used to rank rows uniquely and helps in Top-N queries, pagination, and duplicate detection.


Syntax

ROW_NUMBER() OVER (
    [PARTITION BY column_name ]
    [ORDER BY column_name ASC|DESC]
) AS row_num ;

-- PARTITION BY: Divides the rows into groups (optional).
-- ORDER BY: Specifies the order of rows within each partition (optional).
-- row_num: The alias for the generated row number.

Key Points

Feature Description
Sequential Assigns a unique number to each row starting from 1.
No gaps Each row gets a unique number, even if there are ties in the ORDER BY clause.
Resets per group When used with PARTITION BY, the numbering resets for each partition.
Must use ORDER BY ORDER BY is required to define the order of rows; otherwise, the result is non-deterministic.

Real-Time Scenarios

Scenario 1:- Get row numbers for all employees sorted by salary

SELECT emp_id, name, salary,
ROW_NUMBER() OVER (
    ORDER BY salary DESC ) AS row_num
FROM employees ;

-- This gives the highest-paid employee row number = 1
-- This query assigns a unique row number to each employee based on their salary in descending order.

Scenario 2:- Get top 3 highest-paid employees.

SELECT * FROM (
    SELECT emp_id, name, salary,
    ROW_NUMBER() OVER (
      ORDER BY salary DESC
    ) AS row_num
    FROM employees
) WHERE row_num <= 3 ;

-- This query retrieves the top 3 highest-paid employees by using ROW_NUMBER() to assign row numbers based on salary.

Scenario 3:- Assign row numbers within each department.

SELECT dept_id, emp_name, salary,
ROW_NUMBER() OVER (
    PARTITION BY dept_id
    ORDER BY salary DESC
) AS dept_rank
FROM employees ;

-- This query assigns row numbers to employees within each department based on their salary in descending order.

Scenario 4:- Get row numbers for employees with salary greater than 50000.

SELECT emp_id, name, salary,
ROW_NUMBER() OVER (
    ORDER BY salary DESC
) AS row_num
FROM employees
WHERE salary > 50000 ;

-- This query assigns row numbers to employees with a salary greater than 50000, ordered by salary in descending order.

Scenario 5:- De-duplicate records based on ROW_NUMBER().

You have a customer table with duplicate emails and you want to keep only the latest record (based on created_date):

SELECT * FROM (
    SELECT customer_id, email, created_date,
    ROW_NUMBER() OVER (
      PARTITION BY email
      ORDER BY created_date DESC
    ) AS row_num
    FROM customers
) WHERE row_num = 1 ;

-- This query retrieves the latest record for each unique email by using ROW_NUMBER() to assign row numbers within each email partition.

Common Use Cases

Use Case How ROW_NUMBER() Helps
Top N records Fetch top salary, sales, dates, etc.
De-duplication Remove duplicate rows using partition and sort logic
Pagination Assign numbers for each row in a result set for page viewing
First/last row in group Combine with subqueries to fetch latest per group
Debugging or Analysis Add temporary row numbers for review

ROW_NUMBER() - Errors, Messages & Resolutions

Error Code / Message Cause Resolution
ORA-30483: Window functions are not allowed here. Using ROW_NUMBER() in a place where analytic functions aren't allowed Use ROW_NUMBER() only in the SELECT or ORDER BY clauses, not in WHERE
ORA-00907: Missing right parenthesis Incorrect function syntax (e.g., missing brackets or commas) Ensure correct syntax: ROW_NUMBER() OVER (ORDER BY col)
ORA-00923: FROM keyword not found where expected Syntax error — missing or misplaced FROM clause Check query structure — especially after SELECT
ORA-30484: Missing ORDER BY clause in analytic function Used ROW_NUMBER() without ORDER BY inside OVER() Add ORDER BY inside OVER()
ORA-00904: Invalid identifier Misspelled column name in ORDER BY inside OVER() Verify that the column used in ORDER BY exists and is spelled correctly
ORA-32034 Unsupported use of ROW_NUMBER() in this context Trying to use ROW_NUMBER() in WHERE clause directly Use it in a subquery, then apply WHERE on alias (e.g., WHERE rn = 1)

Do's and Don'ts

Do's Don'ts
Always use ORDER BY with ROW_NUMBER() Don’t assume it ignores duplicates
Use PARTITION BY for per-group numbering Don’t filter directly on ROW_NUMBER() in same query
Use in subqueries for filtering top N or de-dupe Don’t confuse it with RANK() or DENSE_RANK()




RANK() in Oracle SQL

RANK() assigns a ranking number to each row within a partition of a result set. The same rank is given to rows with equal values, and the next rank is skipped accordingly.


    In simple terms: If two employees have the same salary, they will get the same rank. But the next rank will be skipped.

The RANK() function is an Analytical Function used to assign a rank to each row within a partition of a result set, based on the ORDER BY clause.

  • Rows with the same values (ties) get the same rank.
  • The next rank is skipped accordingly (i.e., creates gaps in rank).

Syntax of RANK()

RANK() OVER (
    [PARTITION BY column_name ]
    [ORDER BY column_name ASC|DESC]
) AS rank_alias ;

-- PARTITION BY: Divides the result set into partitions (optional).
-- ORDER BY: Specifies the order of rows within each partition (required).
-- rank_alias: The alias for the generated rank.

Key Features of RANK()

Feature Description
Sequential Ranking Assigns a unique rank to each row based on the ORDER BY clause.
Handles Ties Rows with the same values receive the same rank.
Gaps in Ranking The next rank is skipped after ties (e.g., 1, 1, 3).
Partitioning Can be used with PARTITION BY to rank within groups.
Same values → same rank Duplicate values receive the same rank
Gaps in ranking If 2 rows share a rank, the next rank(s) are skipped
Needs ORDER BY You must define sort order to rank properly

Examples of RANK()

Scenario 1: Rank employees by salary.

SELECT emp_id, name, salary,
RANK() OVER (
    ORDER BY salary DESC
) AS salary_rank
FROM employees ;

-- This query ranks employees based on their salary in descending order.
-- If two employees have the same salary, they will share the same rank (e.g., Rank 1), and the next will be Rank 3.

Scenario 2:- Top 3 ranked employees by salary.

SELECT * FROM (
    SELECT emp_id, name, salary,
    RANK() OVER (
      ORDER BY salary DESC
    ) AS salary_rank
    FROM employees
) WHERE salary_rank <= 3 ;

-- This query retrieves the top 3 ranked employees based on their salary in descending order.

Scenario 3:- Rank employees within each department.

SELECT dept_id, emp_name, salary,
RANK() OVER (
    PARTITION BY dept_id
    ORDER BY salary DESC
) AS dept_rank
FROM employees ;

-- This query ranks employees within each department based on their salary in descending order.

Scenario 4:- Find top 2 sales employees per region.

SELECT * FROM (
    SELECT region, emp_id, sales,
    RANK() OVER (
      PARTITION BY region
      ORDER BY sales DESC
    ) AS sales_rank
    FROM sales_employees
) WHERE sales_rank <= 2 ;

-- This query retrieves the top 2 sales employees in each region based on their sales amount in descending order.

Scenario 5:- Rank products by sales within each category.

SELECT category, product_id, sales,
RANK() OVER (
    PARTITION BY category
    ORDER BY sales DESC
) AS product_rank
FROM products ;

-- This query ranks products within each category based on their sales amount in descending order.

Scenario 6:- Handle tie-breakers.

SELECT emp_id, name, salary,
RANK() OVER (
    ORDER BY salary DESC , hire_date ASC ) AS salary_rank
FROM employees ;
-- This query ranks employees by salary, and in case of ties, it uses hire_date as a secondary sort criterion.

RANK() vs ROW_NUMBER() vs DENSE_RANK()

Function Behavior Use Case
RANK() Assigns the same rank to tied rows, skips ranks for next unique value. When you want to show gaps in ranking for ties.
ROW_NUMBER() Assigns a unique sequential number to each row, no ties. When you need a unique identifier for each row.
DENSE_RANK() Assigns the same rank to tied rows, but does not skip ranks. When you want continuous ranking without gaps.

Things to Remember

  • RANK() is an analytical function, so it must be used with the OVER() clause.
  • ORDER BY is mandatory to define how rows are ranked.
  • PARTITION BY is optional and allows you to rank within groups.
  • RANK() can create gaps in ranking when there are ties.
  • RANK() is useful for generating reports where you need to show ranks along with detailed data.
  • RANK() can be used in subqueries to filter top N records or to de-duplicate data.

Use PARTITION BY for per-group ranking Don’t filter directly on RANK() in same query

DENSE_RANK() in Oracle SQL

DENSE_RANK() is an Analytical Function in Oracle SQL that assigns a ranking to each row within a partition based on the ORDER BY clause, without gaps in ranking values when there are ties.


In simple terms, If two rows have the same value, they get the same rank. But unlike RANK(), the next rank is not skipped.


Syntax of DENSE_RANK()

DENSE_RANK() OVER (
    [PARTITION BY column_name ]
    [ORDER BY column_name ASC|DESC]
) AS rank_alias ;

-- PARTITION BY: Divides the result set into partitions (optional).
-- ORDER BY: Specifies the order of rows within each partition (required).
-- rank_alias: The alias for the generated rank.

Key Features of DENSE_RANK()

Feature Description
Sequential Ranking Assigns a unique rank to each row based on the ORDER BY clause.
Handles Ties Rows with the same values receive the same rank.
No Gaps in Ranking The next rank is not skipped after ties (e.g., 1, 1, 2).
Partitioning Can be used with PARTITION BY to rank within groups.

Examples

Rank employees by salary without skipping ranks:

SELECT emp_id, name, salary,
DENSE_RANK() OVER (
    ORDER BY salary DESC
) AS salary_rank
FROM employees ;

-- This query ranks employees based on their salary in descending order.
-- If two employees have the same salary, they will share the same rank (e.g., Rank 1), and the next will be Rank 2.

Get top 3 salary ranks (no gaps)

SELECT * FROM (
    SELECT emp_id, name, salary,
    DENSE_RANK() OVER (
      ORDER BY salary DESC
    ) AS salary_rank
    FROM employees
) WHERE salary_rank <= 3 ;

-- This query retrieves the top 3 ranked employees based on their salary in descending order, without gaps in ranking.

Rank employees within departments

SELECT dept_id, emp_name, salary,
DENSE_RANK() OVER (
    PARTITION BY dept_id
    ORDER BY salary DESC
) AS dept_rank
FROM employees ;

-- This query ranks employees within each department based on their salary in descending order, without gaps in ranking.

Product sales rank per region.

SELECT region, product_id, sales,
DENSE_RANK() OVER (
    PARTITION BY region
    ORDER BY sales DESC
) AS product_rank
FROM products ;

-- This query ranks products within each region based on their sales amount in descending order, without gaps in ranking.

Handle tie-breaking with additional sort

SELECT emp_id, name, salary,
DENSE_RANK() OVER (
    ORDER BY salary DESC , hire_date ASC ) AS salary_rank
FROM employees ;
-- This query ranks employees by salary, and in case of ties, it uses hire_date as a secondary sort criterion, without gaps in ranking.

DENSE_RANK() vs RANK() vs ROW_NUMBER()

Function Behavior Use Case
DENSE_RANK() Assigns the same rank to tied rows, does not skip ranks. When you want continuous ranking without gaps.
RANK() Assigns the same rank to tied rows, skips ranks for next unique value. When you want to show gaps in ranking for ties.
ROW_NUMBER() Assigns a unique sequential number to each row, no ties. When you need a unique identifier for each row.

PERCENT_RANK() in Oracle SQL

PERCENT_RANK() calculates the relative rank (percentile position) of a row within a partition. The result is a number between 0 and 1, showing how far along the row is in the sorted set.

  • It tells what percentage of rows are below the current row in the order.
  • It’s useful when you want to normalize ranking across different partitions or datasets.
      • It gives the percentile rank of a row in a result set:
    • The lowest ranked row gets 0.
    • The highest ranked row gets 1.
    • Values in between range from > 0 to < 1.

Syntax of PERCENT_RANK()

PERCENT_RANK() OVER (
    [PARTITION BY column1, column2, ... ]
    [ORDER BY column3 ASC|DESC]
) AS rank_alias ;

-- PARTITION BY: Divides the result set into partitions (optional).
-- ORDER BY: Specifies the order of rows within each partition (required).
-- rank_alias: The alias for the generated rank.

Formula Used by Oracle

The formula for PERCENT_RANK() is:

PERCENT_RANK = (RANK - 1) / (Total Rows in Partition - 1) ;

-- Where RANK is the rank of the current row, and Total Rows in Partition is the number of rows in the partition.
  • First row → always gets 0.
  • Last row → gets 1 (only if there are no ties).
  • If only one row → result is always 0

-- The result will show how each employee's salary compares to others in percentage terms.

CUME_DIST() in Oracle SQL

CUME_DIST() is an Analytical Function in Oracle SQL that calculates the cumulative distribution of a value within a partition. It shows the percentage of rows that have a value less than or equal to the current row's value.


Syntax of CUME_DIST()

CUME_DIST() OVER (
    [PARTITION BY column1, column2, ... ]
    [ORDER BY column3 ASC|DESC]
) AS cume_dist_col ;

-- PARTITION BY: Optional — divides data into groups.
-- ORDER BY: Required — defines the sort order.


The formula for PERCENT_RANK() is:

CUME_DIST = (Number of rows with value less than or equal to current row) / (Total rows in partition) ;

-- CUME_DIST returns a value between 0 and 1.
-- The first row in the partition always gets 0, and the last row gets 1 (if no ties).
-- If there are ties, the CUME_DIST value is the same for all tied rows.

Examples / Scenarios

Show the relative percentile (cumulative) of each employee's salary.

SELECT emp_id, name, salary,
CUME_DIST() OVER (
    ORDER BY salary DESC
) AS salary_cume_dist
FROM employees ;

-- This query calculates the cumulative distribution of each employee's salary in descending order.
-- The result will show how each employee's salary compares to others in terms of cumulative percentage.

NTILE(n) in Oracle SQL

NTILE(n) is an analytical function in Oracle SQL that divides a result set into a specified number of groups (or "tiles") and assigns a unique tile number to each row. It is commonly used for statistical analysis, reporting, and data distribution.


  • In simple terms: It helps in splitting data into equal parts, like percentiles, quartiles, or deciles.

Syntax of NTILE(n)

NTILE(n) OVER ( ORDER BY column_name [ASC|DESC]) ;

  • n = number of buckets/tiles you want.
  • PARTITION BY = Optional (divides data into groups).
  • ORDER BY = Required (defines how to sort the data).

Purpose of NTILE(n)

  • To divide a result set into 'n' equal parts.
  • To assign a tile number to each row based on its position in the ordered result set.
  • Useful for statistical analysis, reporting, and data distribution.

How NTILE Works

Suppose you have 10 rows and want to split into 4 tiles:

  • 10 rows ÷ 4 tiles = 2 full rows per tile, 2 remaining rows
  • So:
    • Tile 1 → 3 rows
    • Tile 2 → 3 rows
    • Tile 3 → 2 rows
    • Tile 4 → 2 rows

    Oracle assigns the extra rows to the first few buckets.

h2>Examples of NTILE(n)

Example 1: Basic Usage of NTILE(n)

SELECT emp_id, salary, NTILE(4) OVER ( ORDER BY salary DESC) AS tile_number
FROM employees ;

-- This divides employees into 4 tiles based on salary in descending order.

Example 2: Using NTILE(n) with PARTITION BY

SELECT emp_id, department, salary, NTILE(3) OVER ( PARTITION BY department ORDER BY salary DESC) AS tile_number
FROM employees ;

-- This divides employees into 3 tiles within each department based on salary.

Example 3: Using NTILE(n) with a Window Function

SELECT emp_id, salary, NTILE(5) OVER ( ORDER BY salary) AS tile_number, RANK() OVER ( ORDER BY salary) AS rank_number
FROM employees ;

-- This divides employees into 5 tiles based on salary and also assigns a rank.

-- This helps in analyzing how salaries are distributed across different tiles.

FROM employees ;

-- This divides employees into 5 tiles based on their performance scores.

Scenario 3: Customer Segmentation

FROM customers ;

-- This segments customers into 3 tiles based on their purchase amounts.

Scenario 4:- Bucket products into 10 sales deciles.

FROM products ;

-- This divides products into 10 deciles based on their sales figures.

FROM students ;

-- This divides students into 4 tiles based on their grades.

Key Points / Notes

  • NTILE(n) requires an ORDER BY clause to define how rows are sorted.
  • It can be used with or without PARTITION BY to group data.
  • Tiles are assigned based on the order of rows, not their original position in the table.
  • Useful for statistical analysis, reporting, and data distribution tasks.

LAG(expr, n)

LAG(expr, n) is an analytical function used to access data from a previous row in the result set without using self-joins or subqueries.


It fetches the value of a column from a previous row (n steps before the current row).


Syntax LAG()

LAG(expr, n, default_value) OVER (
    [PARTITION BY column1, column2, ... ]
    [ORDER BY column3 ASC|DESC]
) AS lag_col ;

-- expr: The column or expression to access from the previous row.
-- n: The number of rows back to look (default is 1 if not specified).
-- default_value: Optional value to return if there is no previous row (default is NULL).
-- PARTITION BY: Optional — divides data into groups.
-- ORDER BY: Required — defines the sort order.

Scenarios / Examples

SELECT emp_id, name, salary,
LAG(salary, 1) OVER (
    ORDER BY month
) AS previous_month_salary
FROM employee_salaries ;

-- This query retrieves the salary of each employee from the previous month.

Scenario 2: Compare current and previous year's sales.

SELECT product_id, year, sales,
LAG(sales, 1) OVER (
    PARTITION BY product_id
    ORDER BY year
) AS previous_year_sales
FROM product_sales ;

-- This query compares the current year's sales with the previous year's sales for each product.

Scenario 3: Calculate the difference in sales from the previous month.

LAG(sales, 1) OVER (
    ORDER BY month
) AS previous_month_sales,
sales - LAG(sales, 1) OVER (
    ORDER BY month
) AS sales_difference
FROM monthly_sales ;

-- This query calculates the difference in sales from the previous month for each month.

Scenario 4: Get previous row's value in a sequence.

LAG(amount, 1) OVER (
    ORDER BY order_date
) AS previous_order_amount
FROM orders ;

-- This query retrieves the amount of the previous order based on the order date.

Scenario 5: Get previous row's value in a partitioned dataset.

LAG(salary, 1) OVER (
    PARTITION BY department
    ORDER BY salary
) AS previous_department_salary

Scenario 6: Get previous row's value with a default value.

SELECT emp_id, name, salary,
LAG(salary, 1, 0) OVER (
    ORDER BY emp_id
) AS previous_salary
FROM employees ;

-- This query retrieves the previous salary of each employee, using 0 as the default value if there -- is no previous row.

NTH_VALUE() in Oracle SQL

NTH_VALUE() is an Oracle analytical function used to return the n-th row's value in an ordered window of rows — based on a given position.


In simple terms: It gives the value of the Nth row (like 2nd, 3rd, etc.) in each group or partition after sorting.


Syntax of NTH_VALUE()

NTH_VALUE (expression, n)
OVER (
    [PARTITION BY Column ]
    ORDER BY Column [ ASC|DESC ]
    [ROWS | RANGE BETWEEN . . .]
)
-- This shows what portion of the department’s salary each employee accounts for.

Parameters:

  • expression: The column or value you want to return.
  • n: The N-th row number (must be a positive integer).
  • PARTITION BY: Optional - divides data into groups.
  • ORDER BY: Required - defines the order for the N-th calculation.
  • ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW: Optional - affects how Oracle calculates frames.

Scenarios / Examples of NTH_VALUE()

Scenario 1:- Get 2nd highest salary in each department.

SELECT emp_id, department_id, salary,
    NTH_VALUE (salary, 2)
    OVER (
      PARTITION BY department_id
      ORDER BY salary DESC
      ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS second_highest_salary
FROM employees ;

Scenario 2:- Get the 3rd product launched by each brand.

SELECT brand, product_name, launch_date,
    NTH_VALUE (product_name, 3)
    OVER (
      PARTITION BY brand
      ORDER BY launch_date
      ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS third_launched_product
FROM products ;

Scenario 3:- Find 1st, 2nd, and 3rd place winners in a game.

SELECT player_id, score,
    NTH_VALUE (player_id, 1) OVER ( ORDER BY score DESC
      ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING ) AS winner_1,
    NTH_VALUE (player_id, 2) OVER ( ORDER BY score DESC
      ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING ) AS winner_2,
    NTH_VALUE (player_id, 3) OVER ( ORDER BY score DESC
      ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING ) AS winner_3
FROM game_scores ;

Scenario 4:- Get 2nd expense category by amount in each month.

SELECT month, category, amount,
    NTH_VALUE (category, 2)
    OVER (
      PARTITION BY month
      ORDER BY amount
      ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS second_expense_category
FROM monthly_expenses ;

Scenario 5:- Get 1st customer's order per region.

SELECT region, customer_id, order_date,
    NTH_VALUE (customer_id, 2)
    OVER (
      PARTITION BY region
      ORDER BY order_date
      ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS first_customer
FROM orders ;

Common Errors & Fixes of NTH_VALUE

Error Code & Message Cause Resolution
ORA-30484: Missing ORDER BY clause ORDER BY is mandatory Add ORDER BY inside OVER()
ORA-30485: Invalid value for N in NTH_VALUE() If N is less than 1 or not numeric Ensure N is a positive integer (≥ 1)
Unexpected Output: Returns same value as current row Window frame not set properly Use ROWS BETWEEN UNBOUNDED PRECEDING AND FOLLOWING

Do's and Don'ts of NTH_VALUE

Do's Don'ts
Always use ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING Don’t forget that default frame returns Nth value from current row only
Use PARTITION BY to isolate logical groups Don’t use on non-ordered data (results will be unpredictable)
Test with small data to validate n position Don’t pass negative or zero as n — throws error
