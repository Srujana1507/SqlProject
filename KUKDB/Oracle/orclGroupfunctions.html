Group By-Related Functions in Oracle SQL

Group By-related functions are also known as aggregate functions. These are special SQL functions that operate on multiple rows of data and return a single summary value for each group of data.


They are called "Group By-related" because they are often used with the GROUP BY clause to group rows based on one or more columns, and then perform calculations on each group.


They give you row-by-row results with reference to a group (also called a window).


Why Do We Need Group By-Related Functions

We need these functions to:

  • Summarize data (e.g., total sales, average salary).
  • Analyze grouped results (e.g., employees per department).
  • Support business decisions with summarized metrics.
  • Aggregate information from large volumes of data efficiently.

Group By-Related Constructs and Functions in Oracle SQL

Command/Function Description
PARTITION BY Used with analytic functions, not aggregate functions. It divides the result set into partitions (groups of rows), and the function is applied within each partition without collapsing rows. Example: ROW_NUMBER() OVER (PARTITION BY dept_id ORDER BY salary) assigns row numbers within each department.
CUBE An extension to GROUP BY that calculates all possible combinations of groupings. Useful for multi-dimensional analysis, such as total sales by product, region, and all combinations (product only, region only, etc.). Syntax: GROUP BY CUBE(region, product)
ROLLUP Another extension to GROUP BY that calculates subtotals and grand totals in a hierarchical order. For example: GROUP BY ROLLUP(dept_id, job_id) gives totals for each job in each department, each department total, and the grand total.
GROUPING() A function used with ROLLUP or CUBE to identify whether a column in the result is aggregated (subtotal/grand total). Returns 1 if a column is aggregated (null due to subtotal), otherwise 0.
GROUPING_ID() Returns a bitmask number that shows which columns are aggregated in a row. It works with multiple columns and is more compact than using multiple GROUPING() calls.
GROUP_ID() Distinguishes between duplicate groups when a GROUP BY query contains duplicate grouping sets. It helps uniquely identify rows when multiple grouping sets return the same values.

Key Points

  • Group By-related functions are aggregate functions used to summarize multiple rows.
  • Used along with GROUP BY to generate meaningful group-level results.
  • Essential for analytics, reporting, and business logic.
  • Always be careful with grouping columns and use the HAVING clause for filtered aggregates.
  • Understand the difference between row-level logic and group-level logic.




PARTITION BY in Oracle SQL

PARTITION BY is used inside analytic functions (e.g., ROW_NUMBER(), RANK(), SUM() OVER, etc.) to divide the result set into groups (partitions). The analytic function is then applied independently within each partition.


Syntax of PARTITION BY

[analytic_function] OVER (
    PARTITION BY [column1, column2, . . . ]
    ORDER BY column3
)

  • PARTITION BY — splits the result set into groups.
  • ORDER BY — determines order within each group (optional for some functions).

Key Differences: GROUP BY vs PARTITION BY

Feature GROUP BY PARTITION BY
Row count Reduces result to 1 row per group Keeps all rows
Used with Aggregate functions Analytic/window functions
Aggregation level At group level At row level within a group
Result visibility Summarized rows only Original rows + calculated column

Commonly Used Analytic Functions with PARTITION BY

Function Description
ROW_NUMBER() Row position in each partition
RANK() Rank of values in each group
DENSE_RANK() Dense ranking in each group
SUM(), AVG() Rolling totals/averages within partitions
FIRST_VALUE() First row value in partition
LAG() / LEAD() Compare current row to previous/next

Real-Time Scenarios with PARTITION BY

Scenario 1: ROW_NUMBER() per department.

Assign a unique row number to each employee within their department.

SELECT emp_id, emp_name, dept_id, salary,
    ROW_NUMBER() OVER ( PARTITION BY dept_id
    ORDER BY salary DESC ) AS row_num
FROM employees;

-- Each department starts with row number 1 for the highest-paid employee.

Scenario 2: (SUM() partitioned by region) Calculate total sales per region, while keeping individual rows.

SELECT region, sales_person, sales_amount,
    SUM (sales_amount) OVER ( PARTITION BY region ) AS total_region_sales
FROM sales ;

-- Total region sales is repeated per salesperson in the same region.

Scenario 3: AVG() over partitions (e.g., student scores).

SELECT student_id, subject, marks,
    AVG (marks) OVER ( PARTITION BY subject ) AS subject_avg
FROM student_marks ;

Scenario 4: Find first salary per department.

SELECT emp_id, emp_name, dept_id, salary,
    FIRST_VALUE (salary) OVER ( PARTITION BY dept_id ORDER BY hire_date ) AS first_salary
FROM employees ;

Scenario 5: Scenario 5: LAG() / LEAD() within a group.

Find sales difference from the previous month in each region.

SELECT region, month, sales,
    sales - LAG (sales) OVER ( PARTITION BY region ORDER BY month ) AS sales_diff
FROM monthly_sales ;


Common Errors and Resolutions

Error Code Message Cause Resolution
ORA-30484: Missing ORDER BY clause in analytic function Some functions require ORDER BY. Add ORDER BY inside OVER()
ORA-00904: Invalid identifier Wrong column in PARTITION BY Ensure columns exist in the SELECT or FROM tables
ORA-30483: Window functions not allowed here Used analytic function in WHERE Use a subquery to filter analytic results in outer query

Do's and Don'ts

Do's Don'ts
Use for detailed, grouped calculations Don’t confuse with GROUP BY
Combine with ORDER BY for proper sequence Don’t use directly in WHERE without subquery
Use with functions like SUM(), RANK(), etc. Don’t use PARTITION BY with aggregate-only queries




CUBE() in Oracle SQL

The CUBE() function is an extension of the GROUP BY clause. It generates all possible combinations of groupings for the specified columns.


Think of it as a way to create subtotals and a grand total across multiple dimensions (columns), especially useful for multidimensional reporting like sales by region, product, and time.


Syntax of CUBE

SELECT column1, column2, aggregate_function(column3)
FROM table_name
GROUP BY CUBE (column1, column2) ;
  • Group by column1 and column2
  • Group by column1 only
  • Group by column2 only
  • Grand total (no grouping columns)

Why Do We Use CUBE()

  • To analyze data across all possible combinations of dimensions.
  • To get totals and subtotals automatically without writing multiple UNION queries.
  • Common in OLAP (Online Analytical Processing) and Business Intelligence reports.

What Does CUBE() Do

For n columns inside CUBE(), it creates 2^n combinations.

Columns in CUBE Combinations Generated
1 column 2 (1 group + grand total)
2 columns 4 (each group + subtotal + grand total)
3 columns 8 combinations

Basic Example with CUBE()

SELECT region, product, SUM (sales) AS total_sales
FROM sales
GROUP BY CUBE (region, product) ;

Real-Time Scenarios with CUBE()

Scenario 1: Total sales by year and quarter.

SELECT year, quarter, SUM (sales) AS sales_data
FROM sales
GROUP BY CUBE (year, quarter) ;

Gives subtotals by:

  • Year
  • Quarter
  • Year + Quarter
  • Grand total

Scenario 2: Count orders by Region and Channel

SELECT region, channel, COUNT ( * ) AS order_count
FROM orders
GROUP BY CUBE ( region, channel );

-- Useful in dashboards and executive reports.

Scenario 3: Revenue by category and month.

SELECT category, TO_CHAR (sale_date, 'MON') AS month, SUM (amount)
FROM transactions
GROUP BY CUBE (category, TO_CHAR (sale_date, 'MON') );

-- Aggregates by category, month, and all combinations.

Advanced: Using GROUPING() with CUBE()

When NULL appears, it can be hard to tell whether it’s:

  • Actual NULL in data (or) Subtotal or Grand total row.

Use GROUPING() to find subtotal rows:

SELECT region, product, SUM (sales) AS total_sales,
    GROUPING ( region ) AS grp_region,
    GROUPING ( product ) AS grp_product
FROM sales
GROUP BY CUBE ( region, product) ;

-- GROUPING() returns 1 if the column is aggregated (subtotal), 0 otherwise.

Common Mistakes with CUBE()

Mistake Explanation Fix
Misinterpreting NULL values NULLs in result may represent aggregation, not missing data Use GROUPING() to distinguish
Using too many columns With 5 columns → 2⁵ = 32 combinations → performance hit Use only relevant dimensions
Filtering aggregated rows in WHERE You can’t filter on aggregates in WHERE Use HAVING instead
Ignoring report structure CUBE creates dense result sets Sort and label subtotal rows clearly

Common Errors & Fixes with CUBE()

Error Code & Message Cause Resolution
ORA-00979: Not a GROUP BY expression Missing column in SELECT Add non-aggregated columns to GROUP BY
ORA-00904: Invalid identifier Misspelled column Use correct column name.
NULL confusion: Hard to distinguish NULL meaning NULL could be real or subtotal Use GROUPING() to differentiate

Do's and Don'ts of CUBE()

Do's Don'ts
Use for full multidimensional aggregation reports Don’t use when only a few combinations are needed
Combine with GROUPING() for clarity Don’t forget to alias aggregate columns
Use for building data cubes, pivot-like reports Don’t use on large tables without performance tuning

Summary of CUBE()

Feature Description
Purpose Multidimensional subtotals and grand totals
Used With GROUP BY clause
Output Original rows grouped + subtotal combinations
NULL values Represent subtotal/grand total
Helper Function GROUPING() to detect NULL meanings
Performance Impact Can increase depending on data size and combinations




ROLLUP() in Oracle SQL

The ROLLUP() function is an extension of the GROUP BY clause that creates subtotals that roll up from the most detailed level to a grand total.


The ROLLUP() function is a GROUP BY extension in Oracle SQL used to generate hierarchical subtotals and grand totals in a single query.


It’s used when you want to summarize data at multiple levels of detail — such as totals for each department, and then a grand total for all departments.


Unlike CUBE() (which creates all combinations), ROLLUP() creates hierarchical summaries based on the order of columns listed.


Syntax of CUBE

SELECT column1, column2, aggregate_function(column3)
FROM table_name
GROUP BY ROLLUP (column1, column2) ;

-- The order of columns inside ROLLUP() determines the level of grouping from most detailed to most general.

Important Note

  • The order of columns in ROLLUP() matters.
  • It creates n + 1 grouping levels for n columns.

Given ROLLUP(A, B):


Oracle performs aggregation for the following levels:

  • Group by A and B
  • Subtotal for A (B is NULL)
  • Grand total (both A and B are NULL)
  • So: Total combinations = n + 1 (not 2ⁿ like CUBE())

Why Use ROLLUP()

  • To automatically generate subtotals (e.g., per department)
  • To add a grand total to the result
  • To reduce manual work (no need for multiple UNION queries)
  • Very useful in financial reports, dashboards, and business summaries

Basic Example with CUBE()

SELECT region, product, SUM (revenue) AS total_revenue
FROM sales_data
GROUP BY ROLLUP (region, product) ;

In our example with 2 columns, you get:

  • (region, product)
  • (region)
  • 0

Visual Hierarchy of ROLLUP(region, product)

  • region → product
  • region subtotal
  • grand total

Key Differences: ROLLUP vs CUBE

Feature ROLLUP() CUBE()
Grouping Hierarchical (one path) All combinations (cross-paths)
Use Case Reports with nested subtotals OLAP cubes, pivot tables
Total Sets n + 1 levels 2ⁿ combinations
Performance More efficient More intensive on large data

Real-Time Scenarios with ROLLUP()

Scenario 1: Sales by Region and Year.

SELECT region, year, SUM (sales) FROM sales_data
GROUP BY ROLLUP ( region, year ) ;

-- It Generates:
  • Region + Year totals
  • Region-only totals
  • Grand total

Scenario 2: Department salary summary.

SELECT department, job_title, SUM (salary) FROM employees
GROUP BY ROLLUP ( department, job_title ) ;

-- It Generates:
  • Salary by department and job
  • Salary by department
  • Total salary

Scenario 3: Orders by month and week.

SELECT TO_CHAR ( order_date, 'MON' ) AS month,
    TO_CHAR ( order_date, 'WW' ) AS week,
    COUNT ( * ) AS order_count
FROM orders
GROUP BY ROLLUP ( TO_CHAR ( order_date, 'MON' ), TO_CHAR ( order_date, 'WW' ) ) ;

-- It Generates:
  • Orders by month + week
  • Orders by month
  • Grand total

Using GROUPING() with ROLLUP()

To distinguish NULLs from actual NULL values, use GROUPING():

SELECT region, product, SUM (sales) AS total_sales,
    GROUPING ( region ) AS grp_region,
    GROUPING ( product ) AS grp_product
FROM sales
GROUP BY ROLLUP ( region, product ) ;

Common Mistakes and Errors with ROLLUP()

Mistake Explanation Fix
Misinterpreting NULLs NULLs in the result indicate subtotal or total, not missing data Use GROUPING() to identify
Wrong column order ROLLUP(A, B) is not the same as ROLLUP(B, A) Always sort from detailed → general
Filtering on aggregates in WHERE Aggregates cannot be used in WHERE Use HAVING clause instead
Using too many columns blindly Might return unexpected rows Understand the grouping hierarchy

Common Errors and Resolution with ROLLUP()

Error Code and Message Cause Resolution
ORA-00979: Not a GROUP BY expression Missing column in GROUP BY Add all non-aggregated columns to GROUP BY
NULL Confusion or NULLs not clear Subtotals look like NULL values Use GROUPING() to identify subtotals

Do's and Don'ts

Do's Don'ts
Use when data follows a hierarchy Don’t use ROLLUP when you need full matrix
Use GROUPING() to distinguish subtotals Don’t misinterpret NULLs
Use proper column order for desired rollups Don’t mix unrelated dimensions in ROLLUP

Summary of ROLLUP

Feature Description
Purpose Create subtotals up a hierarchy + grand total
Used With GROUP BY
Output Adds subtotal rows in order of grouping
NULLs Meaning Null = subtotal or grand total, not missing data
Helper Functions GROUPING(), GROUPING_ID()
Output Rows n + 1 subtotal levels (for n columns)
Comparison Simpler and more structured than CUBE()




GROUPING() in Oracle SQL

The GROUPING() function is used to identify whether a column in the result set from a ROLLUP or CUBE operation was aggregated as part of a subtotal or grand total row.


The GROUPING() function is used to differentiate NULL values that appear in the result set due to ROLLUP() or CUBE() from actual NULL values in the data.


When you see NULL in a ROLLUP or CUBE result, you don’t know if it’s a real NULL in the data or a subtotal. GROUPING() helps clarify that.


Syntax of GROUPING()

GROUPING ( Column_Name )

-- It returns:
  • 0 - Column is included in grouping (normal row)
  • 1 - Column is aggregated (subtotal or grand total)

Why Do We Use GROUPING()

  • To differentiate subtotal/null rows from actual NULL values in the table.
  • To format or filter result sets in reports where subtotals and totals are involved.
  • Commonly used in business reports and BI dashboards.

Example with ROLLUP + GROUPING()

SELECT region, product, SUM (revenue) AS total_revenue,
    GROUPING ( region ) AS grp_region,
    GROUPING ( product ) AS grp_product
FROM sales_data
GROUP BY ROLLUP ( region, product ) ;

Real-Time Scenarios with GROUPING

Scenario 1: Labeling total and subtotal rows.

SELECT region, product, SUM (sales) AS total_sales,
    CASE
      WHEN GROUPING ( region ) = 1 AND GROUPING (product) = 1 THEN 'Grand Total'
      WHEN GROUPING ( product ) = 1 THEN 'Region Total'
      ELSE 'Detail'
    END AS row_type
FROM sales
GROUP BY ROLLUP ( region, product ) ;

Scenario 2: Replace NULL with Custom Labels.

    CASE
      WHEN GROUPING ( region ) = 1 THEN 'ALL REGIONS'
      ELSE region
      END AS region,
      WHEN GROUPING ( product ) = 1 THEN 'ALL PRODUCTS'
      ELSE product
      END AS product,
      SUM (sales) AS total_sales
FROM sales
GROUP BY ROLLUP ( region, product ) ;

Key Points of GROUPING

Feature Details
Functionality Detects if a column is aggregated by ROLLUP or CUBE
Return Value 1 = Aggregated, 0 = Not Aggregated
Works with ROLLUP(), CUBE(), GROUPING SETS()
Helps with Report formatting, filtering total/subtotal rows

Common Errors and Misunderstandings

Mistake Why it Happens Correct Approach
Confusing NULL values Users assume NULLs are always from data Use GROUPING() to confirm
Forgetting column order Misinterpretation of rollup levels Keep consistent column order
Using GROUPING() outside rollup/cube Doesn’t work with standard GROUP BY Only meaningful with ROLLUP, CUBE, GROUPING SETS
Comparing GROUPING() in WHERE Not allowed Use in HAVING or SELECT only

Do's and Don'ts with GROUPING

Do's Don'ts
Use in SELECT to label subtotal or total rows Don’t assume all NULLs are from missing data
Use with CASE for readable reporting Don’t ignore GROUPING() if showing rollups
Use to replace NULLs with "Total" or "All" Don’t hardcode logic without GROUPING()




GROUPING_ID() in Oracle SQL

GROUPING_ID() is an advanced Group By-related function used with ROLLUP, CUBE, or GROUPING SETS.

  • It returns a decimal number that represents which columns have been aggregated (i.e., replaced with NULL) in each row.
  • It provides a unique identifier for subtotal and grand total rows when multiple columns are involved in grouping.
  • It works by performing a bitwise OR on the values returned by multiple GROUPING() functions.

Syntax of GROUPING_ID

GROUPING_ID (column1, column2, ..., columnN)

  • Each column is evaluated using GROUPING().
  • Oracle assigns a binary digit (1 for aggregated, 0 for not).
  • The binary digits are converted to a decimal number to give a unique grouping ID.

Why Do We Use GROUPING_ID()

  • To identify exact grouping level in multi-column ROLLUP or CUBE.
  • Helps when GROUPING() alone isn’t sufficient (e.g., many columns).
  • Useful in reporting systems, dashboards, and conditional formatting.
  • Can be used to sort, filter, or label subtotal and total rows.

How Does It Work

  • Oracle assigns a bit value (0 or 1) for each column:
    • 1 = column is aggregated
    • 0 = column is present
  • Bits are placed from right to left, i.e., last column → rightmost bit.

GROUPING_ID (col1, col2, col3 )

IF:
- col1 aggregated → bit = 1 (leftmost)
- col2 present → bit = 0
- col3 aggregated → bit = 1 (rightmost)

Result: 101 (binary) = 5 (decimal)

Example with ROLLUP + GROUPING_ID()

SELECT region, product,
SUM (sales) AS total_sales,
    GROUPING_ID ( region, product ) AS grouping_code
FROM sales
GROUP BY ROLLUP ( region, product ) ;

Real-Time Scenarios with GROUPING_ID

Scenario 1: Label Rows Using GROUPING_ID.

SELECT region, product,
SUM (sales) AS total_sales,
    CASE GROUPING_ID ( region, product )
      WHEN 0 THEN 'Detail'
      WHEN 1 THEN 'Subtotal by Region'
      WHEN 3 THEN 'Grand Total'
    END AS row_type
FROM sales
GROUP BY ROLLUP ( region, product ) ;

Scenario 2: Replace NULL with Labels Using GROUPING_ID.

SELECT
    CASE GROUPING_ID ( region, product ) = 3 THEN 'ALL REGIONS'
      WHEN GROUPING (region) = 1 THEN 'TOTAL'
      ELSE region END AS region,
    CASE GROUPING_ID ( region, product ) IN ( 1, 3 ) THEN 'ALL PRODUCTs'
      ELSE product END AS product ,
    SUM (sales) AS total_sales
FROM sales
GROUP BY ROLLUP ( region, product ) ;

Common Errors and Resolution with GROUPING_ID()

Error code & Message Cause Resolution
ORA-00979: Not a GROUP BY expression Missing GROUP BY clause Ensure columns used are in GROUP BY or aggregate
ORA-00904: Invalid identifier Typo or wrong column name Double-check column names

Do's and Don'ts with GROUPING_ID

Do's Don'ts
Use when you need unique grouping row labels Don’t rely on NULLs alone to detect subtotals
Combine with CASE for custom row types Don’t use hardcoded logic if rollup columns change
Understand column evaluation order (right-to-left) Don’t assume binary weight is left-to-right

Key Differences: GROUPING() vs GROUPING_ID()

Feature GROUPING() GROUPING_ID()
Works on One column Multiple columns
Return type 0 or 1 Integer (bitmask)
Purpose Identify if one column is NULL Identify combination of group levels
Use in formatting Basic totals Complex subtotal levels

Common Mistakes with GROUPING_ID()

Mistake Why it Happens Resolution
Misreading the bit order Columns are read right-to-left in bits Be careful with bit position
Using wrong columns in GROUPING_ID() Output doesn’t match expectations Ensure same column order in GROUP BY and GROUPING_ID()
Using outside ROLLUP/CUBE GROUPING_ID() gives meaningless values Use only with ROLLUP, CUBE, or GROUPING SETS

Summary of GROUPING_ID()

Feature Description
Function Identify level of grouping (as numeric ID)
Return Type Integer (bitmask decimal)
Used With ROLLUP(), CUBE(), GROUPING SETS()
Purpose Identify exact grouping level
Advantage Handles multiple columns better than GROUPING()
Best Use Case Reports with multi-column subtotals/totals




GROUP_ID() in Oracle SQL

The GROUP_ID() function is used to distinguish duplicate grouping sets in a query using GROUP BY GROUPING SETS.


It assigns a unique number (0 or higher) to each duplicate group produced by the GROUPING SETS.


It is only useful when the query has duplicate grouping sets, and Oracle needs to differentiate between them.


Syntax of GROUP_ID()

GROUP_ID

  • It takes no arguments.
  • Returns a 0 when no duplicate grouping sets are present.
  • Returns 1, 2, ... N when there are duplicate groupings (i.e., same grouping set structure appearing more than once).

Why Do We Use GROUP_ID()

  • To distinguish duplicate grouping rows created intentionally or by complex queries.
  • Helps track multiple aggregations with the same grouping set but coming from different logic.
  • Often used in advanced reporting and OLAP-style queries.

Where Is GROUP_ID() Used

  • Primarily with:
    • GROUPING SETS
    • ROLLUP or CUBE when duplicates might appear

Sample Example

Query with GROUPING SETS and Duplicate Groups.

SELECT region, product, SUM (sales) AS total_sales,
    GROUP_ID () AS group_number
FROM sales
GROUP BY GROUPING SETS (
(region, product),
(product, region), -- same as above, reordered
(region) -- different
) ;

Common Errors or Misunderstandings

Error/Issue Explanation
Why is everything GROUP_ID() = 0? No duplicated grouping sets used
Appears same as GROUPING_ID() No — they solve different problems
Doesn’t show different rows Check if grouping sets are actually duplicates

Common Error and Resolution

Error Code & Message Cause Resolution
ORA-00904: GROUP_ID: invalid identifier Typo or unsupported Oracle version Use exact syntax and check Oracle version

Do's and Don'ts of GROUP_ID

Do's Don'ts
Use with GROUPING SETS if groups are repeated Don’t use if grouping sets are all unique
Use in SELECT to track source of grouped rows Don’t confuse with GROUPING() or GROUPING_ID()
Useful for debugging complex groupings Not needed in simple GROUP BY queries




RANK() in Oracle SQL

RANK() assigns a ranking number to each row within a partition of a result set. The same rank is given to rows with equal values, and the next rank is skipped accordingly.


    In simple terms: If two employees have the same salary, they will get the same rank. But the next rank will be skipped.

The RANK() function is an Analytical Function used to assign a rank to each row within a partition of a result set, based on the ORDER BY clause.

  • Rows with the same values (ties) get the same rank.
  • The next rank is skipped accordingly (i.e., creates gaps in rank).

Syntax of RANK()

RANK() OVER (
    [PARTITION BY column_name ]
    [ORDER BY column_name ASC|DESC]
) AS rank_alias ;

-- PARTITION BY: Divides the result set into partitions (optional).
-- ORDER BY: Specifies the order of rows within each partition (required).
-- rank_alias: The alias for the generated rank.

Key Features of RANK()

Feature Description
Sequential Ranking Assigns a unique rank to each row based on the ORDER BY clause.
Handles Ties Rows with the same values receive the same rank.
Gaps in Ranking The next rank is skipped after ties (e.g., 1, 1, 3).
Partitioning Can be used with PARTITION BY to rank within groups.
Same values → same rank Duplicate values receive the same rank
Gaps in ranking If 2 rows share a rank, the next rank(s) are skipped
Needs ORDER BY You must define sort order to rank properly

Examples of RANK()

Scenario 1: Rank employees by salary.

SELECT emp_id, name, salary,
RANK() OVER (
    ORDER BY salary DESC
) AS salary_rank
FROM employees ;

-- This query ranks employees based on their salary in descending order.
-- If two employees have the same salary, they will share the same rank (e.g., Rank 1), and the next will be Rank 3.

Scenario 2:- Top 3 ranked employees by salary.

SELECT * FROM (
    SELECT emp_id, name, salary,
    RANK() OVER (
      ORDER BY salary DESC
    ) AS salary_rank
    FROM employees
) WHERE salary_rank <= 3 ;

-- This query retrieves the top 3 ranked employees based on their salary in descending order.

Scenario 3:- Rank employees within each department.

SELECT dept_id, emp_name, salary,
RANK() OVER (
    PARTITION BY dept_id
    ORDER BY salary DESC
) AS dept_rank
FROM employees ;

-- This query ranks employees within each department based on their salary in descending order.

Scenario 4:- Find top 2 sales employees per region.

PERCENT_RANK() in Oracle SQL

PERCENT_RANK() calculates the relative rank (percentile position) of a row within a partition. The result is a number between 0 and 1, showing how far along the row is in the sorted set.

  • It tells what percentage of rows are below the current row in the order.
  • It’s useful when you want to normalize ranking across different partitions or datasets.
      • It gives the percentile rank of a row in a result set:
    • The lowest ranked row gets 0.
    • The highest ranked row gets 1.
    • Values in between range from > 0 to < 1.

Syntax of PERCENT_RANK()

PERCENT_RANK() OVER (
    [PARTITION BY column1, column2, ... ]
    [ORDER BY column3 ASC|DESC]
) AS rank_alias ;

-- PARTITION BY: Divides the result set into partitions (optional).
-- ORDER BY: Specifies the order of rows within each partition (required).
-- rank_alias: The alias for the generated rank.

Formula Used by Oracle

The formula for PERCENT_RANK() is:

PERCENT_RANK = (RANK - 1) / (Total Rows in Partition - 1) ;

-- Where RANK is the rank of the current row, and Total Rows in Partition is the number of rows in the partition.
  • First row → always gets 0.
  • Last row → gets 1 (only if there are no ties).
  • If only one row → result is always 0

NTILE(n) in Oracle SQL

NTILE(n) is an analytical function in Oracle SQL that divides a result set into a specified number of groups (or "tiles") and assigns a unique tile number to each row. It is commonly used for statistical analysis, reporting, and data distribution.


  • In simple terms: It helps in splitting data into equal parts, like percentiles, quartiles, or deciles.

Syntax of NTILE(n)

NTILE(n) OVER ( ORDER BY column_name [ASC|DESC]) ;

  • n = number of buckets/tiles you want.
  • PARTITION BY = Optional (divides data into groups).
  • ORDER BY = Required (defines how to sort the data).

Purpose of NTILE(n)

  • To divide a result set into 'n' equal parts.
  • To assign a tile number to each row based on its position in the ordered result set.
  • Useful for statistical analysis, reporting, and data distribution.

How NTILE Works

Suppose you have 10 rows and want to split into 4 tiles:

  • 10 rows ÷ 4 tiles = 2 full rows per tile, 2 remaining rows
  • So:
    • Tile 1 → 3 rows
    • Tile 2 → 3 rows
    • Tile 3 → 2 rows
    • Tile 4 → 2 rows

    Oracle assigns the extra rows to the first few buckets.

-- This divides employees into 4 tiles based on salary in descending order.

FROM employees ;

-- This divides employees into 3 tiles within each department based on salary.

Example 3: Using NTILE(n) with a Window Function

-- This divides employees into 5 tiles based on salary and also assigns a rank.

SELECT emp_id, department, salary,

NTH_VALUE() in Oracle SQL

NTH_VALUE() is an Oracle analytical function used to return the n-th row's value in an ordered window of rows — based on a given position.


In simple terms: It gives the value of the Nth row (like 2nd, 3rd, etc.) in each group or partition after sorting.


Syntax of NTH_VALUE()

NTH_VALUE (expression, n)
OVER (
    [PARTITION BY Column ]
    ORDER BY Column [ ASC|DESC ]
    [ROWS | RANGE BETWEEN . . .]
)
-- This shows what portion of the department’s salary each employee accounts for.

Parameters:

  • expression: The column or value you want to return.
  • n: The N-th row number (must be a positive integer).
  • PARTITION BY: Optional - divides data into groups.
  • ORDER BY: Required - defines the order for the N-th calculation.
  • ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW: Optional - affects how Oracle calculates frames.

Scenarios / Examples of NTH_VALUE()

Scenario 1:- Get 2nd highest salary in each department.

SELECT emp_id, department_id, salary,
    NTH_VALUE (salary, 2)
    OVER (
      PARTITION BY department_id
      ORDER BY salary DESC
      ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS second_highest_salary
FROM employees ;

Scenario 2:- Get the 3rd product launched by each brand.

SELECT brand, product_name, launch_date,
    NTH_VALUE (product_name, 3)
    OVER (
      PARTITION BY brand
      ORDER BY launch_date
      ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS third_launched_product
FROM products ;

Scenario 3:- Find 1st, 2nd, and 3rd place winners in a game.

SELECT player_id, score,
    NTH_VALUE (player_id, 1) OVER ( ORDER BY score DESC
      ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING ) AS winner_1,
    NTH_VALUE (player_id, 2) OVER ( ORDER BY score DESC
      ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING ) AS winner_2,
    NTH_VALUE (player_id, 3) OVER ( ORDER BY score DESC
      ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING ) AS winner_3
FROM game_scores ;

Scenario 4:- Get 2nd expense category by amount in each month.

SELECT month, category, amount,
    NTH_VALUE (category, 2)
    OVER (
      PARTITION BY month
      ORDER BY amount
      ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS second_expense_category
FROM monthly_expenses ;

Scenario 5:- Get 1st customer's order per region.

SELECT region, customer_id, order_date,
    NTH_VALUE (customer_id, 2)
    OVER (
      PARTITION BY region
      ORDER BY order_date
      ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS first_customer
FROM orders ;

Error Code & Message Cause Resolution

ORA-30485: Invalid value for N in NTH_VALUE() If N is less than 1 or not numeric Ensure N is a positive integer (≥ 1)

Do's Don'ts
