NVL Function in Oracle SQL

The NVL function in Oracle SQL is used to replace NULL values with a specified default value.


It ensures that calculations and queries do not return unexpected NULL results.


Syntax

NVL (expression, replacement_value)
  • expression: The column or value to check for NULL.
  • replacement_value: The value that replaces NULL when found.

Purpose of NVL Function

Feature Description
Functionality Replaces NULL values with a default value.
Use Cases Used in calculations, reporting, and data handling.
Return Type Same data type as expression.
Key Benefit Prevents NULL from affecting computations.
Works on Any Data Type Can be used with NUMBER, VARCHAR2, DATE, etc.
Used in Aggregations & Reporting Helps in calculations and analytics

Scenario 1:- If an employee's salary is NULL, replace it with 30000.

SELECT emp_id, name,
    NVL (salary, 30000) AS updated_salary
FROM employees ;

Scenario 2:- Replace NULL phone numbers with 'Not Provided'.

SELECT customer_id, customer_name,
    NVL (phone_number, 'Not Provided' ) AS contact_info
FROM Customers ;

Scenario 3:- Avoid NULL values in calculations for bonus.

SELECT employee_id, salary,
    NVL (bonus, 0) AS bonus_amount
    salary + NVL (bonus, 0) AS total_income
FROM Employees ;

Scenario 4:- Replace NULL hire dates with a default date.

SELECT employee_id,
    NVL ( hire_date, TO_DATE ( '2000-01-01', 'YYYY-MM-DD' ) ) AS adjusted_hire_date
FROM Employees ;

Scenario 5:- Ensure NULL values in joins are replaced properly.

SELECT e.employee_id, e.employee_name,
    NVL ( d.department_name, 'Not Assigned' ) AS department_name
FROM Employees e
LEFT JOIN Departments d ON e.department_id = d.department_id ;

Scenario 6:- Ensure total sales calculation doesn't break due to NULL prices.

SELECT SUM ( NVL (price, 0) * quantity) AS total_sales FROM sales ;

Scenario 7:- A company provides discounts on customer orders based on a loyalty program. Some customers do not have a discount (NULL value), and for them, a default discount of 5% should be applied.

SELECT o.order_id, c.customer_name, o.order_amount,
    NVL ( c.loyalty_discount, 0.05 ) AS applied_discount,
    o.order_amount * ( 1 - NVL (c.loyalty_discount, 0.05)) AS final_price
FROM Orders o
LEFT JOIN Departments d ON e.department_id = d.department_id ;

Limitations of NVL Function

Limitation Description
Replacement Value Must Match Data Type NVL(salary, 'No Salary') → (Error due to mismatched types)
Can Impact Performance Used inside WHERE clauses can slow queries
Not Suitable for Conditional Logic For complex conditions, use CASE instead
Works Only for NULLs Cannot handle empty strings ('' in VARCHAR2).

Common Errors with NVL

Error Code Cause Solution
ORA-01722 Invalid number error (e.g., NVL(salary, 'No Salary')) Ensure proper conversion using TO_NUMBER(), TO_DATE().
ORA-00932 Different data types for expression and replacement_value. Use the same data type for both parameters

Do’s and Don’ts of NVL Function

Do's Don'ts
Use NVL to handle NULL values safely Don’t use NVL inside indexes (affects performance)
Ensure replacement value matches column data type Avoid using NVL when COALESCE (multiple fallback values) is better
Use NVL in calculations to prevent NULL issues Don’t overuse NVL in performance-critical queries
Use NVL for default values in reports. Don't use NVL when COALESCE is a better choice.



NVL2 Function in Oracle SQL

The NVL2 function in Oracle SQL extends NVL by providing two different return values:


  • If the expression is NOT NULL, it returns value_if_not_null.
  • If the expression is NULL, it returns value_if_null.

Syntax

NVL2 ( expression, value_if_not_null, value_if_null )
  • expression: The column or value to check for NULL.
  • value_if_not_null: The value returned if expression is NOT NULL.
  • value_if_null: The value returned if expression is NULL.

Key Features of NVL2 Function

Feature Description
Returns Different Values for NULL and NOT NULL Unlike NVL, it provides two replacement values.
Works with Any Data Type Supports NUMBER, VARCHAR2, DATE, etc.
Helps in Conditional Handling Useful in calculations, string replacements, and aggregations.
Can Improve Readability Reduces the need for CASE expressions.

Key Differences Between NVL and NVL2

Feature NVL NVL2
Checks NULL? Yes Yes
Replaces NULL? Yes Yes
Handles NOT NULL separately? No Yes
Returns different values for NULL vs. NOT NULL? No Yes

Scenario 1:- If an employee’s salary is NOT NULL, add 10% bonus; if NULL, set bonus as 5000.

SELECT emp_id, name, salary,
    NVL2 ( salary, salary * 1.1, 5000 ) AS bonus
FROM employees ;
  • If salary exists, bonus = salary + 10%.
  • If salary is NULL, bonus = 5000.

Scenario 2:- Show ‘Active User’ if a last login date exists, otherwise ‘Never Logged In’.

SELECT user_id, name,
    NVL2 (last_login_date, 'Active User' , 'Never Logged In' ) AS status
FROM users ;
  • If last_login_date exists → "Active User"
  • If last_login_date is NULL → "Never Logged In"

Scenario 3:- If a product price is set, apply a 12% tax; otherwise, set a flat tax of $50.

SELECT product_id, name, price,
    NVL2 (price, price * 1.12, 50) AS final_price
FROM products ;
  • If price exists, apply 12% tax.
  • If price is NULL, apply flat $50 tax.

Scenario 4:- If a sales rep has a commission rate, increase it by 5%; otherwise, assign 10%.

SELECT rep_id, name, commission_rate,
    NVL2 ( commission_rate, commission_rate * 1.05, 0.10 ) AS adjusted_commission
FROM sales_reps ;

Scenario 5:- If an employee has a direct manager, show the manager’s name. If an employee has no manager (NULL manager_id), assign "Head Office - Default Manager".

SELECT e.employee_id, e.employee_name,
    NVL2 ( m.manager_name, m.manager_name, 'Head Office - Default Manager' ) AS assigned_manager
FROM Employees e
LEFT JOIN Managers m ON e.manager_id = m.manager_id ;

Scenario 6:- ( Dynamic Performance Bonus for Employees ) If an employee has an assigned performance rating, give a 15% salary bonus.

  • If performance rating is NULL, check if salary is NULL
    • If salary exists, assign a fixed bonus of $2000.
    • If both salary & rating are NULL, assign $1000.


SELECT emp_id, name, salary, performance_rating, NVL2 performance_rating, salary * 1.15, , NVL2 (salary, salary + 2000, 1000) ) AS final_bonus FROM employees ;
  • If performance_rating exists → increase salary by 15%.
  • If performance_rating is NULL but salary exists → add $2000.
  • If both salary & rating are NULL → assign $1000 bonus.

Limitations of NVL2 Function

Limitation Description
Performance Overhead Overuse in large queries may slow down performance
Data Type Restrictions Both value_if_not_null and value_if_null must be of the same data types
Not Always Intuitive In some cases, using CASE statements may be more readable
Works Only for NULLs Cannot handle empty strings ('' in VARCHAR2).

Common Errors with NVL2

Error Code Cause Solution
ORA-01722 Invalid number error (e.g., NVL2(salary, 'Bonus', 100)) Ensure both return values have the same data type
ORA-00932 Inconsistent data types. Convert mismatched types using CAST() or TO_NUMBER().

Do’s and Don’ts of NVL2 Function

Do's Don'ts
Use NVL2 when needing two different return values Don’t use NVL2 when a simple NVL is sufficient
Ensure data type consistency in both return values Don’t use NVL2 excessively in performance-sensitive queries
Use NVL2 to simplify conditional logic Don’t use NVL2 when CASE statements are clearer



NULLIF Function in Oracle SQL

The NULLIF function in Oracle SQL compares two values:


  • If both values are equal, it returns NULL.
  • If values are different, it returns the first value.

Purpose:- Helps in avoiding division by zero and simplifies conditional logic.


Syntax

NULLIF ( expression, value_if_not_null, value_if_null )
  • expression1: The first value to compare.
  • expression2: The second value to compare.
    • If expression1 = expression2 → returns NULL
    • If expression1 ≠ expression2 → returns expression1

Key Features of NULLIF

Feature Description
Prevents Errors Helps avoid division by zero
Simplifies Logic Acts as a shorter alternative to CASE statements
Works with Various Data Types Supports NUMBER, VARCHAR2, DATE, etc.
Commonly Used in Aggregations Useful in avoiding invalid calculations

Scenario 1:- ( Prevent Division by Zero ) Avoid division by zero while calculating sales performance.

SELECT salesperson_id, name, total_sales, total_orders,
    total_sales / NULLIF ( total_orders, 0 ) AS avg_sale_per_order
FROM sales ;
  • If total_orders = 0, NULLIF(0, 0) returns NULL, preventing division by zero.
  • If total_orders ≠ 0, division proceeds as normal.

Scenario 2:- Return NULL if two employees have the same salary; otherwise, return the first employee’s salary.

SELECT e1.emp_id, e1.name, e1.salary, e2.name AS compared_with,
    NULLIF (e1.salary, e2.salary) AS salary_difference
FROM employees e1
JOIN employees e2 ON e1.dept_id = e2.dept_id AND e1.emp_id <> e2.emp_id ;
  • If e1.salary = e2.salary, returns NULL.
  • If e1.salary ≠ e2.salary, returns e1.salary.

Scenario 3:- ( Filter Out Duplicate Order Values ) Compare customer order amounts and filter out identical amounts.

SELECT order_id, customer_id, order_amount,
    NULLIF (order_amount, LAG (order_amount) OVER ( PARTITION BY order_id ) ) AS unique_order
FROM orders ;
  • Uses LAG() to check the previous order amount.
  • If the same as the current order, NULLIF returns NULL (hiding duplicates).

Scenario 4:- If an employee’s exit date is the same as the joining date, return NULL (invalid), otherwise return the exit date.

SELECT emp_id, name, join_date, exit_date,
    NULLIF (exit_date, join_date) AS valid_exit_date
FROM employees ;
  • If exit_date = join_date, it returns NULL (invalid case).
  • If different, it returns exit_date.

Scenario 5:- ( NULLIF in Nested Queries ) If an employee's commission rate is the same as their department average, return NULL.

SELECT emp_id, name, salary, dept_id, commission_rate,
    NULLIF ( m.manager_name, m.manager_name,
      SELECT (commission_rate, ( AVG (commission_rate) FROM employees e2 WHERE e1.dept_id = e2.dept_id)) AS adjusted_commission
FROM employees e1 ;
  • If commission_rate matches the department average, return NULL.
  • If not, return the actual commission_rate.

Scenario 6:- ( Dynamic Pricing Adjustments ) Adjust product prices dynamically:

  • If the current price is the same as the previous month’s price, return NULL.
  • Otherwise, return the new price.


SELECT emp_id, name, salary, performance_rating, NVL2 performance_rating, salary * 1.15, , NVL2 (salary, salary + 2000, 1000) ) AS final_bonus FROM employees ;
  • If performance_rating exists → increase salary by 15%.
  • If performance_rating is NULL but salary exists → add $2000.
  • If both salary & rating are NULL → assign $1000 bonus.

Limitations of NULLIF

Limitation Description
Only Works with Two Values Can only compare two expressions
Returns NULL Instead of Boolean Doesn't return TRUE or FALSE, making filtering harder
NULL Handling Issues If either value is NULL, result is always NULL
Not Suitable for Complex Conditions For complex logic, CASE might be better

Common Errors with NULLIF

Error Code Cause Solution
ORA-01722 Invalid number (e.g., NULLIF('abc', 123)) Ensure both values are comparable types
ORA-00932 Inconsistent data types Use CAST() to match data types

Do’s and Don’ts of NULLIF Function

Do's Don'ts
Use NULLIF to avoid division by zero Don't use NULLIF for complex conditions (use CASE instead)
Use in aggregations to filter out identical values Avoid when both expressions can be NULL (results in NULL)
Ensure both arguments have the same data type Don't expect NULLIF to return TRUE/FALSE (it returns NULL)



Difference Between NVL, NVL2, NULLIF, and COALESCE in Oracle SQL

Function Definition Usage Key Difference
NVL(expr1, expr2) Returns expr2 if expr1 is NULL; otherwise, returns expr1. Used for replacing NULL values with a default value. Can replace only one NULL value, works with two arguments.
NVL2(expr1, expr2, expr3) Returns expr2 if expr1 is NOT NULL, otherwise returns expr3. Used when we need different values for NULL and NOT NULL cases. Returns different outputs for NULL and NOT NULL values.
NULLIF(expr1, expr2) Returns NULL if expr1 = expr2, otherwise returns expr1. Used to avoid divide-by-zero errors or to compare values. Compares two values and returns NULL only if they are equal.
COALESCE(expr1, expr2, ..., exprN) Returns the first non-null expression from a list. Used when multiple fallback values are needed. More flexible than NVL, as it supports multiple expressions.


When to Use?

Use Case Best Function
Replace a NULL value with a default NVL
Define different outputs for NULL and NOT NULL cases NVL2
Compare two values and return NULL if they are equal NULLIF
Use the first non-null value from a list COALESCE
