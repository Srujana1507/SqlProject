    ORDER BY Clause in Oracle SQL

    The ORDER BY clause in Oracle SQL is used to sort the result set of a query in either ascending (ASC) or descending (DESC) order.


    • It is typically the last clause in a SELECT statement and organizes data for better readability and analysis.
    • By default, the sorting is in ascending order, but you can explicitly specify descending order if needed.

    Key Features of ORDER BY Clause

    Feature Description
    Column-Based Sorting Sorts results based on one or more columns.
    Ascending Order (Default) Results are sorted from smallest to largest (e.g., A-Z, 0-9).
    Descending Order Results are sorted from largest to smallest (e.g., Z-A, 9-0).
    Multiple Columns Allows sorting by multiple columns, applying different sorting orders for each column if needed.
    By Column Alias Supports sorting by column aliases or derived columns in the SELECT list.

    1. Basic Syntax

    SELECT column1, column2,. . .
    FROM table_name
    ORDER BY column_name [ASC|DESC] [ NULLS FIRST | NULLS LAST] ;

    • ASC (Ascending) : Default order (e.g., smallest to largest for numbers, A to Z for strings).
    • DESC (Descending) : Reverses the order (e.g., largest to smallest for numbers, Z to A for strings).
    • NULLS FIRST: Places NULL values at the beginning.
    • NULLS LAST: Places NULL values at the end.

    2. Sorting by Column Index

    Instead of specifying column names, you can sort by column index in the SELECT clause.

    SELECT column1, column2
    FROM table_name
    ORDER BY 2 ;

    - - Sorts by the second column
    NOTE : - Sorting by column index is not recommended due to readability and maintainability issues.

    Examples

    Scenario 1:- Retrieve all employees sorted by their last_name in ascending order.

    SELECT employee_id, last_name,salary
    FROM employees
    ORDER BY last_name ;

    - - No need to mention ASC in this scenario, By Default Ascending order.

    Scenario 2:- ( Descending Order )Retrieve employees sorted by salary in descending order.

    SELECT employee_id, name,salary
    FROM employees
    ORDER BY salary DESC ;

    Scenario 3:- ( Sorting by Multiple Columns ) Sort employees by department_id in ascending order and then by salary in descending order.

    SELECT employee_id, name,department_id,salary
    FROM employees
    ORDER BY department_id ASC,salaryDESC ;

    Scenario 4:- ( Sorting by Expressions ) Sort products by the discount percentage.

    SELECT ProductID, Price,Discount,(Discount / Price) * 100 AS DiscountPercentage
    FROM Products
    ORDER BY DiscountPercentage DESC ;

    SELECT employee_id, first_name, LENGTH( first_name ) AS name_length
    FROM employees
    ORDER BY LENGTH( first_name ) DESC ;

    Scenario 5:- ( with Aggregate Functions )Sort departments by the total sales in descending order.

    SELECT department_name, SUM(Sales) AS TotalSales
    FROM Employees
    GROUP BY department_name
    ORDER BY SUM(Sales) DESC ;

    Scenario 6:- ( Sorting by Aliases ) Sort by an alias defined in the SELECT clause.

    SELECT EmployeeID, first_name,salary + NVL( commission_pct * salary, 0 ) AS total_compensation
    FROM Employees
    ORDER BY total_compensation DESC ;

    Scenario 7:- ( ORDER BY with Subqueries ) Sort products based on total sales calculated from another table.

    SELECT ProductID, Name,(SELECT SUM(Quantity)
          FROM Sales
          WHERE Sales.ProductID = Products.ProductID) AS TotalSales
    FROM Products
    ORDER BY TotalSales DESC ;

    Scenario 8:- ( Sorting by Aliases ) Sort by an alias defined in the SELECT clause.

    SELECT EmployeeID, first_name,salary + NVL( commission_pct * salary, 0 ) AS total_compensation
    FROM Employees
    ORDER BY total_compensation DESC ;

    Scenario 9:- ( NULLS FIRST/NULLS LAST ) Control the placement of NULL values in sorted results

    NULLS LAST

    SELECT EmployeeID, Name,Salary
    FROM Employees
    ORDER BY salary ASC NULLS LAST ;

    NULLS FIRST

    SELECT ProductID, ProductName,AvailabilityDate
    FROM Products
    ORDER BY AvailabilityDate DESC NULLS FIRST ;

    Why Use NULLS FIRST or NULLS LAST?

    • Sorting behavior for NULL values varies by database system.
      • In PostgreSQL, NULLS FIRST is the default for descending order, while NULLS LAST is the default for ascending order.
      • In Oracle and SQL Server, NULLS LAST is generally the default.
    • Specifying NULLS FIRST or NULLS LAST ensures consistent and explicit behavior, regardless of the database.


    Performance Considerations / Tips

    • Index Optimization:- Sorting can be optimized if the sorted column is indexed.
    • Avoid Unnecessary Sorting:- Remove ORDER BY clauses in subqueries if sorting is not needed for final results.
    • Large Datasets:- Sorting large datasets can be resource-intensive; limit the rows returned using ROWNUM or FETCH FIRST.
    • Pre-Sorting in Views:- Use views or temporary tables with pre-sorted data for recurring queries.
    • Avoid Sorting Large Data:- Minimize sorting large datasets by filtering rows first with WHERE or JOIN clauses.

    Common Errors with ORDER BY Clause

    Error Cause Solution
    ORA-00907: Missing Right Parenthesis Incorrect syntax when using functions or expressions in ORDER BY. Ensure all functions and expressions in ORDER BY are properly formatted.
    ORA-00904: Invalid Identifier Using a column alias in ORDER BY that isn’t defined in the SELECT list. Verify column aliases in the SELECT clause are used correctly in ORDER BY.
    ORA-01785: ORDER BY Item Not Allowed Using ORDER BY in certain subqueries where sorting is not permitted. Remove ORDER BY from subqueries or restructure the query.

    Do’s and Don’ts When Using ORDER BY

    Do's Don'ts
    Use ASC and DESC to control sorting direction explicitly if required. Don’t assume the default order when ASC or DESC is not specified; explicitly define for clarity.
    Use NULLS FIRST or NULLS LAST to handle NULL values as per business needs. Don’t forget to handle NULL sorting explicitly if it impacts query results.
    Use column aliases or expressions in the ORDER BY clause for complex sorting logic. Don’t use ambiguous column names in ORDER BY if the query involves joins or multiple tables.
    Combine multiple columns in ORDER BY for multi-level sorting. Don’t rely on implicit sorting; always use ORDER BY for deterministic output.
