    IN Operator in Oracle SQL

    The IN operator in Oracle SQL is used to filter rows based on whether a specified value matches any value in a list or subquery.


    • It is a shorthand for multiple OR conditions and is often more readable and efficient.
    • The IN operator is used to specify multiple values in a WHERE clause or similar conditions.
    • It checks whether a given column value matches any value in a list or a subquery.

    Purpose of IN Operator

    • Simplify queries that check for multiple values in a column.
    • Replace multiple OR conditions with a more readable and compact syntax.
    • Filter data using lists or results from a subquery.

    Syntax

    1. Basic IN Syntax

    SELECT column1 , column2 , . . .
    FROM table_name
    WHERE column_name IN ( column1 , column2 , . . . ) ;

    2. IN with Subquery

    SELECT column1 , column2 , . . .
    FROM table_name
    WHERE column_name IN (SELECT column_name FROM another_table ) ;

    Key Features of IN Operator

    Feature Description
    Simplifies Queries Reduces the need for multiple OR conditions.
    Static Lists and Subqueries Works with both static lists of values and dynamic subqueries.
    NULL Handling If the list contains NULL, no match is found for any value (excluding NULL itself).
    Case-Sensitive Comparisons are case-sensitive by default (for character data).


    Examples / Scenarios

    Scenario 1:- ( IN with Static List ) Retrieve employees working in departments 10, 20, or 30.

    SELECT employee_id , department_id , first_name
    FROM employees
    WHERE department_id IN ( 10, 20, 30 ) ;

    Equivalent Query Using OR:

    SELECT employee_id , department_id , first_name
    FROM employees
    WHERE department_id = 10 OR department_id = 20 OR department_id = 30 ;

    Scenario 2:- Retrieve customers located in "Hyderabad", "Mumbai", or "Chennai".

    SELECT customer_id , customer_name , city
    FROM customers
    WHERE city IN ( 'Hyderabad' , 'Mumbai' , 'Chennai' ) ;

    Scenario 3:- ( IN with Subquery )Find all orders placed by customers from "California."

    SELECT OrderID , CustomerID , OrderDate
    FROM Orders
    WHERE CustomerID IN (
        SELECT CustomerID
        FROM customers
        WHERE State = 'Hyderabad'
    ) ;

    Scenario 4:- ( IN with Subquery ) Find employees working in departments with department IDs from the departments table

    SELECT employee_id , first_name , department_id
    FROM employees
    WHERE department_id IN (
        SELECT department_id
        FROM departments
    ) ;

    Scenario 5:- ( IN with Date Values (TO_CHAR) ) Find transactions that occurred on specific dates.

    SELECT transaction_id , transaction_date , amount
    FROM transactions
    WHERE transaction_date IN (
      TO_DATE ( '2025-01-01' , 'YYYY-MM-DD' ) ,
      TO_DATE ( '2025-01-02'' , 'YYYY-MM-DD' )
    ) ;

    Scenario 6:- ( IN with Date Values ) Retrieve orders placed on specific dates.

    SELECT order_id , order_date , customer_id
    FROM orders
    WHERE order_date IN ( '2024-01-01', '2024-01-15', '2024-02-01' ) ;

    Scenario 7:- ( IN with Aggregates and GROUP BY ) Find sales records where the region is in the top-performing regions based on revenue.

    SELECT region_id , SUM (revenue) AS total_revenue
    FROM sales
      WHERE region_id IN (
        SELECT region_id FROM regions
          WHERE performance = 'High'
        ) GROUP BY region_id ;

    Scenario 8:- ( IN with Multiple Columns ) Retrieve employees whose department and job title match specific pairs of values.

    SELECT employee_id , department_id , job_title
    FROM employees
      WHERE ( department_id, job_title ) IN ( ( 10, 'Manager' ), ( 20, 'Analyst' ) ) ;

    Scenario 9:- ( Combining with Other Conditions ) Retrieve employees in departments 10, 20, or 30, who also earn more than $50,000.

    SELECT EmployeeID , Name , department_id , Salary
    FROM employees
      WHERE department_id IN ( 10, 20, 30 ) AND Salary > 50000 ;

    Scenario 10:- (Matching Multiple Columns (Using Subqueries)) Retrieve orders that match specific combinations of customer and product IDs.

    SELECT OrderID , CustomerID , ProductID
    FROM Orders
    WHERE (CustomerID, ProductID) IN (
        SELECT CustomerID , ProductID
        FROM FavoriteProducts
      ) ;

    Scenario 11:- ( IN with NULL Handling ) Find accounts with statuses that include NULL.

    SELECT account_id , account_status
    FROM accounts
      WHERE city IN ( 'Active' , 'Inactive' , NULL ) ;

    Scenario 12:- ( IN with OR ) Retrieve files that are in specific categories or have specific tags.

    SELECT file_id , file_name
    FROM files = 'Inactive'
      WHERE file_category IN ( 'Reports' , 'Invoices')
        OR file_id IN ( SELECT file_id FROM tags
          WHERE tag_name IN ( 'Urgent' , 'Important') ;
        )

    Scenario 13:- ( IN with DELETE ) Delete products belonging to certain categories.

    DELETE FROM products
    WHERE category_id IN ( 1, 2, 3 ) ;

    Scenario 14:- ( IN with Subqueries in DELET ) Delete customers who have not placed any orders.

    DELETE FROM customers
    WHERE category_id NOT IN ( SELECT DISTINCT customer_id FROM orders ) ;

    Scenario 15:- ( IN with UPDATE ) Update the status of customers located in specific cities.

    UPDATE customers
    SET status = 'Inactive'
    WHERE city IN ( 'New York' , 'Los Angeles' , 'Chicago') ;

    8. IN with JOIN Condition

    Scenario 16:- ( IN with JOIN ) Retrieve orders for products belonging to certain categories.

    SELECT o.order_id, p.product_name
    FROM orders o
    JOIN products p ON o.product_id = p.product_id
    WHERE p.category_id IN (
    SELECT category_id FROM categories WHERE category_name = 'Electronics' ) ;

    Scenario 17:- ( IN with HAVING ) Retrieve categories with sales in specific years.

    SELECT category_id, SUM(sales) AS total_sales
    SELECT order_id, customer_id FROM sales
    GROUP BY category_id
    HAVING YEAR ( order_date ) IN ( 2020, 2021 ) ;


    Do's and Don'ts of IN Operator

    Do's Don'ts
    Use IN with indexed columns to optimize performance. Avoid using IN for values that can be handled more efficiently with joins.
    Use IN for filtering values in a smaller list or subquery. Avoid using IN with large lists or subqueries; it may cause performance degradation.
    Combine IN with subqueries for dynamic filtering. Don’t use IN when the list can be represented as a join or when an EXISTS clause is better.
    Use NOT IN carefully, ensuring the subquery doesn't return NULL. Don’t use NOT IN with subqueries if the column can contain NULL values.


    Limitations of IN Operator

    Limitations Description
    Performance on Large Lists Using IN with a large number of values or a large subquery can slow down execution.
    Case Sensitivity Matching is case-sensitive for strings unless transformed with UPPER or LOWER.
    Static Value List Hardcoding values in IN makes the query less dynamic and harder to maintain compared to subqueries.
    Handling of NULL NOT IN fails to work as expected if the subquery or list contains NULL values.
    Not Suitable for Joins For complex comparisons or larger datasets, joins or EXISTS clauses may be more efficient.


    Common Errors of IN Operator

    Error Cause Solution
    ORA-00907: Missing Right Parenthesis Missing a closing parenthesis in the IN clause. Ensure all parentheses are properly opened and closed. Example: IN (1, 2, 3) instead of IN (1, 2, 3.
    ORA-01722: Invalid Number Comparing a string value with a numeric column or invalid data types in the list. Verify that the values in the IN list match the data type of the column. Use TO_NUMBER or TO_CHAR if necessary.
    ORA-00936: Missing Expression Using an empty IN list or incorrect syntax. Ensure the IN clause is not empty. Example: IN (value1, value2) instead of IN ().
    ORA-01427: Single-Row Subquery Returns More than One Row Using a subquery in IN that inadvertently returns multiple columns instead of one. Ensure the subquery returns only one column. Correct query: SELECT column FROM table in the subquery.
    No Rows Returned (Unexpected Behavior) Including NULL in the list of values for comparison, which cannot be matched by IN. Explicitly handle NULL using IS NULL or NVL. Example: WHERE column IN (value1, value2) OR column IS NULL.
    ORA-01722: Invalid Number in Subquery The subquery returns values incompatible with the data type of the column being filtered. Verify the subquery returns compatible data types. Use data type conversion functions like CAST.
    Case-Sensitivity Problems Text values in the IN list do not match due to case sensitivity. Use UPPER or LOWER for case-insensitive comparison. Example: WHERE UPPER(column) IN ('VALUE1', 'VALUE2').
    Performance Issues Using IN with a very large list of values leads to slow query performance. Consider using a JOIN or indexed tables for better performance.
