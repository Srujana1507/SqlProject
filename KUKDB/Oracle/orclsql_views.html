DROP VIEW in Oracle SQL

In Oracle SQL, the DROP VIEW statement is used to remove a view from the database. A view is a virtual table based on the result of a SQL query.


When you drop a view, Oracle removes the definition of the view from the data dictionary, but the underlying base tables remain unaffected.


Syntax

Basic Syntax

DROP VIEW view_name ;

Key Points

  • The DROP VIEW statement removes only the view definition; it does not delete the underlying data or tables.
  • If the view has dependent objects (like other views or synonyms), Oracle will prevent you from dropping the view unless you use the CASCADE CONSTRAINTS option.
  • Dropping a view automatically commits the transaction — it cannot be rolled back.
  • A dropped view cannot be recovered unless you have a backup.
  • Permissions (grants) associated with the view are automatically removed when the view is dropped.

CASCADE CONSTRAINTS

  • If the view is referenced by constraints in other objects (like other views or tables), adding CASCADE CONSTRAINTS will drop the dependent constraints as well.

Truncate Table with DROP STORAGE

DROP VIEW view_name CASCADE CONSTRAINTS ;

Restrictions on DROP VIEW

  • You cannot drop a view
    • That is part of a materialized view.
    • That is referenced by a foreign key constraint without CASCADE CONSTRAINTS.
    • Created in another schema (unless you have DROP ANY VIEW privilege).
  • You cannot roll back a DROP VIEW operation since it's a DDL statement.

Example

1. Drop a Simple View:- Drop a view named employee_view.

DROP VIEW employee_view ;
  • The view employee_view will be removed from the schema.
  • Underlying table data will remain intact.

2. Drop a View Referenced by Other Views:- If the view department_view is referenced by other views or constraints.

DROP VIEW department_view CASCADE CONSTRAINTS ;
  • The view department_view and all dependent constraints or references will be removed.
  • If dependent views or objects exist, they will become invalid unless CASCADE CONSTRAINTS is used.

3. Drop a View Created by Another User (With Permissions):- If a view sales_view was created by another user and you have the DROP ANY VIEW privilege.

DROP VIEW sales_view ;
  • The view will be dropped, but the base tables will remain intact.

4. Drop a View with Grants:- If employee_view has been granted to other users.

DROP VIEW employee_view ;
  • The view will be dropped.
  • All associated privileges granted to other users will be revoked automatically.

5. Drop a View with JOINs:- If the view emp_dept_view is created with a JOIN.

DROP VIEW emp_dept_view ;
  • The view will be dropped without affecting the base tables used in the join.

Differences Between DELETE and TRUNCATE

Feature DROP VIEW DELETE
Purpose Removes the view definition Removes data from the table
Impact on Base Table No effect on the underlying table Affects the underlying table data
Rollback Cannot be rolled back Can be rolled back
Scope Only the view is dropped Rows in the table are deleted
Cascade Option Supported Not supported

Advantages of DROP VIEW

Advantage Description
Frees Up Space Dropping unused views frees up database space and resources.
Simplifies Schema Removing unnecessary views makes the schema easier to manage.
Improved Performance Reduces parsing time and improves query performance by removing unused views.
Immediate Effect View is dropped immediately — no need to wait for completion.
No Data Loss Data in the base table remains intact after dropping a view.

Disadvantages of DROP VIEW

Disadvantage Description
Cannot Roll Back Once dropped, the view cannot be recovered unless restored from backup.
Dependent Objects Issue Dependent objects like other views, procedures, or triggers will become invalid.
Loss of Permissions Any granted privileges on the view will be lost when dropped.
Schema Dependency If the view is part of a larger schema, dropping it may cause cascading failures.
Auto-Commit The DROP VIEW statement commits automatically.

Common Errors and Solutions

Error Code Cause Solution
ORA-00942: table or view does not exist Trying to drop a non-existent view. Check the view name and schema.
ORA-01732: data manipulation operation not legal on this view Attempting to drop a view with insufficient permissions. Grant DROP privileges or use a privileged user.
ORA-02266: unique/primary keys referenced by foreign keys Attempting to drop a view with dependent constraints. Use CASCADE CONSTRAINTS.
ORA-04043: object does not exist View not found in the schema. Verify the view name and schema.
ORA-00911: invalid character Syntax error in the statement. Remove unnecessary characters.

Do's and Don'ts of DROP VIEW

Do's Don'ts
Ensure no critical object depends on the view before dropping it. Don’t drop a view without checking dependent objects.
Use CASCADE CONSTRAINTS if the view is referenced by other objects. Don’t drop a view unless you're sure it's no longer needed.
Check for permissions before dropping a view created by another user. Don’t drop a view directly in a production environment without testing.
Always take a backup before dropping important views. Don’t drop a view used by active sessions or reports.
Verify object dependencies using DBA_DEPENDENCIES before dropping. Don’t drop a system-generated or critical view unless necessary.

Best Practices

  • Always check for dependent objects using the DBA_DEPENDENCIES view before dropping a view.
  • Avoid dropping views directly in a production environment without testing in development.
  • If the view is complex or critical, consider renaming it before dropping.
  • Use CASCADE CONSTRAINTS only when you are sure that the dependent objects are no longer needed.
  • Document the change when dropping important views to maintain version control and transparency.
