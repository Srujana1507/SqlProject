Set Operators in Oracle SQL

In Oracle SQL, SET operators are used to combine results from two or more SELECT statements into a single result set.


SET operators in Oracle SQL are essential when we need to combine results from multiple queries while maintaining logical relationships between datasets.


Instead of writing complex JOIN or EXISTS queries, SET operators provide a clear and efficient way to merge, filter, and compare data.


These operators allow you to merge, intersect, or subtract rows from different queries while maintaining distinct or duplicate values.


List of Set Operators in Oracle SQL

Operator Description
UNION Combines results from multiple queries, removing duplicates.
UNION ALL Combines results from multiple queries, including duplicates.
INTERSECT Returns only the common rows between queries.
MINUS Returns rows from the first query that are not in the second query.

Key Rules for Using Set Operators

  • Same Number of Columns → All SELECT statements must return the same number of columns.
  • Same Data Types → Corresponding columns in each SELECT must have compatible data types.
  • Column Names Taken from First Query → The result set will use the column names from the first SELECT statement.
  • ORDER BY Only at the End → You can only use ORDER BY once, at the end of the entire query.

Reasons for Using SET Operators

Reasons Explanation
Combining Multiple Queries Easily merge results from different tables or queries into a single dataset.
Removing Duplicates (UNION) Automatically ensures unique records without requiring DISTINCT.
Keeping All Rows (UNION ALL) Preserves all rows including duplicates for performance and analysis.
Finding Common Data (INTERSECT) Identifies records that exist in both datasets.
Finding Differences (MINUS) Extracts records from one dataset that do not exist in another.
Improved Readability Queries using SET operators are easier to understand than complex JOIN queries.
Better Performance in Some Cases UNION ALL can be faster than using OR conditions in WHERE clauses.

Importance of SET Operators in Oracle SQL

Feature Importance
Simplifies Complex Queries Instead of using nested subqueries or JOINs, SET operators provide a direct way to compare and merge results.
Ensures Data Integrity Operators like INTERSECT ensure that only common records are processed.
Enhances Query Performance UNION ALL avoids sorting overhead, making it faster than UNION.
Essential for Data Migration Used in ETL (Extract, Transform, Load) processes to merge data from different sources.
Flexible Data Analysis Helps in reporting and analytics by efficiently merging multiple datasets.

Comparison of SET Operators

Feature UNION UNION ALL INTERSECT MINUS
Combines Results? Yes Yes No (only common rows) No (only unique rows)
Removes Duplicates? Yes No Yes Yes
Returns Common Rows? Yes Yes Yes No
Returns Unique Rows from First Query? No No No Yes
Performance Slower (sorts results) Fastest Slower Slower
Memory Usage High (due to sorting) Low High High
Index Usage May not use indexes efficiently Uses indexes better May not use indexes efficiently May not use indexes efficiently

Common Errors and Solutions

Error Cause Solution
ORA-01789: query block has incorrect number of result columns Mismatched columns in SELECT queries Ensure both queries return the same number of columns
ORA-01790: expression must have same datatype as corresponding expression Data type mismatch Use CAST() or TO_CHAR() to convert data types
ORA-00933: SQL command not properly ended Using ORDER BY incorrectly Ensure ORDER BY is placed only at the end of the final query

Limitations of Set Operators

Limitation Description
Column Order Must Match Columns in all queries must appear in the same order.
Cannot Use ORDER BY in Individual Queries ORDER BY can only be used once at the end of the full query.
Cannot Perform Complex Expressions in Set Operations Some expressions (like LOB data types) may not work with set operators.
Data Type Mismatch Errors All columns in the queries must have compatible data types.

Do's and Don'ts of Set Operators

Do's Don'ts
Ensure same number of columns in all queries. Do not assume UNION is faster than UNION ALL. Removing duplicates slows performance.
Use UNION ALL for better performance if duplicates don’t matter. Avoid using MINUS on large datasets without indexing.
Optimize queries using indexes to speed up comparisons. Do not use INTERSECT on large tables without filtering data first.
