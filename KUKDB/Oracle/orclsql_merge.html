MERGE Statement in Oracle SQL (UPSERT Operation)

The MERGE statement in Oracle SQL is used for UPSERT (Update or Insert) operations.


It allows you to conditionally update existing records or insert new records based on a matching condition, eliminating the need for separate INSERT and UPDATE statements.


Syntax of MERGE Statement

MERGE INTO target_table USING source_table
ON (condition)
WHEN MATCHED THEN
    UPDATE SET column1 = value1, column2 = value2
WHEN NOT MATCHED THEN
    INSERT (column1, column2) VALUES (value1, value2) ;
  • MATCHED condition: Updates existing rows in the target table.
  • NOT MATCHED condition: Inserts new rows if no match is found.
  • DELETE clause (optional): Can delete rows when certain conditions are met.

Key Features of MERGE

Feature Description
Single Statement for UPSERT Eliminates the need for separate INSERT and UPDATE statements.
Improves Performance Reduces the number of database operations.
Can Use Joins and Subqueries Allows dynamic data merging.
Supports DELETE Option Can remove records when matched.
Maintains Atomicity Ensures all updates/inserts are processed as a single transaction.

Examples of MERGE Statement

Simple MERGE Example (Basic UPSERT):- Updates employee 101 if they exist, otherwise inserts a new record.

MERGE INTO employees e
USING (SELECT 101 AS employee_id, 'John Doe' AS name, 7000 AS salary
FROM dual) s
ON ( e.employee_id = s.employee_id )
WHEN MATCHED THEN
    UPDATE SET e.salary = s.salary
WHEN NOT MATCHED THEN
    INSERT ( employee_id, name, salary ) VALUES ( s.employee_id, s.name, s.salary ) ;

MERGE Using Another Table as Source:- Updates salaries for matching employees; inserts new employees if not found.

MERGE INTO employees e
USING salary_updates s
ON ( e.employee_id = s.employee_id )
WHEN MATCHED THEN
    UPDATE SET e.salary = s.new_salary
WHEN NOT MATCHED THEN
    INSERT ( employee_id, name, salary ) VALUES ( s.employee_id, s.name, s.new_salary ) ;

MERGE with DELETE Clause:- Deletes employees listed in the terminated_employees table.

MERGE INTO employees e
USING (SELECT employee_id FROM terminated_employees ) t
ON ( e.employee_id = t.employee_id )
WHEN MATCHED THEN
    DELETE ;

MERGE with Additional Conditions:- Only updates employees whose salary is lower than the new salary.

MERGE INTO employees e
USING (SELECT employee_id, new_salary FROM salary_increments ) s
ON ( e.employee_id = s.employee_id )
WHEN MATCHED AND e.salary < s.new_salary THEN
    UPDATE SET e.salary = s.new_salary
WHEN NOT MATCHED THEN
    INSERT ( employee_id, name, salary ) VALUES ( s.employee_id, 'New Employee' , s.new_salary ) ;

MERGE with BULK Data from Another Table:- Updates existing inventory with new stock; inserts new products if not found.

MERGE INTO inventory i
USING incoming_shipments s
ON ( i.product_id = s.product_id )
WHEN MATCHED THEN
    UPDATE SET i.stock = i.stock + s.quantity
WHEN NOT MATCHED THEN
    INSERT ( product_id, stock ) VALUES ( s.product_id, s.quantity ) ;

Common Errors with MERGE

Error Code Cause Solution
ORA-30926:Unable to get a stable set of rows in the source tables Duplicate rows in the source table Use DISTINCT or ensure primary keys are unique
ORA-00001:Unique constraint violated Inserting duplicate values in a unique column Ensure INSERT values do not violate constraints
ORA-06550: PL/SQL: ORA-00933: SQL command not properly ended Incorrect syntax Verify MERGE statement structure
ORA-02292: Child record found (foreign key violation) Attempting to delete a parent record with child records Ensure related child records are removed first

Limitations of MERGE

Limitation Description
Cannot Merge on Remote Tables MERGE does not work with database links (DBLINK).
Cannot Use in Triggers MERGE cannot be used inside triggers.
Does Not Support Complex Joins Can only merge between two tables, not multiple joins.
Primary Key Must Be Unique If duplicates exist, MERGE may throw errors.
Cannot Use RETURNING Clause Unlike INSERT, UPDATE, DELETE, MERGE does not support RETURNING.

Do's and Don'ts of MERGE

Do's Don'ts
Ensure the source and target tables have unique primary keys. Do not use MERGE if the source table has duplicate values for the matching key.
Use additional conditions in WHEN MATCHED to prevent unnecessary updates. Do not include UPDATE logic that modifies a column with the same existing value (redundant update).
Use DELETE carefully to remove unnecessary records. Avoid MERGE if your dataset is highly volatile (frequent changes may cause conflicts).
Test with a smaller dataset before applying MERGE on large tables. Do not rely on MERGE for complex join conditions. Use INSERT + UPDATE instead.

Performance Comparison: MERGE vs. INSERT+UPDATE

Criteria MERGE INSERT + UPDATE
Performance Faster Slower (requires two operations)
Readability More concise More code
Atomicity Single transaction Two separate transactions
Error Handling Harder to debug Easier to debug separately
Use Case Best for bulk updates/inserts Best for smaller datasets
