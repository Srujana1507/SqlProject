RETURNING Clause in Oracle SQL

The RETURNING clause in Oracle SQL is used in DML statements (INSERT, UPDATE, DELETE) to return values from the affected rows without requiring a separate SELECT statement.


It improves performance by avoiding additional queries.


Syntax of RETURNING Clause

DELETE | INSERT | UPDATE
FROM table_name
WHERE condition
RETURNING column_name [, column_name] INTO variable_name [, variable_name] ;
  • table_name → The table being modified.
  • RETURNING column_name → Specifies the columns whose values should be returned.
  • INTO variable_name → Stores the returned values into declared PL/SQL variables.

Key Features of RETURNING Clause

Feature Description
Optimized for Performance Avoids extra SELECT statements after DML.
Works with INSERT, UPDATE, DELETE Can return values from modified rows.
Supports Multiple Columns Can return multiple values at once.
Returns Values from the Affected Rows Useful for logging, auditing, or debugging.
Works in PL/SQL Blocks Cannot be used directly in a standalone SQL query.

Advantages of RETURNING Clause

Feature Description
Reduces Database Calls No need for separate SELECT statements after DML operations.
Performance Improvement Fetching data immediately avoids extra queries.
Works with Multiple Rows Supports single-row and bulk operations with RETURNING BULK COLLECT INTO.
Retrieves Auto-Generated Values Useful for getting SEQUENCE values after an INSERT.

Examples of Using RETURNING Clause

Using RETURNING with DELETE:- Deletes employee with employee_id = 101 and returns their name and salary.

DECLARE
    v_emp_name employees.last_name%TYPE;
    v_salary employees.salary%TYPE;
BEGIN
    DELETE FROM employees
    WHERE employee_id = 101
    RETURNING last_name, salary INTO v_emp_name, v_salary ;
    DBMS_OUTPUT.PUT_LINE( 'Deleted Employee: ' || v_emp_name || ', Salary: ' || v_salary) ;
END ;
/

Using RETURNING with UPDATE:- Updates an employee’s salary and returns the old salary before the update.

DECLARE
    v_old_salary employees.salary%TYPE;
    v_new_salary employees.salary%TYPE := 6000;
BEGIN
    UPDATE employees
    SET salary = v_new_salary
    WHERE employee_id = 102
    RETURNING salary INTO v_old_salary ;
    DBMS_OUTPUT.PUT_LINE( 'Updated Employee 102 Salary from ' || v_old_salary || ' to ' || || v_new_salary ) ;
END ;
/

Using RETURNING with INSERT:- Inserts a new employee and retrieves the generated employee_id.

DECLARE
    v_new_id employees.employee_id%TYPE;
    v_new_name employees.last_name%TYPE := 'Brown' ;
BEGIN
    INSERT INTO employees (employee_id, last_name, salary, department_id)
    VALUES (205, v_new_name, 5000, 10)
    RETURNING employee_id INTO v_new_id ;
    DBMS_OUTPUT.PUT_LINE( 'Inserted Employee ID: ' || v_new_id ) ;
END ;
/

Using RETURNING with BULK DELETE (Multiple Rows):- Deletes multiple employees from department 20 and returns their names using BULK COLLECT.

DECLARE
    TYPE emp_table IS TABLE OF employees.last_name%TYPE;
    v_emp_names emp_table;
BEGIN
    DELETE FROM employees
    WHERE department_id = 20
    RETURNING last_name BULK COLLECT INTO v_emp_names ;


FOR i IN 1..v_emp_names.COUNT LOOP
    DBMS_OUTPUT.PUT_LINE( 'Deleted Employee: ' || || v_emp_names(i) ) ;
END LOOP
END ;
/

Common Errors with RETURNING Clause

Error Code Cause Solution
ORA-00933:SQL command not properly ended. Using RETURNING in a standalone SQL statement Use it only inside PL/SQL blocks
ORA-00947:Not enough values Mismatch between columns in RETURNING and variables in INTO Ensure equal number of columns and variables
ORA-06550: PL/SQL: ORA-00932: inconsistent datatypes Incompatible variable types Use %TYPE for variable declaration
ORA-01403: No data found The WHERE condition did not match any row Ensure the row exists before executing the statement.

Limitations of RETURNING Clause

Limitation Description
Only Works with DML Statements Cannot be used in a SELECT statement.
Only Works in PL/SQL Cannot be executed in plain SQL without BEGIN...END.
Does Not Work with Joins Cannot return data from multiple tables in one query.
Only Returns Affected Rows If no row is modified, no data is returned.
Does Not Work with Remote Databases Cannot be used in INSERT/UPDATE/DELETE on remote tables via database links.

Do's and Don'ts of RETURNING

Do's Don'ts
Use RETURNING to optimize performance instead of separate SELECT queries. Do not use RETURNING in a plain SQL statement—it must be inside PL/SQL.
Use BULK COLLECT for returning multiple rows efficiently. Do not mismatch columns and variables in RETURNING INTO.
Use %TYPE for variables to match column data types. Avoid using RETURNING if the statement might not affect any rows (handle exceptions properly).
Use it for logging and debugging purposes. Do not use RETURNING for complex multi-table updates—it does not support joins.
