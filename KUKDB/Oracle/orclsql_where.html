    WHERE Clause in Oracle SQL


    The WHERE clause is used to filter rows returned by a query based on specified conditions.


    • It limits the rows returned by a query to those that satisfy the conditions specified.
    • It is crucial for narrowing down datasets, improving performance, and targeting specific results.
    • This clause is essential for extracting only the relevant data from large datasets.

    Basic Syntax


    SELECT column1, column2,. . .FROM table_name
    WHERE condition ; - - You can use specific columns are ( * ) - for all columns

    Key Features of the WHERE Clause

    Feature Description
    Row Filtering Filters rows by evaluating each row against the specified condition(s).
    Logical Operators Supports operators like AND, OR, and NOT for complex filtering.
    Comparison Operators Allows comparison using operators like =, <,>, <=,>=, and <> (not equal).
    Wildcard Matching Supports pattern matching using LIKE and wildcards % (multiple characters) and _ (single character).
    Null Checks Handles NULL values explicitly using IS NULL and IS NOT NULL.

    Operators Used in WHERE Clause

    Type of Operator Operators Examples
    Comparison Operators =, <>, <,>, <=,>= WHERE salary > 50000
    Logical Operators AND, OR, NOT WHERE salary > 50000 AND department_id = 10
    Pattern Matching LIKE, %, _ WHERE first_name LIKE 'A%'
    Set Membership IN, NOT IN WHERE department_id IN (10, 20, 30)
    Null Checks IS NULL, IS NOT NULL WHERE manager_id IS NOT NULL
    Range Checks BETWEEN ... AND ... WHERE hire_date BETWEEN '2020-01-01' AND '2023-12-31'
    Subqueries Comparison with subquery results WHERE salary > (SELECT AVG(salary) FROM employees)


    Examples

    Scenario 1:- (Single Condition) Retrieve employees from department 10.

    SELECT employee_id , name, salary
    FROM employees
      WHERE dept_id = 10 ;

    Examples of WHERE Clause

    Scenario 2:- ( Multiple Conditions with AND ) Find employees who work in department 101 and have a salary greater than 70,000.


    SELECT employee_id , name, dept_id,salary
    FROM employees
      WHERE dept_id = 101 AND salary > 70000 ;

    Scenario 3:- ( Multiple Conditions with OR ) Retrieve employees who are in department 20 or have a salary greater than 80,000.

    SELECT employee_id , name, dept_id,salary
    FROM employees
      WHERE dept_id = 10 OR salary > 20 80000 ;

    Scenario 4:- ( Range Filtering with BETWEEN ) Find employees with salaries between 30,000 and 60,000.


    SELECT employee_id , name, dept_id
    FROM employees
      WHERE salary BETWEEN 30000 AND 60000 ;

    Scenario 5:- ( String Matching with LIKE ) Retrieve employees whose names start with 'A'.

    SELECT *
    FROM employees
      WHERE name LIKE 'A%' ;

    Scenario 6:- ( Filter Null Values ) Find employees who have not been assigned a commission.

    SELECT employee_id , name, commission_pct
    FROM employees
      WHERE commission_pct IS NULL ;

    Scenario 7:- ( Exclude Specific Rows ) Retrieve employees who are not managers.

    SELECT employee_id , name, job_title
    FROM employees
      WHERE job_title <> 'Manager' ;

    Scenario 8:- ( Subquery in WHERE ) Find employees who belong to departments located in Hyderabad.

    SELECT employee_id , name, dept_id
    FROM employees
      WHERE dept_id IN (
        SELECT dept_id
        FROM departments
          WHERE location_id = (
            SELECT location_id
            FROM locations
            WHERE city = 'Hyderabad'
            )
        ) ;

    Scenario 7:- ( Date Filtering ) Retrieve employees who were hired after January 1, 2020.

    SELECT employee_id , name, hire_date
    FROM employees
      WHERE hire_date > TO_DATE( '2020-01-01' , 'YYYY-MM-DD' ) ;

    Scenario 8:- ( Using Aggregates with Subqueries ) Find employees who earn the maximum salary in their department.

    SELECT employee_id , name, salary , dept_id
    FROM employees
      WHERE salary (
        SELECT MAX (salary)
        FROM employees e2
          WHERE e2.dept_id = employees.dept_id
        ) ;


    Scenario 9:- ( Using IN ) Find employees who are working in departments HR, Finance, or Testing.

    SELECT *
    FROM employees
    WHERE dept_name IN ( 'HR', ''Finance', 'Testing ') ;

    Scenario 10:- ( Using CASE ) Retrieve employees in departments 10 or 20, but only if their salaries exceed specific thresholds based on their roles.

    SELECT employee_id , name, salary , dept_id , job_title
    FROM employees
    WHERE dept_id IN ( 10, 20 )
      AND salary >
        CASE
          WHEN job_title = 'Manager' THEN 70000
          WHEN job_title = 'Engineer' THEN 50000
          ELSE 40000
        END ;

    Scenario 11:- ( Using CASE with Subqueries ) Retrieve employees who earn above the average salary of their department, adjusted dynamically based on their roles.

    SELECT employee_id , name, salary , dept_id , job_title
    FROM employees
    WHERE dept_id IN ( 10, 20 )
      AND salary >
        CASE
          WHEN job_title = 'Manager' THEN (
            SELECT AVG (Salary) * 1.2 FROM employees e2
              WHERE e2.dept_id = employees.dept_id
              )
          ELSE (
            SELECT AVG (Salary) * 1.2 FROM employees e2
              WHERE e2.dept_id = employees.dept_id
              )
          END ;

    Scenario 12:- ( Filter Based on Time Intervals ) Find employees who were hired within the last 12 months but have not been assigned to a project.

    SELECT employee_id, name, hire_date
    FROM employees
    WHERE hire_date >= ADD_MONTHS( SYSDATE, -12 )
      AND employee_id NOT IN (
        SELECT employee_id
        FROM project_assignments
      ) ;

    Scenario 13:- ( with EXISTS ) Retrieve employees who have worked on at least one project with a budget exceeding 1 million.

    SELECT e.employee_id, e.name
    FROM employees e
    WHERE EXISTS (
      SELECT 1
      FROM project_assignments pa
      JOIN projects p ON pa.project_id = p.project_id
        WHERE pa.employee_id = e.employee_id
        AND p.budget > 1000000
      ) ;

    Scenario 14:- ( used with HAVING ) Identify Departments with More Than 5 Employees.

    SELECT department_id, COUNT ( * )
    FROM employees
    GROUP BY department_id
      HAVING 1
      COUNT ( * ) > 5 ;

    Limitations of WHERE Clause

    Limitations Description
    Cannot filter on aggregate functions directly The WHERE clause cannot use aggregate functions like SUM, AVG, COUNT. Use HAVING instead.
    Performance impact with large datasets Complex filters or unindexed columns can lead to slow query execution.
    Case-sensitivity in string comparisons By default, string comparisons in WHERE are case-sensitive, which might require UPPER or LOWER.
    Dependency on table design Inefficient table design (e.g., missing indexes) can degrade WHERE clause performance.


    Key Points of WHERE Clause

    Key Point Description
    Order of Execution The WHERE clause is applied before data is grouped (GROUP BY) or sorted (ORDER BY).
    Case Sensitivity Oracle SQL is case-sensitive when comparing character strings unless modified by a function like UPPER() or LOWER().
    Indexes Using indexed columns in the WHERE clause improves query performance.
    Null Handling Comparisons with NULL using = or <> are invalid. Always use IS NULL or IS NOT NULL.


    Common Errors in WHERE Clause

    Error Cause Solution
    ORA-00932: inconsistent datatypes Incompatible datatypes in the WHERE clause. Ensure data types match or use appropriate type conversion functions like TO_NUMBER or TO_DATE.
    ORA-01722: invalid number Comparing incompatible data types (e.g., string vs. number). Ensure consistent data types in comparisons.
    ORA-00920: invalid relational operator Incorrect usage of operators like = or <>. Ensure correct operator usage and syntax.
    ORA-01427: single-row subquery returns more than one row Subquery returns multiple rows when only one is expected. Use IN or reframe the query to handle multiple rows.
    ORA-00904: invalid identifier Using a non-existent column in the WHERE clause. Verify column names and their existence in the table.


    Do's and Don'ts of WHERE Clause in Oracle SQL

    Category Do's Don'ts
    Syntax Use proper column names and conditions in the WHERE clause. Avoid missing logical operators or incorrect column references.
    Filtering Use specific and precise conditions to limit the rows processed. Avoid filtering with unnecessary or overly broad conditions that process large datasets.
    Indexes Use indexed columns in the WHERE clause to improve query performance. Don’t apply functions (e.g., UPPER(column_name)) directly on indexed columns as it negates indexing.
    Avoid Redundancy Simplify the conditions by removing duplicate or redundant checks. Don’t include unnecessary conditions that make queries harder to read and maintain.
    NULL Handling Use IS NULL or IS NOT NULL to handle null values explicitly. Don’t use = NULL or != NULL as it results in incorrect or no output.
    Logical Operators Use AND, OR, and NOT carefully to combine conditions effectively. Avoid excessive use of OR without considering alternative approaches like IN.
    Comparison Operators Use =, >, <,>=, and <= appropriately based on requirements. Avoid using vague conditions that can lead to performance overhead, such as !=.
    BETWEEN Use BETWEEN for range filtering to improve readability. Don’t misuse BETWEEN with improper boundaries, e.g., BETWEEN 10 AND 5 results in no rows.
    LIKE Use LIKE with % and _ for flexible string matching. Avoid starting LIKE patterns with % unless necessary, as it skips index usage.
    Joins and Subqueries Use subqueries and joins in the WHERE clause where applicable. Don’t use subqueries if joins or Common Table Expressions (CTEs) provide better performance.
    HAVING vs WHERE Use WHERE for filtering rows before grouping, and HAVING for filtering aggregated results. Don’t use WHERE to filter aggregate functions; use HAVING instead.
    Aliased Columns Use column aliases in the SELECT statement, not in the WHERE clause. Don’t use aliases directly in the WHERE clause, as they are not recognized at this stage.
    Data Types Ensure proper data type alignment between columns and literals in the WHERE clause. Don’t compare incompatible data types, which can cause errors or performance issues.
    Performance Combine multiple conditions logically to reduce unnecessary processing. Don’t overcomplicate queries by adding redundant conditions.
