Introduction to SQL

What is SQL?

  • SQL stands for Structured Query Language.
  • SQL is a domain-specific language used for managing and manipulating relational databases.
  • SQL allows you to perform operations such as querying, updating, and organizing data stored in structured tables in a database.
  • SQL is the backbone of Relational Database Management Systems (DBMS), like MySQL, PostgreSQL, and SQL Server.

What is a Database?

  • A Database is where information is stored on a computer. For example, it can store business data like sales or personal data like a contact list.

What is a DBMS?

  • Database Management System (DBMS) is the software that controls the database. It processes SQL commands and returns the requested data.
  • SQL operates on relational databases where data is stored in tables consisting of rows (records) and columns (attributes).

How is SQL Pronounced?

  • SQL is often pronounced as "sequel", but some people say "S.Q.L." Both are correct.

How Does SQL Works?

  • When you request data, SQL interacts with a database through a system called a Database Management System (DBMS). This process is called a database query.

Common Uses of SQL / Functions of SQL

  • Data Management : SQL excels in managing structured data, which is stored in rows and columns. It allows you to perform the below operations:
  • Retrieve Data: Pull specific data or information from the database when needed(queries).
  • Insert Data : Add new rows (records) to a table.
  • Update Data : Modify existing records in a table.
  • Delete Data : Delete specific records and entire data in a table.
  • Organize Data : SQL helps in structuring, sorting, and filtering data to make it meaningful.
  • Data Integrity : Ensuring that data stays accurate and protected from corruption using integrity constraints such as :Primary key,Foreign key, Unique constraint, Not Null constraint,Check constraint, etc.
  • Data Definition : Setting up the structure and relationships of data in the database.
  • Access Control : Restrict who can view or edit data.
  • Data Sharing : Allowing multiple users to work with the data without interfering with each other.

Ease of Use:

  • SQL is designed to be human-readable. SQL uses English-like commands (SELECT, FROM, WHERE), making it intuitive even for non-programmers.

Why Use SQL?

    Scalability:

    • SQL databases are designed to handle small-scale applications as well as massive enterprise-level systems.
    • Modern SQL databases, like Oracle, MySQL, and PostgreSQL, can manage terabytes of data efficiently.
    • Optimized Queries: Indexing and query optimization allow SQL to process queries on large datasets quickly.
    • Standardized Language: SQL is a standardized language (ISO/IEC 9075) with broad adoption.
    • Cross-Platform Compatibility: SQL syntax remains consistent across most relational database systems (e.g., MySQL, SQL Server, PostgreSQL).

    Industry Standard:

    • SQL’s widespread adoption means developers, analysts, and engineers can work with various databases without learning a new language for each system.

    Portability:

    • Applications developed using SQL can easily migrate from one database to another with minimal code changes.

Importance of SQL?

  • Data-Driven Decisions : SQL enables companies to make informed decisions by analyzing data effectively.
  • Automation : Automates repetitive data processing tasks.
  • Integration : Works seamlessly with multiple tools and applications.
  • Versatility : Used in analytics, app development, and system management.

How Does SQL Performin the Industry Today?

  • SQL remains a critical skill in the industry despite the rise of alternative tools like NoSQL databases.
  • Modern businesses rely on SQL for structured data management, especially in traditional databases.
  • SQL is integrated into data engineering, machine learning pipelines, and cloud platforms like AWS, Azure, and Google Cloud.
  • The SQL job market is robust, with demand for database administrators, data analysts, and backend developers.

Domains Where SQL is Used

  • Finance: Managing transactional records, fraud detection, and generating financial reports.
  • Healthcare: Storing and analyzing patient data, medical records, and hospital operations.
  • E-commerce: Inventory tracking, customer purchase patterns, and personalized recommendations.
  • Telecommunications: Call data records, customer relationship management, and network usage analysis.
  • Education: Student records, course management, and institutional reporting.
  • Entertainment: Managing streaming data, user preferences, and licensing.
  • Retail: Sales analysis, inventory control, and supply chain management.

Best Practices for Writing SQL Queries

  • SQL is case-insensitive, meaning ( SELECT and select ) are treated the same. However, it's a good practice to use uppercase for keywords (SELECT, FROM) and lowercase for table/column names.
  • Use Proper Statement Structure. A basic SQL query follows this structure
    • SELECT column_names
    FROM table_name
    WHERE condition
    GROUP BY column_names
    HAVING condition
    ORDER BY column_names;
  • Always end SQL statements with a semicolon to indicate the query is complete. This is required in some database systems like Oracle, PostgreSQL.
  • Use clear, meaningful names for tables and columns. Avoid spaces in names, instead, use underscores (_).
    • Good Practice: Avoid:
    employee_id, order_date id123, DateOfOrder
  • Use aliases to make column and table names more readable, especially in complex queries.
    • Example SELECT e.name AS employee_name, d.name AS department_name FROM employee e JOIN departments d ON e.dept_id = d.dept_id;
  • Identifiers can typically include letters, numbers, and underscores (_), but cannot include spaces or special characters like @, $, etc., unless enclosed in double quotes.
  • When filtering text or string data, always use single quotes (').
  • Avoid retrieving unnecessary rows. Use WHERE to limit the results.
  • Instead of using SELECT *, specify the columns you need. This improves performance and clarity.
  • Understand the different types of joins (INNER, LEFT, RIGHT, FULL) and use them appropriately to combine data from multiple tables.
  • Add comments for clarity, especially in complex queries. for Single-line comment use '--', and for Multi-line comment use /* This is sample query */
  • Always test your query on a smaller dataset to ensure accuracy before running it on the entire database.
  • Use proper indentation and line breaks to make queries easier to read and debug.
  • Handle NULL values explicitly in conditions to avoid unexpected results.(e.g., using IS NULL or IS NOT NULL) is important.

History of SQL: Key Milestones

  • 1970: Relational Model Concept Introduced - Dr. E.F. Codd, working at IBM, published a paper titled "A Relational Model of Data for Large Shared Data Banks." This paper introduced the concept of relational databases, laying the foundation for SQL.
  • 1974: SQL is Born - SQL was developed by Donald D. Chamberlin and Raymond F. Boyce at IBM. Initially called SEQUEL (Structured English Query Language), it was designed to interact with IBM's relational database system.
  • 1979: Commercialization of SQL - SQL was adopted as a standard by the American National Standards Institute (ANSI) and later by the International Organization for Standardization (ISO). This made SQL the official standard language for relational databases
  • 1986: SQL Standardization by ANSI - Call data records, customer relationship management, and network usage analysis.
  • 1989: SQL-89 (First Revision) - Minor enhancements and clarifications were made to the original SQL standard.
  • 1992: SQL-92 (Significant Enhancements) - Major features like joins, set operations, and integrity constraints were introduced. SQL-92 became widely adopted, forming the foundation of modern SQL.
  • 1999: SQL-99 (Object-Oriented Features) - Added support for object-oriented programming concepts, recursive queries, triggers, and advanced data types like arrays.
  • 2003: SQL:2003 (XML Support) - Introduced XML-related features to support data exchange and integration.
  • 2008: SQL:2008 (Dynamic Capabilities) - Enhanced features like triggers, improved error handling, and data definition capabilities.
  • 2011: SQL:2011 (Temporal Data Support) - Introduced features for handling temporal data, such as querying historical data.
  • 2016: SQL:2016 (JSON Support) - Added support for JSON (JavaScript Object Notation), making SQL more compatible with modern web and API development.
  • Today: Widespread Use and Integration - SQL continues to evolve with database vendors adding custom extensions (e.g., PL/SQL for Oracle, T-SQL for SQL Server). It remains a critical skill for data management, analytics, and application development.

SQL Data Types

What is Data Type?

A Data Type in SQL defines the type of data that a column can hold in a database table. It determines:

  • The kind of data: e.g: number,text/string, dates, or binary data, image, video
  • The Operations allowed: e.g: mathematical operations on numeric types or string functions on text types.
  • The storage requirements: The amount of memory allocated for each data value.

Why Are Data Types Important in SQL?

  • Data Integrity: Ensures only valid data is stored in a column. Example: a DATE column will reject invalid formats like "abc123".
  • Efficient Storage: Optimizes how data is stored and retrieved. Example: Using SMALLINT for small numbers uses less memory than INT.
  • Enhanced Query Performance: Reduces the processing time by matching data with the correct type. Example: Indexing works better when the right data type is used.
  • Logical Constraints: Helps enforce rules like a column only accepting positive numbers or specific text lengths.

Languages in SQL

Languages in SQL is a concept that refers to the classification of SQL commands into different categories based on their functionality. These categories, often called sublanguages, include Data Query Language (DQL), Data Definition Language (DDL), Data Manipulation Language (DML), Data Control Language (DCL), and Transaction Control Language (TCL). Below is a detailed explanation tailored for both beginners and expert-level users.


1. Data Query Language (DQL):

DQL statements can range from simple queries to complex multiple-clause commands. Here are the components

  • Basic Purpose : Used to fetch and query data from the database.
  • Key Command: SELECT
Advanced Use:
Components Purpose Example
Expressions Used to calculate or derive values dynamically. SELECT Price * Quantity AS TotalCost FROM ORDERS;
Clauses Specify the purpose or limits of a statement, like WHERE, GROUP BY, ORDER BY. SELECT ProductID, SUM(Sales) AS TotalSales FROM Sales GROUP BY ProductID ORDER BY TotalSales DESC;
Predicates Define conditions for filtering rows. SELECT CustomerID, customer_name FROM Customer WHERE Age > 30 AND City = 'Chicago';
Logical Connectives Combine multiple conditions (e.g: AND, OR, NOT). SELECT CustomerID, customer_name FROM Customer WHERE City = 'New York' OR City = 'Los Angeles';
Aggregate Functions Perform calculations across rows (e.g: SUM, AVG, COUNT). SELECT COUNT(*) AS TotalCustomers FROM Customer WHERE City = 'New York';
Subqueries Queries embedded within other queries. SELECT FirstName, LastName FROM Customer WHERE CustomerID IN ( SELECT CustomerID FROM Orders WHERE Total > 500);

2. Data Definition Language (DDL):

Purpose:

Data Definition Language (DDL) is a part of SQL used to create, modify, and delete database structures. It defines what the database will look like and how it will store information.

  • It deals with the core elements of a database, like tables, views, schemas, and catalogs.
  • Creates tables, databases, and other structures.
  • Changes or deletes existing database structures.
  • DDL commands define how data is stored and organized within a relational database.

Key Commands:

  • CREATE : Used to create new tables, schemas, views, or databases.
    CREATE TABLE Students (ID INT, Name VARCHAR(100), Age INT);
  • ALTER : Used to modify the structure of an existing table (e.g., add, remove, rename or change data type columns).
    ALTER TABLE Students ADD COLUMN Grade CHAR(1);
  • DROP: Used to delete tables, schemas, or databases when they are no longer needed.
    DROP TABLE Students;

Steps to Design a Database
Steps Example
Identify All Tables List all entities (like customers, products,sales, or orders) that need to be stored.
Define Columns for Each Table Specify the attributes each table should have (e.g., CustomerID, FirstName).
Assign a Primary Key Ensure each table has a unique identifier (e.g., CustomerID) to differentiate rows.
Establish Relationships Include common columns in related tables to create logical links between them.
Normalize the Data Structure the database to avoid duplication and anomalies by using third normal form (3NF) or better.
Document Everything Plan the design on paper first to avoid errors or inefficiencies.

    3. Data Manipulation Language (DML)

    Purpose :

    Data Manipulation Language (DML) is a subset of SQL used to manage and manipulate the actual data stored in a database.

    • DML is used to handle the actual data inside the database.
    • It helps you add, update, delete, or retrieve information.
    • Unlike DDL (Data Definition Language), which defines database structure, DML focuses on the contents within those structures.

    Why is DML Important in SQL?

    • DML bridges the gap between data storage and real-world application requirements.
    • It allows for the dynamic and interactive management of data, which is crucial for businesses, applications, and decision-making processes.

    Key Commands :

    • INSERT : Adds new rows of data to a table.
      INSERT INTO CUSTOMER (CustomerID, FirstName, LastName, City) VALUES (101, 'Yash', 'Man', 'New York');
    • UPDATE :Modifies existing data in a table.
      UPDATE CUSTOMER SET City = 'Los Angeles' WHERE CustomerID = 101;
    • DELETE :Removes specific rows of data from a table based on a condition.
      DELETE FROM CUSTOMER WHERE CustomerID = 101;
    • SELECT : Retrieves data from one or more tables. It is also subset of DQL.
      SELECT FirstName, LastName, City FROM CUSTOMER WHERE City = 'New York';

    Best Practices to Write DML Statements:

    • Break Down Complex Queries - Analyze and test components of complex queries step by step.
    • Use Conditions (WHERE) Thoughtfully - Prevent unintended data manipulation by always specifying conditions where needed.
    • Test Queries on Sample Data - Run queries on a small dataset before applying them to the entire database.
    • Comment Your Code - Use comments to explain logic for future reference.

    Note :Avoid Modifying Data Directly. Always take a backup before running UPDATE or DELETE commands.


    Importance of DML:


    • Data Interaction: Provides mechanisms to interact directly with data stored in relational databases.
    • Fine-Tuned Control: Enables precise control over what data to retrieve, update, or delete.
    • Dynamic Data Handling: Essential for applications that require real-time data updates and retrieval.

    4. Data Control Language (DCL)


    DCL Commands:
    Command Purpose Usage Example
    GRANT Assigns specific permissions or privileges to users or roles. Depends on user and department GRANT SELECT, INSERT ON Employees TO User1;
    REVOKE Removes previously granted permissions from users or roles. Depends on user and department REVOKE INSERT ON Employees FROM User1;

    Data Integrity and Security with DCL

    Preventing Data Corruption

    • SQL transactions ensure that operations are logged and can be rolled back in case of errors.
    • Logging minimizes risks during failures, as incomplete transactions can be undone.

    Managing Multi-User Environments

    • DCL restricts simultaneous conflicting operations by isolating user actions.
    • Example Problems Addressed:
      • Lost Updates: When one user's changes overwrite another's without knowledge.
      • Dirty Reads: When a user reads uncommitted changes made by another user.
      • Inconsistent Data: When changes are partially visible to other users.

    What is User Role?

    • user roles - are a way to group and manage permissions for multiple users within a database system. Instead of assigning permissions individually to each user, roles simplify the process by allowing database administrators to assign permissions to roles, and then assign those roles to users.
    • Authentication - Ensures that only authorized users can access the database.
    • Authorization - Controls what actions an authenticated user can perform.

    Advantages of Roles:

    • Centralized Access Control - Simplifies permission management by grouping users with similar access requirements.
    • Enhanced Security - Avoids granting excessive permissions directly to users.
    • Scalability - Easily add or remove users from a role as team compositions change.

    User Roles in few SQL Systems

      1. SQL Server
      • Predefined roles - db_owner, db_reader, db_writer.
      • Custom roles - Supported.
      2. Oracle
      • Supports roles with the CREATE ROLE command.
      • Example predefined roles: CONNECT, RESOURCE, DBA.
      3. PostgreSQL
      • Combines roles and users. Roles can log in if given login privileges.
      • Uses GRANT and REVOKE for role management.
      4. MySQL
      • Introduced roles in version 8.0.
      • Roles can be created, granted privileges, and assigned to users.
      5. MongoDB
      • Role-based access control (RBAC) system with built-in roles like read, readWrite, and custom roles.

    Advanced Features of DCL

    • Role Management - DCL allows grouping privileges into roles, which can be then assigned to users
    • Protection of Database Objects
      • Tables - Control who can see or modify data.
      • Columns - Restrict access to specific attributes.
      • Views - Grant access to derived / aggregated data.
      • Domains and Constraints - Protect schema-level objects like constraints and types.

    Types of Privileges: 1. Data Access Privileges
    Statement Operation
    GRANT SELECT Used to provide the privilege (or permission) for a user or role to retrieve data from a specific table or view. This allows the specified user or role to read the data but not modify it.
    REVOKE SELECT Used to remove the privilege (or permission) for a user or role to retrieve data from a specific table or view. This ensures that the specified user or role can no longer read the data.
    GRANT INSERT Used to provide the privilege (or permission) for a user or role to add new rows of data into a specific table or view. This allows the specified user or role to insert data but not necessarily view, update, or delete it.
    REVOKE INSERT Used to remove the privilege (or permission) for a user or role to insert new rows into a specific table or view. This ensures that the specified user or role cannot add new data to the table or view.
    GRANT UPDATE Used to provide the privilege (or permission) for a user or role to modify existing data in specific columns of a table or view. This allows the specified user or role to update data but does not permit inserting, deleting, or viewing data unless explicitly granted.
    REVOKE UPDATE Used to remove the privilege (or permission) for a user or role to modify existing data in specific columns of a table or view. This ensures that the specified user or role can no longer update the data.
    GRANT DELETE Used to provide the privilege (or permission) for a user or role to remove rows from a specific table or view. This allows the specified user or role to delete data but does not permit inserting, updating, or viewing data unless explicitly granted.
    REVOKE DELETE Used to remove the privilege (or permission) for a user or role to delete rows from a specific table or view. This ensures that the specified user or role can no longer remove data from the table or view.

    • A collation determines the rules for comparing and sorting strings of text, including case sensitivity, accent sensitivity, and language-specific ordering.

    2. Object Usage Privileges
    Statement Operation
    GRANT USAGE ON DOMAIN Used to grant a user or role the privilege to use a specific domain. By granting USAGE on a domain, the user or role is permitted to reference the domain in their operations, such as creating tables or defining columns using that domain. This privilege is useful for managing access to shared, standardized data types in a database.
    GRANT USAGE ON CHARACTER SET Used to grant a user or role the privilege to use a specific character set in the database. By granting USAGE on a domain, the user or role is permitted to reference the domain in their operations, such as creating tables or defining columns using that domain. This privilege is useful for managing access to shared, standardized data types in a database.
    GRANT USAGE ON COLLATION Used to grant a user or role the privilege to use a specific collation in the database. By granting USAGE on a collation, you allow the specified user or role to reference that collation when defining or altering database objects, such as columns, tables, or queries.
    GRANT USAGE ON TRANSLATION Used to grant a user or role the privilege to use a specific translation in the database. By granting USAGE on a translation, you permit the specified user or role to reference and apply the translation when performing operations that require character set conversion.
    REVOKE USAGE ON DOMAIN Used to remove the privilege (or permission) for a user or role to use a specific domain in the database. By revoking USAGE on a domain, you ensure that the specified user or role can no longer create or reference columns or objects based on that domain.
    REVOKE USAGE ON CHARACTER SET Used to remove the privilege (or permission) for a user or role to use a specific character set in the database. By revoking USAGE on a character set, you restrict the specified user or role from creating or modifying objects (such as tables or columns) that depend on that character set.
    REVOKE USAGE ON COLLATION Used to remove the privilege (or permission) for a user or role to use a specific collation in the database. By revoking USAGE on a collation, you restrict the specified user or role from applying that collation to database objects like tables, views, or columns.
    REVOKE USAGE ON TRANSLATION Used to remove the privilege (or permission) for a user or role to use a specific translation in the database. By revoking USAGE on a translation, the specified user or role is restricted from applying that translation to character data within the database.


    3. Object References Privileges
    Statement Operation Purpose Example
    GRANT REFERENCES Used to give a user or role the privilege to create foreign key constraints that reference a specific table or column. It allows user or Role to Define relationships between tables by referencing the primary or unique key of the table on which the privilege is granted. GRANT REFERENCES ON TableName TO UserName;
    REVOKE REFERENCES Used to remove the privilege of a user or role to create foreign key constraints that reference a specific table or column. Prevents the user or role from creating foreign key relationships that reference the specified table or column. REVOKE REFERENCES ON TableName FROM UserName;


    5. Transaction Control Language (TCL)

      Transaction Control Language (TCL) is a subset of SQL that manages transactions in a database. Transactions are sequences of SQL operations performed as a single logical unit of work. TCL commands ensure that these transactions maintain data integrity and consistency.

    Key Features

    • Atomicity - Ensures that all operations in a transaction are completed successfully. If any operation fails, the entire transaction is rolled back.
    • Consistency - Guarantees that a transaction brings the database from one valid state to another, maintaining defined rules and constraints.
    • Isolation - Ensures that transactions are executed independently of one another.
    • Durability - Once a transaction is committed, changes are permanent even in case of a system failure.

    TCL Commands
    Command Description Syntax
    COMMIT Saves all the changes made during the transaction permanently in the database. COMMIT;
    ROLLBACK Reverts all changes made during the current transaction, restoring the database to its previous state. ROLLBACK;
    SAVEPOINT Creates a checkpoint within a transaction to enable partial rollbacks. SAVEPOINT sp1;
    SET TRANSACTION Sets transaction properties like isolation levels. SET TRANSACTION READ ONLY;

    COMMIT

    • Use Case - Finalizing successful operations.
    • Example
      • BEGIN TRANSACTION;
      INSERT INTO Employees (ID, Name, Department) VALUES (1, 'Alice', 'HR');
      UPDATE Employees SET Department = 'Finance' WHERE ID = 1;
      COMMIT;
      In the above example:
      • The transaction inserts and updates records.
      • The COMMIT statement makes these changes permanent.

    ROLLBACK

    • Use Case - Used when errors occur or when a transaction must be aborted.
    • Example
      • BEGIN TRANSACTION;
      INSERT INTO Employees (ID, Name, Department) VALUES (2, 'Bob', 'IT');
      UPDATE Employees SET Department = 'Marketing' WHERE ID = 2;
      ROLLBACK;
      In the above example:
      • Any changes made by the INSERT and UPDATE statements are undone by ROLLBACK

    SAVEPOINT

    • Use Case - Used for partial rollback within a transaction.
    • Example
      • BEGIN TRANSACTION;
      INSERT INTO Employees (ID, Name, Department) VALUES (3, 'Charlie', 'Sales');
      SAVEPOINT sp1;
      UPDATE Employees SET Department = 'Operations' WHERE ID = 3;
      ROLLBACK TO sp1;
      COMMIT;
      In the above example:
      • The INSERT operation is saved with SAVEPOINT sp1.
      • The UPDATE operation is undone with ROLLBACK TO sp1.
      • The transaction is committed with only the INSERT operation.

    SET TRANSACTION

    • Use Case - Used to control how data modifications and reads interact in a multi-user environment.
    • Example
      • SET TRANSACTION READ ONLY;
      SELECT * FROM Employees WHERE Department = 'HR';
      In the above example:
      • The transaction is set to READ ONLY, ensuring no changes can be made to the data.

    Properties of Transactions

    TCL ensures that every transaction adheres to the ACID properties.

    Properties Description
    Atomicity Ensures that all operations in a transaction succeed or fail as a unit.
    Consistency Guarantees that a transaction leaves the database in a valid state.
    Isolation Ensures that transactions do not interfere with each other.
    Durability Ensures that committed changes persist, even in the event of a system crash.

    Real-World Use Cases

    Banking System

    • Transferring money between accounts involves multiple steps
      • Debit from one account.
      • Credit to another account.
    • TCL ensures that both steps succeed or fail as a unit to maintain consistency.

    E-Commerce Transactions

    • Processing an order involves:
      • Updating inventory.
      • Recording payment.
      • Generating invoices
    • Transactions ensure that all these steps are completed successfully, or none of them are applied.

    DML Manipulate data INSERT, UPDATE, DELETE
    DCL Manage access control GRANT, REVOKE
    TCL Manage transactions COMMIT, ROLLBACK, SAVEPOINT

    SELECT

    • Primarily used to fetch data from a database.
    • It allows you to retrieve specific rows and columns from a table or set of tables, and it can be executed in various ways to access data exactly as required.
    • It allows users to specify the data they want, how to format it, and even apply complex filters, transformations, and aggregations.

    Complete SELECT Syntax:

    SELECT column1, column2, column3, ...
    FROM table_name
    WHERE condition
    GROUP BY column
    HAVING condition
    ORDER BY column ASC|DESC
    LIMIT number;

    Key Components of SELECT

    Clause Description Use
    SELECT Specifies the columns to retrieve from the table.
    • Column names (e.g., SELECT Name, Age).
    • Aliases to rename columns for output (e.g., SELECT Fname AS FirstName)
    • Wildcards (*) to retrieve all columns.
    FROM Identifies the table(s) from which data is to be retrieved. You can use single table or multiple tables with Joins.
    WHERE Filters records from table based on a condition. Conditions can use comparison operators (=, >, <) and logical operators (AND, OR, NOT).
    GROUP BY Groups rows based on specified columns. Groups rows sharing a value in specified columns and applies aggregate functions like COUNT, SUM, or AVG.
    ORDER BY Sorts the result set by one or more columns . You can use either ascending (ASC) or descending (DESC).
    LIMIT Restricts the number of rows returned by the query (database-specific). How many rows you want, It Depends on Database

    Basic SELECT syntax:

    SELECT column1, column2, column3, ..
    FROM table_name;

    Note :You can use specific columns or ( * ) for all columns.


    Examples:

    1. Retrieve specific columns from a table

    SELECT First_name, Last_name,age
    FROM customer;

    2. Retrieving All Columns and Rows

    SELECT *
    FROM customer;

    Note :The asterisk symbol ( * ) is used to select all columns in a table.

    3. Filtering Data :- WHERE

    SELECT *
    FROM customer
    WHERE age >30;     Filtering data with specific columns SELECT Name,age,city
    FROM customer
    WHERE age > 30;

    4. Sorting Data

    SELECT *
    FROM employee
    ORDER BY age DESC;

    5. Aggregating Data and Grouping

    SELECT Department, COUNT(*) AS Empcount
    FROM employee
    GROUP BY Department ;

    6. Using Constants in SELECT

    SELECT first_name, last_name, 'Active' AS status
    FROM employee;


    Best Practices for Using SELECT

    • Use specific column names instead of * for better performance.
    • Index columns used in WHERE, JOIN, and ORDER BY clauses for faster queries.
    • Use aliases (AS) for better readability.
    • Avoid unnecessary joins and subqueries; they can degrade performance.
    • Use aggregate functions with GROUP BY to summarize data efficiently.
    • Use LIMIT or equivalent clauses to prevent fetching excessive data.

    CREATE Table

    • The CREATE TABLE statement in SQL is used to define a new table within a database.
    • It specifies the table’s structure, including its columns, data types, constraints, and default values.
    • Creating tables carefully with a well-thought-out design is crucial because it forms the foundation of a database's schema and ensures that data is stored, managed, and queried effectively.
    Note : Each SQL database (like Oracle, SQL Server, and MySQL) has its own set of supported data types, with slight variations in syntax, but the core purpose and functionality remain consistent.

    Sample tables and Datasets are Available at Resources


    Basic Syntax

    CREATE TABLE table_name (
    column1 Datatype constraint ,
    column2 Datatype constraint ,
    column3 Datatype ,
    column4 datatype ,
    ...........
    ) ;

    Examples of CREATE TABLE

    1. Creating a Simple Table Without Constraints

    CREATE TABLE employee (
    emp_id INT ,

    last_name VARCHAR(15) ,

    2. Creating a Table with Constraints and Default Values

    Oracle:

    last_name VARCHAR2(15) NOT NULL,
    DOB DATE DEFAULT SYSDATE,

    last_name VARCHAR(15) NOT NULL,

    8. Best Practices for Using CREATE TABLE

    1. Define Primary and Foreign Keys

    • Always define PRIMARY KEY constraints on tables for unique row identification, and use FOREIGN KEY constraints for establishing relationships between tables. This ensures data integrity.

    2. Choose Appropriate Data Types

    • Choose data types that match the data as closely as possible.
    • Avoid large data types if not needed (e.g., using VARCHAR(50) for short text fields instead of VARCHAR(255)).
    • Numeric columns should have sufficient precision but should be as compact as possible.

    3. Use Constraints to Enforce Data Integrity

    • Use NOT NULL on columns that require values.
    • UNIQUE constraints can enforce uniqueness.
    • CHECK constraints validate column values within specific ranges or conditions.

    4. Consider Default Values

    • Default values simplify data entry and can serve as placeholders when data is missing or optional.
    • Avoid hard-coding dates as defaults; use system functions like SYSDATE, GETDATE(), or CURRENT_DATE.

    5. Naming Conventions

    • Use consistent naming conventions for table and column names (e.g., snake_case or camelCase) to enhance readability.
    • Prefix foreign key columns with the table name they reference (e.g., department_id instead of just id).

    9. Do’s and Don’ts When Using CREATE TABLE

    Do's :-

    • Do document your schema : Add comments on tables and columns for clarity (some databases support COMMENT for this).
    • Do plan for scalability : Choose a table design that can accommodate potential growth.
    • Do optimize for indexing: When possible, design tables with columns that can efficiently support indexing.

    Don'ts :-

    • Don’t use overly large data types: Avoid VARCHAR(MAX) or TEXT unless necessary; they can hinder performance.
    • Don’t ignore normalization : Properly normalize data to avoid redundancy and potential anomalies in data storage.
    • Don’t mix data types: Avoid columns where inconsistent types are stored, like mixing text and numbers, to maintain data consistency.
