Between

The BETWEEN operator is used to filter query results where a value falls within a specified range, including the boundary values.


It simplifies range-based filtering and works with numerical, date, and text data types.


you can also use BETWEEN with SELECT , UPDATE, DELETE, and CASE statements.


Key Features of BETWEEN

1. Inclusive of Boundary Values :

    • The BETWEEN operator includes both the start and end values of the range.

2. Simplifies Range Queries :

    • It provides a cleaner way to query ranges compared to using >= and <=.

3. Supports Numbers, Dates, and Text :

    • Works with numerical values, dates, and strings.

4. Case-Sensitive for Text (Varies by Database) :

    • Behavior for text comparisons depends on collation settings.

Basic Syntax

SELECT column1, column2
FROM table_name
WHERE column_name BETWEEN value1 AND value2 ;

Using NOT BETWEEN:

SELECT column1, column2
FROM table_name
WHERE column_name NOT BETWEEN value1 AND value2 ;

Key Points for BETWEEN

1. Inclusive :The range includes both value1 and value2.


2. Works with Numeric, Date, and Text Data :Suitable for various data types.


3. Simplifies Range Queries :Equivalent to using >= and <= conditions together.


4. Case Sensitivity :For text data, behavior depends on the database (e.g., case-sensitive by default in Oracle).


Basic Scenarios

1. Numerical Range

Scenario :- Retrieve employees with salaries between 30,000 and 60,000.

SELECT employee_id, first_name, salary
FROM employees
WHERE salary BETWEEN 30000 AND 60000 ;

Equivalent Query Using Logical Operators:

SELECT employee_id, first_name, salary
FROM employees
WHERE salary >= 30000 AND salary <= 60000 ;

2. Date Range

Scenario :- Retrieve orders placed between January 1, 2024, and March 31, 2024.

SELECT order_id , order_date , customer_id
FROM orders
WHERE order_date BETWEEN '2024-01-01' AND '2024-03-31' ;

3. Text Range

Scenario :- Retrieve products whose names fall alphabetically between 'A' and 'M'.

SELECT product_id, product_name
FROM products
WHERE product_name >= 'A' AND product_name <= 'M' ;

4. NOT BETWEEN

Scenario :- Retrieve customers whose credit limits are not between 5000 and 20000.

SELECT customer_id, customer_name, credit_limit
FROM customers
WHERE credit_limit NOT BETWEEN 5000 AND 20000 ;

5. BETWEEN with Dates and Times

Scenario :- Retrieve events scheduled between '01-11-2024 08:00:00' and '15-11-2024 18:00:00'.

SELECT event_id, event_name, event_datetime
FROM events
WHERE event_datetime BETWEEN '2024-11-01 08:00:00' AND '2024-11-15 18:00:00' ;

6. BETWEEN with Subqueries

Scenario :- Retrieve products with prices within the range of the minimum and maximum prices of a specific category.

SELECT product_id, product_name, price
FROM products
WHERE price BETWEEN
    ( SELECT MIN(price) FROM products WHERE category_id = 1 )
    AND
    ( SELECT MAX(price) FROM products WHERE category_id = 1 ) ;

7. BETWEEN with Negative Numbers

Scenario :- Retrieve employees whose performance scores are between -10 and 10.

SELECT employee_id, first_name, performance_score
FROM employees
WHERE performance_score BETWEEN -10 AND 10 ;

8. BETWEEN with UPDATE Statement

Scenario :- Update customer statuses based on credit limits within a range.

UPDATE customers
SET status = 'Preferred'
WHERE credit_limit BETWEEN 10000 AND 50000 ;

9. BETWEEN with DELETE Statement

Scenario :- Delete orders placed within a specific date range.

DELETE FROM orders
WHERE order_date BETWEEN '2024-01-01' AND '2024-06-30' ;

Advanced Scenarios

1. BETWEEN in INSERT INTO SELECT Statement

Scenario :- Insert sales records for a specific period into a historical archive table.

INSERT INTO sales_archive ( sale_id, sale_date, amount )
SELECT sale_id, sale_date, amount
FROM sales
WHERE sale_date BETWEEN '2024-01-01' AND '2024-12-31' ;

2. BETWEEN in CASE Expression

Scenario :- Assign rating tiers based on sales revenue ranges.

SELECT sale_id, revenue,
    CASE
      WHEN revenue BETWEEN 0 AND 1000 THEN 'Low'
      WHEN revenue BETWEEN 1001 AND 5000 THEN 'Medium'
      WHEN revenue BETWEEN 5001 AND 10000 THEN 'High'
      ELSE 'Very High'
    END AS revenue_tier
FROM sales ;

3. BETWEEN in JOIN Conditions

Scenario :- Retrieve overlapping bookings between two tables.

SELECT b1.booking_id, b2.booking_id
FROM bookings b1
JOIN bookings b2 ON b1.start_date BETWEEN b2.start_date AND b2.end_date
WHERE b1.booking_id != b2.booking_id ;

4. BETWEEN in HAVING Clause

Scenario :- Filter grouped data based on aggregate values.

SELECT department_id, SUM( salary ) AS total_salary
FROM employees
GROUP BY department_id
HAVING SUM( salary ) BETWEEN 500000 AND 1000000 ;

Complex Scenarios

1. Combining BETWEEN with Window Functions

Scenario :- Retrieve sales transactions within the middle 50% (quartiles) of total sales.

WITH SalesRank AS (
    SELECT TransactionID, Amount,
      PERCENT_RANK() OVER ( ORDER BY Amount) AS PercentRank
    FROM Sales
)
SELECT TransactionID, Amount
FROM SalesRank
WHERE PercentRank BETWEEN 0.25 AND 0.75 ;

2. Handling Overlapping Date Ranges

Scenario :- Identify events that overlap a given date range ( e.g., July 1, 2023, to July 10, 2023 ).

SELECT EventID, EventName, StartDate, EndDate
FROM Events
WHERE StartDate BETWEEN '2023-07-01' AND '2023-07-10'
    OR EndDate BETWEEN '2023-07-01' AND '2023-07-10'
    OR ( '2023-07-01' BETWEEN StartDate AND EndDate )
    OR ( '2023-07-10' BETWEEN StartDate AND EndDate ) ;

Comparison with Other Operators

Aspect BETWEEN >= and <= IN
Syntax Compact and readable Longer but explicit Limited to discrete values
Boundary Inclusion Includes boundaries Depends on operator N/A
Use Case Ranges (e.g., salary, dates) Ranges or open intervals Specific values

Common Errors with BETWEEN

1. Invalid Ranges:

    • Using BETWEEN with value1 > value2 results in no rows being returned.
WHERE Score BETWEEN 100 AND 50 ; - - Incorrect

2. Boundary Issues:-

    • Forgetting inclusiveness. If you need exclusive boundaries, use > and <.

3. Data Type Mismatch:-

    • Applying BETWEEN on incompatible data types like BLOB or unparsed JSON.

4. Incorrect Date Formats:-

    • Ensure the dates are formatted correctly as per the database engine.

Best Practices for BETWEEN

1. Index the Column:-

    • Ensure the column used in BETWEEN has an index for efficient querying.

2. Combine with Logical Operators:-

    • Enhance BETWEEN with AND/OR for more complex conditions.

3. Use Functions with Care:-

    • Avoid wrapping columns in functions (e.g., YEAR(OrderDate) BETWEEN) as it may prevent index usage.

4. Use with Aggregation:-

    • Leverage BETWEEN in HAVING for post-aggregation filtering.

5. Date and Time Handling:-

    • Be explicit with date formats to avoid unintended results, especially with timestamps.

6. Avoid Overlapping Ranges:-

    • Ensure ranges used in queries do not unintentionally overlap, which could lead to duplicate results.

7. Collation and Case Sensitivity:-

    • For text ranges, be aware of the database's collation settings, as they affect sorting and comparison.
