CASE

The CASE statement is a conditional expression that allows you to add IF-THEN-ELSE logic within SQL queries.


It evaluates a series of conditions and returns a value when the first condition is met. If no conditions are met, it returns a default value specified by an optional ELSE clause.


Key Characteristics

1. Conditional Logic:- Enables dynamic decision-making within SQL queries.


2. Supports Multiple Statements:- Can be used in SELECT, WHERE, GROUP BY, HAVING, ORDER BY, UPDATE, and more.


3. Inline Computation:- Simplifies conditional transformations of data directly in queries.


Syntax

1. Simple CASE Expression

CASE expression
    WHEN value1 THEN result1
    WHEN value2 THEN result2
      .
      .
      .
    ELSE default_result
END
  • Expression : The column or calculation to evaluate.
  • WHEN value THEN result : Specifies the condition and its output.
  • ELSE: Specifies the default result if no conditions are met.
  • END: Marks the end of the CASE statement.

2. Searched CASE Expression

CASE
    WHEN condition1 THEN result1
    WHEN condition2 THEN result2
      .
      .
      .
    ELSE default_result
END
  • Condition : A logical condition that evaluates to TRUE or FALSE.

Basic Examples

1. Simple CASE in SELECT

SELECT EmployeeID, Name,
    CASE JobTitle
      WHEN 'Manager' THEN 'Executive'
      WHEN 'Developer' THEN 'Technical Staff'
      ELSE 'Other'
    END AS RoleCategory
FROM Employees ; - - If JobTitle is 'Manager', the result is 'Executive'; for 'Developer', it's 'Technical Staff'.
- - Default is 'Other'.

2. Searched CASE

Scenario 1 :- Evaluates salary ranges and assigns categories accordingly.

SELECT EmployeeID, Name,
    CASE
      WHEN Salary > 50000 THEN 'High'
      WHEN Salary BETWEEN 30000 AND 50000 THEN 'Medium'
      ELSE 'Low'
    END AS SalaryCategory
FROM Employees ;

Scenario 2:- Assign grades based on a score.

SELECT student_name, Score,
    CASE
      WHEN score >= 90 THEN 'A'
      WHEN score >= 80 THEN 'B'
      WHEN score >= 70 THEN 'C'
      ELSE 'F'
    END AS grade
FROM Students ;

3. Use in WHERE Clause

Scenario :- Filter employees based on conditional criteria.

SELECT employee_id, name, salary
FROM employees
WHERE
    (department_name = 'HR' AND salary > 40000)
    OR (department_name = 'IT' AND salary > 60000 )
    OR (department_name NOT IN ('HR','IT') AND salary > 30000);

4. Use in ORDER BY Clause

Scenario :- Sort products dynamically based on conditions.

SELECT product_id, product_name, category
FROM products
ORDER BY
    CASE
      WHEN category = 'Electronics' THEN 1
      WHEN category = 'Furniture' THEN 2
      ELSE 3
    END ;

5. Use in GROUP BY Clause

Scenario :- Group sales by dynamic ranges.

SELECT
    CASE
      WHEN total_sales < 500 THEN 'Low Sales'
      WHEN total_sales BETWEEN 500 AND 1000 THEN 'Medium Sales'
      ELSE 'High Sales'
    END AS sales_range, COUNT( * ) AS num_orders
FROM sales
GROUP BY
    CASE
      WHEN total_sales < 500 THEN 'Low Sales'
      WHEN total_sales BETWEEN 500 AND 1000 THEN 'Medium Sales'
      ELSE 'High Sales'
    END ;

6. Use in HAVING Clause

Scenario :- Filter aggregated results based on conditions.

SELECT department_id, AVG(salary) AS avg_salary
FROM employees
GROUP BY department_id
HAVING
    (department_id = 1 AND AVG(salary) > 50000)
    OR (department_id<>1 AND AVG(salary) > 30000);

7. Use in UPDATE Statement

Scenario :- Update employee bonuses based on their department.

UPDATE employees
SET bonus = CASE
      WHEN department_name = 'HR' THEN salary * 0.1
      WHEN department_name = 'IT' THEN salary * 0.15
      ELSE salary * 0.05
    END ;

8. Use in DELETE Statement

Scenario :- Delete records based on dynamic criteria.

DELETE FROM employees
WHERE
    ( department_name = 'Sales' AND salary < 40000)
    OR( department_name = 'Marketing' AND salary < 30000)
    OR ( department_name NOT IN ('sales','Marketing') AND salary < 20000);

Advanced Scenarios

1. Conditional Joins

Scenario :- Use CASE in join conditions for dynamic relationships.

SELECT a.order_id, b.customer_name
FROM orders a
LEFT JOIN customers b ON (a.region = 'North' AND a.customer_id = b.customer_id)
OR (a.region <>'North' AND a.customer_id = b.backup_customer_id);

2. Pivoting Data

Scenario :- Transform rows into columns using CASE.

SELECT product_id,
      SUM( CASE WHEN region = 'North' THEN sales ELSE 0 END ) AS north_sales,
      SUM( CASE WHEN region = 'South' THEN sales ELSE 0 END ) AS south_sales
    FROM sales
    GROUP BY product_id ;

3. Generating Flags

Scenario :- Create flags for conditional monitoring or reporting.

SELECT order_id,
    CASE
      WHEN delivery_date < CURRENT_DATE THEN 'Late'
      WHEN delivery_date = CURRENT_DATE THEN 'On Time'
      ELSE 'Scheduled'
    END AS delivery_status
FROM Orders ;

4. Handling NULLs with CASE

Scenario :- Categorize employee salaries, including handling NULL values.

SELECT EmployeeID, Name, Salary,
    CASE
      WHEN Salary IS NULL THEN 'Not Provided'
      WHEN Salary > 100000 THEN 'High'
      WHEN Salary BETWEEN 50000 AND 100000 THEN 'Medium'
      ELSE 'Low'
    END AS SalaryCategory
FROM Employees ;

Common Errors with CASE

  • Missing END:- Forgetting the END keyword results in syntax errors.
  • Non-Exhaustive Cases:- If ELSE is not included, unmatched cases return NULL.
  • Data Type Mismatch:- Ensure all THEN results have compatible data types. Mixed types (e.g., numeric and string) can cause errors.
  • Ignoring NULLs :-If NULL is not explicitly handled, rows with NULL values will return NULL, leading to unexpected results.

Do's and Dont's with CASE

Do's

  • Use meaningful labels for CASE results to improve readability.
  • Leverage CASE to reduce the need for multiple queries or application-side processing.
  • Order conditions from most to least likely for performance optimization.

Don'ts

  • Avoid excessive nesting; split logic into multiple queries if necessary.
  • Don’t use CASE when simpler SQL constructs like IF or COALESCE suffice.
  • Avoid ambiguous conditions that might lead to multiple matches.

Challenges

  • Debugging:- Debugging multi-level CASE statements can be tricky.
  • Complexity:- Can lead to complex and unreadable queries if overused.
  • Database-Specific Differences:- Some databases may have slight variations in syntax or limitations on using CASE.
