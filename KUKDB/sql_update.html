UPDATE

The UPDATE statement is Data Manipulation Language (DML) command, it is used to modify existing data in one or more rows within a table.


UPDATE statement is used to


  • Modifying values in specific columns.
  • Changing one or more rows based on conditions.
  • Updating data across multiple columns in a single command.

Basic Syntax

UPDATE table_name
SET column1 = value1 , column2 = value2, . . .
WHERE condition ;

Examples

1. Update a Specific Row :-

  • Update the department for the employee with employee_id 101.
UPDATE employee
SET department_name = 'Marketing'
WHERE employee_id = 101 ;

2. Updating Multiple Rows Based on a Condition :-

  • Increase the salary by 10% for all employees in the IT department.
UPDATE employee
SET salary = salary * 1.10
WHERE department_name = 'IT' ;

3. Updating Multiple Columns at Once :-

  • Update both last_name and department for a specific employee with employee_id 102.
UPDATE employee
SET last_name = 'Jack' , department_name = 'IT'
WHERE employee_id = 102 ;

4. Updating All Rows in a Table :-

  • Update column status with active value for all rows at once.
UPDATE employee
SET status = 'Active' ;

  • Set the LoginAttempts column to 0 for all users.
UPDATE Users
SET LoginAttempts = 0 ;
NOTE : - Be cautious when using UPDATE without a WHERE clause, as it will affect all rows in the table.

5. Updating Geographic Data

  • Scenario : Update city names to their standard forms in the Addresses table.
UPDATE Addresses
SET City = 'New York'
WHERE City IN ( 'NYC', 'New York City', 'Big Apple' ) ;

Advanced Use Cases for UPDATE :-

1. Using Calculations

  • Increase the price of all products by 10%.
UPDATE Products
SET Price = Price * 1.10 ;

2. Using UPDATE with RETURNING Clause (PostgreSQL and Oracle)

  • In PostgreSQL and Oracle, the RETURNING clause allows you to capture the values that were updated.
  • Scenario : Update all employees salary for the department HR, and return empID and new salary for each row that was updated.
UPDATE employee
SET salary = salary * 1.10
WHERE department_name= 'HR'
RETURNING empID, salary ;

3. Using JOIN in UPDATE Statements (SQL Server and MySQL)

  • Scenario : Update the price of products in the Inventory table to match the corresponding price in the Products table.

Query in SQL Server

UPDATE i
SET i.price = p.price
FROM Inventory i
INNER JOIN Products p
ON i.product_id = p.product_id ;

Query in MySQL

UPDATE Inventory i
INNER JOIN Products p ON i.product_id = p.product_id
SET i.price = p.price ;

4. Update using Subqueries

  • Scenario 1 : Set the salary of employees based on the average salary in their department.
UPDATE employees e
SET salary = (
SELECT AVG(e1.Salary)
FROM Employees e1
WHERE e1.DepartmentID = e.DepartmentID ) ;

  • Scenario 2 : Update department for the employee with employee_id 103 based on the department value from the departments table.
UPDATE employees e
JOIN department d ON e.department_id=d.department_id
SET e.department_name=d.department_name
WHERE e.employee_id=103 AND department_id = 3 ;

5. Bulk Updates Using Ranges

  • Scenario : Increase the price by 5% for products priced $50 and $100.
UPDATE Products
SET Price = Price * 1.05
WHERE Price BETWEEN 50 AND 100 ;

6. Conditional Updates Based on Aggregate Functions

  • Scenario : Update employee bonuses based on department performance. Set a higher bonus for employees in departments with average sales above $1M.
UPDATE Employees
SET Bonus = 1000
WHERE dept_id IN (
SELECT dept_id FROM Sales
GROUP BY dept_id
HAVING SUM(SalesAmount) > 1000000) ;

7. Updating Data with NULL Handling

  • Scenario : Fill missing data with default values. Replace NULL values in the Phone column with 'Not Provided'.
UPDATE Customers
SET Phone = 'Not Provided'
WHERE Phone IS NULL ;

8. Updating Data Using Patterns - using String Functions

  • Scenario : Replace all email domains from @oldmail.com to @newmail.com.
UPDATE Customers
SET Email = REPLACE ( Email, '@oldmail.com', '@newmail.com' )
WHERE Email LIKE '%@oldmail.com' ;

9. Update with Case Sensitivity using Character Function

  • Scenario : Change all customer's first name to uppercase.
UPDATE Customers
SET FirstName = UPPER ( FirstName ) ;

10. Archival or Flagging for Deletion

  • Scenario : Set the Status to 'Inactive' for users who haven’t logged in for over a year.
UPDATE users
SET Status = 'Inactive'
WHERE LastLogin < DATEADD( YEAR , -1, GETDATE() ) ;

11. Data Obfuscation for Testing - using String & Convert functions

  • Scenario : Replace customer phone numbers with dummy data.
UPDATE Customers
SET Phone = CONCAT( '555-' , LPAD( CAST( customer_id AS CHAR ), 4 , '0' ) ) ;

12. Using CASE in UPDATE Statements (SQL Server and MySQL)

  • Scenario 1 : Update the salaries of employees as follows:.
    • Employees with an "Excellent" rating receive a 20% salary increment.
    • Employees with a "Good" rating receive a 10% salary increment
    • Other employees receive no increment

Query in SQL Server

UPDATE e
SET e.salary = CASE
    WHEN p.rating = 'Excellent' THEN e.salary * 1.20
    WHEN p.rating = 'Good' THEN e.salary * 1.10
    ELSE e.salary
END
FROM employees e
INNER JOIN performance p ON e.employee_id = p.employee_id ;

Query in MySQL

UPDATE employees e
INNER JOIN performance p
ON e.employee_id = p.employee_id
SET e.salary = CASE
    WHEN p.rating = 'Excellent' THEN e.salary * 1.20
    WHEN p.rating = 'Good' THEN e.salary * 1.10
    ELSE e.salary
END ;

  • Scenario 2 : Update customer categories based on their total spending.
UPDATE Customers
SET Category = (
    CASE
      WHEN
      (
      SELECT SUM (TotalAmount)
      FROM Orders
      WHERE       Orders.CustomerID = Customers.CustomerID
      ) > 1000
      THEN 'Gold'
      ELSE 'Silver'
    END
) ;

  • Scenario 3 : Update discount for products based on their stock and sales Rank.
UPDATE Products
SET Discount = CASE
      WHEN Stock < 50 THEN Price * 0.10
      WHEN SalesRank <= 10 THEN Price * 0.20
      ELSE Price * 0.05
    END ;

Common Errors

  • Updating All Rows Unintentionally : -Missing a WHERE clause will update every row in the table.
  • Invalid Data Types : -Mismatching column types with the new value.
  • Constraint Violations : -Updates that violate FOREIGN KEY, UNIQUE, or NOT NULL constraints.

Do’s and Don’ts When Using UPDATE

Do's :-

  • Do backup important tables or test updates on a copy, especially if the update is complex.
  • Do use the WHERE clause Carefully Avoid updating all rows unintentionally by always specifying a WHERE clause unless you intend to update every row.
  • Do use transactions For critical updates, especially ones affecting multiple rows, wrap the UPDATE in a transaction. This allows you to rollback changes in case of an error.
  • Do review with SELECT first : - Run a SELECT query with the same WHERE clause to preview the rows that will be affected. This helps verify that only the intended rows are updated.
  • Do Limit UPDATES in large tables : - For large tables, consider updating in smaller batches to avoid performance issues. Adding a WHERE clause with conditions or limiting the number of rows in each transaction.

Don'ts :-

  • Don’t rely on implicit order of columns when not specifying column names, as this can lead to errors if the table structure changes.
  • Don’t hard-code primary key values (like employee_id) if the column is set to auto-increment or has unique constraints, as this may cause conflicts.
  • Don’t insert unvalidated or incomplete data - Ensure data integrity by validating inputs before adding rows.
