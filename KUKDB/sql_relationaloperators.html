Relational Operators in SQL

  • Relational operators (also known as comparison operators) are used to compare two values or expressions.
  • They form the backbone of conditions in SQL queries, allowing the filtering, matching, and comparison of data.
  • These operators return a Boolean result (TRUE, FALSE, or NULL) and are most commonly used in the WHERE clause, JOIN conditions, or filtering data.

List of Relational Operators :-

Operator Description Example
= Checks if two values are equal. column = 10
!= or <> Checks if two values are not equal. column != 10 or column <> 10
< Checks if the left value is less than the right. column < 10
> Checks if the left value is greater than the right. column > 10
<= Checks if the left value is less than or equal to the right. column <= 10
>= Checks if the left value is greater than or equal to the right. column >= 10

Basic Syntax

SELECT column1 , column2
FROM table_name
WHERE column1 < operator > value ;

Examples of Each Operator

1. = (Equal to Operator)

Scenario :- Retrieves all employees who belong to department 10.

SELECT *
FROM employees
WHERE Salary = 50000 ;

2. Inequality ( != or <> )

Scenario :- Find all products not in the category "Electronics."

SELECT ProductID , Name , Category
FROM Products
WHERE Category <> 'Electronic' ;
    - - or
SELECT ProductID , Name , Category
FROM Products
WHERE Category != 'Electronic' ;

3. Greater Than ( > )

Scenario :- Get customers whose age is greater than 30.

SELECT CustomerID , Name , Age
FROM Customers
WHERE Age > 30 ;

4. Less Than ( < )

Scenario :- Find orders with a total amount less than $100.

SELECT OrderID , TotalAmount
FROM Orders
WHERE TotalAmount < 100 ;

5. <= ( Less Than or Equal to Operator )

Scenario :- Retrieves all employees earning 50,000 or less.

SELECT *
FROM employees
WHERE salary <= 50000 ;

6. >= ( Greater Than or Equal to Operator )

Scenario :- Retrieves all orders with a total amount of 1,000 or more.

SELECT *
FROM orders
WHERE total_amount >= 1000 ;

7. NULL Check ( IS NULL, IS NOT NULL )

Relational operators return NULL if one of the values being compared is NULL. Use the IS NULL or IS NOT NULL operators to handle NULL explicitly.


Scenario :- List all orders without a shipping address.

SELECT OrderID , CustomerID
FROM Orders
WHERE ShippingAddress IS NULL ;

Combining Relational Operators

    You can combine relational operators with logical operators like AND, OR, and NOT to create complex conditions.

Scenario :- Retrieves employees in department 10 whose salary exceeds 60,000.

SELECT *
FROM employees
WHERE department_id = 10 AND salary > 60000 ;

Advanced Scenarios

1. Using BETWEEN

Retrieve products priced between $50 and $200.

SELECT ProductID , Name , Price
FROM Products
WHERE Price BETWEEN 50 AND 200 ;

2. Using IN

Get employees working in departments 10, 20, or 30.

SELECT EmployeeID , Name , DepartmentID
FROM Employees
WHERE department_id IN ( 10 , 20 , 30) ;

3. Using LIKE for Pattern Matching.

Find customers whose names start with "A.".

SELECT CustomerID , Name
FROM Customers
WHERE Name LIKE ' A% ' ;

% matches zero or more characters.
_ matches exactly one character.

4. Combining Relational Operators with AND/OR.

Find products priced above $100 but below $500 and belong to the "Electronics" category.

SELECT ProductID , Name , Price , Category
FROM Products
WHERE Price > 100 AND Price < 500 AND Category = ' Electronics ' ;

5. Using Subqueries with Relational Operators.

List employees whose salary is higher than the average salary.

SELECT EmployeeID , Name , Salary
FROM Employees
WHERE Salary > ( SELECT AVG( Salary ) FROM Employees ) ;

Real-World Scenarios

1. Customer Retention: High-Spenders.

Retrieve customers who spent more than $10,000 but not more than $50,000 in the last year.

SELECT CustomerID , Name , TotalSpent
FROM Customers
WHERE TotalSpent BETWEEN 10000 AND 50000 ;

2. Inventory Management: Stock Levels.

List all products with low stock (less than 20 units) or no stock at all.

SELECT ProductID , Name , Stock
FROM Products
WHERE Stock < 20 OR Stock IS NULL ;

3. Fraud Detection: Unusual Transactions.

Identify transactions with amounts greater than 3 times the average transaction amount.

SELECT TransactionID , CustomerID , Amount
FROM Transactions
WHERE Amount > ( SELECT AVG( Amount ) * 3 FROM Transactions ) ;

4. Marketing Campaign: Targeted Customers.

Find customers with names ending in "son" (e.g., "Johnson," "Anderson") for a targeted campaign.

SELECT CustomerID , Name
FROM Customers
WHERE Name LIKE ' %son ' ;

Do’s and Don’ts When Using ORDER BY

Do's :-

  • Understand Data Types : Ensure that the data types of both operands in the relational operation are compatible.Use explicit conversions if necessary.
  • Handle NULL Values Explicitly : Use IS NULL or IS NOT NULL when working with nullable columns. Relational operators return NULL when compared to NULL.
  • Use Indexes for Columns in Relational Conditions: Use indexed columns in relational operators to improve query performance.
  • Combine Relational Operators with Logical Operators Thoughtfully: Use AND, OR, and NOT for complex filtering while maintaining readability.
  • Use Boundaries Appropriately : Specify inclusive or exclusive boundaries clearly in range queries.
  • Test Queries for Accuracy : Validate queries with sample data to ensure correct results, especially when combining multiple relational operators.

Don'ts :-

  • Don’t Compare Incompatible Data Types: Avoid comparing values of different types (e.g., string vs. number), as it may lead to implicit conversion or errors.
  • Don’t Overuse Wildcards in Filtering :- Avoid using broad conditions with relational operators when more specific filters are available.
  • Don’t Overcomplicate Queries : Avoid overly complex relational conditions that make queries hard to read and maintain.
  • Don’t Assume Relational Operators Work with All Data Types : Avoid using relational operators on unsupported or complex data types like JSON or XML.
  • Don’t Ignore Query Optimization : Avoid writing queries without considering performance. For instance, filtering large datasets without indexes will result in slower execution.
