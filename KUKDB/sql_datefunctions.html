Date Functions

SQL provides a variety of date functions to work with date and time data.


These functions allow you to manipulate, format, and extract information from date values effectively.


Date Functions Overview

Function Purpose Description Syntax Uses Limits
CURRENT_DATE Returns the current date without time. Retrieves the system's current date in YYYY-MM-DD format. CURRENT_DATE Use for inserting timestamps or comparing current date. Cannot include time; only date is returned.
GETDATE() Returns current date and time. Retrieves the system's current date and time, typically in YYYY-MM-DD HH:MM:SS format. GETDATE() Use for logging, auditing, or real-time calculations. Varies slightly by database (SQL Server-specific).
DATEADD() Adds a specific interval to a date. Adds or subtracts a specified time interval (e.g., days, months, years) to a given date. DATEADD(interval, number, date) Adjusting schedules or creating future/past dates. Not supported by some databases (like MySQL).
DATEDIFF() Calculates the difference between two dates. Returns the number of specified intervals (e.g., days, months, years) between two dates. DATEDIFF(interval, start_date, end_date) Age calculation, measuring project duration. Interval units vary by database (SQL Server-specific).
FORMAT() Formats date/time values into a specific string pattern. Converts date/time into a user-defined string format. FORMAT(date, format) Customizing date output for reports. Limited or unavailable in some databases (SQL Server-specific).
DATEPART() Extracts a specific part of a date. Returns a portion of a date (e.g., year, month, day, hour). DATEPART(part, date) Breaking down date components for calculations. SQL dialect-specific syntax (SQL Server uses DATEPART).
TO_CHAR() Converts a date/time to a formatted string (Oracle). Returns a date in a specified format like MM/DD/YYYY. TO_CHAR(date, 'format') Use for formatting date in Oracle. Database-specific (Oracle only).
SYSDATE() Returns the system's current date and time (Oracle). Retrieves the system date and time with high precision. SYSDATE Useful for triggers or logging. Database-specific (Oracle only).
NOW() Returns the system's current date and time (MySQL). The NOW() function retrieves the current system date and time in the YYYY-MM-DD HH:MM:SS format (depending on database settings). NOW() Useful for logging, auditing, or generating timestamps in applications. Provides system time in UTC or local timezone based on server settings, which can cause confusion.
DATE_TRUNC() Truncates a date to a specified precision. Trims the date to a specified level of granularity (e.g., month, day, hour). DATE_TRUNC('level', date) Aggregation of data based on time units. PostgreSQL-specific.
EXTRACT() Extracts a specified part of a date (e.g., year, month). Retrieves individual parts of a date/time value. EXTRACT(part FROM date) Use for analytics and granular date analysis. Syntax differences between SQL dialects (standard SQL supported).
TO_DATE() Converts a string to a date in the specified format. Parses a string and converts it into a date value based on the format provided. TO_DATE(string, 'format') Useful for validating or converting user input to a valid date. Only supported in Oracle. Formats must exactly match the string's structure to avoid errors.
SYSDATETIME() Returns the current date and time with precision. Provides the system's current date and time as a DATETIME2 value with fractional seconds precision (up to 7 digits). SYSDATETIME() Use for applications requiring high-precision timestamps (e.g., scientific or logging). SQL Server-specific; precision might not be necessary for all use cases.

CURRENT_DATE

Syntax:

SELECT CURRENT_DATE ;
- - Output: 17-12-2024

Scenario 1:- (Generate Daily Reports) Retrieve sales made today.

SELECT sale_id, sale_date, amount
FROM sales
WHERE sale_date = CURRENT_DATE ;

Scenario 2:- Schedule follow-ups for tomorrow for Customers.

INSERT INTO follow_ups (customer_id, follow_up_date)
SELECT customer_id, CURRENT_DATE + INTERVAL '1 DAY'
FROM customers ;

Scenario 3:- Identify subscriptions that expired before today.

SELECT ubscription_id, expiry_date
FROM subscriptions
WHERE expiry_date < CURRENT_DATE ;

Scenario 4:- Identify customers whose birthdays are today.

SELECT customer_id, name, city, dob
FROM customers
WHERE EXTRACT( MONTH FROM dob) = EXTRACT( MONTH FROM CURRENT_DATE )
    AND EXTRACT( DAY FROM dob) = EXTRACT( DAY FROM CURRENT_DATE ) ;

Scenario 5:- Validate the scheduling of upcoming events.

SELECT event_id, event_date
FROM events
WHERE event_date > CURRENT_DATE ;

Scenario 6:- Retrive a list of employees who were hired today (on the current system date).

SELECT *
FROM employees
WHERE hire_date = CURRENT_DATE ;

TO_DATE()

Returns a date in a specified format like MM/DD/YYYY.


Syntax:

Scenario 1:- Basic Conversion

SELECT TO_DATE( '2024-12-17', 'YYYY-MM-DD' ) AS formatted_date
FROM DUAL ;
- - Output: 17-12-2024

Scenario 2:- Parsing with Time.

SELECT TO_DATE('17-12-2024 14:30:00', 'DD-MM-YYYY HH24:MI:SS')
AS FullDate
FROM dual ;

Scenario 3:- Comparison in WHERE Clause.

SELECT *
FROM orders
WHERE order_date = TO_DATE('2024-12-17', 'YYYY-MM-DD') ;

Scenario 4:- Inserting into Table.

INSERT INTO event_schedule (event_date)
VALUES ( TO_DATE( '25-Dec-2024', 'DD-Mon-YYYY' ) ) ;

Scenario 5:- Inserting into Table.

SELECT ADD_MONTHS(TO_DATE('2024-12-17', 'YYYY-MM-DD'), 6)
AS SixMonthsLater FROM dual ;

Scenario 6:- Schedule an event exactly 6 months from a provided date.

SELECT event_name, TO_DATE('01-DEC-2024', 'DD-MON-YYYY') + INTERVAL '6' MONTH AS event_date
FROM event_schedule ;
- - This query calculates the date 6 months from December 1, 2024.

Scenario 7:- Display employee joining dates in a custom format for reporting.

SELECT employee_id, TO_DATE(hire_date, 'YYYY-MM-DD') AS report_hire_date
FROM employees ;

Scenario 8:- Retrieve all logs older than a specific date.

SELECT log_id, action, log_date
FROM audit_logs
WHERE log_date < TO_DATE('01-01-2022', 'DD-MM-YYYY') ;

Common Errors with TO_DATE()

Error Cause Solution
ORA-01843: not a valid month String doesn't match the format specified. Ensure the input string exactly matches the provided format in TO_DATE.
ORA-01830: date format picture ends... Input string length mismatch with format. Use a format matching the length and structure of the input string.

Do's and Don'ts for TO_DATE()

Do'd Don'ts
Always validate input strings before passing to TO_DATE(). Use TO_DATE() without specifying a format string.
Use the correct format for date and time. Assume TO_DATE() will work with non-standard formats (e.g., custom inputs).

SYSDATETIME()

Returns the current date and time with precision.


Syntax:

Scenario 1:- Basic Conversion Retrieve the current system date and time

SELECT SYSDATETIME() AS currenttime_Timestamp ;
- - Output: 17-12-2024 16:45:22

Scenario 2:- Inserting into Table Insert a new record with a precise timestamp.

INSERT INTO logs (log_time) VALUES ( SYSDATETIME() ) ;

INSERT INTO orders (order_id, order_date ) VALUES ( 101, SYSDATETIME() ) ;

- - Add an entry into the audit table with a timestamp.
INSERT INTO udit_logs ( user_id, action, log_time ) VALUES ( 123, 'Login Attempt', SYSDATETIME() ) ;

Scenario 3:- Extracting Date Parts.

SELECT FORMAT( SYSDATETIME(), 'yyyy-MM-dd' ) AS DateOnly ;

Scenario 4:- Comparing with Stored Date.

SELECT *
FROM transactions
WHERE transaction_date < SYSDATETIME() ;

Scenario 5:- Calculate the processing time of a task.

DECLARE @start_time DATETIME2 = SYSDATETIME();

- - Simulate a process (replace with actual queires )
WAITFOR DELAY '00:00:05'; - - 5- second delay

DECLARE @end_time DATETIME2 = SYSDATETIME();

SELECT DATEDIFF (MILLISECOND, @start_time, @end_time ) AS processing_time_ms ;

- - Output: processing Time (ms): 5000

Scenario 6:- Calculate the time elapsed for processing a transaction.

SELECT transaction_id
DATEDIFF( SECOND , transaction_start, SYSDATETIME()) AS processing_time_seconds FROM transactions ;
- - This measures the duration of each transaction in seconds.

Scenario 7:- Retrieve all records updated in the past 60 minutes.

SELECT record_id, last_updated
FROM inventory
WHERE last_updated > DATEADD( MONTH , -60, SYSDATETIME()) ;

Scenario 8:- Create a high-precision timestamp for analytics calculations.

SELECT SYSDATETIME() AS precise_timestamp,
FORMAT(SYSDATETIME(), 'yyyy-MM-dd HH:mm:ss.fff') AS formatted_timestamp
FROM DUAL ;

Scenario 9:- Identify events that are overdue based on the current system time.

SELECT event_id, event_name, scheduled_time
FROM events
WHERE scheduled_time < SYSDATETIME() ;

Common Errors with SYSDATETIME()

Error Cause Solution
Conversion failed when converting date... Attempting to use SYSDATETIME with a lower precision type like DATE. Explicitly cast SYSDATETIME to a lower precision type, such as CAST(SYSDATETIME() AS DATE).

Do's and Don'ts for SYSDATETIME()

Do'd Don'ts
Use for applications needing high precision timestamps. Use SYSDATETIME where lower precision (e.g., GETDATE()) suffices.
Combine with FORMAT or CAST when precision must be adjusted. Assume SYSDATETIME works across all databases; it is SQL Server-specific.

Database-Specific Notes:

SQL Server Only : Not available in MySQL, Oracle, or PostgreSQL. Equivalent functions include:


  • MySQL: NOW()
  • PostgreeSQL: CURRENT_TIMESTAMP
  • Oracle: SYSTIMESTAMP

NOW()

The NOW() function ( specific to MySQL and PostgreeSQL) returns the current system date and time in the format YYYY-MM-DD HH:MM:SS.


Syntax:

SELECT NOW() ;

Scenario 1:- Retrieve the current date and time.

SELECT NOW () AS current_date_time ;

Scenario 2:- Insert the current date and time into a table.

INSERT INTO orders ( customer_name, order_date )
VALUES ( 'Harsha', NOW() ) ;

Scenario 3:- Retrieve orders placed today.

SELECT *
FROM ( 'Harsha', NOW() )orders
WHERE DATE(order_date) = CURDATE() ;

Scenario 4:- Calculate the time difference in hours between two orders.

SELECT
    o1.order_id AS order1,
    o2.order_id AS order2,
    TIMESTAMPDIFF ( HOUR , o1.order_date, o2.order_date) AS hours_diff
FROM orders o1, orders o2
WHERE o1.order_id < o2.order_id ;

Scenario 5:- Add 7 days to the current date for future orders.

SELECT
    NOW() AS current_date_time,
    DATE_ADD(NOW(), INTERVAL 7 DAY ) AS future_date ;

Scenario 6:- Fetch records created in the last 24 hours

SELECT *
FROM orders
WHERE order_date >= NOW() - INTERVAL 1 DAY future_date ;

Scenario 7:- Retrieve the peak hours of user activity by analyzing login timestamps.

SELECT HOUR (NOW() ) AS current_hour
COUNT(*) AS login_count
FROM user_logins
WHERE DATE (login_time) = DATE(NOW()) GROUP BY HOUR(login_time)
ORDER BY login_count DESC
LIMIT 1 ;

Scenario 8:- Group orders by day and count them.

SELECT HOUR
    DATE( order_date ) AS order_day,
    COUNT(*) AS order_count
FROM orders
GROUP BY DATE(order_date)
ORDER BY order_day ;

Scenario 9:- Schedule recurring orders using a combination of NOW().

INSERT INTO orders (customer_name, order_date)
SELECT
    customer_name,
    DATE_ADD(NOW(), INTERVAL 1 MONTH )
FROM orders
WHERE customer_name = 'Harsha Vardhan'
;

Scenario 10:- Filter records from transactions that belong to the current month , then insert them into the appropriate partition table.

INSERT INTO transactions_202412
SELECT * FROM transactions
WHERE MONTH(Trans_date) = MONTH(NOW())
    AND YEAR (Trans_date) = YEAR(NOW())
;

Scenario 11:- Generate time-based report with intervals.

SELECT
    CONCAT (
      HOUR (order_date), ':00 - ',
      HOUR (order_date) + 1, ':00 ',
    ) AS hour_interval,
    COUNT(*) AS total_orders
FROM orders
WHERE DATE(order_date) = CURDATE()
GROUP BY HOUR (order_date)
ORDER BY hour_interval ;

Scenario 12:- Auto-Suspend of overdue account more than 30 days as of now.

UPDATE users
SET status = 'Suspended'
WHERE DATEDIFF(NOW(), last_payment_date ) > 30
AND status = 'Active' ;

Common Errors with NOW()

Error/Issue Cause Solution
NOW() used in an unsupported context Using NOW() in CHECK constraints or as a default for TEXT columns. Use CURRENT_TIMESTAMP for TIMESTAMP or DATETIME columns.
Incorrect time zone Server time zone settings differ from user expectations. Use UTC_TIMESTAMP() for UTC time consistency across servers.
Misuse in WHERE clause for comparisons Comparing NOW() (datetime) with CURDATE() (date). Use DATE(NOW()) to match formats: WHERE DATE(NOW()) = CURDATE().
Non-deterministic behavior in queries NOW() recalculates in multiple query calls (e.g., SELECT, subqueries). Use NOW() in a subquery or variable to store a single value.
Query performance issues Applying functions like NOW() on indexed columns. Avoid wrapping columns with functions; compare raw values when possible.

Do's and Don'ts for Using NOW()

Do's Don'ts
Use NOW() to get the current date and time. Don’t use NOW() where only the date is required; use CURDATE().
Use NOW() with DATE() or TIME() to extract date or time components. Don’t compare NOW() directly with a DATE column without casting.
Use CURRENT_TIMESTAMP as a default value for TIMESTAMP columns. Don’t use NOW() as a default value for non-timestamp column types.
Use UTC_TIMESTAMP() for applications requiring UTC consistency. Don’t rely on NOW() for cross-time-zone consistency without UTC.
Store NOW() in a variable for consistent results in complex queries. Don’t call NOW() multiple times within a query; it may give different results.
Optimize WHERE clauses by avoiding functions on indexed columns. Don’t use NOW() wrapped in functions like DATE_FORMAT() unnecessarily.

GETDATE()

  • The GETDATE() function returns the current date and time based on the server's system clock.
  • Unlike NOW(), GETDATE() is specific to SQL Server.
  • It returns the date and time in the format: YYYY-MM-DD HH:MI:SS.mmm (with milliseconds).

Syntax

SELECT GETDATE() ;

Scenario 1:- Retrieve the current date and time.

SELECT GETDATE() AS current_date_time ;

Scenario 2:- Insert the current date and time into a table.

INSERT INTO orders (customer_name, order_date)
VALUES ( 'Harsha Vardhan', GETDATE() ) ;

Scenario 3:- retrieve only the date or time.

SELECT
    CAST(GETDATE() AS DATE) AS current_date, CAST(GETDATE() AS TIME) AS current_time ;

Scenario 4:- Calculate the difference in days, hours, or minutes.

SELECT
    order_id, DATEDIFF( HOUR , order_date, GETDATE() ) AS hours_since_order
FROM orders ;

Scenario 5:- Add or subtract time to/from the current date.

SELECT
    GETDATE() HOUR current_date_time,
    DATEADD( DAY , 7, GETDATE() ) AS seven_days_later,
    DATEADD( HOUR , -2, GETDATE() ) AS two_hours_earlier ;

Scenario 6:- recurring monthly orders, add 1 month to the current date.

INSERT INTO orders (customer_name, order_date)
SELECT
    customer_name,
    DATEADD( MONTH , 1, GETDATE() )
FROM orders
WHERE order_id = 1 ;

Scenario 7:- Find records created in the last 24 hours.

SELECT *
FROM orders WHERE order_date >= DATEADD(
DAY , -1, GETDATE() ) ;

Scenario 8:- Calculate exact time differences with milliseconds.

SELECT
    order_id, DATEDIFF( SECOND , order_date, GETDATE() ) AS seconds_since_order,
    DATEDIFF( MILLISECOND, order_date, GETDATE() ) AS milliseconds_since_order
FROM orders ;

Scenario 9:- Retrieve and format the current date and time for a user report.

SELECT FORMAT(GETDATE(), 'yyyy-MM-dd HH:mm:ss') AS standard_time
FROM system_status ;

Use Cases of GETDATE()

Use Case Example SQL Query
Audit logging INSERT INTO audit_log (operation_time) VALUES (GETDATE());
Time-based filtering SELECT * FROM orders WHERE order_date > DATEADD(DAY, -7, GETDATE());
Scheduling recurring events INSERT INTO orders (order_date) VALUES (DATEADD(MONTH, 1, GETDATE()));
Comparing timestamps SELECT * FROM orders WHERE DATEDIFF(HOUR, order_date, GETDATE()) < 24;
Grouping records by date/hour SELECT CAST(order_date AS DATE), COUNT(*) FROM orders GROUP BY CAST(order_date AS DATE);

Common Errors

Error/Issue Cause Solution
GETDATE() in unsupported database. GETDATE() is SQL Server-specific; it won’t work in MySQL or others. Use NOW() in MySQL, CURRENT_TIMESTAMP in standard SQL.
Incorrect comparisons with DATE columns. Comparing DATETIME (GETDATE()) with DATE type columns. Use CAST(GETDATE() AS DATE) for consistency.
Non-deterministic behavior. GETDATE() is recalculated for each call in a query. Store GETDATE() in a variable or subquery for consistency.
Misunderstanding time zones. Server time zone not matching user expectations. Use GETUTCDATE() for UTC-based consistency.

Do's and Don'ts for Using NOW()

Do's Don'ts
Use GETDATE() to fetch the current server date and time. Don’t use GETDATE() where only the date is required; use CAST() instead.
Use DATEADD() to add or subtract time from the current date. Don’t compare GETDATE() with DATE columns without casting.
Use GETUTCDATE() for UTC consistency in time zones. Don’t use GETDATE() for systems that require time zone independence.
Store GETDATE() in a variable if multiple calls are needed in queries. Don’t call GETDATE() multiple times unnecessarily in a query.

DATEADD()

The DATEADD() function is used to add or subtract a specific time interval (like days, months, hours, etc.) to a given date or timestamp.

DATEADD(interval, number, date)

  • interval: The part of the date to add (e.g., year, month, day, hour).
  • number: The number of units to add (can be positive to add or negative to subtract).
  • date: The base date to which the interval will be added.

Supported interval Values

Interval Abbreviation Description
year yy, yyyy Year
quarter qq, q Quarter
month mm, m Month
dayofyear dy, y Day of the year
day dd, d Day
week wk, ww Week
weekday dw Weekday
hour hh Hour
minute mi, n Minute
second ss, s Second
millisecond ms Millisecond

Basic Examples

Scenario 1:- Add 7 days to the current date.

SELECT GETDATE() AS current_date
    DATEADD(DAY , 7, GETDATE()) AS date_after_7_days ;

Scenario 2:- Subtract 1 month from a specific date.

SELECT DATEADD ( MONTH , -1, '2024-06-17' ) AS one_month_earlier ;

Scenario 3:- Add 2 years to a date.

SELECT DATEADD ( YEAR , 2, '2024-06-17') AS two_years_later ;

Scenario 4:- Add 5 years to an employee's joining date to calculate the work anniversary.

SELECT employee_id, hire_date,
DATEADD ( YEAR , 5, hire_date ) AS 5_Years_Anniversary
FROM employees ;

Scenario 5:- Add 1 month to the subscription start date to get the renewal date.

SELECT subscription_id, start_date,
DATEADD ( MONTH , 1, start_date ) AS renewal_date
FROM subscriptions ;

Scenario 6:- Subtract 30 days from the current date to find overdue payment records.

SELECT invoice_id, due_date,
DATEDIFF ( DAY , DATEADD ( DAY , -30, GETDATE()), due_date) AS overdue_days
FROM invoices
WHERE due_date < GETDATE() ;

Scenario 7:- Subtract 1 year from the current date to retrieve last year's records.

SELECT report_id, report_date
FROM reports
WHERE report_date >= DATEADD( YEAR , -1, GETDATE()) ;

Scenario 8:- Add the flight duration in hours to the departure time.

SELECT flight_id, departure_time,
DATEADD ( HOUR , flight_duration, departure_time) AS arrival_time
FROM flights ;

Scenario 9:- Find all orders delivered within the last 30 days

SELECT *
FROM orders
WHERE delivery_date >= DATEADD( DAY , -30, GETDATE()) ;

Error Cause Solution
Conversion failed when converting date... Incorrect data type provided for the date parameter. Ensure the date parameter is of a valid DATE, DATETIME, or TIMESTAMP data type.
Invalid interval Typo in the interval value (e.g., YEAR spelled as YEARS). Use valid interval names as defined in the database documentation.
Overflow error Adding excessively large numbers (e.g., DATEADD(YEAR, 10000, GETDATE())). Limit the value of number to avoid overflow issues.
Use negative values for subtraction clearly (e.g., -7 for subtracting days). Using negative numbers in an unclear way. Use comments to clarify: DATEADD(DAY, -7, GETDATE()) -- subtract 7 days.
Performance issues on large datasets. Using DATEADD() on indexed columns in WHERE clauses. Avoid wrapping indexed columns with DATEADD() in conditions.

Do's and Don'ts for DATEADD()

Do's Don'ts
Use DATEADD() for date arithmetic like scheduling and deadlines. Use DATEADD() with invalid or non-existent interval values.
Combine with DATEDIFF() for calculating durations. Use excessively large number values, as this can cause overflow or invalid date errors.
Ensure compatibility by using database-specific interval syntax. Assume DATEADD() works in all databases. For Oracle, use ADD_MONTHS() or manual calculations.

DATEDIFF()

The DATEDIFF() function is used to calculate the difference between two dates or timestamps, returning the result in a specified unit (e.g., days, months, years).


Syntax

DATEDIFF (interval, start_date, end_date)

  • interval: The unit of measurement for the difference (e.g., year, month, day, etc.).
  • start_date: The starting date of the calculation.
  • end_date: The ending date of the calculation.

Interval Abbreviation Description
year yy, yyyy Difference in years
quarter qq, q Difference in quarters
month mm, m Difference in months
day dd, d Difference in days
week wk, ww Difference in weeks
hour hh Difference in hours
minute mi, n Difference in minutes
second ss, s Difference in seconds
millisecond ms Difference in milliseconds

Examples

Scenario 1:- Calculate the difference in days between two dates.

SELECT DATEDIFF( DAY , '2024-01-01', '2024-06-17') AS Difference_in_Days ;

- - Output: 168

Scenario 2:- Calculate the difference in months.

SELECT DATEDIFF( MONTH , '2023-01-01', '2024-06-17' ) AS Difference_in_Months ;

- - Output: 17

Scenario 3:- Calculate the difference in years.

SELECT DATEDIFF( YEAR , '2000-01-01', '2024-06-17' ) AS Difference_in_Years ;

- - Output: 24

Scenario 4:- Find orders placed in the last 30 days.

SELECT *
FROM orders
WHERE DATEDIFF( DAY , order_date, GETDATE()) <= 30 ;

Scenario 5:- Calculate time elapsed since order placement.

SELECT order_id,
WHERE DATEDIFF( DAY ,order_date, GETDATE() ) AS days_elapsed,
DATEDIFF( HOURS ,order_date, GETDATE() ) AS hours_elapsed
FROM orders ;

Scenario 6:- Calculate how many years an employee has worked since joining.

SELECT employee_id, joining_date,
DATEDIFF( YEAR , joining_date, GETDATE() ) AS years_worked
FROM employees ;

Scenario 7:- Calculate the time taken to resolve support tickets in hours.

SELECT ticket_id, created_time, resolved_time,
DATEDIFF( HOUR , created_time, resolved_time ) AS response_hours,
FROM support_tickets
WHERE status = 'Resolved' ;

Scenario 8:- Calculate the number of months between two sales dates.

SELECT sale_id, first_sale_date, last_sale_date,
DATEDIFF( MONTH , first_sale_date, last_sale_date ) AS months_between
FROM sales ;

Scenario 9:- Calculate the total loan duration in days.

SELECT loan_id, start_date, end_date,
DATEDIFF( DAY , start_date, end_date ) AS loan_period_days
FROM loans ;

Common Errors

Error/Issue Cause Solution
Invalid interval Using an unsupported interval (e.g., days instead of day). Use correct intervals (e.g., DAY, MONTH, YEAR).
Reversed dates Passing start_date after end_date. Ensure start_date < end_date, or handle negative differences.
Date format mismatch Providing an incorrectly formatted date. Use consistent date formats like YYYY-MM-DD.
Performance on large datasets Using DATEDIFF() in WHERE clauses with indexed columns. Avoid wrapping indexed columns in functions; rewrite comparisons.

Do's and Don'ts

Do's Don'ts
Use DATEDIFF() for date comparisons in calculations and reports. Don’t use invalid interval names like days or months.
Validate date formats before using them in queries. Don’t compare dates without understanding the precision of DATEDIFF().
Use DATEDIFF() in SELECT for clean calculations. Don’t use it directly in WHERE on indexed columns; rewrite logic.
Consider edge cases (e.g., leap years, time zones). Don’t assume DATEDIFF() is aware of fractional intervals.

FORMAT()

The FORMAT() function is used to format a value (like a number or date) into a specific format based on a given culture or pattern.


Syntax

FORMAT ( value, format, culture )

  • value: The input value to be formatted (can be a number, date, or datetime).
  • format: The format pattern (e.g., 'yyyy-MM-dd' for dates, 'C' for currency).
  • culture: The optional culture/language code (e.g., 'en-US', 'fr-FR'). If omitted, the system's default culture is used.

Supported Data Types

Date/Time Format Strings

Format Description Example Output (for 2024-12-19)
yyyy-MM-dd Year-Month-Day 2024-12-19
MM/dd/yyyy Month/Day/Year 12/19/2024
dd-MM-yyyy Day-Month-Year 19-12-2024
hh:mm:ss Hour:Minute:Second 03:45:20
dddd, MMMM d Full day and month name hursday, December 19

Numeric Format Strings

Format Description Example Output (for 2024-12-19)
N2 Number with 2 decimal places 1,234,567.89
C Currency format $1,234,567.89
P Percentage 123,456,789.00%
0.00 Custom decimal format 1234567.89

Examples

Scenario 1:- Format a date in different styles.

SELECT
GETDATE() AS original_date,
FORMAT(GETDATE(), 'yyyy-MM-dd' ) AS formatted_date ,
FORMAT(GETDATE(), 'yyyy-MM-dd' ) AS formatted_date_1 ;

Scenario 2:- Format a number as currency.

SELECT
12345.678 AS original_number,
FORMAT( 12345.678, 'C', 'en-US' ) AS formatted_currency_us,
FORMAT( 12345.678, 'C', 'en-IN' ) AS formatted_currency_inr ;

Scenario 3:- Format a number as a percentage.

SELECT
0.875 AS original_number ,
FORMAT( 0.875, 'P' ) AS percentage_format ;

Scenario 4:- Display Employee Joining Dates in Custom Format as 'Day-Month-Year'.

SELECT employee_id, joining_date,
FORMAT( joining_date, 'dd-MM-yyyy' ) AS Join_date
FROM employees ;

Scenario 5:- Display Sales Amounts with Currency Format in US culture

SELECT sale_id, amount,

Common Errors with FORMAT()

Error Cause Solution
Invalid format string Using an unsupported or incorrect format string. Use valid format strings as specified in the SQL Server documentation.
Culture is not supported Specifying an invalid culture or one not supported by the database. Use supported culture codes (e.g., en-US, fr-FR, hi-IN).
Performance issues for large data Formatting on-the-fly for large datasets can slow down queries. Format values in application layers for better performance on large datasets.

Do's and Don'ts for FORMAT()

Do's Don'ts
Use FORMAT() for display purposes, such as reports or user interfaces. Use FORMAT() for data manipulation; instead, store raw values and format during presentation.
Always test custom formats and cultures in your environment. Use FORMAT() in performance-critical queries; it can significantly slow down execution times.
Prefer numeric or date formats aligned with the target audience. Assume FORMAT() works identically across all databases (e.g., not available in Oracle or MySQL).

DATEPART()

The DATEPART() function is used to extract a specific part of a date or time value, such as the year, month, day, hour, minute, etc.


Syntax

DATEPART ( part, date )

  • part: The date part to extract (e.g., YEAR, MONTH, DAY, etc.).
  • date: The date or datetime value to extract from.

Common Date Parts

Part Description Example Output (for 2024-12-19 15:30:45)
YEAR Year 2024
MONTH Month 12
DAY Day of the month 19
HOUR Hour 15
MINUTE Minute 30
SECOND Second 45
WEEKDAY Day of the week (1 = Sunday) 5
QUARTER Quarter of the year 4

Examples

Scenario 1:- Extract year, month, and day from a date.

SELECT transaction_id ,
    DATEPART( YEAR , '2024-12-19' ) AS Date_of_Year
    DATEPART( MONTH , '2024-12-19' ) AS Date_of_Month
    DATEPART( DAY , '2024-12-19' ) AS Date_of_Day ;

Scenario 2:- Extract the year of joining for employees.

SELECT employee_id, joining_date ,
    DATEPART( YEAR , joining_date) AS joining_year
    FROM employees ;

Scenario 3:- Find orders placed in December.

SELECT order_id, order_date
FROM orders
WHERE DATEPART( MONTH , order_date) = 12 ;

Scenario 4:- Find orders placed in December.

SELECT DATEPART( QUARTER, sale_date ) AS sales_quarter,
SUM( amount ) AS total_sales
FROM sales
GROUP BY DATEPART( QUARTER, sale_date ) ;

Scenario 5:- Find employees with birthdays this week.

SELECT employee_id, name, birth_date
FROM employees
WHERE DATEPART( WEEKDAY, birth_date ) BETWEEN 1 AND 7 ;

Scenario 6:- Analyze website traffic volume by hour.

SELECT DATEPART( HOUR , visit_time) AS visit_hour
    COUNT( * ) AS visit_count
FROM website_visits
GROUP BY DATEPART( HOUR , visit_time)
ORDER BY visit_hour ;

Scenario 7:- Find transactions that occurred on weekends.

SELECT transaction_id, transaction_date
FROM transactions
WHERE DATEPART(WEEKDAY, transaction_date) IN ( 1, 7 )
;

Common Errors with DATEPART()

Error Cause Solution
Invalid date format Supplying a date in an incompatible format. Ensure the date value is properly formatted (DATE, DATETIME, or TIMESTAMP).
Invalid part name Using an unsupported or misspelled part name. Double-check part names (YEAR, MONTH, DAY, etc.) for correct spelling.
Misinterpreted day-of-week values. WEEKDAY may start with Sunday as day 1. Adjust logic based on your application’s day-of-week expectations.

Do's and Don'ts for DATEPART()

Do's Don'ts
Use DATEPART() for granular date breakdowns like hours or weekdays. Use DATEPART() for unsupported databases (e.g., PostgreSQL or Oracle). Use EXTRACT() instead.
Validate and test the date formats before querying. Assume day-of-week values (WEEKDAY) align with international standards (Sunday is day 1 in SQL).
Combine with aggregation functions like COUNT() or SUM(). Use for formatting purposes; use FORMAT() for display instead.

DATE_TRUNC()

The DATE_TRUNC() function is used to truncate a date, timestamp, or interval to the specified precision (e.g., year, month, day, hour).

  • It is commonly supported in databases like PostgreSQL, Redshift, and Snowflake, and is particularly useful for grouping data by time intervals.

Syntax

DATE_TRUNC ( precision, source )

  • precision: The level of truncation. Common values include year, quarter, month, week, day, hour, minute, second.
  • source: The date, timestamp, or interval to be truncated.

Supported Precisions

Precision Description
millennium Truncate to the start of the millennium
century Truncate to the start of the century
decade Truncate to the start of the decade
year Truncate to the start of the year
quarter Truncate to the start of the quarter
month Truncate to the start of the month
week Truncate to the start of the ISO week
day Truncate to the start of the day
hour Truncate to the start of the hour
minute Truncate to the start of the minute
second Truncate to the start of the second

Examples

Scenario 1:- Group Sales by Month.

SELECT DATE_TRUNC('month', sale_date) AS Monthly_Sales
    SUM(sale_amount) AS Total_Sales
FROM Sales
GROUP BY DATE_TRUNC('month', sale_date)
ORDER BY Monthly_Sales ;

Scenario 2:- Truncate login timestamps to the start of the day.

SELECT user_id, DATE_TRUNC('day', login_time) AS Login_day
FROM user_logins ;

Scenario 3:- Find orders placed in the week of December 15, 2024.

SELECT order_id, order_date
FROM orders
WHERE DATE_TRUNC('week', order_date) = '2024-12-15 00:00:00' ;

Scenario 4:- Calculate Work Sessions durations by day

SELECT employee_id,
    DATE_TRUNC('day', session_start) AS work_day SUM(session_duration) AS total_work_duration
FROM work_sessions
GROUP BY employee_id, DATE_TRUNC('day', session_start) ;

Scenario 5:- Tracking Daily website page views by day for analytics.

SELECT
    DATE_TRUNC('day', view_time) AS day_start
    COUNT(*) AS total_views
FROM page_views
GROUP BY DATE_TRUNC('day', view_time)
ORDER BY day_start ;

Common Errors with DATE_TRUNC()

Error Cause Solution
function does not exist Using DATE_TRUNC() in an unsupported database (e.g., MySQL) Use alternative functions like DATE_FORMAT() or manual string operations.
invalid input syntax for type Providing an invalid date format. Ensure the date is in a valid format for the database.
invalid interval part Using unsupported or incorrect truncation units. Use only supported units like year, month, day, hour, etc.

Do's and Don'ts for DATE_TRUNC()

Do's Don'ts
Use DATE_TRUNC() for accurate date/time grouping and analysis. Use it for unsupported databases like SQL Server or Oracle. Use alternatives instead.
Validate truncation units before using them in queries. Assume it adjusts dates automatically for time zones; handle time zones explicitly.
Leverage DATE_TRUNC() for filtering intervals. Avoid mixing DATE_TRUNC() with string-based formats unnecessarily.

SYSDATE()

The SYSDATE() function is used to retrieve the current system date and time of the database server.

Syntax

SYSDATE ( )

  • Returns the current date and time based on the database server's clock.
  • It is similar to NOW() in MySQL, but the key difference is that SYSDATE() reflects the time when the function is executed, even if it's used multiple times in the same query.

Database-Specific Behavior

Database Behavior
Oracle SYSDATE returns the date and time from the server's operating system. Precision is limited to seconds.
MySQL SYSDATE() returns the current date and time. It is dynamic in statements unless the query uses SELECT ... FOR UPDATE.
PostgreSQL Not natively supported; use CURRENT_TIMESTAMP or NOW() as an alternative.
SQL Server Not supported; use GETDATE() as an alternative.

Examples

Scenario 1:- Retrieve Current Date and Time.

SELECT SYSDATE() AS current_datetime
;

-- Output: 2024-12-20 07:45:30

Scenario 2:- Retrieve only the current date without the time component.

SELECT DATE(SYSDATE() ) AS current_date
;

-- Output: 2024-12-20

Key Differences Between SYSDATE() and NOW()

Feature SYSDATE() NOW()
Behavior Returns the time of execution. Returns the time the query starts.
Use Case Useful in time-sensitive calculations. Consistent within the same query.

Scenario 3:- Insert a transaction with the current timestamp.

INSERT INTO transactions (transaction_id, amount, transaction_date)
VALUES ( 101, 250.50, SYSDATE() ) ;

Scenario 4:- Find the duration since an event in seconds.

SELECT event_id, event_name,
SYSDATE() - event_time AS seconds_elapsed
FROM events ;

Scenario 5:- Retrieve records created today.

SELECT employee_id, name, created_date
FROM employees
WHERE DATE(created_date) = DATE(SYSDATE()) ;

Scenario 7:- List events occurring within the next 7 days.

SELECT event_id, event_name, event_date
FROM events
WHERE event_date BETWEEN SYSDATE() AND SYSDATE() + INTERVAL 7 DAY ;

Scenario 8:- Generate a list of unresolved tickets that have exceeded the SLA based on the exact system time.

SELECT ticket_id, TIMESTAMPDIFF( MINUTE , created_at, SYSDATE() ) AS minutes_elapsed
FROM tickets
WHERE status = 'OPEN'
    AND TIMESTAMPDIFF( MINUTE , created_at, SYSDATE()) > sla_minutes ;

Common Errors and Solutions

Error/Issue Cause Solution
Unexpected Time Zone The server's timezone differs from user expectations. Use CONVERT_TZ() to adjust to the desired timezone.
Precision Issues SYSDATE() includes fractional seconds by default. Truncate fractional seconds if not needed.
Inconsistent Usage Comparing SYSDATE() with a constant timestamp. Use consistent expressions for time-based queries.

Do's and Don'ts

Do's Don'ts
Use SYSDATE() for real-time or immediate timestamping. Don’t rely on SYSDATE() for consistent query-wide timestamps (use NOW() instead).
Combine with date/time functions like DATE() or TIMESTAMPDIFF() for flexible use. Avoid assuming SYSDATE() is constant during a query.
Adjust time zones explicitly when needed. Don’t forget timezone adjustments in distributed systems.
Validate date and time requirements for your database environment. Use SYSDATE() in place of CURRENT_DATE or NOW() unless precise time is required.

EXTRACT()

The EXTRACT() function is used to retrieve specific parts of a date, time, or timestamp value.


  • It is a versatile function supported by many relational databases, such as PostgreSQL, MySQL, Oracle, SQL Server, and others (with slight variations).

Syntax

EXTRACT ( part FROM source ) ;

  • part: The component to extract, such as year, month, day, hour, etc.
  • source: A date, time, or timestamp value from which the specified part is extracted.

Supported Components

Part Description
year Returns the year from the date.
month Returns the month from the date.
day Returns the day of the month.
hour Returns the hour of the timestamp.
minute Returns the minute of the timestamp.
second Returns the second of the timestamp.
week Returns the ISO week number of the year.
quarter Returns the quarter of the year (1-4).
dow Returns the day of the week (0=Sunday, 1=Monday...).

Examples

Scenario 1:- Extracting the Year.

SELECT EXTRACT( YEAR FROM TIMESTAMP '2024-12-20 14:30:45' ) AS year ;
-- Output: 2024

Scenario 2:- Extracting the Month.

SELECT EXTRACT( MONTH FROM TIMESTAMP '2024-12-20 14:30:45' ) AS month ;
-- Output: 12

Scenario 3:- Extracting the Day.

SELECT EXTRACT( DAY FROM TIMESTAMP '2024-12-20 14:30:45' ) AS day ;
-- Output: 20

Scenario 4:- Identify the quarter in which transactions occurred.

SELECT
transaction_id ,
EXTRACT(QUARTER FROM transaction_date ) AS quarter
FROM Transactions ;

Scenario 5:- Group sales data by month and calculate total sales.

SELECT
EXTRACT( MONTH FROM sale_date ) AS month
SUM(sales_amount) AS Total_sales
FROM sales
GROUP BY EXTRACT( MONTH FROM sale_date)
ORDER BY month ;

Scenario 6:- Summarize revenue by quarter.

SELECT EXTRACT(quarter FROM Trans_date ) AS Trans_Quarter
    SUM(amount) AS Total_Revenue
FROM Transactions
GROUP BY EXTRACT( quarter MONTH FROM Trans_date)
ORDER BY Trans_Quarter ;

Scenario 7:- Find events occurring on Sundays.

SELECT event_id, event_date
FROM events
GROUP BY EXTRACT(dow FROM event_date ) = 0 ;

Scenario 8:- Extract hour and minute components to calculate session duration.

SELECT session_id ,
    EXTRACT( hour FROM session_end - session_start ) * 60 +
    EXTRACT( minute FROM session_end - session_start ) AS session_length_minutes
FROM user_sessions ;

Scenario 9:- Identify the first Monday in December 2024.

SELECT date_value ,
SELECT calendar
WHERE
    EXTRACT( month FROM date_value) = 12
    AND EXTRACT(dow FROM date_value) = 1
    AS session_length_minutes
ORDER BY date_value
LIMIT 1 ;


Common Errors

Error Cause Solution
invalid part name Using an unsupported or incorrect part name. Use valid parts such as year, month, day, hour, etc.
function does not exist Using EXTRACT() in an unsupported database (e.g., SQLite). Use alternatives like strftime() or DATENAME() depending on the database.
NULL values in date column Attempting to extract from NULL dates or timestamps. Handle NULL values using COALESCE() or filters.

Do's and Don'ts

Do's Don'ts
Use EXTRACT() for precise date/time analysis or filtering. Use unsupported parts in your queries; check database documentation for valid parts.
Validate date columns to ensure they are not NULL. Assume the function works across all databases; some may require alternatives or adjustments.
Combine with aggregation or grouping functions for better insights. Use it for direct date formatting; use TO_CHAR() or FORMAT() for presentation purposes.
