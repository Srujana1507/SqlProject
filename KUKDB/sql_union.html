UNION Operator

The UNION operator is a set operator that combines the results of two or more SELECT statements into a single result set.


It removes duplicate rows by default, ensuring the final output contains only unique rows.


Key Characteristics of UNION

  • Combines Results:- Merges results from multiple SELECT statements.
  • Duplicates:- Removes duplicates unless specified with UNION ALL.
  • Data Type Compatibility:-
    • The number of columns in each SELECT must be the same.
    • Data types of corresponding columns must be compatible.
  • Order of Data:- Sorting in the combined result can be achieved using ORDER BY at the end of the UNION query.

Syntax

SELECT column1, column2, . . .
FROM table1
WHERE condition1

UNION

SELECT column1, column2, . . .
FROM table2
WHERE condition2 ;

Examples

1. Basic UNION Example

Scenario :- Combine lists of employees from two tables.

SELECT employee_id, name, department
FROM employees_2023
UNION
SELECT employee_id, name, department
FROM employees_2024 ;

- - Combines employees from both tables.
- - Duplicates are removed in the final result.

2. Using UNION with Different WHERE Conditions

Scenario 1:- Get all active and terminated employees from separate tables.

SELECT employee_id, name, status
FROM employees
WHERE status = 'Active'
UNION
SELECT employee_id, name, status
FROM terminated_employees ;

Scenario 2:- Retrieves products priced over $50 from both the US and UK markets, with an indicator column specifying the market.

SELECT ProductID, ProductName, 'USA' AS Market
FROM Products_US
WHERE Price > 50
UNION
SELECT ProductID, ProductName, 'UK' AS Market
FROM Products_UK
WHERE Price > 50 ;

3. UNION with Expressions

Scenario :- Combine sales data from multiple years with calculated fields using UNION.

SELECT product_id, sales AS total_sales, '2023' AS year
FROM sales_2023
UNION
SELECT product_id, sales * 1.1 AS total_sales, '2024' AS year
FROM sales_2024 ;

4. Using UNION with ORDER BY

Scenario 1:- Combine employee data and sort final result by name.

(SELECT employee_id, name
FROM employees_2023
UNION
SELECT employee_id, name
FROM employees_2024) ORDER BY name ;

- - ORDER BY applies to the entire result set, not individual queries.

Scenario 2:- Combines employee names and sorts the combined result set by LastName in ascending order.

(SELECT FirstName, LastName
FROM Employees_US
UNION
SELECT FirstName, LastName
FROM Employees_UK ) ORDER BY LastName ASC ;

- - ORDER BY applies to the entire result set, not individual queries.

Common Use Cases

1. Merging Data Across Tables:

Combine similar data from multiple tables, such as annual records or regional data.

2. Combining Different Conditions:

Use different conditions for fetching related data.

3. Aggregating Results:

Merge results from aggregated data sets (e.g., totals, averages).


Advanced Use Cases

1. Combining Data from Different Sources

Scenario :- Combine customer records from multiple databases.

SELECT customer_id, name, country
FROM db1.customers
UNION
SELECT customer_id, name, country
FROM db2.customers ;

2. Creating a Unified View

Scenario :- Create a view that combines employee data from multiple years.

CREATE VIEW all_employees AS
SELECT employee_id, name, department, '2023' AS year
FROM employees_2023
UNION
SELECT employee_id, name, department, '2024' AS year
FROM employees_2024 ;

3. UNION with Aggregation

Scenario :- Combine sales totals across regions.

SELECT region, SUM( sales ) AS total_sales
FROM sales_north
GROUP BY region
UNION
SELECT region, SUM( sales ) AS total_sales
FROM sales_south
GROUP BY region ;

4. Combining Queries with Different Filters

Scenario :- Combines recent orders from the Orders table and historical orders from the HistoricalOrders table

SELECT OrderID, CustomerID
FROM Orders
WHERE OrderDate >= '01-01-2023'
UNION
SELECT OrderID, CustomerID
FROM HistoricalOrders
WHERE OrderDate BETWEEN '01-01-2023' AND '01-01-2024' ;

Database-Specific Notes

Oracle:

  • Fully supports UNION and UNION ALL.
  • Use ORDER BY only after all SELECT statements.

SQL Server:

  • Syntax and behavior are consistent with the standard.
  • Aliases from the first query are used for column naming in the result set.

MySQL:

  • Supported and behaves similarly to other databases.
  • Enforces column compatibility.

Performance Considerations

UNION vs. UNION ALL :

    • UNION performs an additional DISTINCT operation, which can be slow for large data sets.
    • Use UNION ALL if you don’t need duplicate elimination.

Indexing :

    • Ensure proper indexing on the columns used in SELECT statements to improve performance.

Batch Processing :

    • Divide large queries into smaller batches to avoid performance bottlenecks.

Do's and Don'ts

Do's

  • Ensure Compatibility:- Verify that the number of columns and their data types match across all SELECT queries.
  • Use Aliases for Clarity:- Rename columns for consistency, especially when combining tables with different column names.
  • Use UNION ALL for Performance:- Prefer UNION ALL when duplicates do not need to be removed, as it is faster than UNION.
  • Apply ORDER BY at the End:- Use ORDER BY in the final result set to avoid errors.

Don'ts

  • Mismatch Columns:- Avoid combining queries with different numbers or types of columns.
  • Apply ORDER BY in Individual Queries:- Sorting must be applied only in the final result set.
  • Ignore Performance:- Avoid using UNION where UNION ALL is sufficient to reduce computational overhead.
  • Don’t use UNION when a JOIN would be more appropriate.

Limitations

  • Column Count:- All queries must have the same number of columns.
  • Column Data Types:- Corresponding columns must have compatible data types.
  • Order of Columns:- Columns must appear in the same order in all queries.

Comparison: UNION vs UNION ALL

Feature UNION UNION ALL
Duplicates Removes duplicates Includes duplicates
Performance Slower ( requires sorting and comparison ) Faster (no duplicate check)
Use Case When unique rows are needed When all rows are needed
