IN Operator

The IN operator is used to filter rows where a column matches any value from a given set of values.


It simplifies queries by allowing you to specify multiple values in a WHERE or HAVING clause, rather than using multiple OR conditions.


Execution:- It picks one by one value from list of values.


We can use IN with SELECT, Update, DELETE statments.

Key Features of the IN Operator

  • Simplifies Queries:- Replaces long OR conditions with a concise syntax.
  • Used in WHERE and HAVING Clauses:- Commonly applied to filter rows based on a list of values or the results of a subquery.
  • Supports Subqueries:- Can compare column values to the results of a subquery.
  • Supports Datatypes:- It supports Number , Characters and Date values.
  • Case-Sensitive in Some Databases:- The behavior of IN can vary depending on the database collation.

Syntax

1. Basic IN Syntax

SELECT column1 , column2 , . . .
FROM table_name
WHERE column_name IN ( column1 , column2 , . . . ) ;

2. IN with Subquery

SELECT column1 , column2 , . . .
FROM table_name
WHERE column_name IN (SELECT column_name FROM another_table ) ;

Basic Examples

Scenario 1:- Retrieve employees working in departments 10, 20, or 30.

SELECT employee_id , department_id , first_name
FROM employees
WHERE department_id IN ( 10, 20, 30 ) ;

Equivalent Query Using OR:

SELECT employee_id , department_id , first_name
FROM employees
WHERE department_id = 10 OR department_id = 20 OR department_id = 30 ;

Scenario 2:- Retrieve customers located in "Hyderabad", "Mumbai", or "Chennai".

SELECT customer_id , customer_name , city
FROM customers
WHERE city IN ( 'Hyderabad' , 'Mumbai' , 'Chennai' ) ;

Subquery with IN

Scenario 1:- Find all orders placed by customers from "California."

SELECT OrderID , CustomerID , OrderDate
FROM Orders
WHERE CustomerID IN (
      SELECT CustomerID
      FROM customers
      WHERE State = 'Hyderabad'
) ;

Scenario 2:- Retrieve products belonging to categories available in the categories table.

SELECT product_id , product_name
FROM products
WHERE category_id IN (
    SELECT category_id
    FROM categories
    WHERE status = 'Active'
) ;

IN with Date Values

Scenario 1:- Retrieve orders placed on specific dates.

SELECT order_id , order_date , customer_id
FROM orders
WHERE order_date IN ( '2024-01-01', '2024-01-15', '2024-02-01' ) ;

IN with Multiple Columns (SQL Server and Oracle)

Scenario 1:- Retrieve employees whose department and job title match specific pairs of values.

SELECT employee_id , department_id , job_title
FROM employees
WHERE ( department_id, job_title ) IN ( ( 10, 'Manager' ), ( 20, 'Analyst' ) ) ;

Combining with Other Conditions

Scenario 1:- Retrieve employees in departments 10, 20, or 30, who also earn more than $50,000.

SELECT EmployeeID , Name , department_id , Salary
FROM employees
WHERE department_id IN ( 10, 20, 30 ) AND Salary > 50000 ;

Advanced Scenarios

1. Matching Multiple Columns (Using Subqueries)

Scenario :- Retrieve orders that match specific combinations of customer and product IDs.

SELECT OrderID , CustomerID , ProductID
FROM Orders
WHERE (CustomerID, ProductID) IN (
      SELECT CustomerID , ProductID
      FROM FavoriteProducts
    ) ;

2. Handling NULL with NOT IN

Scenario :- NOT IN excludes rows if any value in the list or subquery is NULL. This can lead to unexpected results.

SELECT employee_id
FROM employees
WHERE department_id NOT IN ( 10 , 20, NULL ) ; - - No rows are returned because the NULL value causes NOT IN to evaluate to UNKNOWN.

Solutions

SELECT employee_id
FROM employees
WHERE department_id NOT IN ( 10 , 20) AND AND department_id IS NOT NULL ;

3. IN with UPDATE Statement

Scenario :- Update the status of customers located in specific cities.

UPDATE customers
SET status = 'Inactive'
WHERE city IN ( 'New York' , 'Los Angeles' , 'Chicago') ;

4. IN with SET Clause (MySQL Specific Use)

Scenario :- Set the region code for customers based on their cities.

UPDATE customers
SET region_code = CASE
    WHEN city IN ( 'New York' , 'Boston' ) THEN 'East'
    WHEN city IN ( 'Los Angeles' , 'San Francisco' ) THEN 'West'
    WHEN 'Central'
END ;

5. IN with DELETE Statement

Scenario :- Delete products belonging to certain categories.

DELETE FROM products
WHERE category_id IN ( 1, 2, 3 ) ;

6. IN with Subqueries in DELETE

Scenario :- Delete customers who have not placed any orders.

DELETE FROM customers
WHERE category_id NOT IN ( SELECT DISTINCT customer_id FROM orders ) ;

7. IN with INSERT INTO SELECT Statement

Scenario :- Insert orders into an archive table for customers from specific countries.

INSERT INTO orders_archive ( order_id, customer_id, order_date )
SELECT order_id, customer_id, order_date
FROM orders
WHERE country IN ( 'UAS' , 'INDIA' , 'UK' ) ;

8. IN with JOIN Condition

Scenario :- Retrieve orders for products belonging to certain categories.

SELECT o.order_id, p.product_name
FROM orders o
JOIN products p ON o.product_id = p.product_id
WHERE p.category_id IN (
SELECT category_id FROM categories WHERE category_name = 'Electronics' ) ;

9. IN with HAVING Clause

Scenario :- Retrieve categories with sales in specific years.

SELECT category_id, SUM(sales) AS total_sales
SELECT order_id, customer_id FROM sales
GROUP BY category_id
HAVING YEAR ( order_date ) IN ( 2020, 2021 ) ;

10. IN with Dynamic Filters

In stored procedures or dynamic queries, the IN operator is often used for passing multiple values as parameters.

Scenario :- IN with Dynamic Filters

DECLARE @CustomerIDs VARCHAR( MAX ) = '101,102,103' ;
FROM orders
WHERE customer_id
IN (
SELECT value FROM STRING_SPLIT( @CustomerIDs, ',' ) ) ;

Using IN vs. OR

Equivalent Query Using OR

WHERE DepartmentID = 10 OR DepartmentID = 20 OR DepartmentID = 30 ;

Preferred Query Using IN

WHERE DepartmentID IN ( 10, 20, 30) ;

Why prefer IN?

  • Readability :- Easier to write and understand.
  • Performance :- Optimized by the database engine, especially for indexed columns.
  • Scalability :- Works well with dynamically generated lists or subqueries.

Common Errors

1.NULL in NOT IN

- - Always handling NULLs like below
WHERE DepartmentID NOT IN ( 10, 20 ) AND DepartmentID IS NOT NULL ;

2.List Too Large

- - Providing a very long list can degrade performance.
WHERE ID IN ( 1, 2, 3, . . . . . , 1000 ) ; - - -- Not efficient for large lists.

Performance Considerations

  • Efficiency with Indexing:- The IN operator can leverage indexes if the list contains indexed columns. However, it may not be as efficient as JOIN for large datasets.
  • Subquery Performance:- Using IN with a subquery can be slower compared to EXISTS, especially if the subquery returns a large result set.
  • Alternatives for Large Lists:- For large lists of values, consider using a temporary table or JOIN for better performance.

Use Cases

1. Filtering Data :Example: Retrieve products belonging to a specific set of categories.


2. Matching Against Subqueries :Example: Find employees working on active projects.


3. Exclusion with NOT IN :Example: Exclude products that belong to inactive categories.


4. Dynamic Filters :Example: Use IN to filter rows dynamically based on user input or application data.


Best Practices

1. Avoid NULL in NOT IN:-

    • Always account for NULL values when using NOT IN to prevent unintended results.

2. Limit List Size:-

    • Avoid excessively large lists in the IN clause as it may degrade performance.

3. Consider Alternative Operators:-

    • For complex queries, EXISTS or JOIN may be more efficient than IN.

4. Use with Indexed Columns:-

    • Apply the IN operator on columns that are indexed to improve performance.

5. Combine with EXISTS or JOIN:-

    • For complex queries, consider alternatives like EXISTS for better scalability.
