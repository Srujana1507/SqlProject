SELECT DISTINCT

The SELECT DISTINCT statement is used to retrieve unique values from a column or combination of columns in a table.


Key Features of SELECT DISTINCT

  • Eliminates Duplicates :- Removes duplicate rows based on the selected columns.
  • Applicable to Single or Multiple Columns :- Removes duplicate rows based on the selected columns.
  • Works Without Affecting the Original Data :- Operates only on the result set, leaving the table data unchanged.
  • Common Use Cases :-
    • To identify unique values in a column.
    • To count distinct values in a dataset.

Syntax

SELECT DISTINCT column1 , column2 , . . .
FROM table_name ;

1. Basic Examples

Sample table

CustomerID Name Country
1 Ram India
2 Harsha USA
3 Vardhan USA
4 Uday Canada
5 kankati India

Scenario 1:

Retrieve the list of unique countries from Customers table.

SELECT DISTINCT Country
FROM table_name ;

Output

Country
India
USA
Canada

Scenario 2:

Retrieve distinct departments in the employees table.

SELECT DISTINCT department_name
FROM employees ;

Scenario 3:

Unique Product Categories :- Retrieve unique product categories from a products table.

SELECT DISTINCT category
FROM products ;

2. Multiple Columns Example

Scenario 1: Retrieve unique combinations of department and job titles.

SELECT DISTINCT department_name , job_title
FROM employees ;

Scenario 2: Retrieve distinct customer names and their countries.

SELECT DISTINCT customer_name , country
FROM customers ;

Advanced Examples

3. Using DISTINCT with Expressions

Scenario :- Retrieve distinct salary values with an additional bonus calculation

SELECT DISTINCT salary + 1000 AS adjusted_salary
FROM employees ; - - The DISTINCT operator applies to the computed value (salary + 1000).

4. Distinct with Aggregate Functions

Scenario 1:- To count the number of unique departments.

SELECT COUNT( DISTINCT department_name ) AS unique_departments
FROM employees ;

Scenario 2:- Count the total number of unique cities where orders have been placed.

SELECT COUNT( DISTINCT city ) AS unique_cities
FROM orders ;

Complex Scenarios

Scenario 1:- Filtering with WHERE Clause: Retrieve unique product categories with prices above $50.

SELECT DISTINCT Category
FROM Products
WHERE Price > 50 ;

Scenario 2:- Using DISTINCT in a Subquery: Find customers who placed orders in at least two unique countries.

SELECT CustomerID
FROM Orders
GROUP BY CustomerID
HAVING COUNT( DISTINCT Country ) >= 2 ;

Scenario 3:- Combining DISTINCT with Joins: Retrieve unique product categories ordered by customers.

SELECT DISTINCT p.Category
FROM Products p
INNER JOIN Orders o
ON p.ProductID = o.ProductID ;

Common Mistakes and How to Avoid Them

1. Using DISTINCT on All Columns:

DISTINCT applies to the entire row. Ensure you understand that it checks all selected columns for uniqueness.

SELECT DISTINCT *
FROM orders ; - - If the orders table has many columns, this can lead to unexpected results.

2. Expecting DISTINCT to Ignore Formatting Differences:

DISTINCT treats 'John' and 'john' as different values in a case-sensitive collation. Use functions like UPPER() or LOWER() to normalize.

SELECT DISTINCT LOWER (name)
FROM employees ;

3. Applying DISTINCT with Irrelevant Columns:

Adding unnecessary columns can reduce the effectiveness of DISTINCT.

SELECT DISTINCT department_name , salary
FROM employees ; - - May not return expected distinct departments.

4. Performance Issues:

  • DISTINCT can be slow for large datasets as it involves sorting and filtering.
  • Use indexes or pre-aggregated data to optimize queries.

Misunderstanding DISTINCT vs. GROUP BY:

Both eliminate duplicates, but GROUP BY is used for aggregation, while DISTINCT is for deduplication.


Best Practices

1. Use DISTINCT Judiciously

    • Only use DISTINCT when duplicates are a problem. Avoid overusing it for every query as it can degrade performance.

2. Combine with Filters

    • Apply filters using WHERE or HAVING to reduce the dataset before deduplication.

3. Leverage Indexing

    • Ensure that columns used with DISTINCT are indexed for better performance.

4. Compare with GROUP BY

    • For queries involving aggregations, GROUP BY may be more efficient than DISTINCT.
