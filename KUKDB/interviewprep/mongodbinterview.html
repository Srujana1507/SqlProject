Mongo DB Beginner


1. What is MongoDB?


MongoDB is a NoSQL, document-oriented database that stores data in JSON-like BSON (Binary JSON) format. Unlike traditional relational databases, MongoDB doesn't rely on tables and rows but uses collections and documents, making it flexible and scalable. It is particularly useful for applications with large-scale data, real-time analytics, or rapidly changing schemas.



2. What is a collection in MongoDB?


A collection in MongoDB is analogous to a table in relational databases. It holds multiple documents and does not enforce a schema, allowing documents within the same collection to have different fields. Collections are created automatically when a document is inserted for the first time.



3. What is a document in MongoDB?


A document is the basic unit of data in MongoDB and is stored in BSON format. It is a set of key-value pairs, similar to a JSON object. Each document can have nested fields, arrays, and varying structures, providing flexibility.



4. How do you insert a document in MongoDB?


You can use the insertOne() or insertMany() methods to insert documents.

Example:

db.users.insertOne({ name: "Alice", age: 25, city: "New York" })

- - Output:
{ "acknowledged": true, "insertedId": ObjectId("...") }


5. How do you retrieve data in MongoDB?


To retrieve data from a collection, use the find() method. It returns a cursor to the documents that match the query criteria.

Example:

db.users.find({ city: "New York" })

- - Output:
{ "_id": ObjectId("..."), "name": "Alice", "age": 25, "city": "New York" }


6. What is the difference between MongoDB and MySQL?


- Data Model: MongoDB is document-oriented and schema-less, while MySQL is relational and schema-based.
- Data Storage: MongoDB stores data as BSON documents in collections; MySQL stores data in rows within tables.
- Scalability: MongoDB supports horizontal scaling (sharding), while MySQL primarily supports vertical scaling.
- Query Language: MongoDB uses a JSON-like query language, while MySQL uses SQL.
- Transactions: MySQL has full ACID-compliant transactions; MongoDB added multi-document transactions in newer versions.



7. What are indexes in MongoDB?


Indexes in MongoDB improve the efficiency of search operations on collections. Without indexes, MongoDB must scan every document in a collection, which can be slow. Indexes are created on fields that are frequently used in queries to reduce query response time.

Example:

db.users.createIndex({ name: 1 })

- - Output:
{ "createdCollectionAutomatically": false, "numIndexesBefore": 1, "numIndexesAfter": 2, "ok": 1 }


8. What is a primary key in MongoDB?


Every document in MongoDB has a special field called _id which uniquely identifies that document within a collection. This field is the primary key in MongoDB. If not provided explicitly, MongoDB automatically generates a unique ObjectId for it.



9. How do you update documents in MongoDB?


You can update documents using updateOne(), updateMany(), or replaceOne(). The $set operator is often used to update specific fields.

Example:

db.users.updateOne({ name: "Alice" }, { $set: { age: 26 } })

- - Output:
{ "acknowledged": true, "matchedCount": 1, "modifiedCount": 1 }


10. How do you delete documents in MongoDB?


Documents can be deleted using deleteOne() or deleteMany(). These functions remove documents that match a given condition.

Example:

db.users.deleteOne({ name: "Alice" })

- - Output:
{ "acknowledged": true, "deletedCount": 1 }


11. What is aggregation in MongoDB?


Aggregation in MongoDB is a way of processing a large number of documents and transforming them into meaningful summarized results. It is similar to SQL’s GROUP BY clause. The most common way to perform aggregation is by using the aggregate() function with a pipeline of stages like $match, $group, $sort, etc.

Example:

db.orders.aggregate([
  { $group: { _id: "$customerId", total: { $sum: "$amount" } } }
])

- - Output:
[ { "_id": "cust123", "total": 400 }, { "_id": "cust456", "total": 250 } ]


12. What is a replica set in MongoDB?


A replica set is a group of MongoDB servers that maintain the same data set to provide high availability and redundancy. It consists of one primary node and multiple secondary nodes. The primary node receives all write operations, and the secondaries replicate data from the primary. If the primary fails, one of the secondaries is automatically elected to become the new primary.



13. What is sharding in MongoDB?


Sharding is the process of distributing data across multiple machines to support deployments with large data sets and high throughput. It helps in horizontal scaling by dividing the data into smaller parts called shards, which are stored in separate nodes. The mongos router directs queries to the appropriate shard.



14. What are the different data types supported by MongoDB?


MongoDB supports a wide range of data types including:

  • String
  • Number (int, long, double, decimal)
  • Boolean
  • Date
  • Array
  • Object
  • Null
  • ObjectId
  • Binary Data



15. What is the use of the ObjectId in MongoDB?


ObjectId is the default value for the _id field and serves as the primary key for each document. It is a 12-byte identifier consisting of:

  • 4 bytes for the timestamp
  • 5 bytes for a random value
  • 3 bytes for an incrementing counter
This ensures uniqueness and provides some useful metadata such as the creation time of the document.



16. How do you update a document in MongoDB?


You can update documents in MongoDB using the updateOne(), updateMany(), or replaceOne() methods. These methods allow you to modify fields, add new ones, or replace entire documents. The $set operator is commonly used to update specific fields.

Example:

db.users.updateOne(
  { name: "Alice" },
  { $set: { age: 30 } }
)

- - Output:
{ "acknowledged" : true, "matchedCount" : 1, "modifiedCount" : 1 }


17. What is the difference between find() and findOne() in MongoDB?


- find(): Returns a cursor to all documents that match the query. You can iterate over the cursor to access all matching documents.
- findOne(): Returns a single document that matches the query. It stops scanning after finding the first match.

Example:

db.users.find({ age: { $gt: 25 } })
db.users.findOne({ name: "Bob" })

- - Output (findOne):
{ "_id": ObjectId("..."), "name": "Bob", "age": 28 }


18. How does indexing work in MongoDB?


Indexing in MongoDB improves the performance of queries by allowing the database to find data without scanning every document in a collection. The most common type is the single field index. You can also create compound indexes, text indexes, geospatial indexes, etc.
Indexes are created using the createIndex() method.

Example:

db.users.createIndex({ age: 1 })

- - Output:
"age_1"


19. What is a capped collection in MongoDB?


A capped collection is a fixed-size collection that maintains insertion order. When the specified size is reached, the oldest documents are automatically overwritten by newer ones.
It is useful for logging, caching, and other use-cases where you want to keep only the most recent data.

Example:

db.createCollection("logs", { capped: true, size: 1048576 })

- - Output:
{ "ok" : 1 }


20. How do you delete documents in MongoDB?


You can delete documents using deleteOne() or deleteMany() methods.
- deleteOne(): Deletes the first document that matches the filter.
- deleteMany(): Deletes all documents that match the filter.

Example:

db.users.deleteOne({ name: "Alice" })

- - Output:
{ "acknowledged" : true, "deletedCount" : 1 }


21. What is the aggregation framework in MongoDB?


The aggregation framework in MongoDB is used for data processing and transformation. It works like a data pipeline, where documents pass through multiple stages such as $match, $group, $sort, $project, etc. It is powerful for performing complex data analysis and computations directly within MongoDB.

Example:

db.orders.aggregate([
  { $match: { status: "delivered" } },
  { $group: { _id: "$customerId", total: { $sum: "$amount" } } },
  { $sort: { total: -1 } }
])

- - Output:
[ { "_id": 123, "total": 1500 }, { "_id": 456, "total": 1000 } ]


22. What is a replica set in MongoDB?


A replica set is a group of MongoDB servers that maintain the same data set, providing redundancy and high availability. One node is the primary that receives all write operations, and the others are secondaries that replicate data from the primary. In case the primary fails, an automatic election promotes one of the secondaries to be the new primary.



23. What is sharding in MongoDB?


Sharding is the process of distributing data across multiple machines to support horizontal scaling. It helps MongoDB handle large datasets and high-throughput operations by partitioning data into smaller pieces called shards. MongoDB uses a sharding key to determine the distribution of data.



24. What is the difference between embedded documents and referenced documents?


- Embedded Documents: Store related data in the same document. It provides fast read operations and atomicity.
- Referenced Documents: Use references (ObjectId) to link documents stored in different collections. It is more normalized and scalable.

Example:

// Embedded:
{ _id: 1, name: "John", address: { city: "NY", zip: "10001" } }

// Referenced:
{ _id: 1, name: "John", addressId: ObjectId("abc123") }
{ _id: "abc123", city: "NY", zip: "10001" }


25. How do you perform sorting in MongoDB?


MongoDB provides the sort() method to order query results based on field values. Use 1 for ascending order and -1 for descending order.

Example:

db.users.find().sort({ age: -1 })

- - Output:
Users sorted from oldest to youngest


26. What is the use of the ObjectId in MongoDB?


In MongoDB, every document stored in a collection requires a unique identifier, which is the _id field. If not provided explicitly, MongoDB generates an ObjectId by default. It is a 12-byte identifier consisting of:

  • 4-byte timestamp
  • 5-byte random value (machine + process)
  • 3-byte incrementing counter

This structure ensures uniqueness across different machines and time, and allows for efficient indexing.



27. How do you update a document in MongoDB?


MongoDB provides several update methods such as updateOne(), updateMany(), and replaceOne(). You can use update operators like $set, $inc, $unset to modify specific fields in a document.

Example:

db.users.updateOne(
  { name: "John" },
  { $set: { age: 30 } }
)

- - Output:
{ "acknowledged" : true, "matchedCount" : 1, "modifiedCount" : 1 }


28. What is a capped collection in MongoDB?


A capped collection is a fixed-size collection that maintains insertion order and automatically overwrites the oldest documents when the size limit is reached. It is ideal for logging or real-time data like sensor outputs.

Example:

db.createCollection("log", { capped: true, size: 100000 })


29. What is the use of $lookup in MongoDB?


The $lookup operator is used in aggregation to perform a left outer join between two collections. It allows you to fetch related documents from another collection based on a common field.

Example:

db.orders.aggregate([
  { $lookup: {
    from: "customers",
    localField: "cust_id",
    foreignField: "_id",
    as: "customer_info"
  } }
])

- - Output:
Each order document includes an array field customer_info with matched customer data.


30. How do you delete a document from a MongoDB collection?


MongoDB provides deleteOne() to delete a single document and deleteMany() to delete multiple documents that match a filter.

Example:

db.users.deleteOne({ name: "John" })

- - Output:
{ "acknowledged" : true, "deletedCount" : 1 }

Mongo DB Advanced

1. What are MongoDB indexes and how do they improve query performance?


Indexes in MongoDB are special data structures that store a small portion of the collection’s data set in an easily traversable form. They are used to improve the speed and efficiency of query operations by allowing MongoDB to quickly locate documents without scanning every one in a collection.

MongoDB supports various types of indexes including:

  • Single Field Index
  • Compound Index
  • Multikey Index
  • Text Index
  • Hashed Index
  • Geospatial Index
However, creating too many indexes can increase write overhead and storage requirements.



2. What is the Aggregation Framework in MongoDB?


The Aggregation Framework is a powerful feature in MongoDB used to process data records and return computed results. It allows for operations like filtering, grouping, sorting, reshaping, and more.

It uses a pipeline approach where documents pass through stages:

  • $match: Filters documents.
  • $group: Groups documents by a specified identifier.
  • $project: Reshapes documents by adding, removing, or renaming fields.
  • $sort, $limit, $skip: For sorting and pagination.



3. How does MongoDB handle replication and what is a replica set?


MongoDB uses replica sets to provide redundancy and high availability. A replica set is a group of mongod instances that maintain the same data set.

Key components of replication:

  • Primary: Handles all write operations.
  • Secondaries: Replicate data from the primary and can serve read requests (if enabled).
  • Arbiter: Participates in elections but does not hold data.
If the primary fails, an election is held to promote a secondary to primary automatically.



4. What is sharding in MongoDB?


Sharding is the process of distributing data across multiple machines to support horizontal scaling. MongoDB uses sharding to handle large data sets and high throughput operations.

Components include:

  • Shard: Each holds a subset of the data.
  • Config Servers: Store metadata and configuration settings.
  • Query Routers (mongos): Route client requests to appropriate shards.



5. What is the difference between a primary key in SQL and _id in MongoDB?


In MongoDB, the _id field acts as a primary key for documents in a collection. It is a unique identifier automatically added to every document if not provided.

Differences from SQL primary key:

  • Required: _id is mandatory in MongoDB documents.
  • Type: It can be any type (commonly ObjectId), unlike SQL primary keys which are often numeric.
  • Uniqueness: MongoDB enforces uniqueness on _id by default.



6. How does MongoDB handle transactions?


MongoDB supports multi-document ACID transactions starting from version 4.0 for replica sets and 4.2 for sharded clusters. Transactions in MongoDB allow applications to group multiple read and write operations into a single atomic operation.

Key points:

  • Uses session.startTransaction() and session.commitTransaction()
  • Ensures atomicity, consistency, isolation, and durability.
  • Ideal for financial or critical multi-document updates.
  • Impacts performance due to overhead, so use judiciously.



7. What is a capped collection in MongoDB?


A capped collection is a fixed-size, circular collection that automatically overwrites the oldest documents when it reaches its maximum size. It preserves the insertion order and is ideal for logging and caching scenarios.

Features:

  • High insertion performance.
  • Maintains insertion order.
  • Does not support document deletion or updates that increase document size.



8. What is a TTL index in MongoDB and how is it used?


TTL (Time-To-Live) indexes allow automatic deletion of documents after a specified time. It is useful for storing temporary data such as sessions, logs, or cache.

To create a TTL index:

db.sessions.createIndex({ "createdAt": 1 }, { expireAfterSeconds: 3600 })

This deletes documents 1 hour after the createdAt time.



9. What is the difference between embedded and referenced documents in MongoDB?


MongoDB supports two main ways to model relationships between documents:

  • Embedded Documents: Store related data in the same document. Better for performance and atomicity.
  • Referenced Documents: Store data in separate documents and use manual references. Suitable for normalization and large related datasets.

Choosing between the two depends on query patterns, document size limits, and update frequency.



10. How can you improve MongoDB query performance?


MongoDB query performance can be improved through:

  • Indexing: Use appropriate indexes for your queries.
  • Projection: Return only required fields.
  • Query Optimization: Use explain("executionStats") to analyze performance.
  • Schema Design: Optimize schema based on access patterns.
  • Avoid $where: Don’t use JavaScript-based queries unless necessary.



11. What is the Aggregation Framework in MongoDB?


The Aggregation Framework is a powerful tool in MongoDB for data processing and transformation. It processes data records and returns computed results, similar to SQL’s GROUP BY operations.

Common aggregation stages include:

  • $match – Filters documents based on conditions.
  • $group – Groups documents by a specified identifier and performs accumulations.
  • $project – Modifies the structure of documents.
  • $sort – Sorts documents.
  • $limit and $skip – Control the number of documents returned.



12. What is the purpose of the $lookup operator?


The $lookup operator performs a left outer join to another collection in the same database to filter in documents from the “joined” collection.

Example:

db.orders.aggregate([
  { $lookup: {
    from: "customers",
    localField: "customer_id",
    foreignField: "_id",
    as: "customer_info"
  } }
])



13. What is a Sharded Cluster in MongoDB?


A sharded cluster is a method of distributing data across multiple servers or shards in MongoDB. It helps scale horizontally to handle large datasets and high-throughput applications.

Components:

  • Shard: Stores a subset of the data.
  • Config Server: Stores metadata and configuration settings.
  • Query Router (mongos): Routes queries to the appropriate shards.



14. How does MongoDB handle indexing for performance?


MongoDB uses B-tree-based indexes to quickly locate data without scanning every document. Types of indexes include:

  • Single Field Index
  • Compound Index
  • Multikey Index – For array fields
  • Text Index – For full-text search
  • Hashed Index – For sharding
  • Wildcard Index – Indexes all fields
Use db.collection.getIndexes() to list existing indexes.



15. What is the difference between $inc and $set operators in MongoDB?


These are update operators used to modify document values:

  • $set: Sets the value of a field. Creates the field if it doesn’t exist.
  • $inc: Increments a field by a specified value. Creates the field if it doesn’t exist.

Example:
db.users.updateOne(
  { name: "John" },
  { $set: { city: "Delhi" }, $inc: { age: 1 } }
)



16. What are MongoDB Transactions and when are they used?


Transactions in MongoDB allow multiple operations on multiple documents or collections to be executed atomically. This means either all operations succeed, or none do—maintaining data consistency.

Transactions are mostly used in:

  • Financial applications (e.g., transferring money between accounts)
  • Systems requiring ACID compliance
  • Multi-document updates
They are supported in replica sets (from MongoDB 4.0) and in sharded clusters (from 4.2).

21. What is the difference between MongoDB and RDBMS?


MongoDB is a NoSQL database, while RDBMS (like MySQL, PostgreSQL) is a traditional relational database. Here's a comparison:

  • Schema: MongoDB is schema-less; RDBMS requires predefined schemas.
  • Data Format: MongoDB uses JSON-like documents; RDBMS uses tables with rows and columns.
  • Joins: RDBMS supports joins natively; MongoDB uses embedding or $lookup aggregation.
  • Scalability: MongoDB is horizontally scalable; RDBMS is usually vertically scalable.
  • Transactions: RDBMS is transactional by design; MongoDB supports multi-document transactions since version 4.0.

27. How does MongoDB handle concurrency?


MongoDB uses a multi-granularity locking mechanism to ensure data consistency during concurrent access:

  • Uses a reader-writer lock at the document level in WiredTiger (the default storage engine).
  • Multiple readers can access simultaneously, but only one writer per document at a time.
  • Supports optimistic concurrency control using findAndModify and $inc.

29. Explain the purpose of the db.currentOp() command.


The db.currentOp() command provides a snapshot of all currently running operations in the MongoDB instance. It is used to monitor long-running or stuck operations and for performance diagnostics.

30. What are transactions in MongoDB and how are they used?


Transactions in MongoDB allow multiple operations to execute in an all-or-nothing fashion, ensuring atomicity and consistency. This feature is available for replica sets (since v4.0) and sharded clusters (since v4.2).

const session = db.getMongo().startSession();
session.startTransaction();

try {
  session.getDatabase("store").inventory.updateOne({ item: "pen" }, { $inc: { qty: -2 } });
  session.getDatabase("store").orders.insertOne({ item: "pen", qty: 2 });
  session.commitTransaction();
} catch (error) {
  session.abortTransaction();
}

1. What is the difference between MongoDB's WiredTiger and MMAPv1 storage engines?


WiredTiger is the default storage engine in MongoDB since version 3.2. It supports document-level locking and compression.
MMAPv1, the older engine, uses memory-mapped files with collection-level locking and no compression.

  • WiredTiger: Better concurrency, compression support, efficient memory usage.
  • MMAPv1: Simple and fast for workloads with low concurrency.


2. How does MongoDB handle sharded cluster queries internally?


When a query is sent to a sharded MongoDB cluster:

  • The query router (mongos) determines which shards to contact using the shard key.
  • If the query is targeted, only relevant shards are queried. If it's scatter-gather, all shards are queried.
  • Each shard processes the query locally and returns results to mongos.
  • mongos merges, sorts, and returns the final response to the client.


3. What is the purpose of the $lookup aggregation stage in MongoDB?


$lookup performs a left outer join to combine documents from two collections. It's used in the aggregation pipeline to match and merge data from another collection.

Example:

db.orders.aggregate([
{ $lookup: {
from: "products",
localField: "product_id",
foreignField: "_id",
as: "product_details"
}}
])

- - Output:
Orders with embedded product details from the "products" collection.


4. How do you create a TTL (Time To Live) index in MongoDB, and what are its use cases?


A TTL index automatically removes expired documents after a set time. Useful in session expiration, log cleanup, and cache scenarios.

Example:

db.sessions.createIndex(
{ "createdAt": 1 },
{ expireAfterSeconds: 3600 }
)

- - Output:
Documents older than 1 hour will be deleted automatically by MongoDB.


5. Explain the concept of write concern in MongoDB and its impact on consistency.


Write concern determines the level of acknowledgment requested from MongoDB for write operations. It affects consistency and durability guarantees.

  • w:1: Acknowledged by primary only.
  • w:majority: Acknowledged by the majority of replica set members.
  • wtimeout: Time to wait for write acknowledgment before returning an error.


6. How does MongoDB ensure high availability in a replica set?


MongoDB provides high availability using replica sets, which consist of a primary and multiple secondary nodes.

  • If the primary node fails, an automatic election occurs to promote a secondary to primary.
  • Clients automatically reconnect to the new primary with minimal downtime.
  • Writes always go to the primary, while reads can be configured to use secondaries based on read preferences.


7. What is the difference between $merge and $out stages in aggregation?


Both stages write aggregation results to a collection, but they differ in functionality:

  • $out: Replaces or creates a collection with the aggregation result. It drops the collection if it already exists.
  • $merge: Merges results into an existing collection with more flexible modes like merge, replace, or keepExisting.


8. How does MongoDB handle large data sets efficiently in aggregation pipelines?


MongoDB uses the following techniques for efficient aggregation on large datasets:

  • Indexes are used in the initial $match stage to reduce input size.
  • Disk use is enabled with allowDiskUse: true for pipelines exceeding memory limits.
  • Streaming of intermediate results avoids unnecessary memory buildup.


9. What are Change Streams in MongoDB and how are they used?


Change Streams allow real-time monitoring of data changes (insert, update, delete, etc.) in collections, databases, or entire clusters without polling.

Example:

const changeStream = db.collection("orders").watch();
changeStream.on("change", (next) => {
console.log("Change detected:", next);
});

- - Output:
Real-time event logs whenever documents in "orders" are modified.


10. What is the role of journaling in MongoDB?


Journaling in MongoDB ensures durability by recording all write operations before applying them to the data files. This allows MongoDB to recover data to a consistent state in case of crashes.

  • By default, journaling is enabled for 64-bit builds.
  • Data is flushed to disk every 100ms, and the journal is replayed during recovery.
  • Works in conjunction with write concern to provide strong durability guarantees.


11. How does MongoDB support multi-document transactions?


MongoDB supports multi-document ACID transactions starting from version 4.0 for replica sets and 4.2+ for sharded clusters.

  • Transactions provide atomicity across multiple operations and documents.
  • They follow a similar syntax to relational databases using startSession(), startTransaction(), commitTransaction(), and abortTransaction().

Example:

const session = client.startSession();
session.startTransaction();
try {
orders.insertOne({item: "Laptop"}, {session});
payments.insertOne({status: "Paid"}, {session});
session.commitTransaction();
} catch (e) {
session.abortTransaction();
}

- - Output:
Both inserts succeed or both are rolled back on failure.


12. What are MongoDB's write concern levels and how do they impact performance and durability?


Write concern in MongoDB defines the level of acknowledgment requested from the database after a write operation.

  • Unacknowledged (w: 0): No confirmation, fastest but unsafe.
  • Acknowledged (w: 1): Default level, confirms receipt by primary.
  • Majority (w: "majority"): Ensures durability by waiting for majority of nodes to confirm write.


13. What is a MongoDB bucket pattern and when should you use it?


The bucket pattern is a data modeling technique used to store multiple related records in a single document (a "bucket") to reduce read operations.

  • Ideal for time-series data, like logs or metrics.
  • Reduces the number of documents and increases read efficiency.
  • Must manage document size to stay within the 16MB limit.


14. How do you optimize large-scale aggregations in sharded collections?


To optimize aggregations on sharded collections:

  • Use $match and $project stages early to reduce data transfer.
  • Ensure shard key is used in the query for targeted operations.
  • Use $merge to combine results efficiently.
  • Enable allowDiskUse for memory-intensive pipelines.


15. What is the purpose of $graphLookup in MongoDB?


$graphLookup is an aggregation stage that allows recursive joins on a collection to model graph-style relationships.

  • Used for hierarchy traversal, like finding subordinates in an organization or product category trees.
  • Supports depth control and cycle detection.

Example:

db.employees.aggregate([
{ $match: { name: "Alice" } },
{ $graphLookup: {
from: "employees",
startWith: "$_id",
connectFromField: "_id",
connectToField: "managerId",
as: "reportingHierarchy"
}}
])

- - Output:
Nested array of all employees reporting to Alice, directly or indirectly.


16. How can you implement full-text search in MongoDB?


MongoDB provides native full-text search using text indexes. These indexes support searching for string content in documents using the $text operator.

  • Text indexes can include fields with string content and analyze them using stemming and stop-word removal.
  • Supports case-insensitive and language-specific search.

Example:

db.articles.createIndex({ content: "text" });
db.articles.find({ $text: { $search: "database" } });

- - Output:
All documents containing the word “database” in the content field.


17. What is the purpose of the $merge stage in MongoDB aggregation?


The $merge stage in an aggregation pipeline writes the result of the aggregation to a specified collection.

  • It can insert new documents or update existing ones.
  • Useful for ETL operations, materialized views, or merging aggregated results.

Example:

db.sales.aggregate([
{ $group: { _id: "$product", total: { $sum: "$amount" } } },
{ $merge: "product_totals" }
])

- - Output:
Aggregated totals per product are written to the product_totals collection.


18. How do you handle schema evolution in MongoDB?


MongoDB's flexible schema allows documents in the same collection to have different structures. However, schema evolution still requires careful planning:

  • Use versioning fields to track document structure versions.
  • Migrate old documents using update scripts or background jobs.
  • Validate documents using $jsonSchema with validation rules.


19. What are the internal storage engines in MongoDB and how do they affect performance?


MongoDB primarily uses the WiredTiger storage engine by default, which provides:

  • Document-level concurrency control for high throughput.
  • Compression (snappy/zlib/zstd) to reduce disk usage.
  • Checkpointing and journaling for crash recovery.

Other engines like In-Memory or Encrypted are available for special use cases (e.g., ephemeral data or security compliance).



20. How does MongoDB ensure horizontal scalability with sharding?


Sharding in MongoDB allows the distribution of data across multiple servers (shards) to support horizontal scaling.

  • Collections are partitioned into chunks based on a shard key.
  • Each chunk is assigned to a shard and managed by a mongos query router.
  • MongoDB handles rebalancing, chunk migration, and distributed queries automatically.


21. How does MongoDB’s aggregation pipeline optimize performance internally?


MongoDB optimizes aggregation pipelines by reordering certain stages, applying indexes early, and pushing down operations closer to the data source. Key performance features include:

  • Pipeline optimization: MongoDB may merge or reorder non-dependent stages for efficiency.
  • Index usage: Stages like $match and $sort can benefit from indexes when placed early.
  • Covered queries: If all fields are indexed and projected, MongoDB can avoid fetching documents from disk.


22. What is a change stream in MongoDB and how is it used?


Change streams allow real-time, event-driven applications by watching changes in collections or databases without polling. They rely on the oplog and are available only on replica sets or sharded clusters.

  • Use watch() to monitor insert, update, delete, and replace operations.
  • Ideal for real-time analytics, notifications, and data synchronization.

Example:

const changeStream = db.collection.watch();
changeStream.on("change", next => {
  console.log(next);
});

- - Output:
A JSON change event document whenever a modification happens.


23. What are MongoDB buckets and how are they used in time-series collections?


In time-series collections, MongoDB groups measurements into internal structures called buckets to store time-based data efficiently. Each bucket contains:

  • A time range (e.g., 1 minute of sensor data).
  • Multiple measurements compressed together.
  • Meta fields for indexing and filtering.

They improve compression, reduce write amplification, and speed up query performance.



24. What is the role of election in MongoDB replication and how does it work?


In a MongoDB replica set, elections determine which node becomes the primary. When the primary fails, an election ensures availability:

  • Each eligible secondary can start an election.
  • Voting is done by all nodes using a term-based consensus.
  • Majority vote wins, and the new primary takes over writes.

Automatic failover ensures high availability and minimizes downtime.



25. How does MongoDB handle ACID transactions, and what are best practices?


MongoDB supports multi-document ACID transactions starting in version 4.0 for replica sets and 4.2 for sharded clusters. Transactions ensure atomicity, consistency, isolation, and durability.

  • Use session.startTransaction() to begin a transaction.
  • Keep transactions short to reduce lock contention.
  • Best used for related operations like transferring funds or batch updates.

Example:

const session = client.startSession();
session.startTransaction();
try {
  db.accounts.updateOne({name: "A"}, {$inc: {balance: -100}}, {session});
  db.accounts.updateOne({name: "B"}, {$inc: {balance: +100}}, {session});
  session.commitTransaction();
} catch (e) {
  session.abortTransaction();
}

- - Output:
Atomic update of both accounts or none if an error occurs.


26. What is snapshot isolation in MongoDB, and how does it work in transactions?


Snapshot isolation in MongoDB ensures that all read operations within a multi-document transaction see a consistent view of the data as it was at the start of the transaction. This avoids read anomalies like dirty reads and non-repeatable reads.

  • All reads within a transaction operate on a snapshot from the beginning of the transaction.
  • Helps maintain data consistency even if other operations modify the data concurrently.
  • Write conflicts are detected at commit time, not during the transaction.


27. What is a resumable change stream and how does MongoDB support it?


MongoDB change streams are resumable, meaning you can continue watching from a specific point using a resumeToken. This ensures reliability in case of temporary disconnections.

  • Each change stream event includes a _id field that acts as a resume token.
  • You can restart the stream with the resumeAfter or startAfter option.

Example:

const changeStream = db.collection.watch();
changeStream.on("change", next => {
  const resumeToken = next._id;
  // Use resumeToken to resume if needed
});

- - Output:
A stream of changes that can continue seamlessly after disruptions.


28. How do you analyze and tune query performance in MongoDB?


MongoDB provides several tools and strategies to analyze and improve query performance:

  • Explain Plans: Use db.collection.explain() to inspect how MongoDB executes a query.
  • Indexing: Ensure appropriate indexes on fields used in $match, $sort, and joins.
  • Aggregation Tuning: Move filtering and limiting stages early in pipelines.
  • Monitor Tools: Use MongoDB Atlas Performance Advisor or mongotop, mongostat.


29. What is hybrid index scanning in MongoDB 7.0+ and how does it help?


Hybrid index scanning is a feature introduced in MongoDB 7.0 that allows the query engine to merge results from multiple indexes when a single index does not satisfy the entire query efficiently.

  • Improves performance for complex queries with multiple indexed fields.
  • Allows partial scanning and deduplication of results across indexes.
  • Can be seen in explain() output with IXSCAN and AND_HASH stages.


30. How would you secure a production-grade MongoDB deployment?


Securing MongoDB involves multiple layers of protection:

  • Authentication: Enable access control and create users with roles using SCRAM-SHA-256 or LDAP.
  • Authorization: Apply Role-Based Access Control (RBAC) to restrict actions.
  • Encryption: Use TLS for in-transit data, and enable at-rest encryption (FLE or storage engine encryption).
  • Auditing: Enable audit logs to track access and changes.
  • Network Security: Bind MongoDB only to trusted IPs, use firewalls, and avoid exposing ports publicly.
