Java Beginner


1. What is Java?


Java is a high-level, class-based, object-oriented programming language developed by Sun Microsystems in 1995 and now maintained by Oracle Corporation. It follows the principle of "Write Once, Run Anywhere" (WORA), meaning compiled Java code can run on any platform that supports the Java Virtual Machine (JVM). Java is widely used for building enterprise-scale applications, Android apps, web servers, and backend systems due to its stability, security, and large developer community.



2. What are the main features of Java?


Java provides several powerful features:
- Platform Independent: Bytecode runs on any JVM, regardless of the platform.
- Object-Oriented: Everything in Java is treated as an object.
- Robust: Java handles errors using strong memory management and exception handling.
- Secure: Java has built-in security features like bytecode verification and a security manager.
- Multithreaded: Java supports concurrent execution using threads.
- High Performance: The Just-In-Time (JIT) compiler improves performance by compiling bytecode to native machine code at runtime.



3. What is the Java Virtual Machine (JVM)?


The Java Virtual Machine (JVM) is an abstract computing machine that enables a computer to run Java programs. It loads, verifies, and executes Java bytecode. The JVM is platform-dependent but allows Java programs to be platform-independent. It also provides features such as automatic memory management (garbage collection), runtime optimization, and security enforcement.



4. What is the difference between JDK, JRE, and JVM?


- JVM (Java Virtual Machine): It runs Java bytecode and is responsible for the runtime environment.
- JRE (Java Runtime Environment): It includes the JVM and standard Java class libraries. It is used to run Java applications.
- JDK (Java Development Kit): It includes the JRE and development tools such as the Java compiler (`javac`). It is required for developing Java applications.



5. What is a Class in Java?


A class in Java is a blueprint or prototype from which objects are created. It defines the structure and behavior (fields and methods) that the objects of the class will have. For example, a `Car` class can define properties like color, model, and speed, and methods like accelerate and brake.



6. What is an Object in Java?


An object is an instance of a class. It represents a real-world entity that has state (attributes) and behavior (methods). In Java, objects are created using the `new` keyword. For example:
Car myCar = new Car();



7. What is the main() method in Java?


The `main()` method is the entry point of any Java application. It is defined as:
public static void main(String[] args)
- public: Accessible from anywhere.
- static: No object is needed to call this method.
- void: No return value.
- String[] args: Accepts command-line arguments.



8. What is the difference between method overloading and method overriding?


- Method Overloading: Occurs within the same class when two or more methods have the same name but different parameter lists. It is a compile-time polymorphism.
- Method Overriding: Occurs in a subclass when a method defined in the parent class is redefined with the same name and parameters. It is runtime polymorphism.



9. What are constructors in Java?


A constructor is a special method used to initialize objects. It has the same name as the class and no return type. Java provides a default constructor, but you can also create parameterized constructors to set initial values.
public Car(String model) { this.model = model; }



10. What is inheritance in Java?


Inheritance is one of the core concepts of OOP where one class (child/subclass) inherits the fields and methods of another class (parent/superclass). This promotes code reuse and establishes an "is-a" relationship.
class Dog extends Animal



11. What is Polymorphism in Java?


Polymorphism means "many forms". In Java, it allows one method or object to behave differently based on the context. It can be achieved in two ways:

  • Compile-time Polymorphism (Method Overloading): Same method name with different parameter lists in the same class.

  • Runtime Polymorphism (Method Overriding): Subclass provides a specific implementation of a method already defined in the parent class.

Example:

class Animal {
  void sound() {
    System.out.println("Animal makes a sound");
  }
}

class Dog extends Animal {
  void sound() {
    System.out.println("Dog barks");
  }
}

public class TestPolymorphism {
  public static void main(String[] args) {
    Animal a = new Dog();
    a.sound(); // Dog barks
  }
}


12. What is Encapsulation in Java?


Encapsulation is the concept of wrapping data (variables) and code (methods) together as a single unit. It protects the internal state of an object by using access modifiers.

  • Declare variables private.

  • Provide public getter and setter methods to access and modify the private variables.

Example:

class Employee {
  private int salary;

  public int getSalary() {
    return salary;
  }

  public void setSalary(int sal) {
    salary = sal;
  }
}


13. What is Abstraction in Java?


Abstraction is the process of hiding internal details and showing only the necessary features of an object. It helps reduce complexity and increase efficiency. In Java, abstraction is achieved using:

  • Abstract Classes: A class declared with the abstract keyword that may contain abstract (without body) and non-abstract methods.

  • Interfaces: A completely abstract class that can have only abstract methods (Java 8+ supports default/static methods).

Example:

abstract class Shape {
  abstract void draw();
}

class Circle extends Shape {
  void draw() {
    System.out.println("Drawing Circle");
  }
}


14. What is the difference between an Interface and an Abstract Class in Java?


  • Abstract Class can have both abstract and concrete methods, whereas Interface can only have abstract methods (until Java 7).

  • Interface supports multiple inheritance, abstract classes do not.

  • Variables in Interface are implicitly public static final.

  • Abstract Class can have constructors and member variables; Interface cannot (before Java 8).

Example:

interface Drawable {
  void draw();
}

abstract class Shape {
  abstract void display();
}


15. What is the difference between Array and ArrayList in Java?


  • Array: Fixed in size, can hold primitive types and objects.
  • ArrayList: Dynamic size, only holds objects, and provides methods for manipulation.



16. What is the difference between == and equals() in Java?


  • ==: Compares the reference (memory address) of two objects.

  • equals(): Compares the content/value of two objects (can be overridden).

Example:

String a = new String("Hello");
String b = new String("Hello");
System.out.println(a == b); // false
System.out.println(a.equals(b)); // true

- - Output:

true


17. What are static methods and variables in Java?


Static methods and variables belong to the class rather than instances of the class. They are shared across all objects. They are accessed using the class name and don't require object creation.

Example:

class MathUtils {
  static int count = 0;
  static void printCount() {
    System.out.println("Count: " + count);
  }
}

MathUtils.count = 10;
MathUtils.printCount();

- - Output:
Count: 10


18. What is the final keyword in Java?


The final keyword in Java is used to restrict the user. It can be applied to variables, methods, and classes:

  • Final variable: Value cannot be changed once assigned.

  • Final method: Cannot be overridden by subclasses.

  • Final class: Cannot be inherited.

Example:

final int x = 100;
System.out.println(x);
x = 200; // Compile-time error

- - Output:
Compile-time error: cannot assign a value to final variable 'x'


19. What is the use of this keyword in Java?


The this keyword is used to refer to the current object inside a class. It's commonly used to differentiate between instance variables and parameters with the same name.

Example:

    this.model = model;
  }

20. What are access modifiers in Java?


Access modifiers control the visibility of classes, methods, and variables. Java has four types:

  • private: Accessible only within the class.

  • default (no modifier): Accessible within the same package.

  • protected: Accessible within the same package and subclasses.

  • public: Accessible from anywhere.



21. What is a Java Wrapper Class, and why is it used?


Wrapper classes provide object representations for primitive data types (e.g., Integer, Double). They’re useful when you need objects instead of primitives (e.g. in Collections like ArrayList<Integer>) and offer utility methods for parsing and conversion.



22. What is Autoboxing and Unboxing in Java?


Autoboxing is the automatic conversion of primitive types into their corresponding wrapper classes (e.g., int → Integer), and Unboxing is the reverse process.

Example:

int x = num; // Unboxing
System.out.println(num + x);

23. What is Exception Handling in Java?


Java handles runtime errors using exceptions and provides a robust try-catch mechanism to manage them. You can use try, catch, finally, and throw to manage error cases without crashing the program.



Example:

try {
  int result = 10 / 0;
} catch (ArithmeticException e) {
  System.out.println("Division by zero!");
} finally {

}

24. What is the difference between Checked and Unchecked Exceptions?


- Checked Exceptions (e.g., IOException) are checked at compile time and must be handled. - Unchecked Exceptions (e.g., NullPointerException) are runtime exceptions and don’t require mandatory handling.



25. What is a Java Package and why is it used?


A package groups related classes and interfaces together, providing:
- **Namespace management**, preventing naming conflicts
- **Access control**, as scoped with package-private visibility
- **Organization**, making large codebases easier to manage



26. What is the difference between String, StringBuilder, and StringBuffer in Java?


- String: Immutable. Once created, it cannot be changed.
- StringBuilder: Mutable, faster than StringBuffer, but not thread-safe.
- StringBuffer: Mutable and thread-safe (synchronized), but slightly slower than StringBuilder.

Example:

str.concat(" World");
System.out.println(str); // Immutable, result still "Hello"

StringBuilder sb = new StringBuilder("Hello");
sb.append(" World");
System.out.println(sb); // Mutable, result is "Hello World"

- - Output:

Hello World

29. What is the use of the 'this' keyword in Java?

A Singleton class allows only one instance to exist during the application lifecycle. It is used for things like database connections or logging services.

33. What is a Marker Interface?

35. What is method chaining in Java?


Method chaining is a technique where multiple methods are called on the same object in a single statement. Each method returns the object so the next method can be called.

Example:

class Student {
  Student setName(String name) {
    System.out.println("Name: " + name);
    return this;
  }
  Student setAge(int age) {
    System.out.println("Age: " + age);

public class Main {

  }

1. What is the difference between HashMap, LinkedHashMap, and TreeMap in Java?


These three classes are implementations of the Map interface, but they differ in internal data structure and order of elements:

  • HashMap: Uses a hash table. No guaranteed order of keys. Allows one null key and multiple null values.
  • LinkedHashMap: Maintains insertion order using a doubly-linked list. Useful when order matters.
  • TreeMap: Implements a Red-Black tree. Keys are stored in natural or custom order (sorted map). Does not allow null keys.


2. Explain the concept of Java Memory Model (JMM) and its relevance in multithreading.


The Java Memory Model (JMM) defines how threads interact through memory and what behaviors are allowed in concurrent execution. It ensures:

  • Visibility: Changes made by one thread to shared variables are visible to other threads.
  • Atomicity: Actions like reading/writing a variable are performed atomically.
  • Ordering: Rules to prevent instruction reordering that breaks correctness.
JMM provides the foundation for `volatile`, `synchronized`, and `java.util.concurrent` tools.


3. What is the difference between wait(), sleep(), and join() methods in Java?


  • wait(): Releases the lock and allows other threads to execute. It must be called from a synchronized block or method.
  • sleep(): Pauses the thread for a specified time but does not release the lock.
  • join(): Waits for another thread to finish execution before continuing.


4. How does Java handle memory management and garbage collection?


Java uses an automatic garbage collector to reclaim memory used by unreachable objects. The memory is divided into:

  • Young Generation: Stores short-lived objects. Minor GC occurs here.
  • Old Generation: Stores long-lived objects. Major GC (or Full GC) is triggered here.
  • Metaspace: Replaces PermGen from Java 8, stores class metadata.
Garbage collection algorithms include Serial, Parallel, CMS, and G1 GC.


5. What is the difference between final, finally, and finalize() in Java?


  • final: A keyword used to declare constants, prevent method overriding, or inheritance of classes.
  • finally: A block used with try-catch to execute important code like resource cleanup, regardless of exception.
  • finalize(): A method called by the garbage collector before an object is reclaimed. Deprecated from Java 9 onwards.


6. What are the different types of class loaders in Java?


Java uses class loaders to load classes at runtime. The main types are:
- Bootstrap ClassLoader: Loads core Java classes (e.g., java.lang).
- Extension ClassLoader: Loads classes from the `ext` directory.
- System/Application ClassLoader: Loads classes from the application's classpath.
Developers can also create custom class loaders to load classes in specific ways, often for modular systems or security.



7. What is the difference between `final`, `finally`, and `finalize()` in Java?


  • final: Used to declare constants, prevent method overriding, or inheritance.

  • finally: A block that always executes after try-catch for cleanup code.

  • finalize(): A method called by the garbage collector before destroying an object (deprecated in recent Java versions).


Example:

final int a = 10;

try {
  System.out.println("Try block");
} finally {
  System.out.println("Finally block executed");
}


8. What is the Java Memory Model (JMM)?


The Java Memory Model defines how threads interact through memory and what behaviors are allowed in concurrent programming. It handles:
- Visibility of variables across threads
- Instruction reordering by the compiler or CPU
- Happens-before relationships
This ensures consistency and safe multithreaded programming using `volatile`, `synchronized`, and other constructs.

11. What is the difference between `HashMap` and `ConcurrentHashMap`?


- HashMap is not thread-safe and can lead to data inconsistency when accessed by multiple threads concurrently.
- ConcurrentHashMap is thread-safe and designed for concurrent access by using internal segment locking.
- In HashMap, structure can be corrupted if modified while iterating, whereas ConcurrentHashMap avoids `ConcurrentModificationException`.



12. What is the volatile keyword in Java?


The volatile keyword ensures visibility and ordering of variables across threads. When a variable is declared volatile:
- Reads/writes go directly to main memory.
- It prevents threads from caching variables locally.
- It doesn’t guarantee atomicity; useful for flags and simple state changes.



13. How does Java handle memory management?


Java handles memory management using:
- Heap Memory: Stores objects and class instances.
- Stack Memory: Stores method calls and local variables.
- Garbage Collection: Automatically removes unused objects to free memory.
Java's Garbage Collector uses algorithms like Mark-and-Sweep, Generational GC, G1 GC, and ZGC in recent versions.



14. What is reflection in Java?


Reflection is a feature in Java that allows programs to inspect and manipulate classes, methods, and fields at runtime using classes in the java.lang.reflect package.
It is commonly used in frameworks, tools, and libraries like Spring and Hibernate.

16. What is the difference between checked and unchecked exceptions in Java?


- Checked Exceptions are checked at compile-time. The compiler ensures you handle or declare them using `try-catch` or `throws`. Examples: IOException, SQLException.
- Unchecked Exceptions are checked at runtime. These are subclasses of RuntimeException. Examples: NullPointerException, ArrayIndexOutOfBoundsException.



17. What is the Java Memory Model (JMM)?


The Java Memory Model defines how threads interact through memory and what behaviors are allowed in concurrent execution. It specifies:
- Rules about visibility of shared variables.
- Effects of synchronization and `volatile`.
- Reordering of instructions for performance.
JMM ensures visibility and ordering guarantees necessary for correct multithreaded behavior.

19. What is the Fork/Join framework in Java?


The Fork/Join framework is a parallel computing framework introduced in Java 7 that helps in executing tasks concurrently by breaking them into smaller subtasks (fork), and then combining the results (join).
It is part of the java.util.concurrent package and is useful for CPU-intensive operations.

21. What is the difference between `synchronized` block and `ReentrantLock`?


Both are used to provide thread safety, but there are differences:
- `synchronized` is a keyword with implicit lock management and no explicit lock/unlock mechanism.
- `ReentrantLock` (from `java.util.concurrent.locks`) allows more flexible lock control, including try-locking, interruptible locks, and fairness policies.
It also provides methods like lockInterruptibly(), tryLock(), and unlock() for fine-grained control.



22. What is the volatile keyword in Java?


The volatile keyword ensures that changes to a variable are always visible to all threads. It prevents caching of the variable and guarantees visibility and ordering. However, it does not ensure atomicity or synchronization of compound actions.


Example:

23. How does Java handle memory leaks?


Java uses automatic garbage collection to reclaim memory. However, memory leaks can still occur if object references are unintentionally held (e.g., in static collections).
Common causes:
- Static field holding reference to an object.
- Unclosed resources (e.g., streams, sockets).
- Listeners or callbacks not deregistered.
Tools like VisualVM or Eclipse MAT help detect memory leaks.



24. What are phantom references in Java?


A phantom reference is the weakest level of reference in Java, used to determine exactly when an object is removed from memory. It is used in conjunction with ReferenceQueue to do post-mortem cleanup activities after garbage collection.
Unlike soft/weak references, phantom references always return null on get().

1. What are the different memory areas allocated by the JVM?


The JVM divides memory into several areas for efficient program execution and memory management:
- Heap: Stores objects and class instances.
- Stack: Stores method call frames, local variables, and partial results.
- Method Area: Stores class-level data such as method and field information, runtime constant pool.
- Program Counter (PC) Register: Stores the address of the current executing instruction.
- Native Method Stack: Used for native (non-Java) method calls.



2. What is the difference between a strong, weak, soft, and phantom reference in Java?


Java provides different types of references to control memory more precisely, especially in cache implementations:

  • Strong Reference: The default type. Objects are not garbage collected as long as strong references exist.

  • Soft Reference: Objects are collected only when memory is low. Useful for implementing memory-sensitive caches.

  • Weak Reference: Objects are collected at the next GC cycle if only weak references are pointing to them.

  • Phantom Reference: Used to determine exactly when an object was removed from memory, before final cleanup.


3. Explain the concept of memory leaks in Java and how to detect them.


A memory leak in Java occurs when objects are no longer needed but are still referenced, preventing garbage collection. Over time, this can lead to increased memory usage and OutOfMemoryError.

Detection tools: VisualVM, JProfiler, Eclipse MAT, Java Flight Recorder. These tools help identify objects occupying memory without being released.



4. What is the volatile keyword in Java and how does it work?


The volatile keyword ensures visibility and ordering in multi-threaded environments. When a variable is declared volatile, updates to that variable are always visible to all threads.

It prevents threads from caching variables locally. Instead, every read/write is done directly from/to the main memory.


Example:

private volatile boolean flag = false;

public void setFlagTrue() {
    flag = true;
}
public void waitForFlag() {
    while (!flag) {
        // busy wait
    }
}


5. How does the Java Memory Model (JMM) handle thread communication and instruction reordering?


The JMM defines how threads interact through memory and what behaviors are allowed in concurrent execution. It specifies:

  • When writes by one thread become visible to another.

  • Instruction reordering and the rules to ensure visibility and atomicity.

  • Use of synchronized blocks, volatile variables, and final fields to establish happens-before relationships.


This prevents unexpected results from compiler or CPU optimizations in a concurrent environment.



6. What is the difference between ReentrantLock and synchronized block?


Both are used for thread synchronization, but they differ in features and flexibility:

  • synchronized: Simpler to use. The thread acquires an intrinsic lock automatically. Cannot try to acquire a lock with timeout or interruptibility.

  • ReentrantLock: More flexible. Allows interruptible lock acquisition, timeout, and tryLock. Also supports fair locking and condition variables for advanced thread coordination.


Example:

ReentrantLock lock = new ReentrantLock();

lock.lock();
try {
    // critical section
} finally {
    lock.unlock();
}


7. What are ThreadLocal variables in Java?


ThreadLocal provides thread-local variables, meaning each thread accessing the variable gets an isolated copy. It's useful when you want to avoid synchronization and ensure that variables are not shared between threads.


Example:

ThreadLocal<Integer> userId = new ThreadLocal<>();
userId.set(100);
Integer id = userId.get();


8. What is the difference between fail-fast and fail-safe iterators?


Iterators behave differently when the underlying collection is modified:

  • Fail-Fast: Throws ConcurrentModificationException if the collection is modified while iterating. Example: ArrayList, HashMap.

  • Fail-Safe: Allows modifications during iteration by working on a cloned copy. Example: CopyOnWriteArrayList, ConcurrentHashMap.



9. How does Garbage Collection work in Java? Explain G1 and CMS collectors.


Java uses automatic garbage collection to reclaim memory used by unreachable objects. JVM provides various collectors:

  • G1 (Garbage First): Breaks the heap into regions and prioritizes low-pause-time collection. Suitable for large heaps and real-time applications.

  • CMS (Concurrent Mark-Sweep): Minimizes pause times by performing most GC work concurrently with the application threads. It's deprecated in recent JDK versions.



10. What are functional interfaces and how are they used in Java 8?


A functional interface is an interface with only one abstract method. They are used primarily with lambda expressions and method references.

Java provides many built-in functional interfaces like Runnable, Callable, Consumer, Predicate, Function, etc.


Example:

@FunctionalInterface
interface Calculator {
    int add(int a, int b);
}

Calculator calc = (x, y) -> x + y;
System.out.println(calc.add(10, 20));

- - Output:
30


11. What is a memory leak in Java and how can it be avoided?


A memory leak in Java occurs when objects are no longer used by the application but are still referenced, preventing garbage collection. This leads to increased memory usage and potential OutOfMemoryError.

Common causes include:

  • Unclosed resources like InputStream, Connection.

  • Static collections holding object references indefinitely.

  • Event listeners not being removed.

Use tools like VisualVM or Eclipse MAT to detect memory leaks. Always release resources in finally blocks or use try-with-resources.



12. What is the volatile keyword in Java?


The volatile keyword in Java ensures that the value of a variable is always read from the main memory, not from a thread's local cache. It is used for variables accessed by multiple threads without using synchronization.

It guarantees visibility but not atomicity. Use it when updates are simple and do not depend on the current value (e.g., flags).


Example:

private volatile boolean running = true;

public void stop() {
    running = false;
}


13. What are method references in Java 8?


Method references are a shorthand notation of lambda expressions to call a method directly. They improve code readability.

Types of method references:

  • ClassName::staticMethod

  • object::instanceMethod

  • ClassName::new (for constructor references)

Example:

List<String> list = Arrays.asList("Java", "Python", "C++");
list.forEach(System.out::println);

14. What is the difference between Callable and Runnable in Java?


  • Runnable: Does not return a result and cannot throw a checked exception.

  • Callable: Returns a result (via Future) and can throw checked exceptions.

Example:

Callable<Integer> task = () -> { return 123; };
ExecutorService executor = Executors.newSingleThreadExecutor();
Future<Integer> future = executor.submit(task);
System.out.println(future.get());

- - Output:
123


15. What are default methods in interfaces?


Introduced in Java 8, default methods allow interfaces to have method implementations. This enables interface evolution without breaking existing implementations.

Example:

interface MyInterface {
    default void greet() {
        System.out.println("Hello!");
    }
}


16. What is the difference between fail-fast and fail-safe iterators in Java?


  • Fail-Fast: These iterators throw ConcurrentModificationException if the collection is modified during iteration (e.g., ArrayList, HashMap).

  • Fail-Safe: These iterators work on a clone of the collection, so they don’t throw exceptions when the collection is modified (e.g., CopyOnWriteArrayList, ConcurrentHashMap).


17. How does the Java memory model work?


The Java Memory Model (JMM) defines how threads interact through memory and what behaviors are allowed in concurrent execution. It ensures visibility, ordering, and atomicity of variable access. Key components:

  • Main Memory: Shared among all threads.

  • Working Memory: Thread-local memory storing copies of variables.

  • Happens-Before Relationship: Guarantees visibility and ordering of actions.


18. What is the difference between String, StringBuilder, and StringBuffer?


  • String: Immutable, thread-safe. New objects are created on modification.

  • StringBuilder: Mutable, not thread-safe. Better for single-threaded operations.

  • StringBuffer: Mutable, thread-safe. Suitable for multi-threaded usage but slower than StringBuilder.

Example:

StringBuilder sb = new StringBuilder("Hello");
sb.append(" World");
System.out.println(sb);

- - Output:
Hello World


19. What is the use of the transient keyword in Java?


The transient keyword is used to mark a variable as not serializable. When an object is serialized, transient variables are skipped.

Example:

class Employee implements Serializable {
    String name;
    transient int salary; // will not be serialized
}


20. What are soft, weak, and phantom references in Java?


  • SoftReference: Cleared only when JVM is low on memory.

  • WeakReference: Cleared on next GC cycle, even if memory is available.

  • PhantomReference: Used to schedule post-mortem cleanup actions. Requires a ReferenceQueue.

Use Cases: SoftReference for caches, WeakReference for mappings that shouldn’t prevent GC, PhantomReference for cleanup before GC reclaims memory.



21. What is the difference between stack memory and heap memory in Java?


  • Stack Memory: Stores primitive values and references to objects. Each thread has its own stack. Memory is allocated/deallocated in LIFO order.

  • Heap Memory: Used for storing actual objects. Shared among all threads. Managed by the Garbage Collector.


22. What is the volatile keyword in Java?


The volatile keyword is used to mark a variable as being stored in main memory. All threads will read the variable's value directly from main memory, ensuring visibility but not atomicity.

Example:

class SharedObject {
    volatile boolean flag = false;
}


23. How do you implement a thread-safe singleton in Java?


You can use double-checked locking with volatile to implement a thread-safe singleton pattern.

Example:

class Singleton {
    private static volatile Singleton instance;
    private Singleton() {}
    public static Singleton getInstance() {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}


24. What are method references in Java 8?


Method references are a shorthand syntax for calling methods in lambda expressions. They are expressed using :: operator and improve code readability.

Example:

List<String> names = Arrays.asList("John", "Alice", "Bob");
names.forEach(System.out::println);


25. How does Garbage Collection work in Java?


Java’s Garbage Collector (GC) automatically deallocates memory by removing unreachable objects. Key phases:

  • Mark: Identify live objects.

  • Sweep: Remove unreferenced objects.

  • Compact: Rearranges memory to reduce fragmentation.

GC can be tuned using JVM options like -Xms, -Xmx, and collectors like G1, CMS, and ZGC.



26. What is the difference between ReentrantLock and synchronized in Java?


  • synchronized: Simpler to use, automatically releases the lock. Cannot interrupt a thread waiting for the lock. No tryLock feature.

  • ReentrantLock: More flexible. Allows interruptible lock acquisition, tryLock(), and fairness policies. Requires manual unlock.

Example:

ReentrantLock lock = new ReentrantLock();
lock.lock();
try {
    // critical section
} finally {
    lock.unlock();
}


27. What is the Java Memory Model (JMM)?


The Java Memory Model defines how threads interact through memory and what behaviors are allowed in multithreaded environments. It governs visibility and ordering of variables across threads. It ensures:

  • Atomicity, visibility, and ordering of variables.

  • Happens-before relationships (e.g., thread start happens-before its execution).

  • Rules for using volatile, synchronized, and final.


28. How does CompletableFuture differ from Future in Java?


  • Future: Represents a pending result of an async computation. Limited, blocking API.

  • CompletableFuture: Enhances Future with callbacks, chaining, and non-blocking execution using functional programming.

Example:

CompletableFuture.supplyAsync(() -> "Hello")
    .thenApply(s -> s + " World")
    .thenAccept(System.out::println);

- - Output:
Hello World


29. What are PhantomReferences in Java?


PhantomReference is one of Java’s reference types used in garbage collection. Unlike Soft or Weak references, PhantomReference.get() always returns null. It is used to perform post-mortem cleanup after an object is finalized but before memory is reclaimed.

Example:

PhantomReference<MyObject> phantomRef =
    new PhantomReference<>(new MyObject(), new ReferenceQueue<>());


30. What is the difference between JNI and JNA?


  • JNI (Java Native Interface): A low-level API to call C/C++ code from Java. Requires native code compilation and boilerplate.

  • JNA (Java Native Access): High-level library that provides Java access to native shared libraries without writing JNI code.

JNA is easier to use for simple native integrations, whereas JNI provides greater control and performance for complex operations.
