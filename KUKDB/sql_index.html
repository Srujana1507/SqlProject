Index

An index is a database object created to speed up the retrieval of rows by using a pointer mechanism.


  • They function like a roadmap for the database, allowing it to quickly locate rows in a table without scanning the entire dataset.
  • Indexes are created on columns of a table or a view and can be applied to one or multiple columns.

Why are Indexes important in a Database

Reason Description
Faster Query Execution Improves the speed of SELECT queries, especially for large tables.
Efficient Sorting Allows faster execution of queries involving ORDER BY and GROUP BY.
Join Optimization Enhances the performance of JOIN operations by indexing the joined columns.
Supports Constraints Enforces constraints like primary keys and unique constraints effectively.
Avoid Full Table Scans Reduces the need for a full table scan by directly accessing rows based on indexed columns.
Impact on DML Operations Indexes can slow down INSERT, UPDATE, and DELETE operations due to the need for index maintenance.
Composite Index Order Order matters. Place columns with higher selectivity (more unique values) first.


SQL Syntax for Creating Indexes

1. Create a Simple Index

CREATE INDEX index_name
    ON table_name (column1) ;


2. Create a Unique Index

CREATE UNIQUE INDEX index_name
    ON table_name (column1) ;


3. Create a Composite Index

CREATE INDEX index_name
    ON table_name (column1, column2) ;


4. Drop an Index

DROP INDEX index_name ON table_name ; -- For SQL Server

DROP INDEX index_name ; -- For MySQL, Oracle and PostgreSQL


5. View Indexes

- - For most of the Databases
SHOW INDEXES FROM table_name ;

-- For SQL Server
SELECT * FROM sys.indexes
WHERE object_id = OBJECT_ID('table_name') ;


Behavior

Feature Description
Implicit Indexing Primary key and unique constraints automatically create indexes.
Data Redundancy Indexes store a copy of the indexed columns, increasing storage usage.
Query Optimization The database query optimizer decides when and how to use indexes during query execution.

Key Features of INDEXES

Key Point Description
Column-based Indexes are applied to specific columns of a table.
Improved Read Performance Queries with indexed columns execute faster.
Trade-off Indexes consume storage and can slow down write operations (INSERT, UPDATE, DELETE).
Storage Indexes require additional storage and can increase the size of the database.


Real-Time Scenarios

Scenario 1:- Find all orders placed by a specific customer.

CREATE INDEX idx_customer_id
    ON orders (customer_id) ;

    SELECT *
    FROM Orders
    WHERE customer_id = 12345 ;


Scenario 2:- Optimize queries filtering orders by date.

CREATE INDEX idx_order_date
    ON orders (order_date) ;

    SELECT *
    FROM Orders
    WHERE order_date
    BETWEEN '2024-01-01' AND '2024-12-31' ;


Scenario 3:- Speed up a query joining orders and customers tables.

CREATE INDEX idx_customer_id
    ON customers (customer_id) ;

    SELECT o.order_id, c.name
    FROM Orders o
    JOIN customers c
    ON o.customer_id = c.customer_id ;


Scenario 4:- Retrieve employees with no manager assigned (manager_id is NULL).

-- Create an index on the manager_id column
CREATE INDEX idx_manager_id
    ON Employees (manager_id) ;

    - - Retrieve employees with no manager
    SELECT employee_id, employee_name
    FROM Employees
    WHERE manager_id IS NULL ;


Scenario 5:- (Using Aggregations) Retrieve the highest salary for each department in a company.

- - Create an index on department and salary
CREATE INDEX idx_salary_department
    ON Employees (department, salary) ;

    - - Use an aggregate function
    SELECT department, MAX(salary) AS max_salary
    FROM Employees
    GROUP BY department ;


Scenario 6:- (Covering Index) Retrieve product details without accessing the base table.

- - Create a covering index for the query
CREATE INDEX idx_covering_product
    ON Products (product_name, price, category) ;

    - - Query using the indexed columns
    SELECT product_name, price, category
    FROM Products
    WHERE category = 'Electronics' AND price > 500 ;


Scenario 7:- (Low Cardinality) Optimize searches for employees with NULL or specific statuses.

- - Create a filtered index (SQL Server specific)
CREATE INDEX idx_filtered_status
    ON Employees (status)
    WHERE status IS NOT NULL ;

    - - Query using the indexed column
    SELECT employee_id, status
    FROM Employees
    WHERE status = 'Active' ;


Scenario 8:- Search for products containing specific words in their descriptions.

- - Create a full-text index for large text columns
CREATE FULLTEXT INDEX
    ON Products (description) ;

    - - Query for text matching
    SELECT product_name
    FROM Products
    WHERE CONTAINS (description, 'wireless AND headset') ;


Scenario 9:-(Parallel Query Execution with Partitioned Indexes) Retrieve sales data by year from a large Sales table.

- - Create a partitioned index by sales year
CREATE PARTITION FUNCTION pf_sales_year (INT)
    AS RANGE LEFT FOR VALUES (2019, 2020, 2021) ;

    CREATE PARTITION SCHEME ps_sales_year
      AS PARTITION pf_sales_year ALL TO ([ PRIMARY]) ;

      CREATE INDEX idx_sales_year
        ON Sales (sales_year)
        ON ps_sales_year ;

        - - Query the partitioned table
        SELECT *
        FROM Sales
        WHERE sales_year = 2020 ;


Types of Indexes in SQL

Index Type Description
Clustered Index Determines the physical order of data in a table. Only one clustered index is allowed per table.
Non-Clustered Index A separate structure that maintains a reference to the actual table rows. Multiple can exist.
Unique Index Ensures that all values in the index column(s) are unique.
Filtered Index Index with a WHERE clause to improve query performance for a subset of rows (SQL Server).
Bitmap Index Used in some databases (e.g., Oracle) for columns with a low cardinality of values.
Full-Text Index Optimized for full-text searches and supports advanced searching like prefix matches and synonyms.
Composite Index Created on multiple columns.


Advantages of Indexes

Advantage Description
Improved Query Performance Speeds up data retrieval significantly.
Reduces Disk I/O Limits the amount of data scanned, improving overall system efficiency.
Improves Join Performance Enhances the speed of complex joins by indexing join keys.
Facilitates Sorting Accelerates queries with ORDER BY or GROUP BY clauses.
Search Flexibility Full-text indexes enable advanced text searches.


Disadvantages of Indexes

Disadvantage Description
Maintenance Overhead Indexes require regular maintenance, especially for large datasets.
Limited Use for Small Tables Small tables may not benefit significantly from indexing.
Increased Storage Requires additional storage for maintaining indexes.
Slower DML Operations INSERT, UPDATE, and DELETE operations are slower because the index must be updated.


Common Errors with INDEX

Error Explanation Solution
Index Not Used Query plan shows no index usage despite being created. Ensure the index matches query patterns (e.g., WHERE).
Incorrect Column Order in Composite Index Poorly ordered columns can render composite indexes inefficient. Use the most selective column first in the index.
Duplicate Index Creation Unknowingly creating multiple indexes on the same column(s). Check existing indexes before creating new ones.
Index Fragmentation Over time, frequent updates cause index fragmentation. Rebuild or reorganize indexes regularly.
Unused Indexes Some indexes may never be used, wasting resources. Use database monitoring tools to identify and drop unused indexes.


Performance Hints for Indexing

Hint Description
Index Selective Columns Index columns with high cardinality (e.g., unique or near-unique values).
Use Covering Indexes Create indexes that "cover" all columns used in a query to avoid accessing the base table.
Monitor Fragmentation Regularly rebuild or reorganize indexes to reduce fragmentation.
Avoid Over-Indexing Too many indexes can degrade write performance.
Use Composite Indexes Wisely Use composite indexes for queries that filter or sort on multiple columns.
Index Only Frequently Queried Columns Avoid indexing every column to reduce overhead.


Do's and Don'ts

Do's Don'ts
Use indexes for frequently queried columns. Don’t index columns with low cardinality (few unique values).
Index foreign key columns for joins. Don’t use indexes on volatile columns that change frequently.
Regularly rebuild or reorganize indexes. Don’t rely solely on indexes for performance; optimize queries too.
Use composite indexes for multi-column filtering. Don’t ignore query performance testing before deploying indexes.
Monitor and maintain index performance. Don’t create too many indexes on a single table.
