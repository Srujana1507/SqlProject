ALTER

  • The ALTER TABLE statement in SQL is used to modify the structure of an existing table without needing to recreate it.

  • The ALTER statement can be used to perform the following actions on various database objects (e.g., table, Views, Schemas, Triggers, etc..)

  • It allows changes like adding, modifying, or deleting columns, as well as applying constraints. ALTER TABLE is a crucial tool for database maintenance and incremental changes in a database schema.

  • Operations on Tables:
    • Add Columns : Add new columns to an existing table.
    • Modify Columns : Change a column's data type, size, or constraints.
    • Drop Columns: Remove a column from a table.
    • Rename Columns (in some DBMS) : Change the name of a column.
    • Add Constraints : Add constraints such as PRIMARY KEY, FOREIGN KEY, UNIQUE, or CHECK.
    • Drop Constraints : Remove existing constraints.
  • ALTER actions on Objects:
    • Alter Views : Modify an existing view's definition or its schema.
    • Rename an existing index and Rebuild a fragmented index to improve performance (in some DBMS ).
    • Modify Schemas - Change the ownership of a schema or database object.
    • Modify Databases - Change Database Properties such as collation or character set.
    • Modify Storage Options (MySQL) - Add or modify partitions in a table.
    • Modify Triggers (in some DBMS) - Temporarily disable or re-enable triggers.
    • Restart or Set Sequence Values - in PostgreSQL

    Syntax

    The basic syntax of ALTER TABLE varies slightly by the specific action you wish to perform. below are action's syntax and examples.

    ALTER TABLE table_name
    [ ADD | DROP | MODIFY | RENAME | ALTER COLUMN ] ;

    1. Add a new column to existing Table:

    ALTER TABLE table_name
    ADD column_name datatype ;

    Example:
    ALTER TABLE employee
    ADD Mobile VARCHAR( 10 ) ;

    2. Add a constraint to existing Table:

    ALTER TABLE table_name
    ADD CONSTRAINT constraint_name constraint_definition ;

    Example:
    • Adding a Primary Key Constraint :
    ALTER TABLE employee
    ADD CONSTRAINT pk_employee_id PRIMARY KEY (emp_id) ;

    • Adding a Foreign Key Constraint :
    ALTER TABLE employee
    ADD CONSTRAINT fk_department
    FOREIGN KEY (dept_id) REFERENCES departments(dept_id) ;

    3. Modifying an Existing Column (Modify Table - add hyper link here, create a seperate topic) :

    Oracle
    ALTER TABLE table_name
    MODIFY column_name new_datatype ;

    ALTER TABLE employees
    MODIFY phone_number VARCHAR2(20) ;
    Note : make sure the new datatype can handle the old datatype, otherwise you will get an error.

    SQL Server
    ALTER TABLE employees
    ALTER COLUMN phone_number NVARCHAR(20) ;

    MySQL
    ALTER TABLE employees
    MODIFY phone_number VARCHAR(20) ;

    PostgreSQL
    ALTER TABLE employees
    ALTER COLUMN salary TYPE NUMERIC( 10, 2 ) ;

    4. Drop a column :

    ALTER TABLE table_name
    DROP COLUMN column_name ;

    Example
    ALTER TABLE employees
    DROP COLUMN phone_number ;

    5. Dropping Constraints :

    ALTER TABLE table_name
    DROP CONSTRAINT constraint_name ;

    Oracle and SQL Server
    ALTER TABLE employees
    DROP CONSTRAINT pk_employee_id ;

    MySQL
    ALTER TABLE employees
    DROP PRIMARY KEY ;

    6. Renaming Columns

    Renaming a Column (Only supported in some databases directly in ALTER TABLE).

    SQL Server
    EXEC sp_rename 'employees.phone_number', 'contact_number', 'COLUMN';

    MySQL
    ALTER TABLE employees

    CHANGE phone_number contact_number VARCHAR(20) ;

    Oracle and MySQL
    ALTER TABLE employees

    RENAME TO Staff ;

    ALTER TABLE employees RENAME TO staff;

    Advanced Scenarios

    1. Add Multiple Columns

    ALTER TABLE employees
    ADD dept_id INT ,
    ADD location VARCHAR(50) ;

    2. Modify a Column’s Default Value

    ALTER TABLE employees
    ALTER COLUMN status
    SET DEFAULT 'active' ;

    3. Add and Drop Indexes (MySQL Specific)

    Add an index on the email column
    ALTER TABLE employees
    ADD INDEX idx_email (email) ;

    Drop an index
    ALTER TABLE employees
    DROP INDEX idx_email ;

    4. Partitioning Table (MySQL)

    ALTER TABLE orders
    PARTITION BY RANGE (order_date) (
    PARTITION p1 VALUES LESS THAN ( '2023-01-01'),
    PARTITION p2 VALUES LESS THAN ( '2024-01-01') ) ;

    Invalid Examples

    1. Modify column Datatype from INT to BOOLEAN on Multiple Columns

    ALTER TABLE employees

    ALTER COLUMNS salary TYPE BOOLEAN ;


    Error : DECIMAL values cannot be converted to BOOLEAN.

    2. Modify Foreign Key column Datatype to BIGINT

    ALTER TABLE Orders

    ALTER COLUMNS order_id TYPE BIGINT ;


    Error : order_id is referenced by another table and cannot be changed directly.

    3. Modify column size

    ALTER TABLE Products

    ALTER COLUMNS prod_name TYPE VARCHAR( 10 ) ;


    Risk : Statement will execute without error , but existing values exceeding 10 characters will be truncated.

    Best Practices When Changing Data Types

    • Backup Data : Always take a backup before performing schema changes.
    • Test in a Dev Environment : Verify changes in a non-production environment first.
    • Check Data Compatibility : Ensure the new type supports all existing data.
    • Drop Constraints Temporarily : Drop foreign keys, unique constraints, or indexes if necessary, and recreate them after the change.
    • Minimize Downtime : Schedule the change during maintenance windows for large tables.

    Do’s and Don’ts with ALTER

    Do's :-

    • Do validate changes with a SELECT query after making modifications, especially when altering constraints or default values.
    • Do keep your schema under version control or document changes to track updates.
    • Do check for dependencies: Make sure no other tables, views, or procedures are adversely impacted by the structural change.

    Don'ts :-

    • Don’t drop columns without verifying dependencies: Dropping columns can break dependent views, triggers, and procedures.
    • Don’t modify data types carelessly : Changing data types can cause data loss (e.g., changing VARCHAR to INT), so ensure compatibility.
    • Don’t ignore index considerations: Adding columns and altering data types may affect indexes, impacting query performance.
