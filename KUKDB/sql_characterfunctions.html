Character Functions

Character functions allow you to manipulate and analyze string (text) data. They are widely used for formatting, searching, transforming, or extracting substrings.


Key Arithmetic Functions

Function Purpose Description Uses Limits
UPPER() Convert to uppercase Converts all characters in a string to uppercase. Standardizing text for comparison, case-insensitive search. Non-alphabetic characters remain unchanged.
LOWER() Convert to lowercase Converts all characters in a string to lowercase. Similar to UPPER(), but for lowercase. Non-alphabetic characters remain unchanged.
INITCAP() Capitalize first letter Capitalizes the first letter of each word and converts the rest to lowercase. Formatting names, titles, or other strings. Available in Oracle only.
LENGTH() Find length of a string Returns the number of characters in a string (including spaces). Validating data length, e.g., phone numbers or identifiers. Varies between databases when handling multi-byte characters.
TRIM() Remove leading/trailing spaces Removes leading, trailing, or both spaces from a string. Cleaning up user input or data retrieved from files. Does not handle internal spaces (use REPLACE for that).
LTRIM() Remove leading spaces Removes spaces from the beginning of a string. Data sanitization, preparing strings for further processing. Same as TRIM, limited to leading spaces.
RTRIM() Remove trailing spaces Removes spaces from the end of a string. Similar to LTRIM, but for trailing spaces. Same as TRIM, limited to trailing spaces.
SUBSTR() Extract substring Extracts a portion of a string starting at a specified position. Extracting parts of strings, e.g., area codes or domain names. Returns NULL if position exceeds the string length.
REPLACE() Replace substring Replaces all occurrences of a substring with another substring. Replacing keywords, correcting data. Does not support regex patterns (use REGEXP_REPLACE if needed).
CONCAT() Concatenate strings Combines two or more strings into one. Merging names, addresses, or other strings. Limited to two arguments in some databases. In such cases, use `
INSTR() Find position of a substring Returns the position of the first occurrence of a substring within a string. Searching for specific patterns or characters. Returns 0 if the substring is not found.
LPAD() Pad string on the left Pads a string to a specified length with a given character. Formatting data for reports, ensuring fixed-width fields. Can truncate the string if padding exceeds the length.
RPAD() Pad string on the right Similar to LPAD, but pads on the right. Useful for aligning strings in output. Same limits as LPAD.
ASCII() Get ASCII value of a character Returns the ASCII code of the first character in a string. Encoding checks, mapping characters to their ASCII codes. Limited to single character at the beginning of the string.
CHR() Get character from ASCII value Converts an ASCII code into its corresponding character. Reverses the functionality of ASCII. Limited to valid ASCII code range (0-255).
REGEXP_REPLACE() Replace using a regular expression Replaces a substring that matches a regular expression pattern. Advanced string manipulations, such as removing special characters or validating data formats. May not be supported in all databases.
REGEXP_INSTR() Find position using a regular expression Returns the position of the first match of a regular expression in a string. Advanced searching and text analysis. Not available in all SQL databases.

Basic Examples

1. Case Conversion Functions

A. UPPER() : Converts all characters to uppercase.

-- SQL Server, MySQL
SELECT UPPER('hello world') AS UpperText ;
- - Output: HELLO WORLD

-- Oracle
SELECT UPPER('hello world') AS UpperText FROM DUAL ;
- - Output: HELLO WORLD

Scenario : Normalize user inputs to ensure consistent case handling during for user login.

SELECT UPPER(username) AS Capital_Name
FROM users
WHERE user_id = 101 ;

- - Input: 'HarshaVardhan'
- - Output: 'HARSHAVARDHAN'

B. LOWER() : Converts all characters to lowercase.

-- SQL Server, MySQL
SELECT LOWER('Hello World') AS LowerText ;
- - Output: hello world

-- Oracle
SELECT LOWER('Hello World') AS LowerText FROM DUAL ;
- - Output: hello world

Scenario:- Prepare email addresses for validation by ensuring they are in lowercase.

SELECT LOWER( email ) AS NormalizedEmail
FROM customers WHERE customer_id = 202 ;

- - Input: 'UDAY.KUMAR@EMAIL.COM'
- - Output: 'uday.kumar@email.com'

C. INITCAP() : Capitalizes the first letter of each word (Oracle, PostgreSQL).

SELECT INITCAP('hello world') AS LowerText FROM DUAL ;
- - Output: Hello World

Scenario :- Format customer names for display in proper case.

SELECT INITCAP(customer_name) AS Initi_Name FROM Orders ;

- - Input: uday KUMAR
- - Output: Uday Kumar

2. Length and Substring Functions

A. LENGTH() / LEN() : Returns the number of characters in a string.

-- SQL Server
SELECT LENGTH('SQL Tutorial') AS StringLength ;
- - Output: 12

--MYSQL/Oracle
SELECT LENGTH('SQL Tutorial') AS StringLength FROM DUAL ;
- - Output: 12


Scenario :- Check if passwords meet the minimum length requirement.

SELECT CASE
    WHEN LENGTH(password) >= 8 THEN 'Valid' ELSE 'Invalid'
    END AS PasswordStatus
FROM users ;

- - Input: uday123
- - Output: Invalid

B. SUBSTRING() / SUBSTR() : Extracts a portion of the string.

SELECT SUBSTRING('SQL Tutorial', 1, 3) AS Sub_string FROM DUAL ;

- - Output: SQL

Scenario 1:- Extract area codes from phone numbers.

SELECT SUBSTR(phone_number, 1, 3) AS AreaCode FROM contacts ;

- - Input: 9912660135
- - Output: 991

Scenario 2:- Extract domain names from email addresses.

SELECT SUBSTR( email, INSTR( email, '@') + 1 ) AS Domain FROM users ;

- - Input: harsha.vardhan@sample.com
- - Output: sample.com

C. LEFT() / RIGHT(): These functions are used to extract a specified number of characters from the beginning(left) or end (right) of a string.

LEFT ()

Scenario 1:-
You have a list of employee names, and you need to extract the first two letters as initials.

SELECT LEFT (employee_name, 2) AS Initials FROM employees ;

- - Input: Thammisetti
- - Output: Th

Scenario 2:-
You need to extract the first 4 characters (year) from a string-formatted date (YYYY-MM-DD).

SELECT LEFT (hire_date, 4) AS Year , COUNT(*) AS emp_count FROM employees
GROUP BY LEFT (hire_date,4) ;

- - Input: '2024-12-12'
- - Output: 2024, emp_count: 5

RIGHT()

Scenario 1:- ( Extract File Extensions ) You have a list of file names, and you need to extract the file extension.

SELECT RIGHT ( file_name, CHARINDEX('.', REVERSE( file_name ) ) - 1 ) AS FileExtension FROM files ;

- - Input: kukreport.pdf
- - Output: pdf

Scenario 2:- ( Last 4 Digits of a Credit Card Number ) You need to display only the last 4 digits of a credit card number for security purposes.

SELECT CONCAT ('**** **** **** ', RIGHT (credit_card_number, 4 ) ) AS MaskedCard
FROM transactions ;

- - Input: '1234567812345678'
- - Output: **** **** **** 5678

Notes on Usage

  • LEFT() is generally used when you need to extract prefixes, leading characters, or first few elements in structured data.
  • RIGHT() is generally used when you need to extract suffixes, trailing characters, or the last few elements in structured data.

3. Trimming and Padding Functions

A. TRIM(): Removes leading, trailing, or both types of spaces from a string.

.

SELECT TRIM(' SQL Tutorial ') AS Trim_String ;

- - Output: SQL Tutorial

Scenario :- Remove both leading and trailing spaces from a product description.

SELECT TRIM(' Amazing Product ') AS Ext_Description ;

- - Input: ' Amazing Product '
- - Output: 'Amazing Product'

B. LTRIM() / RTRIM(): Removes spaces or specific characters from the left or right side.

SELECT LTRIM(' SQL Tutorial') AS LeftTrim_String,
RTRIM('SQL Tutorial ') AS RightTrim_String ;

- - Output: SQL Tutorial

LTRIM()

Scenario :- Remove unwanted leading characters in user-generated codes.

SELECT LTRIM('00012345', '0') AS Code ;

- - Input: '00012345'
- - Output: '12345'

RTRIM()

Scenario :- Trim trailing spaces from file names before saving.

SELECT RTRIM('report ') AS Filename ;
- - Input: 'report '
- - Output: 'report'

4. String Comparison Functions

A. INSTR(): The INSTR() function returns the position of the first occurrence of a substring within a string. If the substring is not found, it returns 0.

SELECT INSTR ( 'SQL Tutorial', 'Tutorial' ) AS Position ;

- - Output: 5

Scenario 1:- Find the position of a special character in file paths.

SELECT INSTR ('/home/user/documents/file.txt', '/') AS Fileposition ;

- - Output: 1

Scenario 2:- Identifying the Position of a Character in Email Addresses.

SELECT email,
SUBSTR( email, INSTR( email, '@') + 1 ) AS Domain FROM users ;

Scenario 3:- If the substring does not exist, INSTR() returns 0. Use this for conditional checks:

SELECT email,
CASE
    WHEN INSTR(email,'@') > 0 THEN SUBSTR(email,INSTR(email,'@') + 1) END AS Domain
FROM users ;

Scenario 4:- Identify all orders shipped via "EXPRESS" (part of a larger string) and find the starting position of "EXPRESS" in the details.

SELECT OrderID,
    ShippingDetails, INSTR ( ShippingDetails, 'EXPRESS' ) AS ExpressPosition
FROM Orders
WHERE INSTR ( ShippingDetails, 'EXPRESS' ) > 0 ;

Scenario 5:- Identify customers who mention the keyword "refund" (case-sensitive) in their reviews.

SELECT CustomerID,
    Review, INSTR (Review, 'refund') AS RefundKeywordPosition
FROM Customers
WHERE INSTR (Review, 'refund') > 0 ;

The STRCMP() function (MySQL specific)

It compares two strings lexicographically and returns:

  • 0 if the strings are equal.
  • 1 if the first string is greater than the second string.
  • -1 if the first string is less than the second string.

Scenario 1 :- Compare two simple strings to see their lexicographical order.

SELECT STRCMP ( 'apple', 'banana' ) AS Strcmp_output ;
- - Output : -1

Scenario 2 :- Sort a list of products based on a custom lexicographical comparison, ignoring case differences.

SELECT ProductName
FROM Products
ORDER BY STRCMP( LOWER( ProductName ), LOWER( 'mango' ) ) ;

- - LOWER(ProductName) ensures a case-insensitive comparison.
- - STRCMP() compares each product name with the string 'mango' lexicographically.
- - The ORDER BY sorts the product names based on the comparison results.

Scenario 3 :- Retrieve all product names that lexicographically come after "grape".

SELECT ProductName
FROM Products
WHERE STRCMP( ProductName,'grape') > 0 ;

- - The WHERE clause uses STRCMP() to filter product names that are greater than 'grape' lexicographically.

Concatenation Functions

Concatenation functions are used to combine two or more strings into one.


Key Characteristics

  • Combines strings or string expressions.
  • Allows dynamic content creation (e.g., full names, custom messages).
  • Handles NULL values differently across databases:
    • MySQL: Treats NULL as an empty string.
    • Oracle, SQL Server, PostgreSQL: Returns NULL if any operand is NULL.

Common Concatenation Functions by Database

Database Function Syntax
Oracle CONCAT() or || Removes the negative sign from a number.
MySQL CONCAT() or CONCAT_WS(separator) CONCAT(string1, string2) or CONCAT_WS('-', string1, string2)
SQL Server + string1 + string2
PostgreSQL || string1 || string2

Basic Syntax Examples

Oracle

SELECT CONCAT ( first_name, ' ', last_name ) AS FullName
FROM employees ;
SELECT first_name || ' ' || last_name AS FullName
FROM employees ;

MySQL

SELECT CONCAT ( 'Order: ', order_id, ', Date: ', order_date ) AS OrderSummary
FROM orders ;

SQL Server

SELECT 'Customer: ' + customer_name + ', City: ' + city AS CustomerDetails
FROM customers ;

PostgreSQL

SELECT customer_name ||' - '|| phone_number AS ContactInfo
FROM customers ;

Do's and Don'ts

Do's

1. Handle NULLs Carefully

  • Use COALESCE() to replace NULL values with defaults (e.g., empty strings).
    • SELECT CONCAT( COALESCE(first_name, ''), ' ', COALESCE(last_name, '') ) AS Fullname
    FROM employees ;

2. Use Explicit Conversions for Non-String Data :

  • Convert numbers or dates explicitly to strings before concatenation:
    • SELECT CONCAT( 'Order# ', CAST(order_id AS CHAR ) ) AS OrderInfo
    FROM orders ;

3. Optimize for Readability:

  • Use aliases to simplify query outputs.

Don'ts

1. Don't Assume Uniform NULL Behavior

  • Each database handles NULL differently. Use COALESCE() or ISNULL() where needed.

2. Don't Ignore Performance

  • Overusing concatenation on large datasets can degrade performance, especially if combined with sorting or joins.

3. Don't Hardcode Separators

  • Convert numbers or dates explicitly to strings before concatenation:
    • SELECT CONCAT_WS( ', ', first_name, last_name, city ) AS Details
    FROM customers ;

Replacement Functions

  • Replacement functions are used to find and replace specific text or patterns within a string.
  • They are commonly used for data cleaning, formatting, or making adjustments to textual data in databases.

Common Replacement Functions Across Databases

    Database Function Description
    Oracle REPLACE() Replaces all occurrences of a substring within a string.
    MySQL REPLACE() Replaces all occurrences of a substring within a string.
    SQL Server REPLACE() Replaces all occurrences of a substring within a string.
    PostgreSQL REPLACE()
    REGEXP_REPLACE()     		Replaces all occurrences of a substring within a string.
    Replaces substrings matching a regular expression pattern.

Basic Syntax

1. REPLACE()

SELECT REPLACE(string, substring_to_replace, replacement_string) FROM Tablename ;

REGEXP_REPLACE() (PostgreSQL & Oracle)

SELECT REGEXP_REPLACE(string, pattern, replacement_string [, flags]) FROM Tablename ;

Key Characteristics

  • Case Sensitivity: Replacement is typically case-sensitive.
  • Partial Matches: Replaces exact matches of the substring (or pattern in regex functions).
  • Bulk Updates: Can be used in UPDATE statements to replace text in columns.

Basic Examples

Using REPLACE()

MySQL/Oracle/SQL Server/PostgreSQL

SELECT REPLACE( 'Hello World', 'World', 'SQL' ) AS Result ;
- - Output: 'Hello SQL'

Using REGEXP_REPLACE()

PostgreSQL

SELECT REGEXP_REPLACE( 'Hello World', 'World$', 'SQL' ) AS Result ;
- - Output: 'Hello SQL' (Replaces 'World' at the end of the string).

Scenario 1 : Format phone numbers by replacing - with a space.

SELECT customer_name,
REPLACE(phone_number, '-', ' ') AS Cust_phone
FROM customers ;

Scenario 2 : Remove # and @ symbols from product codes.

SELECT product_id,
REPLACE( REPLACE( product_code, '#', ''), '@', '' ) AS CleanedProductCode
FROM customers ;

SQL Query (PostgreSQL):

Scenario 3 : Replace the name of an obsolete product with "Updated Product" in the products table.

UPDATE products
SET product_name = REPLACE(product_name,'OldProduct','Updated Product')
WHERE product_name
LIKE '%OldProduct%' ;

Do's and Don'ts

Do's

1. Handle Case Sensitivity

  • Use LOWER() or UPPER() for case-insensitive replacements if required.
    • SELECT REPLACE( LOWER(column_name), 'old', 'new' ) FROM table_name ;

2. Test Before Updating :

  • Always run SELECT queries before UPDATE or DELETE to confirm the results.

3. Use Regular Expressions (if supported) :

  • For more complex replacements, leverage REGEXP_REPLACE().

Don'ts

1. Don't Replace Partial Matches Unintentionally

  • Ensure the substring is specific enough to avoid unintended replacements.
    • - - Problem: "cat" is replaced inside "category"
    SELECT REPLACE('category', 'cat', 'dog') FROM dual ;
    - - Output: 'dogegory' (unexpected)

2. Avoid Overusing Nested Replacements:

  • Use chained replacements judiciously to maintain query performance.

REGEXP_REPLACE()

The REGEXP_REPLACE function is used to search for a pattern (regular expression) within a string and replace it with another string.

  • It is highly useful for complex string manipulation, allowing operations like replacing substrings, formatting strings, or sanitizing inputs.
  • This function is supported in databases like Oracle, PostgreSQL, MySQL 8.0+, and others, though syntax and features may vary slightly between them.

Basic Syntax

SELECT REGEXP_REPLACE(source_string, pattern, replacement [, position [, occurrence [, match_parameter]]]) FROM table_name ;

Parameters:

  • Source_string: The string where the search and replace operation is performed.
  • Pattern: The regular expression pattern to search for.
  • replacement: The string to replace the matching pattern with.
  • position (optional): The starting position in the source_string where the search begins (default is 1).
  • Occurrence (optional): Specifies which occurrence of the pattern to replace
    • Default is 0 (replaces all occurrences).
  • match_parameter (optional): A string controlling matching behavior.
    • 'i' for case-insensitive matching.
    • 'c' for case-sensitive matching.
    • 'n' for allowing the period (.) to match newline characters.

Database Support

    Database Syntax
    Oracle REGEXP_REPLACE(source, pattern, replacement)
    PostgreSQL REGEXP_REPLACE(source, pattern, replacement [, flags])
    MySQL Not supported (use user-defined functions).
    SQL Server Not supported (use CLR or LIKE + REPLACE)

Basic Examples

Scenario 1:- Replace all instances of the word 'cat' with 'dog' in a string.

SELECT REGEXP_REPLACE('The cat sat on the cat mat.', 'cat', 'dog')
AS RegExp FROM dual ;

- - Output: 'The dog sat on the dog mat.'

Scenario 2:- Remove Digits from a String.

SELECT REGEXP_REPLACE('Order12345', '\d', '')
AS CleanedString FROM dual ;

- - Output: 'Order'
  • \d: Matches any digit.
  • '': Replaces matched digits with an empty string.

Scenario 3:- Replace Case-Insensitive Pattern.

SELECT REGEXP_REPLACE('Hello World', 'world', 'Universe', 'i')
AS result FROM dual ;

- - Output: 'Hello Universe'
  • i: Makes the replacement case-insensitive.

Replace All Matches (Global Replacement)

PostgreSQL Example: Remove All Special Characters

SELECT REGEXP_REPLACE('Hello, World! SQL is #1.', '[^a-zA-Z0-9\s]', '', 'g')
AS Postgre_Example ;

- - Output: 'Hello World SQL is 1'
  • [^a-zA-Z0-9\s]: Matches any character that is not a letter, digit, or space.
  • 'g': Global replacement.

PostgreSQL Example: Remove non-numeric characters from phone numbers.

SELECT customer_name,
REGEXP_REPLACE(phone_number, '[^0-9]', '', 'g') AS Phone_number
FROM customers ;

- - Output: Uday 9912660135

Scenario 1:- Standardize phone numbers in the Customers table to the format (XXX) XXX-XXXX.

SELECT CustomerID, Name,
REGEXP_REPLACE(Phone, '(\d{3})[\.\-]?(\d{3})[\.\-]?(\d{4})', '(\1) \2-\3') AS Phone_number
FROM Customers ;

- - Output: Uday 9912660135
  • Pattern (\d{3})[\.\-]?(\d{3})[\.\-]?(\d{4}) matches phone numbers with various delimiters (. or -).
  • (\1) \2-\3 reorders and formats the phone number.

Scenario 2:- Protect privacy by masking employee email addresses except the first and last character before the domain.

SELECT EmployeeID, Name,
REGEXP_REPLACE(Email, '(\w)(\w+)(\w)(@\w+\.\w+)', '\1****\3\4') AS MaskedEmail
FROM Employees ;

  • (\w)(\w+)(\w)(@\w+\.\w+): Captures the first, middle, and last characters before the domain.
  • \1****\3\4: Keeps the first and last characters, replacing the middle with asterisks.

Scenario 3:- Clean up order descriptions by removing any special characters except spaces and alphanumeric characters.

SELECT OrderID,
REGEXP_REPLACE(OrderDescription, '[^a-zA-Z0-9 ]', '') AS Order_desc
FROM Orders ;

  • [^a-zA-Z0-9 ] matches any character that is not a letter, digit, or space.
  • Replacing with '' removes these unwanted characters.

Scenario 4:- Extract only the shipping codes from a field containing combined details.

SELECT ShippingID,
REGEXP_REPLACE(ShippingDetails, '.*#', '') AS Shipping_code
FROM Shipping ;

  • Pattern .*# matches everything up to and including the # symbol.
  • Replacing it with '' leaves only the shipping code.

Scenario 5:- Ensure ZIP codes are always 5 digits, and prepend a 0 if necessary.

SELECT DepartmentID,
REGEXP_REPLACE(DepartmentCode, '(.{2})', '\1-') AS Dept_Code
FROM Departments ;

- - Expected Output is : HR-01-
  • Pattern (.{2}) captures every two characters.
  • \1- adds a dash after every match.

Scenario 6:- Normalize ZIP codes to ensure they are exactly 5 digits by padding with leading zeros and removing non-numeric characters.

SELECT CustomerID, Name,
REGEXP_REPLACE(LPAD(ZipCode, 5, '0'), '[^0-9]', '') AS Zip_Code
FROM Customers ;

- - Expected Output is : 01234
  • LPAD(ZipCode, 5, '0'): Pads the ZipCode to ensure it’s at least 5 digits.
  • REGEXP_REPLACE(..., '[^0-9]', ''): Removes any non-digit characters.

REGEXP_INSTR

The REGEXP_INSTR function is used to find the position of a substring within a string that matches a regular expression pattern.


Key Characteristics

  • Flexible Pattern Matching: Allows for complex search patterns using regular expressions.
  • Position Control: Can return the starting or ending position of the match.
  • Occurrence Handling: Supports finding the first, second, or nth occurrence of the pattern.
  • Case Sensitivity: Can be toggled using modifiers (e.g., i for case-insensitive search).
  • Multi-line Mode: Useful for handling strings with newline characters.
REGEXP_INSTR(source_string, pattern [, start_position [, occurrence [, return_option [, modifiers]]]])

Parameters:

  • source_string: The string to be searched.
  • pattern: The regular expression pattern to search for.
  • start_position (optional): The position to start the search (default is 1).
  • occurrence (optional): Specifies which occurrence of the pattern to find (default is 1).
  • return_option (optional):
    • 0: Returns the starting position of the match (default).
    • 1: Returns the ending position of the match.
  • modifiers (optional): Specifies pattern matching behavior (e.g., i for case-insensitive, m for multi-line).

Database-Specific Details

    Database Support Notes
    Oracle Fully Supported Standard syntax as shown above.
    PostgreSQL No native function Use POSITION() or REGEXP_MATCHES() combined with string functions.
    MySQL No native function Use custom UDFs or substring + regex for similar functionality.
    SQL Server No native function Use CLR functions or third-party tools for regex support.

Basic Examples

Scenario 1:- Find the Position of a Pattern.

SELECT REGEXP_INSTR( 'Learning SQL is fun with SQL!', 'SQL' ) AS Position
FROM Dual ;

- - Output: 10
- - The word "SQL" starts at position 10 in the string.

Scenario 2:- Find the position of the second occurrence of the word "SQL" in the same string.

SELECT REGEXP_INSTR('Learning SQL is fun with SQL!', 'SQL', 1, 2) AS Position
FROM Dual ;

- - Output: 25

Scenario 3:- Return the position immediately after the first match of the word "SQL".

SELECT REGEXP_INSTR('Learning SQL is fun with SQL!', 'SQL', 1, 1, 1) AS Position_After
FROM Dual ;

- - Output: 13

Scenario 4:- Find the position of "sql", ignoring case.

SELECT REGEXP_INSTR('Learning sql is fun with SQL!', 'sql', 1, 1, 0, 'i') AS Position
FROM Dual ;

- - Output: 10
- - 'i' enables case-insensitive matching.

Advance Examples

Scenario 1:- Find the position of special characters in product names.

SELECT product_id,
REGEXP_INSTR(product_name, '[^a-zA-Z0-9 ]') AS SpecialChar_Position
FROM products ;

Scenario 2:- Find the starting position of the first numeric sequence in the Orders table.

SELECT OrderID,
REGEXP_INSTR(Description, '\d+') AS Position
FROM Orders ;

- - \d+ matches one or more digits.
- - The position of the first numeric sequence (1234 or 5678) starts at position 8.

Scenario 3:- Find the position of the email domain in the Employees table.

SELECT EmployeeID,
REGEXP_INSTR(Email, '@([^\.]+)', 1, 1, 0, NULL, 1) AS Domain_Position
FROM Employees ;

- - Pattern @([^\.]+) captures everything after the @ until the first . (e.g., company or example).
- - 1 in the sub_expression parameter tells the function to return the position of the captured group.

Scenario 4:- Find the position of the last digit in the shipping information.

SELECT ShippingID,
REGEXP_INSTR(ShippingDetails, '\d', 1, 1, 0, 'c') AS FirstDigit_Position,
REGEXP_INSTR(ShippingDetails, '\d', -1, 1, 0, 'c') AS LastDigit_Position
FROM Shipping ;

- - The first digit is matched at position 8 (the #-prefixed order number).
- - The last digit is matched using negative position (-1), which looks from the end of the string.

Do's and Don'ts

Do's

1. Use Subexpressions for Granular Matching: When dealing with complex patterns, use subexpressions to capture specific groups.


2. Combine with Other Functions : Use SUBSTR() or REGEXP_SUBSTR() with REGEXP_INSTR for advanced extraction.


3. Leverage Match Parameters : Use 'i' for case-insensitivity or 'm' for multiline patterns as needed.

4. Test Patterns: Always test your regex patterns thoroughly before applying to production data.


Don'ts

1. Avoid Overlapping Matches: If you need multiple matches, ensure you correctly adjust the occurrence parameter.


2. Don't Ignore Performance: Regex operations can be slow on large datasets—optimize queries when possible.


3. Avoid NULL Handling Issues : REGEXP_INSTR returns NULL for NULL inputs. Use NVL() or COALESCE() to handle these cases.
