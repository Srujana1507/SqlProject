Aggregation or Group Functions

Aggregation functions are used to perform calculations on a set of values and return a single summarized result.


Function Purpose Syntax Notes/Limits
COUNT() Counts rows or non-NULL values in a column. COUNT(expression) or COUNT(*) Includes/excludes NULL based on syntax.
SUM() Calculates the total of numeric values in a column. SUM(expression) Only works with numeric data.
AVG() Returns the average value of numeric data. AVG(expression) Ignores NULL values automatically.
MAX() Retrieves the maximum value in a column. MAX(expression) Works with numeric, string, and date data types.
MIN() Retrieves the minimum value in a column. MIN(expression) Works with numeric, string, and date data types.
GROUP_CONCAT() Concatenates values in a group into a single string (MySQL-specific). GROUP_CONCAT(expression) Limited by group_concat_max_len in MySQL.
STRING_AGG() Concatenates values in a group with a specified separator (PostgreSQL). STRING_AGG(expression, delimiter) More flexible than GROUP_CONCAT().
VARIANCE() Calculates the variance of numeric values in a column (PostgreSQL). VARIANCE(expression) Requires numeric data; not widely supported.
STDDEV() Calculates the standard deviation of numeric data. STDDEV(expression) Ignores NULL values; supported in PostgreSQL.
LEAST() Compares multiple expressions and returns the smallest (or "least") value from them. LEAST(value1, value2, ..., valueN) All input values must have compatible data types; otherwise, errors occur.
GREATEST() Compares multiple expressions and returns the largest (or "greatest") value from them. GREATEST(value1, value2, ..., valueN) All input values must have compatible data types; otherwise, errors or inconsistent results may occur.

Key Reasons to Use Aggregation Functions

1. Summarize Data:- They provide summaries like totals, averages, counts, or ranges.

  • Example: Total sales for the year, average employee salary.

2. Identify Extremes:- Help find minimum or maximum values.

  • Example: The highest sales record or the earliest hire date.

3. Group-Level Insights:- Work with GROUP BY to get summarized statistics for subsets of data.

  • Example: Average salary by department.

4. Data Analysis:- Essential for analytical and business intelligence reports.

  • Example: Generating KPIs, trends, or performance metrics.

5. Simplify Queries:- Eliminate the need for additional calculations in application logic by summarizing data directly in SQL.


1.COUNT()

Counts rows or specific non-NULL column values.


Syntax

COUNT(expression) - - Counts non-NULL values
COUNT(*) -- Counts all rows, including rows with NULL

Examples

Scenario 1:- Count total rows in a table.

SELECT COUNT(*) AS Total_Employees
FROM employees ;

Scenario 2:- Count the number of active employees in a company.

SELECT COUNT(*) AS Active_employees
FROM employees
WHERE status = 'Active' ;

Scenario 3:- Count the number of unique job roles in the organization.

SELECT COUNT( DISTINCT job_role) AS Distinct_Roles
FROM employees ;

Scenario 4:- Count the number of employees in each department.

SELECT department_id, COUNT(*) AS Emp_Count
FROM employees
GROUP BY department_id ;

Scenario 5:- Count distinct job roles in active departments.

SELECT COUNT(DISTINCT job_role) AS DISTINCT_Roles
FROM employees
WHERE status = 'Active' ;

Scenario 6:- Count the total number of orders placed by each customer.

SELECT c.customer_id, COUNT(o.order_id) AS total_orders
FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id
GROUP BY customer_id ;

  • A LEFT JOIN ensures all customers are included, even if they haven't placed any orders.
  • Groups by customer_id to count the number of orders for each customer.

Scenario 7:- Find departments with more than 10 employees.

SELECT department_id, COUNT(*) AS Emp_Count
FROM employees
GROUP BY department_id
HAVING COUNT(*) > 10 ;

Scenario 8:- Find customers who have placed more than 5 orders.

SELECT customer_id
FROM orders
GROUP BY customer_id
HAVING COUNT(order_id) > 5 ;

Scenario 9:- Rank employees based on the number of projects they are part of.

SELECT employee_id, total_projects,
    RANK() OVER ( ORDER BY total_projects DESC) AS rank
FROM

( SELECT employee_id, COUNT(project_id) AS total_projects FROM project_Assignments GROUP BY employee_id)
AS project_counts ;


Scenario 10:- Count the number of active and inactive employees in the organization.

SELECT
COUNT( CASE WHEN status = 'Active' THEN 1 END ) AS active_employees,
COUNT( CASE WHEN status = 'Inactive' THEN 1 END ) AS inactive_employees
FROM employees ;

Scenario 11:- Count the number of employees per department who joined in each year.

SELECT department_id,
YEAR (hire_date) AS hire_year, COUNT(*) AS Emp_Count
FROM employees
GROUP BY department_id, YEAR (hire_date)
ORDER BY department_id, hire_year ;

2.SUM()

The SUM() function is used to calculate the total sum of numeric values in a specified column.


Syntax

SUM(expression)
- - expression: A numeric column or a calculation on numeric columns.

SUM () Key Features

  • Works only with numeric data types (e.g., integers, floats).
  • Ignores NULL values automatically.
  • Commonly used with GROUP BY, HAVING, and WHERE clauses.

Examples

Scenario 1:- Calculate the total sales.

SELECT SUM(sales_amount) AS Total_Sales
FROM sales ;

Scenario 2:- Calculate the total sales for a specific region (North).

SELECT SUM( sales_amount ) AS Region_Sales
FROM sales
WHERE region = 'North' ;

Scenario 3:- Calculate the total sales for each region (Group By).

SELECT region, SUM(sales_amount) AS Region_Sales
FROM sales
GROUP BY region ;

Scenario 4:- Calculate the total revenue for each customer based on orders.

SELECT c.customer_id, SUM( o.order_amount ) AS Total_Revenue
FROM customers c
JOIN orders o ON c.customer_id = o.customer_id
GROUP BY c.customer_id ;

Scenario 5:- Find departments where total salaries exceed $1,000,000.

SELECT department_id
FROM (
    SELECT department_id, SUM( salary ) AS Total_Salary
    FROM employees
    GROUP BY department_id
) subquery WHERE Total_Salary > 1000000 ;

Scenario 6:- Calculate a running total of sales over time with Window Functions.

SELECT sales_date, sales_amount,
SUM( sales_amount ) OVER ( ORDER BY sales_date ) AS Running_Total
FROM sales ;

Scenario 7:- Calculate the total sales for products above and below $50 price.

SELECT
SUM ( CASE WHEN price >= 50 THEN sales_amount ELSE 0 END ) AS High_Sales,
SUM ( CASE WHEN price < 50 THEN sales_amount ELSE 0 END ) AS Low_Sales
FROM sales ;

Scenario 8:- Calculate total revenue while handling NULL values explicitly.

SELECT SUM( COALESCE(revenue, 0) ) AS total_revenue
FROM sales ;

Scenario 9:- Calculate the total cost of a product, including nested components in a Bill of Materials (BOM) structure.

WITH RECURSIVE ComponentCost AS (
    SELECT component_id, cost
    FROM components
    WHERE parent_id IS NULL
    UNION ALL SELECT c.component_id, c.cost
    FROM components c
    JOIN ComponentCost cc ON c.parent_id = cc.component_id
) SELECT SUM(cost) AS total_cost
FROM ComponentCost ;

Using SUM() with All SQL Clauses

    Clause Usage with SUM()
    WHERE Apply conditions to filter rows before summing.
    GROUP BY Summarize data for each group (e.g., region or department).
    HAVING Filter groups based on the aggregated sum.
    JOIN Combine data from multiple tables and sum values.
    CASE Sum data conditionally (e.g., high-price vs low-price products).
    WINDOW FUNCTION Calculate cumulative sums or partitions without collapsing rows.
    UNION Combine results from multiple queries and sum across all rows.

Common Errors with SUM()

    Characteristic Common Errors
    Data Type Attempting to sum non-numeric columns, e.g., SUM(name) results in an error.
    NULL Handling Ignoring NULL values can lead to missing parts of the sum.
    GROUP BY Usage Forgetting GROUP BY when selecting non-aggregated columns causes errors.
    Multiple Aggregates Misplacing or combining SUM() with other aggregation functions incorrectly.
    Performance Using SUM() on large datasets without indexes leads to slow performance.

3.AVG()

The AVG() function returns the arithmetic mean of a column's values, ignoring NULL values.


Syntax

AVG ( expression )

  • expression: A numeric column or an expression involving numeric columns.

Key Features

1. Works only with numeric data types (e.g., integers, floats).

2. Automatically ignores NULL values.

3. Can be used with clauses like GROUP BY, HAVING, and WHERE.


Examples

Scenario 1:- Find the average salary of all employees.

SELECT AVG(salary) AS avg_salary
FROM employees ;

Scenario 2:- Find the average salary of employees in the "IT" department.

SELECT AVG(salary) AS avg_salary
FROM employees WHERE department = 'IT' ;

Scenario 3:- Find the average salary for each department.

SELECT department, AVG(salary) AS avg_salary
FROM employees GROUP BY department ;

Scenario 4:- List employees whose salaries are above the company-wide average.

SELECT employee_id, name, salary
FROM employees
WHERE salary > ( SELECT AVG(salary) FROM employees ) ;

Scenario 5:- Find the average salary of managers and non-managers.

SELECT
    AVG( CASE WHEN job_title = 'Manager' THEN salary ELSE NULL END ) AS avg_manager_salary,
    AVG( CASE WHEN job_title != 'Manager' THEN salary ELSE NULL END ) AS avg_non_manager_salary
FROM employees ;

Scenario 6:- Calculate the average salary of employees in departments that have more than 10 employees.

SELECT d.department_name, AVG( e.salary ) AS avg_salary
FROM departments d
JOIN employees e ON d.department_id = e.department_id
GROUP BY d.department_name HAVING COUNT(e.employee_id) > 10 ;

Scenario 7:- Calculate the average salary, explicitly including NULL as 0.

SELECT AVG( COALESCE(salary, 0) ) AS Avg_Sal
FROM employees ;

Scenario 8:- Find a weighted average salary, where weight is the years of experience.

SELECT SUM( salary * years_experience ) / SUM( years_experience ) AS Avg_Sal
FROM employees ;

Scenario 9:- Calculate the running average salary over time.

SELECT employee_id, salary,
    AVG(salary) OVER ( ORDER BY hire_date ) Avg_Salary
FROM employees ;

Scenario 10:- Calculate the average of unique salaries.

SELECT AVG(salary) AS Distinct_Avg_Salary
FROM
    ( SELECT DISTINCT salary FROM employees) AS unique_salaries ;

Scenario 11:- Calculate average salaries at each management level.

WITH ManagementHierarchy AS (
    SELECT employee_id, salary, manager_id, 1 AS LEVEL
    FROM employees
    WHERE manager_id IS NULL
    UNION ALL
SELECT e.employee_id, e.salary,e.manager_id , mh.level+1 FROM employees e
JOIN ManagementHierarchy mh ON e.manager_id = mh.employee_id )
SELECT LEVEL, AVG(salary) AS avg_salary
FROM ManagementHierarchy
GROUP BY LEVEL ORDER BY LEVEL ;

Common Errors with AVG()

Error Cause Fix
"Operand data type is invalid for AVG operator." Applying AVG() to non-numeric columns. Use only numeric columns with AVG().
"Invalid column in the SELECT list." Using non-aggregated columns without GROUP BY. Include all non-aggregated columns in GROUP BY.
Incorrect averages due to NULL values. Ignoring NULL handling explicitly. Use COALESCE to handle NULL values explicitly.
Performance issues on large datasets. Lack of indexes or optimized filtering. Index columns in WHERE or JOIN clauses.

Do's and Don'ts for AVG()

Do's Don'ts
Use AVG() for numeric columns only. Don’t use AVG() on non-numeric or categorical columns—it will throw errors.
Combine AVG() with COALESCE to handle NULL values explicitly when needed. Don’t assume NULL values are included—they are ignored by default.
Use GROUP BY to calculate averages for specific groups (e.g., departments, regions). Don’t forget the GROUP BY clause when including other columns in the query.
Use window functions for advanced calculations like running averages or partitioned data. Don’t misuse PARTITION BY or forget to specify ORDER BY in window functions.
Validate business logic before using DISTINCT in AVG(). Don’t blindly apply DISTINCT without understanding its impact on the result.

4.MAX()

The MAX() function returns the largest value from a specified column. It works on both numeric and date types and ignores NULL values.


MAX ( expression )

- - expression: The column or expression to evaluate.

Key Features

1. Finds the maximum value in a column.

2. Works on numeric, date, and string data types.

3. Ignores NULL values by default.

4. Can be combined with GROUP BY, HAVING, and other SQL clauses.


Examples

Scenario 1:- Find the highest salary in the employees table.

SELECT MAX( salary ) AS max_salary
FROM employees ;

Scenario 2:- Find the most recent hire date.

SELECT MAX( hire_date ) AS Recent_hire_date
FROM employees ;

Scenario 3:- Find the last name that comes last in alphabetical order. .

SELECT MAX( Last_name ) AS Last_name
FROM employees ;

Scenario 4:- Find the highest salary for each department (Group By).

SELECT department_id, MAX( Salary ) AS max_sal
FROM employees
GROUP BY department_id ;

Scenario 5:- Find the highest salary in the "IT" department (Where).

SELECT Dept_Name, MAX(Salary) AS IT_max_sal
FROM employees
WHERE Dept_Name = 'IT' GROUP BY Dept_Name ;

Scenario 6:- Identify employees with the highest salary in the company (Sub Query).

SELECT Emp_Id,Ename, Salary
FROM employees
WHERE Salary = ( SELECT MAX(Salary) FROM employees) ;

Scenario 7:- Find the department with the highest average salary.

SELECT Dept_Name,Avg_Salary FROM (
    SELECT Dept_Name, AVG(Salary) AS avg_salary
    FROM employees
    GROUP BY Dept_Name
) subquery ORDER BY avg_salary DESC LIMIT 1 ;

Scenario 8:- Calculate the maximum salary within each department while keeping all rows (Window Function).

SELECT Emp_Id, Dept_Name, Salary,
    MAX( Salary ) OVER ( PARTITION BY Dept_Name ) AS Max_Dept_Sal
FROM employees ;

Scenario 9:- Find the maximum salary of managers only ( CASE ).

SELECT
    MAX( CASE WHEN job_title = 'Manager' THEN salary ELSE NULL END ) AS max_manager_salary
FROM employees ;

Scenario 10:- Find the longest tenure of an employee (difference between hire date and current date).

---postgreSQL SELECT
MAX(CURRENT_DATE - hire_date) AS Long_Service_Emp FROM employees ;

Common Errors with MAX()

Error Cause Fix
"Invalid column in the SELECT list." Using non-aggregated columns without GROUP BY. Include non-aggregated columns in the GROUP BY.
"Operand data type is invalid for MAX operator." Applying MAX() on unsupported data types (e.g., TEXT). Use supported data types like numeric or date.
Incorrect results when handling NULL values. Misunderstanding how NULL values are ignored. Use COALESCE for explicit NULL handling.

Do's and Don'ts for MAX()

Do's Don'ts
Use MAX() on numeric, date, or string data for meaningful maximum values. Don’t apply MAX() on unsupported or ambiguous data types like complex objects.
Combine MAX() with GROUP BY to find maximums for grouped data. Don’t forget to include GROUP BY for non-aggregated columns when using MAX().
Use subqueries to identify rows corresponding to maximum values. Don’t expect MAX() to return rows—it returns a single scalar value unless used with OVER.
Apply MAX() as a window function for row-wise comparisons within partitions. Don’t overuse MAX() in subqueries or nested logic without proper indexing.
Handle NULL values explicitly when necessary using COALESCE. Don’t assume NULL values are part of the calculation—they are ignored by default.

5.MIN()

The MIN() function returns the smallest value from a specified column or expression.

  • It works for numeric, date, and string data types and ignores NULL values by default.
  • It’s commonly used to determine the smallest number, earliest date, or alphabetically first string in a dataset.
MIN ( expression )

- - expression: The column or calculated value from which to find the minimum.

Key Features

1. Works with numeric, date, and string data types.

2. Automatically ignores NULL values.

3. Can be combined with SQL clauses like GROUP BY, HAVING, and WHERE.

4. Efficiently finds the smallest value in both simple and complex scenarios.


Examples

Scenario 1:- Find the lowest salary in the employees' table.

SELECT MIN( salary ) AS min_salary
FROM employees ;

Scenario 2:- Find the first hire date.

SELECT MIN( hire_date ) AS First_hire_date
FROM employees ;

Scenario 3:- Find the first name alphabetically.

SELECT MIN( Last_name ) AS First_Name_Order
FROM employees ;

Scenario 4:- Find the lowest salary for each department (Group By).

SELECT department_id, MIN(Salary) AS Min_Sal
FROM employees
GROUP BY department_id ;

Scenario 5:- Find the department with the lowest employee salary and its details.

SELECT d.Dept_Name, MIN( e.salary ) AS Min_Sal
FROM departments d
JOIN employees e ON d.department_id = e.department_id
GROUP BY d.Dept_Name ;

Scenario 6:- Find the earliest order date for each customer.

SELECT customer_id, MIN( order_date ) AS First_Order_Date
FROM orders
GROUP BY customer_id ;

Scenario 7:- Calculate the minimum salary, treating NULL as 0.

SELECT MIN( COALESCE( salary, 0 ) ) AS Min_Sal
FROM employees ;

Common Errors with MIN()

Error Cause Fix
Operand data type is invalid for MIN operator. Applying MIN() on non-comparable data types. Use supported data types like numeric, date, or string.
Invalid column in the SELECT list. Using non-aggregated columns without GROUP BY. Include all non-aggregated columns in GROUP BY.
Incorrect results due to NULL values. Misunderstanding how NULL values are ignored. Use COALESCE to handle NULL values explicitly.

Do's and Don'ts for MIN()

Do's Don'ts
Use MIN() to find the smallest value in numeric, date, or string columns. Don’t use MIN() on unsupported data types like JSON or complex objects.
Combine MIN() with GROUP BY to calculate minimums for specific groups. Don’t forget to include GROUP BY when using other columns alongside MIN().
Apply MIN() as a window function for advanced analytics. Don’t overuse MIN() in subqueries without optimization—may lead to performance issues.
Handle NULL values explicitly when necessary using COALESCE. Don’t assume NULL values are included—they are ignored by default.
Use indexing on columns to improve performance when calculating minimums. Don’t use MIN() without proper indexing on large datasets—it can cause slow queries.

6.GROUP_CONCAT()

The GROUP_CONCAT() function concatenates values from a specified column or expression for rows grouped by GROUP BY.


  • It is particularly useful for creating comma-separated lists or aggregating data into a single row.
  • It works with string data and can include custom separators, sorting, and filtering.
GROUP_CONCAT( expression [ ORDER BY expression ASC | DESC ] [SEPARATOR 'string'])

  • expression: The column or calculated value to concatenate.
  • ORDER BY: Optional. Specifies the order of concatenation.
  • SEPARATOR: Optional. Specifies the string to separate concatenated values (default is a comma ,).

Key Features

1. Concatenates values from multiple rows into a single string.

2. Supports custom ordering of concatenated values.

3. Allows custom separators for concatenated values.

4. Works only with MySQL and MariaDB (not standard in other SQL dialects).


Examples

Scenario 1:- Create a comma-separated list of employee names.

SELECT GROUP_CONCAT(name) AS employee_names
FROM employees ;
- - Output: A single string of all employee names separated by commas.

Scenario 2:- List employee names separated by a semicolon (;).

SELECT GROUP_CONCAT(name SEPARATOR '; ') AS employee_names
FROM employees ;
-- Output: A single string with employee names separated by semicolons.

Scenario 3:- List employee names in alphabetical order.

SELECT GROUP_CONCAT( name ORDER BY name ASC ) AS employee_names
FROM employees ;

Scenario 4:- Concatenate employee names grouped by department.

SELECT department_id,
    GROUP_CONCAT( name ORDER BY name ASC ) AS employee_names
FROM employees
GROUP BY department_id ;

Scenario 5:- Concatenate names of employees hired after 2020.

SELECT GROUP_CONCAT(name) AS Recent_Employee
FROM employees
WHERE hire_date > '2020-01-01' ;

Scenario 6:- Concatenate names of employee with lowest salary.

SELECT GROUP_CONCAT(name ORDER BY name) AS lowest_paid_employees
FROM employees
WHERE Salary = ( SELECT MIN(Salary) FROM employees) ;

Scenario 7:- Find the department with the highest average salary.

SELECT c.category_name,
    GROUP_CONCAT(p.product_name ORDER BY p.product_name ASC SEPARATOR ',') AS products
FROM categories c
JOIN products p ON c.category_id = p.category_id
GROUP BY c.category_name ;

Scenario 8:- Concatenate project names handled by the highest-paid employee in each department.

SELECT e.department_id,
    ( SELECT GROUP_CONCAT(project_name)
    FROM projects p
    WHERE p.employee_id = e.employee_id ) AS project_list
FROM employees e
WHERE salary = ( SELECT MAX(salary) FROM employees WHERE department_id = e.department_id ) ;

Scenario 9:- Concatenate names of employees along with their department's highest salary.

SELECT d.department_id,
    MAX( e.salary ) AS max_salary,
    GROUP_CONCAT( e.name ORDER BY e.salary DESC ) AS employees_by_salary
FROM departments d
JOIN employees e ON d.department_id = e.department_id GROUP BY d.department_id ;

Scenario 10:- Create JSON-formatted data for front-end applications.

SELECT JSON_OBJECT(
      'department_id', department_id,
      'employees', GROUP_CONCAT(name SEPARATOR ', ')
    ) AS department_data
FROM employees GROUP BY department_id ;

Common Errors with GROUP_CONCAT()

Error Cause Fix
Function not recognized GROUP_CONCAT() is not available in non-MySQL databases. Use a compatible database like MySQL or MariaDB.
Row size too large Result exceeds group_concat_max_len. Increase the limit with SET SESSION group_concat_max_len.
Values not ordered as expected Missing ORDER BY in GROUP_CONCAT(). Add ORDER BY clause in the function.
Performance issues on large datasets. Lack of proper indexing. Index columns used in the query to improve performance.

Do's and Don'ts for GROUP_CONCAT()

Do's Don'ts
Use ORDER BY in GROUP_CONCAT() for predictable output ordering. Don’t use GROUP_CONCAT() on extremely large datasets without increasing the limit.
Use SEPARATOR to create custom-delimited strings like JSON, XML, or CSV. Don’t forget to index columns in joins or GROUP BY for performance optimization.
Increase group_concat_max_len when working with large concatenated results. Don’t assume GROUP_CONCAT() results are inherently unique—use DISTINCT if necessary.
Use subqueries for combining GROUP_CONCAT() results with other aggregates. Don’t use GROUP_CONCAT() in databases that don’t support it (e.g., SQL Server, PostgreSQL).

7.STRING_AGG()

The STRING_AGG() function is a powerful aggregate function, it is used to concatenate values from multiple rows into a single string.


  • It is similar to GROUP_CONCAT() in MySQL but is widely supported in SQL Server and PostgreSQL.
STRING_AGG(expression, separator) [ WITHIN GROUP ( ORDER BY expression)]

  • expression: The column or value to concatenate.
  • separator: The string used to separate concatenated values (e.g., ,, |).
  • WITHIN GROUP (ORDER BY expression): Optional. Specifies the order of concatenated values.

Key Features

1. Concatenates values from multiple rows into a single string.

2. Supports ordering of concatenated results with the WITHIN GROUP clause.

3. Allows flexible separators, making it useful for custom-delimited outputs like CSV or pipe-separated data.

4. Automatically excludes NULL values.

5. Supported in SQL Server (2017 and later) and PostgreSQL (9.0 and later).


Examples

Scenario 1:- Create a comma-separated list of employee names.

SELECT STRING_AGG(name, ', ' ) AS employee_names
FROM employees ;
- - Output: A single string with all employee names separated by commas.

Scenario 2:- List employee names separated by semicolons (;).

SELECT STRING_AGG(name, '; ' ) AS employee_names
FROM employees ;
-- Output: Employee names concatenated with a semicolon as the separator.

Scenario 3:- Create a list of employee names sorted alphabetically.

SELECT STRING_AGG(name, ', ') WITHIN GROUP ( ORDER BY name ASC ) AS employee_names ;

Scenario 4:- Concatenate employee names grouped by department.

SELECT Dept_Name,
    STRING_AGG(name, ', ' ) WITHIN GROUP ( ORDER BY name ASC ) AS Emp_Names_Sort
FROM employees
GROUP BY Dept_Name ;

Scenario 5:- Concatenate employee names hired after 2022.

SELECT STRING_AGG(name, ', ' ) AS Recent_Employee
FROM employees
WHERE hire_date > '2022-01-01' ;

Scenario 6:- List project names for each employee.

SELECT e.Emp_Id,
    STRING_AGG(p.project_name, ', ' ) AS Emp_Project_List
FROM employees e
JOIN projects p ON e.Emp_Id = p.Emp_Id
GROUP BY e.Emp_Id ;

Scenario 7:- Generate JSON-formatted output for API consumption.

SELECT JSON_BUILD_OBJECT(
      'department_id', department_id,
      'employees', STRING_AGG(name, ', ')
    ) AS department_data
FROM employees
GROUP BY department_id ;

Scenario 8:- Include NULL as a placeholder for missing values.

SELECT STRING_AGG( COALESCE( name, 'N/A'), ', ' ) AS employee_names
FROM employees e

- - STRING_AGG() ignores NULL values by default. To include them explicitly, use COALESCE.

Scenario 9:- Concatenate product names for each supplier.

SELECT s.supplier_name,
    STRING_AGG( p.product_name, ', ' ) AS products
FROM suppliers s
JOIN products p ON s.supplier_id = p.supplier_id
GROUP BY s.supplier_name ;

Scenario 10:- Split concatenated results into chunks.

SELECT array_to_string(array_agg(name), ', ') AS employee_chunks FROM employees GROUP BY department_id ;

Common Errors with STRING_AGG()

Error Cause Fix
Function STRING_AGG does not exist Using in unsupported databases (e.g., MySQL). Use GROUP_CONCAT() or install extensions.
Invalid ORDER BY clause in WITHIN GROUP Using unsupported expressions in ORDER BY. Use valid columns or expressions in ORDER BY.
String length exceeds limit. Concatenated string is too large. Use arrays (array_agg) for handling large strings.
Incorrect results when NULL values are present. Misunderstanding how NULL is handled. Use COALESCE to handle NULL explicitly.

Do's and Don'ts for STRING_AGG()

Do's Don'ts
Use WITHIN GROUP for predictable ordering of concatenated results. Don’t use STRING_AGG() in databases that don’t support it natively.
Handle NULL values explicitly using COALESCE if needed. Don’t forget to account for large outputs if concatenating many rows.
Leverage STRING_AGG() for creating delimited or formatted outputs like CSV or JSON. Don’t use STRING_AGG() in performance-critical scenarios without optimization.
Use appropriate separators based on the use case (e.g., commas, pipes, newlines). Don’t forget to test concatenated outputs for long strings or unexpected formats.

STRING_AGG() vs GROUP_CONCAT()

Feature STRING_AGG() GROUP_CONCAT()
Supported Databases SQL Server, PostgreSQL MySQL, MariaDB
Ordering Support Yes (WITHIN GROUP) Yes (ORDER BY)
Custom Separator Yes Yes
Handling Large Outputs Flexible with array functions Requires increasing group_concat_max_len.

8.VARIANCE(expression)

The VARIANCE() function in SQL calculates the statistical variance of a numeric column or expression.

  • Variance is a measure of the dispersion of a set of values, showing how far individual numbers in a dataset are from the mean.
  • Variance quantifies how spread out the data points in a dataset are.
  • Mathematically, it is the average of the squared differences from the mean.
VARIANCE( expression )

  • MySQL: VARIANCE() is supported as of version 8.0. In earlier versions, you can use VAR_POP() for population variance.
  • PostgreSQL: Supports VARIANCE() for sample variance and also VAR_POP() and VAR_SAMP().
  • SQL Server: Does not support VARIANCE(). Use VAR() for sample variance and VARP() for population variance.
  • Oracle: Supports VARIANCE() for population variance.

Examples

Scenario 1:- Calculate the variance of salaries across all employees.

SELECT VARIANCE( salary ) AS salary_variance
FROM employees ;

Scenario 2:- Find how monthly sales vary for a product.

SELECT product_id,
VARIANCE( sales ) AS sales_variance
FROM monthly_sales
GROUP BY product_id ;

Scenario 3:- Compute variance of distinct item prices in an inventory.

SELECT VARIANCE(price)
AS price_variance
FROM ( SELECT DISTINCT price FROM inventory ) AS distinct_prices ;

Scenario 4:- Measure variance in employee performance scores.

SELECT department_id,
    VARIANCE( performance_score ) AS performance_variance
FROM employee_performance GROUP BY department_id ;

Scenario 5:- Calculate variance in daily website traffic.

SELECT VARIANCE( traffic_count ) AS traffic_variance
FROM website_traffic WHERE visit_date BETWEEN '2024-01-01' AND '2024-12-31' ;

Scenario 6:- Calculate variance in project budgets per department.

SELECT d.department_name,
VARIANCE( p.budget ) AS budget_variance
FROM departments d
JOIN projects p ON d.department_id = p.department_id
GROUP BY d.department_name ;

Scenario 7:- Compare variance and standard deviation of sales for top-performing products.

SELECT product_id,
    VARIANCE( sales ) AS sales_variance,
    STDDEV( sales ) AS sales_stddev
FROM sales_data
WHERE sales > 10000
GROUP BY product_id ;

Scenario 8:- Calculate variance of test scores with a weightage factor.

SELECT student_id,
    VARIANCE( score * weight ) AS weighted_variance
FROM test_scores
GROUP BY student_id ;

Scenario 9:- Find variance in sales relative to a moving average.

WITH moving_avg_sales AS (
    SELECT product_id,sale_date,sales, AVG(sales) OVER ( PARTITION BY product_id ORDER BY sale_date ROWS BETWEEN 6 PRECEDING AND CURRENT ROW ) AS moving_avg
FROM sales ) SELECT product_id,
    VARIANCE( sales - moving_avg ) AS variance_from_avg
FROM moving_avg_sales GROUP BY product_id ;

Scenario 10:- Find variance of product prices for the highest-selling categories.

SELECT category_id,
    VARIANCE(price) AS price_variance
FROM products
WHERE category_id IN (
    SELECT category_id
    FROM sales
    GROUP BY category_id
    HAVING SUM(quantity) > 1000
) GROUP BY category_id ;

Common Errors with VARIANCE()

Error Cause Fix
Function not recognized VARIANCE() is not supported. Use database-specific functions like VAR_POP().
Incorrect results due to NULL values NULL values are included implicitly. Use WHERE clause to filter out NULL values.
Performance issues on large datasets. Lack of proper indexing or grouping. Optimize with indexes or reduce dataset size.

Do's and Don'ts for VARIANCE()

Do's Don'ts
Use GROUP BY to calculate variance for specific groups or categories. Don’t use VARIANCE() on datasets with mixed numeric and non-numeric data.
Combine variance with other statistical functions like AVG or STDDEV. Don’t assume NULL values are excluded—filter them explicitly if needed.
Optimize queries by filtering unnecessary data early using WHERE. Don’t forget to check database compatibility (e.g., SQL Server uses VAR).

9.STDDEV(expression)

The STDDEV() function calculates the standard deviation of a set of numeric values.

  • Standard deviation is a measure of how spread out the numbers in a dataset are around their mean.
  • It is commonly used in statistics to evaluate variability or consistency.
  • Low standard deviation: Data points are close to the mean.
  • High standard deviation: Data points are more spread out.
STDDEV( expression )

  • expression: The numeric column or calculation for which you want to calculate the standard deviation.
  • DISTINCT: Optional. Calculates the standard deviation of distinct values only.
  • ALL: Optional (default). Includes all values.

Standard Deviation Functions

Database Function Notes
PostgreSQL STDDEV() Calculates sample standard deviation.
MySQL STDDEV_SAMP() and STDDEV_POP() STDDEV() is an alias for STDDEV_SAMP() in MySQL.
SQL Server STDEV() Use STDEV() for sample SD, STDEVP() for population SD.
Oracle STDDEV() Oracle supports STDDEV() for sample SD and STDDEV_POP() for population SD.

Key Features

  • Measures variability or consistency in numeric datasets.
  • Can calculate for all values (ALL) or distinct values only (DISTINCT).
  • Supports grouping and filtering for targeted calculations.
  • Database-specific variations exist (e.g., STDEVP() for population SD).

Examples

Scenario 1:- Calculate the standard deviation of all employee salaries.

SELECT STDDEV(salary) AS Stddev_Sal
FROM employees ;

Scenario 2:- Compute standard deviation of salaries for employees in a specific department.

SELECT STDDEV( salary ) AS Dept_Stddev_Salary
FROM employees
WHERE department_id = 101 ;

Scenario 3:- Calculate the standard deviation of unique item prices.

SELECT STDDEV(price) AS distinct_stddev_price
    FROM ( SELECT DISTINCT price FROM inventory ) AS distinct_prices ;

Scenario 4:- Find the standard deviation of sales per region.

SELECT region, STDDEV( sales ) AS Stddev_Sales FROM Sales
GROUP BY region ;

Scenario 5:- Compare average and standard deviation of sales across products (Using Aggregation Function)

SELECT product_id,
    AVG( sales ) AS average_sales ,
    STDDEV( sales ) AS sales_stddev
FROM Sales GROUP BY product_id ;

Scenario 6:- Compute standard deviation for top-selling categories only.

SELECT category_id,
    STDDEV( price ) AS price_stddev
FROM products
WHERE category_id IN (
    SELECT category_id
    FROM Sales
    GROUP BY category_id
    HAVING SUM(quantity) > 1000
) GROUP BY category_id ;

Scenario 7:- Compare variance and standard deviation of sales for top-performing products.

SELECT product_id,
    VARIANCE( sales ) AS sales_variance ,
    STDDEV( sales ) AS sales_stddev
FROM sales_data
WHERE sales > 10000
GROUP BY product_id ;

Scenario 8:- Generate JSON-like output for performance metrics.

SELECT JSON_BUILD_OBJECT (
    'department', department_id,
    'performance_stddev', STDDEV(performance_score)
) AS department_performance FROM employee_performance
GROUP BY department_id ;

Common Errors with STDDEV()

Error Cause Fix
Function not recognized STDDEV() is not supported in the database. Use database-specific alternatives like STDEV().
Results include NULL values NULL values are not automatically excluded. Use WHERE clause to filter out NULL values.
Performance issues on large datasets. Lack of optimization in the query. Use indexes and appropriate filtering.

Do's and Don'ts for STDDEV()

Do's Don'ts
Use GROUP BY to calculate standard deviation for specific groups. Don’t apply STDDEV() to non-numeric columns or expressions.
Filter out NULL values explicitly with WHERE. Don’t forget to check database compatibility for STDDEV().
Compare STDDEV() with other metrics like AVG or VARIANCE. Don’t assume STDDEV() gives population SD by default.
Combine with DISTINCT for unique values analysis. Don’t assume STDDEV() gives population SD by default.

10.LEAST()

The LEAST() function returns the smallest value from a list of provided arguments, which can include columns, literals, or expressions.

  • It works with various data types, such as integers, decimals, strings, and dates, while ensuring proper comparison.
  • If any argument is NULL, the result is NULL, making it sensitive to incomplete data (except when handled with COALESCE()).
  • It is supported in databases like MySQL, PostgreSQL, and Oracle, but SQL Server does not have a built-in LEAST() function.

LEAST( value1, value2, ..., valueN )

  • value1, value2, ..., valueN: A list of expressions or values to compare. These can be columns, literals, or expressions.
  • The function returns the smallest (minimum) value from the provided arguments.

Examples

Scenario 1:- Compare fixed values to find the smallest.

SELECT LEAST(10, 20, 5, 15) AS smallest_value ;

-- Output : 5

Scenario 2:- Identify the lowest score of students.

SELECT student_id,
    LEAST( math_score, science_score, english_score ) AS lowest_score
FROM student_scores ;

Scenario 3:- Find the earliest event date.

SELECT event_id,
    LEAST( start_date, end_date ) AS earliest_date
FROM events ;

Scenario 4:- Find the earliest date from multiple date columns.

SELECT employee_id,
    LEAST( joining_date, probation_end_date, contract_end_date ) AS earliest_date
FROM employees ;

Scenario 5:- Find the smallest value after applying a calculation.

SELECT
LEAST(s.sum_sales, s.avg_sales, s.max_sales) AS lowest_stat FROM (
    SELECT SUM(Sales) AS sum_sales,
    AVG(Sales) AS avg_sales,
    MAX(Sales) AS max_sales
    FROM sales_data
) AS s ;

Scenario 6:- Find the smallest discount applicable to a product.

SELECT product_id,
    LEAST( discount_rate, special_offer_rate, seasonal_offer_rate ) AS best_discount
FROM product_discounts ;

Scenario 7:- Compare timestamp and date to find the earliest.

SELECT LEAST( '2024-12-19 10:30:00', '2024-12-19' ) AS earliest_datetime ;

Common Errors with LEAST()

Error Cause Solution
Inconsistent data types Mixing incompatible data types (e.g., strings and numbers). Ensure all input values have compatible data types.
Function does not exist Using LEAST() in SQL Server where it is not natively supported. Use a CASE statement or implement a custom scalar function.
NULL result Any input value is NULL, leading to the entire result being NULL. Use COALESCE() to handle NULL values before passing them to the LEAST() function.
Unsupported in SQL Server SQL Server doesn’t support LEAST(). Use MIN() with VALUES or CASE as a workaround.

Do's and Don'ts for LEAST()

Do's Don'ts
Use LEAST() to simplify conditional logic when comparing multiple values. Assume LEAST() is supported in all databases; check the database documentation first.
Handle NULL values using COALESCE() to avoid unexpected NULL results. Use incompatible data types as arguments (e.g., mixing numbers and strings).
Use LEAST() for clean and concise queries where multiple comparisons are needed. Overcomplicate queries with LEAST() where simpler conditions (e.g., MIN()) suffice.

11.GREATEST()

The GREATEST() function returns the largest value from a list of provided values.

  • It can compare different data types (numbers, strings, dates) if the database supports implicit type conversion.
  • If any argument is NULL, the result is NULL unless explicitly handled.
  • Fully supported in MySQL, PostgreSQL, and Oracle, but requires workarounds in SQL Server.

GREATEST( value1, value2, ..., valueN )

  • value1, value2, ..., valueN: A list of expressions or values to compare. These can be columns, literals, or expressions.
  • The function returns the largest (maximum) value among the provided arguments.

Examples

Scenario 1:- Find the largest from the given set .

SELECT GREATEST( 10, 20, 5, 15 ) AS largest_value ;
