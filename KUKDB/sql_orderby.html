ORDER BY

  • The ORDER BY clause is used to sort the results of a query in ascending or descending order based on one or more columns or expressions.
  • By default, the sorting is in ascending order, but you can explicitly specify descending order if needed.

1. Basic Syntax

SELECT column1, column2,. . .
FROM table_name
ORDER BY column1 [ASC|DESC] , column2 [ASC|DESC] ,. . . ;
  • ASC (Ascending) : Default order (e.g., smallest to largest for numbers, A to Z for strings).
  • DESC (Descending) : Reverses the order (e.g., largest to smallest for numbers, Z to A for strings).

2. Sorting by Column Index

Instead of specifying column names, you can sort by column index in the SELECT clause.

SELECT column1, column2
FROM table_name
ORDER BY 2 ;

- - Sorts by the second column
NOTE : - Sorting by column index is not recommended due to readability and maintainability issues.

3.Null Handling in ORDER BY Clause

    The placement of NULL values depends on the database.


  • Oracle : By default, NULL values are placed last in ascending order and first in descending order.
  • SQL Server and MySQL:- NULL values are treated as the lowest value.

Basic Examples

Example 1: Simple Sorting

Sort employees by their salary in ascending order.

SELECT employee_id, name,salary
FROM employees
ORDER BY salary;

- - By Default Ascending order.

Example 2: Descending Order

Sort employees by salary in descending order.

SELECT employee_id, name,salary
FROM employees
ORDER BY salary DESC;

Example 3: Sorting by Multiple Columns

Sort employees first by department ID in ascending order and then by salary in descending order.

SELECT employee_id, name,department_id,salary
FROM employees
ORDER BY department_id ASC,salary DESC;

Example 4: Sorting by Expressions

Sort products by the discount percentage.

SELECT ProductID, Price,Discount,(Discount / Price) * 100 AS DiscountPercentage
FROM Products
ORDER BY DiscountPercentage DESC;

Advanced Scenarios

1. Combining with Aggregate Functions

Sort departments by the total sales in descending order.

SELECT department_name, SUM(Sales) AS TotalSales
FROM Employees
GROUP BY department_name
ORDER BY SUM(Sales) DESC;

2. Sorting by Aliases

Sort by an alias defined in the SELECT clause.

SELECT EmployeeID, Name,Salary,Salary * 0.1 AS Bonus
FROM Employees
ORDER BY Bonus DESC;

3. Using ORDER BY with Subqueries

Sort products based on total sales calculated from another table.

SELECT ProductID, Name,(SELECT SUM(Quantity)
FROM Sales
WHERE Sales.ProductID = Products.ProductID) AS TotalSales FROM Products
ORDER BY TotalSales DESC;

4. Sorting with NULL Values

  • By default, NULL values are treated as the smallest values in ascending order and the largest in descending order.
  • Use NULLS FIRST or NULLS LAST for explicit control.

NULLS LAST

SELECT EmployeeID, Name,Salary
FROM Employees
ORDER BY salary ASC NULLS LAST;

NULLS FIRST

SELECT ProductID, ProductName,AvailabilityDate
FROM Products
ORDER BY AvailabilityDate DESC NULLS FIRST;

Why Use NULLS FIRST or NULLS LAST?

  • Sorting behavior for NULL values varies by database system.
    • In PostgreSQL, NULLS FIRST is the default for descending order, while NULLS LAST is the default for ascending order.
    • In Oracle and SQL Server, NULLS LAST is generally the default.
  • Specifying NULLS FIRST or NULLS LAST ensures consistent and explicit behavior, regardless of the database.

5. Combining ORDER BY with Window Functions

Retrieve the top 3 highest-paid employees in each department.

WITH RankedSalaries AS
(
    SELECT EmployeeID, Name , department_name, Salary ,
    RANK() OVER (PARTITION BY department_name ORDER BY Salary DESC) AS Rank
    FROM Employees
)
SELECT EmployeeID, Name , department_name, Salary
FROM RankedSalaries
WHERE Rank <= 3
ORDER BY department_name , Rank ;

6. Using ORDER BY with LIMIT/OFFSET

Retrieve the top 5 most expensive products.

SELECT ProductID, ProductName, Price
FROM Products
ORDER BY Price DESC
LIMIT 5 ;

Retrieve rows 6–10 for pagination.

SELECT ProductID, ProductName, Price
FROM Products
ORDER BY Price DESC
LIMIT 5 OFFSET 10 ;

Real-time Scenarios

1. E-commerce: Sorting by Price and Rating

Retrieve the top 10 cheapest products with the highest ratings.

SELECT ProductID, ProductName,Price,Rating
FROM Products
ORDER BY Price ASC , Rating DESC
LIMIT 10 ;

2. Employee Analysis: Salary Band Analysis

Sort employees by salary bands and within each band by years of experience.

SELECT EmployeeID, emp_name,SalaryGrade,Total_exp
FROM Employees
ORDER BY SalaryGrade,Total_exp DESC ;

3. Event Management: Upcoming Events

Retrieve the next 5 events sorted by date.

SELECT EventID, EventName,EventDate
FROM Events
WHERE EventDate >= CURRENT_DATE ORDER BY EventDate ASC LIMIT 5;

Best Practices

1. Use Aliases for Derived Columns.

Simplify queries by naming calculated columns.

  • Example:
    • SELECT Name, Salary * 0.1 AS Bonus
    FROM Employees
    ORDER BY Bonus DESC ;

2. Optimize Sorting with Indexes:

  • Create indexes on frequently sorted columns to improve query performance.

3. Combine with Pagination for Large Datasets:

  • Use LIMIT and OFFSET to fetch manageable chunks of sorted data.

4. Test Sorting on Large Data:

  • Ensure your query performs efficiently on large datasets, especially when sorting multiple columns.

5. Avoid Column Positions:

  • Instead of using column numbers (e.g., ORDER BY 2), use column names for clarity.

6. Avoid ORDER BY in Subqueries:

  • Subqueries with ORDER BY are not guaranteed to preserve order unless explicitly required (e.g., using TOP or LIMIT).

Common Errors

1. Error: "Invalid column name in ORDER BY clause"

  • Cause : Referring to a column that does not exist in the SELECT list or the table.
  • Fix : Ensure the column exists and is spelled correctly.

2. Error: "ORDER BY items must appear in the SELECT list (SQL Server)"

  • Cause :Trying to sort by a column or alias not included in the SELECT list (specific to SQL Server when DISTINCT is used).
  • Fix :Add the column or alias to the SELECT list.

3. Error: "ORDER BY position is out of range"

  • Cause :Referring to a column index that doesn't exist.
  • Fix :Use valid column indexes or column names.

Do’s and Don’ts When Using ORDER BY

Do's :-

  • Use Explicit Sorting: Always specify ASC or DESC for clarity.
  • Sort by Meaningful Columns : Use columns that add value to your results (e.g., sorting invoices by date or amount).
  • Optimize Performance:
    • Ensure the sorted columns are indexed for large datasets.
    • Combine sorting with LIMIT to avoid performance hits when fetching only a subset of rows.

Don'ts :-

  • Avoid Sorting by Non-Selected Columns: While technically possible, it can lead to confusion.
  • Avoid Sorting by Column Index in Production :- Column order may change, breaking your query.
