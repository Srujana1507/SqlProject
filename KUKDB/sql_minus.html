MINUS Operator

The MINUS operator is used to return the rows from the first SELECT query that are not present in the second SELECT query.


It essentially subtracts one result set from another, eliminating duplicates in the process, similar to the concept of subtraction in mathematics.


Key Characteristics of MINUS

  • Set Operation:- MINUS is a set operator that works on two result sets.
  • Excludes Matching Rows:- Returns rows from the first query that are not found in the second query.
  • Order:- The MINUS operator preserves the order of the first query result.
  • Compatibility:- Columns must be:
    • The same in number.
    • The same or compatible data types.
    • In the same order in both queries.

Syntax

SELECT column1, column2, . . .
FROM table1
WHERE condition1
MINUS
SELECT column1, column2, . . .
FROM table2
WHERE condition2 ;

Database Support

  • Oracle:- Fully supports the MINUS operator.
  • SQL Server:- Does not directly support MINUS. You can achieve similar functionality using the EXCEPT operator.
  • MySQL:- Does not support MINUS or EXCEPT. You can replicate this functionality using subqueries or LEFT JOIN.

Examples

1. Basic Usage

Scenario 1:- Find employees who are in department_A but not in department_B.

Oracle:

SELECT employee_id, name
FROM department_A
MINUS
SELECT employee_id, name
FROM department_B ;

SQL Server:

-- SQL Server (using EXCEPT)

SELECT employee_id, name
FROM department_A
EXCEPT
SELECT employee_id, name
FROM department_B ;
-- SQL Server (using NOT IN)

SELECT employee_id, name
FROM department_A
WHERE ( employee_id, name ) NOT IN
( SELECT employee_id, name
FROM department_B) ;

Scenario 2:- Retrieves employees present in the US table but not in the IN table.

- - Oracle
- - SQL Server (replace MINUS with EXCEPT )

SELECT EmployeeID, Name
FROM Employees_US
WHERE total_purchase_amount > 500
MINUS
SELECT EmployeeID, Name
FROM Employees_IN ;

2. Using MINUS with Conditions

Scenario :- Find customers who purchased in 2023 but not in 2024 and whose total purchase amount in 2023 exceeded $500.

- - Oracle
- - SQL Server (replace MINUS with EXCEPT)

SELECT customer_id, name, city
FROM sales_2023
WHERE total_purchase_amount > 500
MINUS
SELECT customer_id, name, city
FROM sales_2024 ;

3. MINUS with Filtering

Scenario :- Lists electronic products available in 2023 but not in 2024.

SELECT ProductID, Category
FROM Products_2023
WHERE Category = 'Electronics'
MINUS
SELECT ProductID, Category
FROM Products_2024
WHERE Category = 'Electronics' ;

Advanced Examples

1. Using MINUS to Find Missing Data

Scenario :- Identifies students enrolled in courses they have not yet completed.

SELECT StudentID, CourseID
FROM CurrentEnrollments
MINUS
SELECT StudentID, CourseID
FROM CompletedCourses ;

2. MINUS with Aliased Columns

Scenario :- Compares product prices in 2023 and 2024, identifying products with prices only in 2023 but not in 2024.

SELECT ProductID, Price AS Price_2023
FROM (
SELECT ProductID, Price
FROM Products_2023
MINUS
SELECT ProductID, Price
FROM Products_2024 ) ;

3. Combining MINUS with Subqueries

Scenario :- Finds employees in New York whose salaries are not greater than $100,000.

SELECT EmployeeID, Name, Job, City FROM Employees
WHERE DepartmentID IN
( SELECT DepartmentID FROM Departments WHERE Location = 'NY' )
MINUS
SELECT EmployeeID, Name, Job,City
FROM Employees
WHERE Salary > 100000 ;

4. Using MINUS in INSERT

Scenario :- Insert products that exist in products_table_2021 but not in products_table_2022 into a new table.

INSERT INTO missing_products ( product_id, name )
SELECT product_id, name
FROM products_table_2021
MINUS
SELECT product_id, name
FROM products_table_2022 ;

5. Using MINUS in DELETE

Scenario :- Remove rows from a table where records exist in another.

DELETE FROM orders
WHERE ( order_id, product_id ) IN
    (SELECT order_id, product_id
    FROM orders
    MINUS
    SELECT order_id, product_id
    FROM orders_2021 ) ;

6. MINUS with UPDATE

Scenario :- Update the status of orders in orders_2023 that are not present in orders_2024.

UPDATE orders_2023
SET status = 'Inactive'
WHERE (order_id, product_id) IN
( SELECT order_id, product_id
FROM orders_2023
MINUS
SELECT order_id, product_id
FROM orders_2024) ;

7. MINUS with Aggregated Dataand GROUP BY

Scenario :- Find departments that had expenses in 2023 but not in 2024.

SELECT department_id, SUM( expenses ) AS total_expenses
FROM expenses_2023
GROUP BY department_id
MINUS
SELECT department_id, SUM( expenses ) AS total_expenses
FROM expenses_2024
GROUP BY department_id ;

Performance Considerations

  • Indexing:- Create indexes on the columns used in the SELECT statements to improve performance.
  • Large Datasets:- For large datasets, MINUS can be resource-intensive as it compares the results of two queries.
  • Alternative Approaches:- Use LEFT JOIN or subqueries if the database does not support MINUS.
  • Partitioning:- Partition tables to narrow the scope of the operation
  • Avoid Unnecessary Calculations::- Simplify queries to reduce computational overhead.

Performance Comparison: UNION vs UNION ALL

Feature MINUS INTERSECT
Purpose Returns rows in first query not in second Returns common rows between queries
Duplicates Removes duplicates Removes duplicates
Result Set Subtraction of result sets Intersection of result sets
Performance May be slower with large datasets Slower with large datasets

Do's and Don'ts

Do's

  • Ensure that columns in both queries are compatible in terms of data type, order, and count.
  • Use MINUS for scenarios where exact differences between datasets are required.
  • Optimize your queries with proper indexing.

Don'ts

  • Avoid using MINUS for unrelated datasets.
  • Do not use MINUS if duplicates need to be preserved; use a LEFT JOIN instead.
  • Don't forget that MINUS is case-sensitive for text columns (depending on database settings).
