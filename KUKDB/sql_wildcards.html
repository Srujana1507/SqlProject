Wildcards

    Wildcards are special characters used with the LIKE operator in SQL to perform pattern matching within text fields.

Purpose of Wildcards

    1. Flexible Searching:- Retrieve records based on partial matches or patterns.

    2. Dynamic Queries:- Support complex and dynamic search requirements.

    3. Data Cleaning:- Identify inconsistent data patterns for correction.


Types of Wildcards in SQL

1. % ( Percent Sign )

  • Matches zero, one, or more characters.
  • Used for broader searches, including substrings.
Pattern Meaning Example Match
'Ha%' Starts with "Ha" Harsha, Hari
'%ala' Ends with "ala" Ujhala, Ujwala, utkala
'%or%' Contains "or" George, Morgan

2. _ (Underscore)

  • Matches exactly one character.
  • Useful for more precise searches.
Pattern Meaning Example Match
'T_ _a' Starts with "Ha" Tana, Tara, Teja, Tina
'_ _ _aya' Six-character string ending with "ana" Samaya, Sanaya

3. [ ] (Square Brackets )

  • Matches any single character within the brackets (SQL Server only).
  • Can define ranges (e.g., [A-Z]) or specific characters.
Pattern Meaning Example Match
'J[oa]n' Matches "Jan" or "Jon" Jan, Jon
'T[aeiou]m' Matches "Tam", "Tem", "Tim", etc. Tom, Tim

4. 4. [^ ] (Caret in Brackets)

  • Matches any single character not within the brackets (SQL Server only).
Pattern Meaning Example Match
'J[^o]n' Matches "Jan", not "Jon" Jan, Jun

5. ESCAPE Clause

  • Used to treat % or _ as literal characters instead of wildcards.
  • Define an escape character to differentiate.

Pattern Meaning Example Match
'%\%%' ESCAPE '\' Matches strings containing a % 50%, 100%
'%\_%' ESCAPE '\' Matches strings containing _ a_b, 1_2

Syntax

Basic Syntax:

SELECT column1, column2
FROM table_name
WHERE column_name LIKE pattern ;

Using NOT LIKE:

SELECT column1, column2
FROM table_name
WHERE column_name NOT LIKE pattern ;

Using ESCAPE:

SELECT column1, column2
FROM table_name
WHERE column_name LIKE 'pattern' ESCAPE 'escape_character' ;

Examples for Wildcards

1. Basic Prefix Search

    Retrieve employees whose names start with "A".
SELECT employee_id, first_name
FROM employees
WHERE first_name LIKE 'A%' ;

2. Matching Specific Characters

    Retrieve employees whose names start with "J" or "K" (SQL Server).
SELECT employee_id, first_name
FROM employees
WHERE first_name LIKE '[ JK ]%' ;

3. Excluding Characters

    Find employees whose names start with "J" but not "John" (SQL Server).
SELECT employee_id, first_name
FROM employees
WHERE first_name LIKE 'J [^o ]%' ;

4. Escape Special Characters

    Retrieve file names containing the literal %.
SELECT file_name
FROM files
WHERE file_name LIKE '%\%%'ESCAPE '\' ;

5. Escape Character for Literal % or _

    Retrieve file names that include a literal underscore (_).
SELECT file_name
FROM files
WHERE file_name LIKE '% \ _%'ESCAPE '\' ;

6. Pattern Matching in Numbers (Converted to Strings)

    Find order IDs starting with "2023".
SELECT order_id
FROM orders
WHERE CAST(order_id AS CHAR) LIKE '2024%' ;

Performance Considerations

1. Index Usage

    Queries with leading % (e.g., '%pattern') cannot leverage indexes effectively, leading to full table scans.

2. Optimize Patterns

    Use patterns like prefix% or substring%suffix for better performance.

3. Case Sensitivity

    Behavior depends on the database.
    • Oracle: Case-sensitive by default.
    • SQL Server and MySQL: Case-insensitive by default.

4. Avoid Overuse:

    Avoid LIKE for large-scale searches on massive datasets; consider full-text indexing.

Comparison of Wildcards Across Databases

Wildcard Oracle SQL Server MySQL
% Supported Supported Supported
_ Supported Supported Supported
[ ] Not Supported Supported Not Supported
[^ ] Not Supported Supported Not Supported
[^ ] or ! Not Supported Supported Not Supported
ESCAPE Clause Supported Supported Supported

Best Practices


1. Avoid Leading % :

    • Use specific prefixes where possible to optimize performance.

2. Use ESCAPE for Literal Matching :

    • Use specific prefixes where possible to optimize performance.

3. Combine with Other Filters :

    • Use LIKE with additional conditions to minimize unnecessary matches.

4. Understand Database Behavior :

    • Consider case sensitivity and collation settings for consistent results.
