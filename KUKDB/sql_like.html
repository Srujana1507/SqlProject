Like Operator

  • 1. The LIKE operator is used to search for a specified pattern within a column.
  • 2. It is typically used with SELECT, UPDATE, or DELETE statements to perform partial matches in text-based data.
  • 3. The LIKE operator allows for flexible pattern matching using wildcards.

Why Use the LIKE Operator?

  • To filter records based on partial text matches.
  • To search for patterns within text columns.
  • To handle cases where exact matches (=) are not practical.
  • To retrieve data with flexible matching criteria such as prefixes, suffixes, or substrings.

Key Wildcards in LIKE

Wildcard Description
% Matches zero, one, or more characters.
_ Matches exactly one character.
[ ] Matches any one character within the brackets (only in SQL Server).
[^ ] or ! Matches any single character NOT within the brackets (only in SQL Server).
ESCAPE Specifies an escape character to search for literal % or _ .

Syntax

Basic Syntax:

SELECT column1, column2
FROM table_name
WHERE column_name LIKE pattern ;

Using NOT LIKE:

SELECT column1, column2
FROM table_name
WHERE column_name NOT LIKE pattern ;

Examples:

1. Match Strings Starting with a Specific Character

Scenario :- Retrieve all employees whose names start with "Ha".

SELECT employee_id, first_name
FROM employees
WHERE first_name LIKE 'Ha%' ;

2. Match Strings Ending with a Specific Character

Scenario :- Retrieve products that end with "Pro".

SELECT product_id, product_name
FROM products
WHERE product_name LIKE '%Pro' ;

3. Match Strings Containing a Specific Substring

Scenario 1:- Retrieve customers whose email contains "gmail".

SELECT customer_id, email
FROM customers
WHERE email LIKE '%gmail%' ;

Scenario 2:- Retrieve customers names whose name starts and end with "A" .

SELECT customer_id, name
FROM customers
WHERE name LIKE 'A%A' ;

Scenario 3:- Find all IP addresses starting with "192.168" . .

SELECT user_id, ip_address
FROM user_logs
WHERE ip_address LIKE '192.168%' ;

4. Single Character Matching ( _ ) and Match Strings of Specific Length

Scenario 1:- Retrieve employees whose names are exactly 4 characters long and start with "A".

SELECT employee_id, first_name
FROM employees
WHERE first_name LIKE 'A____' ;
- - Output: Anand

- - Each "_ " is a single character in LIKE operator.

Scenario 2:- Retrieve employees whose names contains second letters as "a".

SELECT employee_id, first_name
FROM employees
WHERE first_name LIKE '_a%' ;

5. Finding Numeric Patterns in Strings

Scenario :- Retrieve employee IDs that start with "E" and have exactly 3 digits following it (e.g., E123).

SELECT employee_id, first_name
FROM employees
WHERE employee_id LIKE 'E___' ;

6. Finding Numeric Patterns in Strings

Scenario :- Retrieve all employee names with exactly 5 characters.

SELECT employee_id, first_name
FROM employees
WHERE first_name LIKE '_____' ;

7. Partial Matching for Web URLs

Scenario :- Find all users visiting URLs from a specific domain.

SELECT *
FROM web_logs
WHERE visit_url LIKE 'https://www.example.com%' ;

8. LIKE in DELETE

Scenario :- Delete products whose names include "Demo".

DELETE FROM products
WHERE product_name LIKE '%Demo%' ;

9. LIKE in UPDATE

Scenario :- Update the status of inactive customers whose names start with "Test".

UPDATE customers
SET status = 'Inactive'
WHERE name LIKE 'Test%' AND status!= 'Inactive' ;

Advanced Examples

1. Locating Null-like Entries

Scenario :- Identify rows with placeholder text (e.g., "N/A" or "UNKNOWN") instead of actual data.

SELECT *
FROM data_table
WHERE column_name IN ( 'N/A','UNKNOWN' );

2. Combine LIKE with AND/OR

Scenario :- Find all products that either start with "Choco" or end with "Mix".

SELECT ProductName
FROM Products
WHERE ProductName LIKE 'Choco%' OR ProductName LIKE '%Mix' ;

3. Case-Insensitive Search

Scenario :- Find employee names containing "harsha", regardless of case.

SELECT employee_id, first_name
FROM employees
WHERE LOWER(first_name) LIKE '%harsha%' ; - - Use LOWER() or UPPER() for case-insensitive matching since LIKE may be case-sensitive depending on the database.

4. Using LIKE in Subqueries

Scenario :- Find customers who purchased products with names containing "luxury".

    SELECT CustomerID , CustomerName
    FROM Customers
    WHERE CustomerID IN (
      SELECT CustomerID
      FROM Orders
      WHERE ProductName LIKE '%luxury%'
    ) ;

5. Use LIKE with NOT for Exclusions

Scenario :- Retrieve customer names that do not start with "A".

SELECT customer_id, CustomerName
FROM customers
WHERE CustomerName NOT LIKE 'A%' ;

6. Matching Multiple Prefixes

Scenario :- Retrieve customer names that start with "Mr.", "Mrs.", or "Dr.".

Query (SQL Server):

SELECT customer_id, CustomerName
FROM customers
WHERE CustomerName LIKE 'Mr.%' OR CustomerName LIKE 'Mrs.%' OR CustomerName LIKE 'Dr.%' ;

Common Errors

1. Using LIKE Without Wildcards:

- - Incorrect WHERE Name LIKE 'John' ; - -This is equivalent to =. Use wildcards for partial matches.

2. Case Sensitivity Confusion:

    Ensure you know if your database treats LIKE as case-sensitive. Use UPPER() or LOWER() for consistency.

3. Neglecting Escaping:

    Forgetting to escape % or _ can lead to incorrect results.

4. Inefficient Queries:

    Using %term% in large datasets can degrade performance due to full table scans.

Best Practices

1. Optimize Patterns:-

    • Use % only where necessary. For example, prefer LIKE 'term%' over LIKE '%term%' to allow index usage.

2. Combine with Other Filters:-

    • Narrow down the dataset using other filters (WHERE, JOIN) before applying LIKE.

3. Full-Text Search for Complex Queries:-

    • Use LIKE for simple pattern matching, but migrate to full-text search for extensive queries.

4. Escape User Input:-

    • Sanitize input patterns to prevent SQL injection.

5. Escape Special Characters:-

    • Use the ESCAPE clause when searching for % or _.

Comparison of LIKE Across Databases

Database Case Sensitivity Special Features
Oracle Case-sensitive by default (use UPPER() or LOWER() for insensitivity). Supports escape characters.
SQL Server Case-insensitivity depends on collation (default is insensitive). Supports [ ] for ranges and [^ ] for exclusions.
MySQL Case-insensitive by default. Uses _ and % only.
