INSERT INTO SELECT

The INSERT INTO SELECT statement is used to copy data from one table into another table by selecting rows from the source table.


  • SELECT INTO, it does not create a new table; it inserts data into an existing table.
  • This is particularly useful for copying data between tables or performing data transformations during insertion.

Definition and Purpose

Definition

  • The INSERT INTO SELECT statement inserts the results of a SELECT query into an existing table.

Purpose

  • To copy data from one table to another.
  • To migrate or backup data.
  • To insert transformed or aggregated data into a new table.

Syntax

1. With All Columns

INSERT INTO target_table
    SELECT *
    FROM source_table ;

2. With Specific Columns

INSERT INTO target_table (column1, column2, . . . )
    SELECT column1, column2, . . .
    FROM source_table
    WHERE condition ;

Key Points

Key Point Explanation
Column Matching Columns in the SELECT must match the target table's structure (number, type, and order).
Data Transformation Supports transformations like CASE, JOIN, and GROUP BY in the SELECT.
Schema Validation Target table must exist and match the data types of the selected columns.
NULL Handling Ensure default values or NULL handling for non-selected columns in the target table.
No Table Creation Unlike SELECT INTO, INSERT INTO SELECT does not create a new table; the target must pre-exist.


Basic Scenarios

Scenario 1:- ( Insert All Data )Copy all rows from the Products table to the ProductsArchive table.

INSERT INTO ProductsArchive
    SELECT *
      FROM Products ;


Scenario 2:- ( Insert Filtered Data ) Copy only active products into the ActiveProducts table.

INSERT INTO ActiveProducts
    SELECT ProductID, ProductName, Category, Price
      FROM Products
        WHERE Status = 'Active' ;


Scenario 3:- (Insert with Transformation ) Copy product data with a 10% price increase into the DiscountedProducts table.

INSERT INTO DiscountedProducts ( ProductID, ProductName, NewPrice )
    SELECT ProductID, ProductName, Price * 1.10
      FROM Products ;


Scenario 4:- ( Using Joins to Transform Data ) Insert enriched order details by combining customer and order data.

INSERT INTO enriched_orders ( order_id, customer_name, order_date, total_amount )
    SELECT o.order_id, c.name, o.order_date, o.total_amount
      FROM orders o
    JOIN customers c ON o.customer_id = c.customer_id ;


Scenario 5:- ( Partitioned Data Insertion ) Insert data for a specific region into a partitioned table.

INSERT INTO regional_sales ( region, product_id, sales_amount )
    SELECT region, product_id, SUM( sales_amount )
      FROM Sales
    WHERE region = 'North'
    GROUP BY region, product_id ;


Scenario 6:- ( Combining Data from Multiple Sources ) Insert data from two tables using a UNION.

INSERT INTO all_orders ( order_id, customer_id, order_date, total_amount )
    SELECT order_id, customer_id, order_date, total_amount
      FROM online_orders
    UNION
    SELECT order_id, customer_id, order_date, total_amount
      FROM store_orders ;


Scenario 7:- ( Insert with Conditional Logic ) Copy products into the DiscountedProducts table with conditional discounts based on categories.

INSERT INTO DiscountedProducts ( ProductID, ProductName, DiscountedPrice )
    SELECT ProductID, ProductName,
      CASE
        WHEN Category = 'Electronics' THEN Price * 0.90
        WHEN Category = 'Furniture' THEN Price * 0.85
        ELSE Price * 0.95
      END
FROM Products ;


Scenario 8:- ( Insert Across Databases ) Insert rows from a table in one database into another database.

INSERT INTO TargetDB.dbo.Customers (CustomerID, CustomerName, City)
    SELECT CustomerID, CustomerName, City
FROM SourceDB.dbo.Customers ;


Scenario 9:- ( Data Backup Before Deletion ) Backup data before performing a cleanup operation.

INSERT INTO old_orders_backup
    SELECT *
      FROM Orders
        WHERE order_date < DATEADD ( YEAR , -2, GETDATE() ) ;


Scenario 10:- Consolidate sales data from online_sales and store_sales into a unified table. Each source has different date formats and naming conventions.

--SQL server
INSERT INTO unified_sales (sale_id, sale_date, sale_amount, source)
SELECT sale_id,
    CONVERT ( DATE, sale_date, 103 ) AS sale_date,
    sale_amount,
    'Online' AS source
FROM online_sales
UNION ALL
SELECT sale_id,
    CONVERT ( DATE, sale_date, 103 ) AS sale_date,
    sale_amount,
    'Store' AS source
FROM store_sales ;

Common Errors with INSERT INTO SELECT

Error Explanation Solution
Column Count Mismatch The number of columns in the SELECT doesn't match the target table. Ensure the SELECT query matches the column count of the target table.
Data Type Mismatch Column data types in SELECT and target table are incompatible. Verify that the data types align or use explicit casting in SELECT.
Unique Constraint Violation Duplicate data violates a unique constraint on the target table. Filter duplicates using DISTINCT or a WHERE clause in the SELECT.
Target Table Not Found The target table does not exist. Create the target table before executing the INSERT INTO SELECT.
NULL Constraint Violation NULL values inserted into a non-nullable column. Provide default values or exclude columns that cannot accept NULL.
Insufficient Permissions User lacks permission to insert data into the target table. Grant INSERT permission on the target table.


Performance Hints for INSERT INTO SELECT

Hint Description
Use Indexing Ensure indexes exist on the columns involved in SELECT and target table.
Limit Data Scope Use WHERE clauses to filter data, reducing the size of data being processed.
Optimize Joins Minimize joins in the SELECT query by indexing join columns and using appropriate join types.
Avoid Duplicate Data Use DISTINCT or GROUP BY to eliminate duplicates if the target table has unique constraints.
Batch Processing For large datasets, process data in smaller batches to avoid locking or resource contention.
Use Appropriate Filters Filter unnecessary data to reduce insertion overhead.
Check Constraints Ensure that the target table’s constraints are compatible with the selected data.


Do's and Don'ts with INSERT INTO SELECT

Do's Don'ts
Match column types and order. Don’t insert large datasets without using a transaction or logging.
Use WHERE clauses to limit data. Don’t ignore index usage for frequently queried or joined columns.
Validate data before insertion. Don’t insert into a table without understanding its constraints.
Backup critical data before insertion. Don’t assume compatibility between source and target table schemas without verification.
Test with a smaller dataset first. Don’t overlook NULL handling for non-nullable columns.
