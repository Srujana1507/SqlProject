TRUNCATE

  • TRUNCATE command is a Data Definition Language (DDL) statement, used to remove all rows from a table, but keeps the table structure, columns, indexes, and constraints intact.
  • TRUNCATE is faster and more efficient for clearing a table compared to the DELETE statement,which frees storage gradually.
  • TRUNCATE applies to the entire table and does not allow conditions (e.g., WHERE clause).

Syntax

TRUNCATE TABLE table_name ;

Scenarios

1. Remove all rows from the employees (Oracle, SQLite, SQL Server, PostgreSQL, MySQL)

TRUNCATE TABLE employees ;

2. Resetting a Table for Fresh Data

  • If you’re using a table to temporarily store data (such as staging data), you might truncate it after each use to ensure it’s empty.
TRUNCATE TABLE temp_staging_data ;

Truncate tables with Foreign Key

MySQL:
  • In MySQL, TRUNCATE TABLE cannot truncate tables with foreign key constraints unless the constraints are temporarily disabled.
SET FOREIGN_KEY_CHECKS = 0 ;
TRUNCATE TABLE employees ;
    Temporarily disable foreign key checks, truncate table, and re-enable them
TRUNCATE TABLE Orders ;
SET FOREIGN_KEY_CHECKS = 1 ;

PostgreSQL:
  • In PostgreSQL, TRUNCATE TABLE supports transactional behavior and allows truncating tables with foreign key constraints using the CASCADE option.
TRUNCATE TABLE employees ;
  • Truncate a table with dependent foreign keys
TRUNCATE TABLE Orders CASCADE ;
  • Truncate multiple tables
TRUNCATE TABLE Orders, Customers ;
  • Transactional truncation
BEGIN ;
TRUNCATE TABLE Sales ;
ROLLBACK ;

SQL Server:
  • In SQL Server, TRUNCATE TABLE resets the identity column, but it cannot be used on tables referenced by foreign keys.
  • Basic truncation
TRUNCATE TABLE employees ;
  • Reset identity column manually after truncation
DBCC CHECKIDENT ('Employees', RESEED, 0) ;
  • Identity column is reset, and foreign key constraints must be removed or disabled before truncation.

Oracle :
  • Oracle allows TRUNCATE TABLE, but it does not support transactional rollbacks. Truncation cannot be used on tables with foreign key constraints unless the constraints are disabled.
  • Basic truncation
TRUNCATE TABLE employees ;
  • Truncate a partitioned table
TRUNCATE TABLE Sales TRUNCATE PARTITION Qtr1_2024;
  • Disable foreign key constraints, truncate, and re-enable.
ALTER TABLE Orders DISABLE CONSTRAINT fk_customer_orders ;
TRUNCATE TABLE Orders ;
ALTER TABLE Orders ENABLE CONSTRAINT fk_customer_orders ;
  • No transactional rollback; affects dependent tables only if constraints are disabled.

SQLite:
  • SQLite does not support the TRUNCATE TABLE command. Instead, you must use the DELETE command.
  • Delete all rows (alternative to TRUNCATE)
DELETE FROM emp ;
  • Reset the auto-increment counter
DELETE FROM sqlite_sequence WHERE name = 'Employees' ;


Comparison of Syntax and Behavior
DBMS Syntax Foreign Keys Transactional Resets Identity
MySQL TRUNCATE TABLE table_name; Requires disabling constraints. No Yes
PostgreSQL TRUNCATE TABLE table_name; Supports CASCADE. Yes Yes
SQL Server TRUNCATE TABLE table_name; Not allowed with constraints. Yes Yes
Oracle TRUNCATE TABLE table_name; Constraints must be disabled. No Yes
SQLite Not supported Not applicable. Not applicable. Not applicable.


Best Practices for TRUNCATE

  • Use TRUNCATE for High-Performance Table Resets - Because it bypasses row-by-row deletions, TRUNCATE is faster and preferred when you need to empty a large table quickly.
  • Avoid TRUNCATE if you need to keep a log of deletions for recovery or auditing.
  • Do not use TRUNCATE if you want to remove only certain rows; DELETE with a WHERE clause is better in those cases.
  • Understand the Impact on Constraints - TRUNCATE often requires the absence of foreign key constraints in many systems (some databases prevent truncating tables with foreign keys).
  • TRUNCATE is irreversible in most databases because it automatically commits. Use it with caution, especially in production environments.

Do’s and Don’ts With TRUNCATE

Do's :-

  • Do use TRUNCATE for temporary or staging tables to quickly reset them.
  • Do ensure foreign key dependencies are cleared if truncating tables with dependencies.
  • Do use TRUNCATE on archived tables if the data is already backed up and the table is simply being prepared for a new data load.

Don'ts :-

  • Don’t use TRUNCATE in transactional workflows where you need a rollback.
  • Don’t rely on TRUNCATE for auditing - If tracking deletions is needed, use DELETE with logging instead.
  • Don’t use TRUNCATE casually in production without confirming that data loss is acceptable, as it is commited immediately in most systems.

Difference Between TRUNCATE and DELETE
Feature TRUNCATE DELETE
Speed Faster (deallocates pages). Slower (logs row deletions).
WHERE Clause Not supported. Supported.
Transaction Rollback depends on DBMS. Always transactional.
Identity Reset Yes (resets counter). No
Logging Minimal logging (page-level). Fully logged (row-level).
Permissions Requires DROP or ALTER privileges. Requires DELETE privilege.
