UNION ALL

The UNION ALL operator is used to combine the results of two or more SELECT queries into a single result set including duplicates.


Unlike the UNION operator, UNION ALL does not filter out duplicate rows, making it more efficient because no duplicate-checking operation is performed.


Key Characteristics of UNION ALL

  • Combines Rows:- Merges rows from two or more queries into a single result set.
  • Retains Duplicates:- Does not eliminate duplicate rows.
  • Column Compatibility:- Each SELECT query must have the same number of columns and compatible data types.
  • Faster Performance:- Since it skips the duplicate elimination step, UNION ALL is faster than UNION.

Syntax

- - SQL Server, MySQL, Oracle
SELECT column1, column2, . . .
FROM table1
WHERE condition1

UNION ALL

SELECT column1, column2, . . .
FROM table2
WHERE condition2 ;

Examples

1. Basic Usage of UNION ALL

Scenario :- Combine employee details from two departments, including duplicate entries.

SELECT employee_id, name, department
FROM department_A
UNION ALL
SELECT employee_id, name, department
FROM department_A ;

- - This query will list employees from both departments, retaining duplicates where employees exist in both.

2. Use in Calculations

Scenario :- Calculate the total sales by combining data from two regions, including duplicate entries.

SELECT region, sales
FROM sales_region1
UNION ALL
SELECT region, sales
FROM sales_region2 ;

- - If a sale appears in both regions, it will be counted twice, providing an accurate reflection of the total data set.

3. Using UNION ALL with Calculations

Scenario :- Combines product data from IN and UK tables, calculating discounts with different rates, while including duplicates.

SELECT ProductID, Price, Price * 0.9 AS DiscountedPrice
FROM Products_UK
UNION ALL
SELECT ProductID, Price, Price * 0.85 AS DiscountedPrice
FROM Products_IN ;

4. Using UNION ALL with Literal Values

Scenario :- Generate a list of predefined data combined with actual table data.

SELECT 'Manual Entry' AS Source, 'Product A' AS product
UNION ALL
SELECT 'Database Entry', product_name
FROM products ;

- - This query combines a manually defined row with data fetched from the database.

5. UNION ALL Without Filtering

Scenario :- Combines rows where some categories overlap, and duplicates are retained.

SELECT CategoryID, CategoryName
FROM Categories
WHERE CategoryID < 5
UNION ALL
SELECT CategoryID, CategoryName
FROM Categories
WHERE CategoryID > 3 ;

Advanced Scenarios

1. Aggregate Data After UNION ALL

Scenario :- Combines rows from two employee tables, and then groups and counts employees by department, including duplicates in the count.

SELECT DepartmentID, COUNT( * ) AS TotalEmployees
FROM (
      SELECT DepartmentID FROM Employees_US
      UNION ALL
      SELECT DepartmentID FROM Employees_IN
) Combined GROUP BY DepartmentID ;

2. Combining Logs from Multiple Sources

Scenario :- Merge log entries from application and system logs.

SELECT log_id, log_message, 'Application' AS log_source
FROM app_logs
UNION ALL
SELECT log_id, log_message, 'System' AS log_source
FROM system_logs ;

3. Combining Results from Different Conditions

Scenario :- Retrieve all products under two price ranges.

SELECT product_id, price
FROM products
WHERE price < 50
UNION ALL
SELECT product_id, price
FROM products
WHERE price BETWEEN 50 AND 100 ;

- - This query combines products in the two ranges, and if a product qualifies for both ranges, it will appear twice.

Performance Comparison: UNION vs UNION ALL

Feature UNION UNION ALL
Duplicates Removes duplicates Retains duplicates
Performance Slower due to duplicate check Faster without duplicate check
Use Case Unique rows are required All rows, including duplicates, are needed

Common Errors for UNION and UNION ALL

1. Column Count Mismatch

SELECT column1, column2
FROM table1
UNION ALL
SELECT column1
FROM table2 ;
- - Error: Different number of columns

2. Data Type Mismatch

SELECT column1, column2
- - Integer type FROM table1
UNION ALL
SELECT column1, column2
FROM table2 ;
- - Error: Different number of columns

Do's and Don'ts with UNION ALL

Do's

  • Use UNION ALL for Performance:- When duplicates are not an issue, prefer UNION ALL to avoid the overhead of duplicate elimination.
  • Verify Column Alignment:- Ensure the same number of columns and compatible data types in all SELECT queries.
  • Combine Related Datasets:- Use UNION ALL for merging related datasets, such as current and historical data.

Don'ts

  • Don't Use Without Need:- Avoid using UNION ALL if you specifically need unique rows.
  • Mismatch Columns:- Ensure all SELECT statements have the same column count and data types, or you'll get an error.
  • Ignore Sorting Requirements:- If sorting is required, apply ORDER BY at the end.
