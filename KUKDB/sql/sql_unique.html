UNIQUE

The UNIQUE constraint ensures that all values in a column or a combination of columns are distinct.


It prevents duplicate entries but allows a single NULL value (depending on the database).


Key Points

Aspect Details
Uniqueness Guarantees that no two rows in a table have the same value in a specified column or combination of columns.
Allows NULL Values Most databases allow one NULL value in a column with a UNIQUE constraint, as NULL is treated as "unknown" and not comparable.
Multiple UNIQUE Constraints A table can have multiple columns or combinations of columns with the UNIQUE constraint.
Automatic Index Creation When a UNIQUE constraint is added, the database automatically creates a unique index on the column(s) to efficiently enforce uniqueness.

Syntax

1. During Table Creation

CREATE TABLE table_name (
    column_name data_type UNIQUE ,
    other_column data_type ) ;

2. Multiple Columns as UNIQUE

CREATE TABLE table_name (
    Column1 DataType,
    Column2 DataType,
    CONSTRAINT ConstraintName UNIQUE (Column1, Column2) ) ;

3. Adding to Existing Table

ALTER TABLE table_name
    ADD CONSTRAINT ConstraintName UNIQUE (ColumnName) ;

Behavior of UNIQUE

Scenario Behavior
Inserting Duplicate Value Throws an error if an attempt is made to insert a duplicate value in a column with the UNIQUE constraint
Allows One NULL Allows a single NULL value in most databases.
Combination of Columns Ensures uniqueness across the combination of values in multiple columns when applied to more than one column.

Advantages of UNIQUE

Advantage Description
Data Integrity Prevents duplicate values, ensuring consistent and accurate data.
Automatic Indexing Improves query performance as a unique index is automatically created.
Supports Composite Uniqueness Ensures unique combinations of multiple columns.
Simplifies Validation Removes the need to enforce uniqueness manually in application logic.

Examples

Scenario 1:- Ensuring Email Uniqueness in a Users Table.

CREATE TABLE Users (
    UserID INT PRIMARY KEY , Email VARCHAR(150) UNIQUE , FullName VARCHAR(100) ) ;

Scenario 2:- Add a UNIQUE constraint to the PhoneNumber column in the Customers table to ensure no duplicate phone numbers.

ALTER TABLE Customers
    ADD CONSTRAINT UQ_PhoneNumber UNIQUE (PhoneNumber) ;

Scenario 3:- Enforcing Unique Combination of First and Last Name.

CREATE TABLE Users (
    StudentID INT PRIMARY KEY , FirstName VARCHAR(50) ,
    LastName VARCHAR(50),
    DateOfBirth DATE,
    CONSTRAINT UQ_StudentName UNIQUE (FirstName, LastName)) ;

Scenario 4:- Preventing Duplicate Product Codes( In a Products table, ensure each product has a unique ProductCode)

CREATE TABLE Products (
    ProductID INT PRIMARY KEY ,
    ProductName VARCHAR(100) ,
    ProductCode VARCHAR(50) UNIQUE ,
    Price DECIMAL(10, 2) ) ;

Scenario 5:- Dropping a UNIQUE Constraint.

---SQL Server/PostgreSQL

ALTER TABLE employees
    DROP CONSTRAINT unique_employee_code ;

Scenario 6:- Adding a UNIQUE Constraint with Default Values( Ensure that the CountryCode column has unique values but allows a default.)

CREATE TABLE Countries (
    CountryID INT PRIMARY KEY , CountryCode CHAR(2) UNIQUE ,
    CountryName VARCHAR(100)) ;

Common Errors with UNIQUE

Error Explanation Solution
Duplicate Key Error Attempt to insert duplicate value in a column with UNIQUE constraint. Ensure data is unique before insertion.
Violation of Composite UNIQUE Constraint Insert violates a combination of columns defined as UNIQUE. Validate the combination of values before inserting.
Constraint Already Exists Adding UNIQUE constraint to a column that already has one. Avoid adding duplicate constraints.
NULL Consideration Misunderstanding NULL handling in UNIQUE constraints. Remember that NULL is treated as unique and does not violate the constraint.

Performance Hints for UNIQUE

Hint Description
Plan Constraints During Design Apply UNIQUE constraints during table creation to avoid post-modification efforts.
Combine with NOT NULL Use NOT NULL along with UNIQUE for mandatory fields that must also be unique.
Name Constraints Clearly Use meaningful constraint names for easy identification (e.g., unique_email).
Check for Existing Duplicates Before adding a UNIQUE constraint to an existing table, ensure no duplicate values exist.
Optimize Index Usage Leverage the automatically created unique index for performance gains in SELECT queries.

Key Differences Between UNIQUE and PRIMARY KEY

Aspect UNIQUE Constraint PRIMARY KEY
Purpose Ensures distinct values in a column or group of columns. Uniquely identifies each row in a table.
NULL Handling Allows one NULL value (in most databases). Does not allow NULL values.
Count per Table Multiple UNIQUE constraints allowed. Only one PRIMARY KEY per table.
Indexing Creates a unique index. Creates a unique index with NOT NULL.

Do's and Don'ts with UNIQUE

Do's Don'ts
Use UNIQUE for fields requiring distinct values. Don’t assume UNIQUE will prevent NULL values—each NULL is treated as distinct.
Combine UNIQUE with composite keys when needed. Don’t use UNIQUE unnecessarily; it may impact write performance for high-volume tables.
Test constraints thoroughly during schema updates. Don’t attempt to add UNIQUE constraints to columns with existing duplicates.
Use explicit names for constraints. Don’t mix UNIQUE and PRIMARY KEY on the same column—it’s redundant.
Leverage UNIQUE for data integrity. Don’t use UNIQUE constraints for columns where duplicates are valid (e.g., tags, descriptions).
