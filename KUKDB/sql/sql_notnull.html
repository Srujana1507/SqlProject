NOT NULL

The NOT NULL constraint ensures that a column cannot have NULL values.


It is a rule applied to a column that makes it mandatory to have a value when a new row is inserted or an existing row is updated.


Key Points

Aspect Details
Behavior Prevents NULL values in the specified column.
Use Case Ideal for primary keys, foreign keys, or mandatory fields like names, IDs, and emails.
Default Behavior If NOT NULL is not explicitly applied, columns are allowed to accept NULL values.
Combining with DEFAULT Can be combined with DEFAULT to ensure a value is always assigned if none is provided.
Modification Adding a NOT NULL constraint to an existing column requires ensuring no NULL values exist.

Syntax

Applying NOT NULL During Table Creation

CREATE TABLE table_name (
    column_name data_type NOT NULL ,
    other_column data_type ) ;

Adding NOT NULL to an Existing Table

ALTER TABLE table_name
    MODIFY column_name data_type NOT NULL ;

-- SQL Server/PostgreSQL
ALTER TABLE table_name
    ALTER COLUMN column_name data_type NOT NULL ;

Examples

Scenario 1:- Enforcing Mandatory Employee Names(NOT NULL on regular field).

CREATE TABLE employees (
    employee_id INT PRIMARY KEY , employee_name VARCHAR(50) NOT NULL , department_id INT ) ;

Scenario 2:- Ensures that the order_date column cannot have NULL values.

ALTER TABLE orders
    MODIFY order_date DATE NOT NULL ;

Scenario 3:- Ensures that the price cannot be NULL, and assigns a default value, if no value is provided.

CREATE TABLE products (
    product_id INT PRIMARY KEY ,
    product_name VARCHAR(100) NOT NULL ,
    price DECIMAL(10, 2) NOT NULL DEFAULT 0.00 ) ;

Scenario 4:- Ensures that an order must always reference a valid customer.

CREATE TABLE orders (
    order_id INT PRIMARY KEY ,
    customer_id INT NOT NULL ,
    FOREIGN KEY (customer_id) REFERENCES customers(customer_id) ) ;

Scenario 5:- Removing NULL Values Before Adding Constraint

-- Update NULL values
UPDATE employees
    SET employee_name = 'Unknown'
    WHERE employee_name
    IS NULL ;

-- Add NOT NULL constraint
ALTER TABLE employees
    MODIFY employee_name VARCHAR(50) NOT NULL ;

Scenario 6:- Combining NOT NULL with Composite Keys (Ensures that region_id and product_id are mandatory for every record.)

CREATE TABLE sales (
    region_id INT NOT NULL ,
    product_id INT NOT NULL ,
    sales_amount DECIMAL(10, 2),
    PRIMARY KEY ( region_id, product_id ) ) ;

Scenario 7:- Enforcing Not-Null on an Auto-Increment primary key (defines A ProductID column, as an auto-incremented primary key which cannot be NULL.)

CREATE TABLE Products (
    ProductID INT AUTO_INCREMENT NOT NULL PRIMARY KEY,
    ProductName VARCHAR(100) NOT NULL ,
    Price DECIMAL(10, 2)) ;

Common Errors and Solutions

Error Explanation Solution
NULL Value in NOT NULL Column Attempt to insert a NULL value in a NOT NULL column. Ensure all mandatory fields have valid data before insertion.
Cannot Add NOT NULL to Existing Column Attempt to add a NOT NULL constraint to a column with existing NULL values. Update or remove NULL values before applying the constraint.
Default Value Missing with NOT NULL Data insertion fails if no value is provided for NOT NULL column without a default. Use the DEFAULT constraint for columns that require fallback values.

Performance Hints For NOT NULL

Hint Description
Combine with DEFAULT Pair NOT NULL with DEFAULT to avoid manual data entry errors.
Data Validation Ensure the application layer validates data before insertion to prevent runtime errors.
Database Design Use NOT NULL for columns that represent essential entities or attributes (e.g., primary keys).
Indexing Impact Avoid marking frequently updated or nullable columns as NOT NULL unnecessarily.
Migration When modifying existing tables, clean up NULL values first to avoid constraint violations.

Do's and Don'ts with NOT NULL

Do's Don'ts
Apply NOT NULL for critical fields. Don’t apply NOT NULL constraints to columns where missing data is valid or expected.
Validate data before applying NOT NULL. Don’t add NOT NULL to existing columns without checking for NULL values first.
Document all constraints in your schema design. Don’t use NOT NULL with overly flexible columns (e.g., description fields).
Test application behavior with the constraint. Don’t assume that NOT NULL alone will catch all data entry errors—validate at the application layer too.
Use DEFAULT with NOT NULL when appropriate. Don’t leave essential columns without constraints if data integrity is critical.
