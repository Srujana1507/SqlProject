INTERSECT

The INTERSECT operator is used to return the common rows between two SELECT statements.


It works by finding the intersection of the result sets, ensuring that only rows present in both queries are included in the final output.


Key Characteristics of INTERSECT

  • Duplicate Elimination:- Like UNION, the INTERSECT operator removes duplicate rows in the result set.
  • Set Logic:- It returns only rows that exist in both queries.
  • Performance:- Processing large datasets with INTERSECT can be computationally expensive, as it involves comparing rows from both result sets.

Syntax

SELECT column1, column2, . . .
FROM table1
WHERE condition1

INTERSECT

SELECT column1, column2, . . .
FROM table2
WHERE condition2 ;

  • Both SELECT statements must have the same number of columns.
  • The data types of the columns must be compatible.
  • The order of columns in both SELECT statements must match.

Examples

1. Basic Usage of INTERSECT

Scenario :- Find employees working in both department_A and department_B.

-- SQL Server, Oracle
SELECT employee_id, name
FROM department_A
INTERSECT
SELECT employee_id, name
FROM department_B ;

- - Only employees present in both departments will be listed.

2. INTERSECT with Additional Conditions

Scenario :- Identify customers who made purchases in 2023 and 2024.

-- SQL Server, Oracle
SELECT customer_id
FROM sales_2023
INTERSECT
SELECT customer_id
FROM sales_2024 ;

- - This query filters customers who have purchase records in both years.

3. Using INTERSECT with Filtering

Scenario :- Retrieves customers who placed orders in both 2023 and 2024.

-- SQL Server, Oracle
SELECT CustomerID, OrderDate
FROM Orders_2023
WHERE OrderDate >= '2023-01-01'
INTERSECT
SELECT CustomerID, OrderDate
FROM Orders_2024 WHERE OrderDate < '2024-01-01' ;

4. Combining INTERSECT with Additional Filters

Scenario :- Finds electronics products common to both the US and UK product tables.

- - SQL Server, Oracle
SELECT ProductID, Category
FROM Products_IN
WHERE Category = 'Electronics'
INTERSECT
SELECT ProductID, Category
FROM Products_UK WHERE Category = 'Electronics' ;

Advanced Scenarios

1. INTERSECT with Aliased Columns

Scenario :- Retrieves common ProductID and Price values between the US and IN products tables. Aliases are used for clarity.

SELECT ProductID, Price FROM Products_IN
INTERSECT
SELECT ProductID, Price FROM Products_US ;

2. Using INTERSECT in Subqueries

Scenario :- Finds customers in the USA who have placed orders with an amount greater than $500.

SELECT CustomerID
FROM Orders
WHERE CustomerID IN (
    SELECT CustomerID FROM Customers
    WHERE Country = 'USA'
) INTERSECT
SELECT CustomerID
FROM Orders WHERE OrderAmount > 500 ;

3. Using INTERSECT with Complex Joins

Scenario 1:- Retrieves employees based in New York with salaries above $100,000.

SELECT E.EmployeeID, E.Name
FROM Employees E
INNER JOIN Departments D ON E.DepartmentID = D.DepartmentID
WHERE D.Location = 'New York'
INTERSECT
SELECT EmployeeID, Name
FROM Employees WHERE Salary > 100000 ;

Scenario 2:- Combine INTERSECT with JOIN to find common rows based on more complex relationships.

SELECT e.employee_id, e.name
FROM Employees E
JOIN salaries s ON e.employee_id = s.employee_id
INTERSECT
SELECT e.employee_id, e.name
FROM employees e
JOIN bonuses b ON e.employee_id = b.employee_id ;

4. INTERSECT in UPDATE

Scenario :- Update the status of products that are both in table_A and table_B.

UPDATE inventory
SET status = 'common'
WHERE product_id IN (
    SELECT product_id
    FROM table_A
    INTERSECT
    SELECT product_id FROM table_B ) ;

5. INTERSECT in DELETE

Scenario :- Delete orders that exist in both the old_orders and new_orders tables.

DELETE FROM orders
WHERE order_id IN (
    SELECT order_id
    FROM old_orders
    INTERSECT
    SELECT order_id FROM new_orders) ;

6. INTERSECT in INSERT

Scenario :- Insert data common to two tables into a third table.

INSERT INTO common_data ( id, name )
SELECT id, name
FROM table1
INTERSECT
SELECT id, name FROM table2 ;

7. INTERSECT in HAVING

Scenario :- Find regions where the total sales in two tables are the same.

SELECT region, SUM( sales ) AS total_sales
FROM sales_data1
GROUP BY region
HAVING SUM( sales ) IN (
    SELECT SUM( sales ) FROM sales_data2
    GROUP BY region
    INTERSECT
    SELECT SUM( sales ) FROM sales_data3
    GROUP BY region ) ;

8. INTERSECT in Views

Scenario :- Create a view to show common customers between two regions.

CREATE VIEW common_customers AS
SELECT customer_id, name
FROM region_A_customers
INTERSECT
SELECT customer_id, name FROM region_B_customers ;

Performance Considerations

  • Indexing:- Create indexes on the columns involved in the SELECT queries to improve performance.
  • Optimize Filters:- Apply restrictive filters to minimize the size of result sets before performing the INTERSECT operation.
  • Avoid Unnecessary Calculations:- Simplify the queries to avoid redundant computations.
  • Duplicate Handling:- Be mindful of duplicate elimination and its impact on query execution time.
  • Alternative:- For databases that do not support INTERSECT (e.g., MySQL), use JOIN or subqueries.

Do's and Don'ts with INTERSECT

Do's

  • Use INTERSECT for queries where you need exact matches between datasets.
  • Ensure data compatibility across both SELECT statements.
  • Optimize with indexes to improve performance.

Don'ts

  • Don’t use INTERSECT for unrelated datasets; this will return no results.
  • Avoid using INTERSECT for large datasets without indexing, as it may result in poor performance.
  • Don't use it where INNER JOIN or EXISTS provides a better or faster solution.

INTERSECT VS UNION

Feature INTERSECT UNION
Purpose Retrieves common rows Combines all rows
Duplicates Removes duplicates Removes duplicates
Result Set Common rows only Union of all rows
Performance Comparatively slower Faster than INTERSECT
