DELETE:

  • The DELETE statement in SQL is used to remove one or more records (rows) from a table in a database.
  • It allows you to delete specific rows based on a condition, or all rows if no condition is specified.

  • Key Points to Remember:

    • Using DELETE without a WHERE clause deletes all rows in the table but retains the table structure..
    • Always include a WHERE clause unless the intention is to clear the table.
    • DELETE removes rows but does not remove the table definition or schema.
    • If foreign keys are defined with ON DELETE CASCADE , deleting a parent row may also delete associated child rows.
    • DELETE operation is logged and can be rolled back if performed within a transaction, making it safer than the TRUNCATE statement.
    • DELETE can be slower than TRUNCATE for large tables because DELETE logs each deleted row for rollback, while TRUNCATE does not.
    • Always back up the data before large or critical deletions, especially in production databases.
    • For complex conditions, test the DELETE statement in a development or test environment to verify it behaves as expected.

General Syntax

1.Delete all rows from a table

DELETE FROM emp ;

2. Delete specific rows from a Table:

ALTER TABLE emp
WHERE dept_name = 'HR' ;

Advanced Usage Examples:

1. Delete Using a Subquery

  • Deletes rows in the employees table based on a condition derived from another table.
DELETE FROM emp
WHERE dept_id IN (
SELECT dept_id
FROM dept
WHERE location = 'New York' );

2. Using JOIN in DELETE (MySQL, PostgreSQL, etc.):

  • Deletes employees who belong to the 'Finance' department.
DELETE e
FROM employees e
INNER JOIN departments d ON e.dept_id = d.dept_id
WHERE d.dept_name = 'Finance' ;

3. LIMIT Clause in DELETE (MySQL):

  • Deletes only 10 rows from the orders table where status is 'Pending'.
DELETE FROM Orders
WHERE status = 'Pending'
LIMIT 10;

4. DELETE with RETURNING Clause (PostgreSQL, Oracle)

  • Deletes rows where status is 'Shipped' and returns the deleted order_id and customer_id.
DELETE FROM Orders
WHERE status = 'Shipped'
RETURNING order_id, CustID ;

5. Delete Duplicate Records

DELETE FROM emp
WHERE EmpID NOT IN (
SELECT MIN (EmpID)
FROM emp
GROUP BY job ) ;

Best Practices:

1. Always Use Transactions


    - Wrap DELETE statements in transactions to ensure you can rollback in case of errors.
BEGIN TRANSACTION ;
DELETE FROM employees WHERE dept_name = 'HR' ;
ROLLBACK ;
COMMIT ;

2. Verify with SELECT Before DELETE

SELECT * FROM employees WHERE dept_name = 'HR' ;
DELETE FROM employees WHERE dept_name = 'HR' ;

Do’s and Don’ts When Using DELETE

Do's :-

  • Do validate the data to be deleted by running a SELECT with the same WHERE condition first.
  • Do use transactions for critical deletions to allow easy rollback.
  • Do monitor impact on indexes: Frequent deletions can fragment indexes, so consider rebuilding indexes as needed.

Don'ts :-

  • Don’t delete without a WHERE clause unless you intend to clear the table entirely.
  • Don’t ignore cascading effects : Check for ON DELETE CASCADE constraints if deleting from tables with foreign key relationships.
  • Don’t run mass deletions during peak hours in high-transaction environments, as they can impact performance.
