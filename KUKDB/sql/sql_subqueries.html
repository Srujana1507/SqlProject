SUBQUERIES

Definition

A subquery is a SQL query nested inside another query,used to perform intermediate calculations or to fetch data that the main query will use.

  • Subqueries are powerful tools for breaking down complex queries into manageable parts.
  • It is enclosed in parentheses and can be used in various parts of an SQL statement, such as the SELECT, FROM, WHERE, HAVING, or even JOIN clauses.
  • Subqueries allow dynamic data retrieval by providing intermediate results to the main query.

Why Use Subqueries?

  • To break down complex problems into manageable steps.
  • To dynamically retrieve data without hardcoding values.
  • To compare aggregate data or computed values.
  • To simplify query construction and improve readability.

Basic Syntax

SELECT column_name
FROM table_name
WHERE column_name [operator]
    ( SELECT column_name
    FROM another_table
    WHERE condition ) ;

Types of Subqueries

1. Single-row Subquery

Scenario :- Retrieve employees who earn more than the average salary.

  • Returns a single row with one or more columns.
  • Used with comparison operators like =, <,>, <=,>=, <>.
    • SELECT employee_id, Name, Salary
    FROM Employees
    WHERE Salary > ( SELECT AVG(Salary) FROM Employees ) ;


2. Multi-row Subquery

Scenario :- Find employees who work in specific departments.

  • Returns multiple rows.
  • Used with operators like IN, ANY, ALL.
    • SELECT Name
    FROM Employees
    WHERE DepartmentID IN ( SELECT DepartmentID FROM Departments
    WHERE Location = 'India' ) ;


3. Multi-column Subquery

Scenario :- Identify current employees who are qualified for or aligned with open job positions.

  • Returns multiple rows.
  • Often used in IN or comparison with tuples.
    • SELECT Name
    FROM Employees
    WHERE (DepartmentID, JobTitle) IN ( SELECT DepartmentID, JobTitle FROM OpenPositions ) ;


4. Correlated Subquery

Scenario :- Identify employees whose salaries are higher than the average salary within their respective departments.

  • Subquery depends on the outer query for its execution.
  • Evaluated once for each row in the outer query.
    • SELECT employee_id, Name, Salary, JobTitle
    FROM Employees E
    WHERE Salary > ( SELECT AVG( Salary ) FROM Employees WHERE DepartmentID = E.DepartmentID ) ;


5. Nested Subquery

Scenario :- Find the employee(s) with the highest salary in the department located in Hyderabad.

  • Subqueries within subqueries.
  • Useful for deeply layered logic.
    • SELECT employee_id, Name, JobTitle
    FROM Employees E
    WHERE Salary =
      ( SELECT MAX(Salary) FROM Employees WHERE DepartmentID =
      ( SELECT DepartmentID FROM Departments WHERE Location = 'Hyderabad' )) ;


Using Subqueries in SQL Statements

1. Subquery in WHERE Clause

Scenario :- Retrieve employees who earn more than the average salary.

SELECT employee_id, name, salary
FROM Employees
WHERE Salary > ( SELECT AVG( salary ) FROM Employees);

2. Subquery in SELECT Clause

Scenario :- Show each employee's salary along with the company’s average salary.

SELECT employee_id, name, salary,
( SELECT AVG(salary) FROM Employees ) AS avg_salary FROM Employees ;

3. Subquery in FROM Clause (Inline View)

Scenario :- Find the highest salary in each department.

SELECT department_id, MAX(salary) AS max_salary
FROM ( SELECT department_id, salary FROM Employees )
AS temp_table GROUP BY department_id ;

4. Subquery with EXISTS

Scenario :- Check if a department has employees with a salary above $50,000.

SELECT department_id, department_name
FROM departments d WHERE EXISTS
( SELECT 1 FROM employees e WHERE e.department_id = d.department_id AND e.salary > 50000) ;

5. Subquery in UPDATE

Scenario :- Update salaries of employees by 10% in departments with fewer than 5 employees.

UPDATE employees
SET salary = salary * 1.10
WHERE department_id IN
( SELECT department_id FROM employees GROUP BY department_id HAVING COUNT(*) < 5 ) ;

6. Subquery in DELETE

Scenario :- Remove employees who haven’t worked on any projects.

DELETE FROM employees
WHERE employee_id NOT IN ( SELECT employee_id FROM project_assignments ) ;

7. Scalar Subquery

Scenario :- Use a single-value subquery to display a constant.

SELECT employee_id, name, salary,
( SELECT COUNT(*) FROM employees ) AS total_employees FROM employees ;

Advanced Scenarios

1. Combining Subqueries with Joins

Scenario 1:- Retrieve departments where the average salary exceeds the global average.

SELECT d.department_id, d.department_name
FROM departments d
JOIN ( SELECT department_id, AVG( salary ) AS avg_salary
      FROM employees
      GROUP BY department_id) temp
ON d.department_id = temp.department_id
WHERE temp.avg_salary > ( SELECT AVG( salary ) FROM employees ) ;

Scenario 2:- Rank employees based on salary within their department.

SELECT Name, DepartmentID, Salary,
( SELECT COUNT(*)
FROM Employees E2 WHERE E2.DepartmentID = E1.DepartmentID AND E2.Salary > E1.Salary ) + 1 AS Rank
FROM Employees E1 ORDER BY DepartmentID,Rank ;

- - The subquery counts the number of employees in the same department with a higher salary.
- - The rank is calculated as the count + 1.

2. Find Top-N Per Group

Scenario :- Get the highest-paid employee in each department.

SELECT Name, DepartmentID, Salary
FROM Employees E1
WHERE Salary = ( SELECT MAX(Salary)
FROM Employees E2
AND E1.DepartmentID = E2.DepartmentID);

3. Use in Complex Filtering

Scenario :- Find employees who have more than the average salary in departments located in 'UK'.

SELECT Name, Salary
FROM Employees
WHERE DepartmentID IN
( SELECT DepartmentID FROM Departments WHERE Location = 'UK')
AND Salary > ( SELECT AVG( Salary ) FROM Employees ) ;

4. Recursive Subqueries (With Clause)

Some databases like PostgreSQL or SQL Server allow recursive subqueries for hierarchical data.


Scenario :- Find all employees under a specific manager.

WITH RECURSIVE subordinates AS (
SELECT employee_id, manager_id FROM employees WHERE manager_id = 101 UNION ALL
SELECT e.employee_id, e.manager_id FROM employees e
JOIN subordinates s ON e.manager_id = s.employee_id)
SELECT * FROM subordinates ;

Do's and Don'ts with SUBQUERIES

Do's

  • Use for Modularization:- Break down complex queries into smaller, understandable subqueries.
  • Use Derived Tables for Clarity:- Use subqueries in FROM to improve readability when multiple aggregations are involved.
  • Optimize Performance:- Index columns used in subqueries for better performance.

Don'ts

  • Avoid Correlated Subqueries if Possible:- They can be inefficient due to repeated execution for each outer query row.
  • Beware of NULLs:- Ensure subqueries return expected values, handling NULL appropriately.
  • Avoid Deep Nesting:- Deeply nested subqueries can become hard to read and maintain.

Common Errors with SUBQUERIES

1. Subquery Returns Multiple Rows

  • Using = with a multi-row subquery results in an error.
  • Fix: Use IN or ANY.
    • - - Error:
    SELECT Name FROM Employees WHERE DepartmentID = ( SELECT DepartmentID FROM Departments ) ;

    - - Fix:
    SELECT Name FROM Employees WHERE DepartmentID = ( SELECT DepartmentID FROM Departments ) ;

2. NULL Handling

  • If a subquery returns NULL, comparisons may fail.
  • Fix: Fix: Use IS NOT NULL.
    • SELECT Name
    FROM Employees
    WHERE Salary > ( SELECT MAX( Salary ) FROM Employees WHERE DepartmentID IS NOT NULL ) ;

3.Performance Issues

  • Unoptimized subqueries can lead to slow queries.
  • Fix: Use EXISTS or joins where applicable.

Best Practices

  • Use Joins When Possible:- For performance, replace subqueries with joins if the logic allows.
  • Leverage EXISTS:- Use EXISTS for checking row existence instead of IN for better performance in large datasets.
  • Limit Columns in SELECT:- Ensure subqueries return only the necessary columns to minimize computation.

Database-Specific Details

Oracle:

  • Oracle supports subqueries in almost all SQL contexts and allows them in UPDATE, DELETE, and MERGE statements.

SQL Server:

  • SQL Server supports subqueries in common table expressions (CTEs) and allows correlated subqueries in CASE statements.

MySQL:

  • MySQL supports subqueries but has limitations on certain types (e.g., LIMIT in subqueries for older versions).

PostgreSQL:

  • PostgreSQL supports advanced recursive subqueries using the WITH RECURSIVE clause.
