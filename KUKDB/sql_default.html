Default

The Default Constraint in SQL is used to set a default value for a column when no value is specified during an INSERT operation.


It ensures that a column has a value even if the user does not explicitly provide one.


Key Points

Aspect Details
Purpose To automatically assign a default value to a column when no value is provided.
Behavior Applies the default value only when the column value is not explicitly set.
Data Integrity Helps maintain data integrity by preventing NULL or unintended values.
Limitations Cannot use subqueries or expressions that depend on other columns or tables.
Usage Scope Can be applied to most data types, such as numbers, strings, and dates.

Syntax(SQL Server)

1. Defining a DEFAULT Constraint During Table Creation

CREATE TABLE table_name (
    column_name data_type DEFAULT default_value ) ;

    2. Using Named Constraints

    CREATE TABLE table_name (
      ColumnName DataType,
      CONSTRAINT ConstraintName DEFAULT default_value FOR column_name ) ;

    3. Adding a DEFAULT Constraint to an Existing Table

    ALTER TABLE table_name
      ADD CONSTRAINT constraint_name DEFAULT default_value FOR column_name ;

    4. Dropping a Default Constraint

    ALTER TABLE table_name
      DROP CONSTRAINT ConstraintName ;

    ( OR )

    ALTER TABLE table_name
      ALTER COLUMN column_name DROP DEFAULT ;

    Examples

    Scenario 1:- Assign Pending as the default status for new orders.

    CREATE TABLE orders (
      order_id INT PRIMARY KEY ,
      customer_id INT,
      order_status VARCHAR(20) DEFAULT 'Pending' ) ;

    Scenario 2:- Set Default Discount Percentage for Products.

    CREATE TABLE products (
      product_id INT PRIMARY KEY ,
      product_name VARCHAR(100),
      discount_percentage INT DEFAULT 0 ) ;

    Scenario 3:- Provide Default Salary for New Hires.

    CREATE TABLE Employees (
      EmployeeID INT PRIMARY KEY ,
      EmployeeName VARCHAR(100),
      Salary DECIMAL(10, 2) DEFAULT 3000 ) ;

    Scenario 4:- Assign Default Role for Newly Created Users.

    CREATE TABLE Users (
      UserID INT PRIMARY KEY ,
      UserName VARCHAR(100),
      UserRole VARCHAR(50) DEFAULT 'User' ) ;

    Scenario 5:- Default Tax Rate for Sales.

    CREATE TABLE Sales (
      SaleID INT PRIMARY KEY ,
      SaleAmount DECIMAL(10, 2),
      TaxRate DECIMAL(5, 2) DEFAULT 0.18 ) ;

    Scenario 6:-( Adding a DEFAULT Constraint to an Existing Table ) Set Active as the default value for the status column in the employees table.

    ALTER TABLE employees
      ADD CONSTRAINT df_status DEFAULT 'Active' FOR status ;

    Scenario 7:- Remove the default value for the status column.

    ALTER TABLE employees
      ALTER COLUMN status DROP DEFAULT ;

    Scenario 8:- Set the default value of a column based on another column, where possible. For example, assigning a future delivery date for orders.

    CREATE TABLE delivery_schedule (
      delivery_id INT PRIMARY KEY ,
      order_id INT,
      delivery_date DATE DEFAULT DATEADD( DAY , 7, GETDATE() ) ) ;

    Scenario 9:- ( Dynamic Default Value Based on Another Column )

    In a Products table, the Discount column should have a default value that depends on the Category.

  • If the Category is "Electronics," the default discount is 10%
  • If the Category is "Clothing," the default discount is 20%.
  • For other categories, the default discount is 5%

    • CREATE TABLE Products (
      ProductID INT PRIMARY KEY ,
      ProductName VARCHAR(100),
      Category VARCHAR(50),
      Price DECIMAL(10, 2),
      Discount DECIMAL(5, 2) DEFAULT
        CASE
          WHEN Category = 'Electronics' THEN 10
          WHEN Category = 'Clothing' THEN 20
          ELSE 5
        END
      ) ;

    Scenario 10:- ( Default Value for Timestamps in Audit Tables ) In an AuditLogs table, automatically populate

      • Created At with the current timestamp when a new record is inserted.
      • Updated At with the same value as CreatedAt initially but updated whenever the record is modified.
    CREATE TABLE AuditLogs (
      LogID INT PRIMARY KEY ,
      Action VARCHAR(100),
      CreatedAt DATETIME DEFAULT GETDATE() ,
      UpdatedAt DATETIME DEFAULT GETDATE()
    ) ;

    Common Errors with DEFAULT

    Error Explanation Solution
    NULL Value Despite DEFAULT Default value not applied because NULL was explicitly inserted. Do not explicitly insert NULL if the DEFAULT value should be used.
    Invalid Default Expression Default expression is not supported (e.g., using a subquery). Ensure the DEFAULT value is a constant or valid function.
    Column Data Type Mismatch Default value does not match the column's data type. Provide a value compatible with the column's data type.
    Conflict With NOT NULL Default value violates a NOT NULL constraint. Ensure the DEFAULT value satisfies all column constraints.
    Default Value on Unsupported Data Types Certain databases (e.g., MySQL) do not support default values on TEXT or BLOB columns. Avoid using default constraints on unsupported data types or redesign the schema to use supported types like VARCHAR.
    Changing Existing Default Values Many databases do not support directly modifying a default value without first dropping the constraint. Drop the existing default constraint and recreate it with the new value using ALTER TABLE.

    Performance Hints with DEFAULT

    Hint Description
    Use for Frequently Used Values Ideal for columns like status, created_at, or flags.
    Combine With NOT NULL Use DEFAULT with NOT NULL to ensure valid non-null data.
    Avoid Overusing Don’t apply DEFAULT values indiscriminately; use only where meaningful.
    Test Default Behavior Verify how DEFAULT values interact with explicit NULL or DEFAULT keyword in INSERT statements.
    Consistent Formatting Use consistent formats for date or string default values.

    Do's and Don'ts with DEFAULT

    Do's Don'ts
    Define meaningful default values. Don’t use DEFAULT for columns where values must always be explicitly provided.
    Use DEFAULT with data types like DATE, INT. Don’t assume DEFAULT applies when explicitly inserting NULL.
    Combine DEFAULT with constraints. Don’t use complex expressions or subqueries as default values—they are not supported.
    Test default logic thoroughly. Don’t use arbitrary defaults that might confuse users or applications.
    Combine NOT NULL with default for stricter integrity. Don’t assume default constraints will apply to UPDATE operations.
    Use database functions for dynamic defaults. Don’t use complex or computationally expensive expressions.
